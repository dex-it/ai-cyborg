# ADR-0003 Сессия Claude Code - нативный CLI в псевдотерминале, наблюдение через хуки и файл событий

> Реконструировано из кода, не согласовано.

## Decision Drivers

- Сессия остаётся нативной: поведение и транскрипт Claude Code не отличаются от запуска в терминале (BRD, BR-001, anti-metrics).
- Дерево сессии следует за рабочим каталогом и действиями сессии (BR-002).
- Интерактивный интерфейс CLI требует настоящего терминала.

## Context

Cyborg должен показывать сессию так, как её видит пользователь в терминале, и знать, когда сессия что-то сделала
и где она сейчас работает.

## Decision

1. Сессия - процесс CLI `claude`, запущенный в псевдотерминале через логин-оболочку пользователя, чтобы
   действовало его окружение и `PATH`.
2. Cyborg не оборачивает CLI и не разбирает его вывод: вывод терминала передаётся интерфейсу как есть.
3. О ходе сессии Cyborg узнаёт только из хуков Claude Code, подключённых дополнительным файлом настроек при
   запуске: хук дописывает JSON события в файл событий своей сессии, Cyborg читает файл по мере роста.
4. Из события берутся рабочий каталог и факт активности; неполная последняя строка ждёт следующего чтения.
5. Переменные окружения, по которым CLI считает себя дочерней сессией, процессу не передаются.
6. Прочие репозитории проекта передаются сессии дополнительными каталогами.
7. Файл событий удаляется по завершении сессии; файлы событий завершённых экземпляров Cyborg удаляются при старте.
8. Проверка: сессия, запущенная из Cyborg, пишет транскрипт как терминальная; смена каталога сессией меняет корень дерева.
9. Сессия, начатая из задачи либо MR трекера, получает первое сообщение начальным позиционным аргументом CLI,
   стоящим до дополнительных каталогов; текст собирает главный процесс из проверенной ссылки на задачу либо MR и
   намерения (ревью, доработка), чужой текст (название, ветки, автор) в него не входит. Других добавок к CLI, кроме хуков, каталогов, начального промпта, инструкции изоляции
   (`--append-system-prompt`) и `--resume` при продолжении сессии (ADR-0012), нет (внешний источник: решение владельца
   2026-10-23, BRD продукта, раздел 11; расширение - Issue #10). Проверка: аргументы запуска с задачей либо MR -
   промпт первым позиционным (в том числе начинающийся с `/`), затем `--add-dir`; без них - прежние.

## Consequences

- Positive: пользователь работает с CLI без изменений; Cyborg не зависит от формата вывода.
- Negative: сведения о сессии ограничены набором событий хуков.
- Risks: смена формата событий или флагов CLI ломает наблюдение без изменения в Cyborg.

## Alternatives Considered

- **Собственный клиент через API или SDK.** Pros: полный контроль над событиями. Cons: сессия перестаёт быть нативной. Why rejected: противоречит драйверу нативности.
- **Разбор вывода терминала.** Pros: не нужны хуки. Cons: хрупко, вывод меняется с версией CLI. Why rejected: хуки дают структурированные события.
- **Первое сообщение вводом в терминал после старта.** Pros: CLI запускается как без задачи. Cons: ввод гоняется
  с готовностью интерфейса CLI. Why rejected: аргумент запуска детерминирован (п.9).
- **Промпт, собранный в интерфейсе.** Pros: проще канал. Cons: главный процесс передал бы CLI произвольный текст.
  Why rejected: п.9, недоверенный интерфейс (ADR-0002 п.5).
- **Промпт после `--add-dir`.** Pros: нет. Cons: флаг вариадичный и забирает промпт каталогом. Why rejected: п.9.
- **Канал хука через сокет или именованный канал.** Pros: без опроса файла. Cons: хук сложнее, нужен сервер. Why rejected: дозапись в файл проще и переживает гонки чтения.

## Расхождения с текущим кодом

Расхождений нет.
