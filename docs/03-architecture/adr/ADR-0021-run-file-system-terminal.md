# ADR-0021 Запуск файла: решение в главном процессе, одобрение по содержимому и команде, окно системного терминала с постоянным скриптом

> Решения по цели `run-file-in-terminal` (2026-11-15): ответы оператора о кнопке, признаках запускаемости и системном терминале (D-01, D-02, D-04 фичи 18), его команда об отказе при логин-оболочке не семейства sh (D-15 фичи 18), допущения цели, принятые оператором. Решения составителя, выведенные из кода правки, - D-05 (команда в одобрении), D-07..D-09, D-16..D-18 фичи 18, не согласованы. Опирается на ADR-0002 (интерфейсу не доверяют) и ADR-0003 (сессия - нативный CLI в своём pty).

## Decision Drivers

- Файлы репозитория меняют сессии Claude Code и чужие коммиты: имя, содержимое и первая строка файла - недоверенные данные (BR-011).
- Интерфейс показывает недоверенные данные и не решает, что запускать (ADR-0002).
- Одобрение человека относится к тому, что он видел: к содержимому и к команде, а не к имени файла.
- Терминал, транскрипт и pty сессии Claude Code не меняются (ADR-0003, BRD продукта, раздел 11).
- Новых npm-зависимостей нет.

## Context

До правки Cyborg исполнял только `claude`, `git`, CLI трекеров и `ssh`; файл репозитория он показывал и открывал приложением системы, причём исполняемый файл каналом `path:open` не открывался. Цель требует запуска файла по действию разработчика с предупреждением и запоминаемым одобрением. Запуск программы из репозитория - самая широкая возможность из всех каналов интерфейса, поэтому её граница записана отдельным решением.

## Decision

1. Интерфейс передаёт главному процессу только путь файла. Запускаемость, команду, хэш, текст предупреждения, одобрение и сообщения об отказе определяет и показывает главный процесс; интерфейс получает признак запускаемости и больше ничего. Проверка: `test/run-file.test.ts` («runnable: boolean, бит не нужен для .sh, нет для .ts, каталог - false», «регистрирует file:runnable и file:run, каждому свой обработчик с одним аргументом-путём»). Источник: ADR-0002 п.5; цель (D-06 фичи 18).
2. Путь запуска судится по физическому пути: символьная ссылка раскрывается, цель вне раскрытых разрешённых каталогов - отказ; запускаемость, хэш и ключ одобрения берутся у файла-цели. Это та же граница, что у записи Markdown, и она строже границы чтения (ADR-0002 п.5). Проверка: `test/run-file.test.ts` («путь вне разрешённых и ссылка наружу - отказ без диалога и запуска», «ссылка внутри репозитория: ключ - цель, одобрение общее»). Источник: цель; инженерный вывод (D-13 фичи 18).
3. Одобрение - пара «SHA-256 содержимого и команда запуска» на физический путь; новое заменяет прежнее. Запуск без вопроса идёт только при совпадении обоих. Проверка: `test/run-file.test.ts` («тот же хэш - без предупреждения», «хэш тот же, команда другая (после одобрения выставлен бит): спрашивает снова с новой командой»). Источник: формулировка оператора (хэш); инженерный вывод (команда, D-05 фичи 18).
4. После согласия человека путь, команда и хэш определяются заново; расхождение с показанным - отказ без запуска и без сохранения одобрения. Проверка: `test/run-file.test.ts` («файл переписан, пока открыт диалог: отказ, без запуска и одобрения», «содержимое то же, команда другая (снят бит): отказ, без запуска и одобрения»). Источник: цель (D-06 фичи 18).
5. Файл исполняется в окне системного терминала, своего pty у запуска нет. Данные - каталог файла и слова команды - передаются оболочке отдельными аргументами скрипта запуска, текст которого постоянен; эмулятору команда передаётся по элементам; на macOS сценарий для Terminal.app постоянен и получает данные аргументами `osascript`. Строка команды из предупреждения к исполнению не идёт. Проверка: `test/run-file.test.ts` («имя файла и каталога со спецсимволами: исполняется этот файл, текст из имени - нет», «форма передачи команды по эмулятору, argv поэлементно», «darwin: скрипт AppleScript постоянен, каталог и файл - отдельными элементами»). Источник: ответ оператора «Системный терминал» (D-04 фичи 18); инженерный вывод (D-08 фичи 18).
6. Скрипт запуска читает логин-оболочка пользователя, из окружения сняты маркеры сессии Claude Code и переменные Cyborg, наследуемые от сессии; на Linux эмулятор запускается процессом, не зависящим от Cyborg, на macOS Cyborg ждёт `osascript` и показывает его ошибку. Проверка: `test/run-file.test.ts` («unset всех переменных сессии», «darwin ждёт osascript и не зовёт отрыв; linux отрывает и не зовёт osascript»). Источник: цель (допущение, принятое оператором).
7. Скрипт запуска пишется на POSIX sh. Логин-оболочка, которая его не разбирает, определяется до предупреждения по имени из `SHELL`, и запуск отклоняется с названной оболочкой; на macOS так же отклоняется каталог либо команда с обратной косой чертой. Проверка: `test/run-file.test.ts` («логин-оболочка не семейства sh - отказ с её именем на обеих ОС, эмулятор не ищется», «darwin: обратная косая черта в каталоге или команде - отказ, linux её пропускает»). Источник: команда оператора (D-15 фичи 18); инженерный вывод (D-16 фичи 18).
8. Соответствие «расширение - интерпретатор» - закрытая таблица в коде; интерпретатор из shebang - только абсолютный путь из первой строки. Проверка: `test/run-file.test.ts` («без бита и shebang - по расширению», «негодный shebang: относительный, пустой, управляющие символы, не UTF-8, длинный»). Источник: ответ оператора (D-02, D-03 фичи 18); инженерный вывод (D-09 фичи 18).

Открытый вопрос: откуда брать соответствие «расширение - интерпретатор» - реестр ОС либо настройки приложения (D-03 фичи 18). Рабочий дефолт до ответа - таблица п.8.

## Consequences

- Positive: имя файла и его содержимое не становятся текстом команды; изменённый после одобрения файл без нового согласия не исполняется; терминал сессии не затронут; отказ запуска назван причиной.
- Negative: Cyborg не знает, что произошло в окне терминала, - ему виден только старт эмулятора либо ошибка `osascript`; разработчик с логин-оболочкой не семейства sh запускает файл сам; хэш большого файла считается на каждое нажатие целиком; отзыва одобрения в интерфейсе нет.
- Risks: файл может смениться между последней сверкой хэша и исполнением в эмуляторе - принято (D-07 фичи 18); эмулятор вне перечня получает команду формой `-e` и может её не принять; оболочка определяется по имени из `SHELL`, оболочка не семейства sh под другим именем не распознаётся; запуск через Terminal.app на настоящей macOS не проверен (D-11 фичи 18).
- Откат: убрать каналы `file:runnable`, `file:run` и кнопку; файл `run-approvals.json` в каталоге данных приложения можно удалить, других следов запуск не оставляет.

## Alternatives Considered

- **Свой терминал или pty в окне Cyborg.** Pros: вывод рядом с файлом, единый вид на обеих ОС. Cons: вторая разновидность терминала рядом с сессиями, своё управление жизнью процесса. Why rejected: ответ оператора «Системный терминал» (D-04 фичи 18).
- **Вопрос о запуске на клик по строке дерева.** Pros: буквально по формулировке. Cons: модальное окно на каждое открытие скрипта. Why rejected: ответ оператора «Кнопка в шапке просмотра» (D-01 фичи 18).
- **Хэш и команда от интерфейса.** Pros: меньше каналов. Cons: решение о запуске в недоверенной части. Why rejected: ADR-0002 п.5.
- **Одобрение только по хэшу.** Pros: буквально по формулировке. Cons: выставленный или снятый бит исполнения меняет команду при том же хэше. Why rejected: D-05 фичи 18.
- **История одобренных хэшей пути.** Pros: возврат к прежнему содержимому без вопроса. Cons: одобренным остаётся содержимое, которое человек давно не видел. Why rejected: осторожный вариант, принят оператором (D-05 фичи 18).
- **Временный скрипт-файл с путём в тексте.** Pros: одна форма для всех эмуляторов. Cons: подстановка пути в текст команды, уборка файла, гонка за него. Why rejected: D-08 фичи 18.
- **Формы эмуляторов с командой одной строкой.** Pros: короче. Cons: строку эмулятор разбирает сам, имя с пробелом или кавычкой ломается либо исполняется. Why rejected: D-08 фичи 18.
- **Исполнение копии файла либо передача открытого дескриптора.** Pros: закрывает окно между сверкой и исполнением. Cons: меняет `$0` и каталог, которые видит файл. Why rejected: D-07 фичи 18.
- **Запускать при любой логин-оболочке.** Pros: нет отказа. Cons: оболочка не семейства sh скрипт не разбирает, окно закрывается сразу, а Cyborg сообщает об успехе. Why rejected: команда оператора (D-15 фичи 18).
- **Свой текст скрипта под каждую оболочку.** Pros: запуск работает у всех. Cons: несколько скриптов с разным кавычением, каждый - отдельная поверхность внедрения. Why rejected: D-15 фичи 18.

## Расхождения с текущим кодом

- ADR-0002 п.5 называл `path:open` каналом, который исполняемый файл не открывает; он таким и остался, запуск идёт отдельным каналом `file:run` с проверками этого ADR (п.1-п.4).
- Проверка п.6 о логин-оболочке покрыта составом аргументов запуска; исполнение под настоящими `fish`, `tcsh` и Terminal.app автотестом не проверяется.
