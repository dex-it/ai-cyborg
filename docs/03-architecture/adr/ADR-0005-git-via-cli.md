# ADR-0005 Git-состояние читается через CLI git

> Реконструировано из кода, не согласовано.

## Decision Drivers

- Дереву нужны корень репозитория, текущая ветка и статус файлов (BR-002).
- Статус должен совпадать с тем, что видит пользователь и сама сессия в терминале.
- Без нативных зависимостей сверх терминала (ADR-0001).

## Context

Cyborg только читает git-состояние и ничего в репозитории не меняет (BRD, non-goals).

## Decision

1. Git-состояние читается вызовом установленного `git` без оболочки, с каталогом репозитория аргументом.
2. Статус берётся в машиночитаемом формате с нулевым разделителем, включая неотслеживаемые файлы.
3. Cyborg вызывает только читающие команды git.
4. Ошибка git, в том числе при сборе перекрываемых ключей (кроме кода 1 `git config` - «ключей нет»), имя ключа фильтра либо путь заполненного вложенного репозитория не в UTF-8 (через окружение такой ключ не перекрыть) и вложенность репозиториев глубже 8 уровней дают отсутствие статуса, а не ошибку интерфейса и не статус без перекрытия. Проверка: при таком входе `git status` не запускается и драйвер фильтра не выполнен.
5. Проверка: в коде нет вызова git-команды, меняющей репозиторий; статус совпадает с `git -c core.fsmonitor=false -c core.hooksPath=/dev/null status` в том же каталоге (в репозитории без драйверов фильтров в его конфиге).

## Consequences

- Positive: поведение и конфигурация как у git пользователя, кроме ключей конфига репозитория, исполняющих команды: `core.fsmonitor` и `core.hooksPath` отключаются при каждом вызове, а `filter.<имя>.clean`, `.process` и `.required` из конфига репозитория и вложенных репозиториев (не из пользовательского и системного) перекрываются при запросе статуса, где git гоняет clean-фильтр; нет библиотеки.
- Перекрываемые ключи отбирает сам git: по шаблону имени и области `local`/`worktree`, вывод читается байтами. Повторный отбор имени в JS отвергнут: регэксп JS без флага `s` расходится с ERE git и пропускал имя подсекции с U+2028, фильтр выполнялся. Незаполненный подмодуль (gitlink без `<путь>/.git`) пропускается без вызова git, как его пропускает и сам `git status`; спуск в него из `git -C` находил родителя и зацикливал сбор.
- Negative: процесс на каждый опрос.
- Risks: на больших репозиториях опрос статуса нагружает систему.

## Alternatives Considered

- **Библиотека на JS (isomorphic-git).** Pros: без внешнего бинаря. Cons: расхождения с настоящим git, медленнее. Why rejected: статус должен совпадать с git пользователя.
- **libgit2 (nodegit).** Pros: быстро. Cons: нативный модуль под Electron. Why rejected: лишняя нативная зависимость.

## Расхождения с текущим кодом

Расхождений нет.
