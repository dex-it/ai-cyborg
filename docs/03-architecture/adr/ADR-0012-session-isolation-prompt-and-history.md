# ADR-0012 Изоляция параллельных сессий инструкцией в системном промпте и история по журналам Claude Code

> Реконструировано из кода и прогона на настоящем Claude Code 2.1.310, не согласовано. Расширяет ADR-0003, п.9: у запуска
> `claude` есть добавки сверх хуков, каталогов и начального промпта. П.1 отступает от драйвера нативности - решение владельца
> открыто (D-02 фичи 09).

## Decision Drivers

- Несколько сессий в одних репозиториях правят одни файлы и меняют ветку друг под другом (BR-9001).
- Cyborg не должен ни оборачивать CLI, ни хранить свою копию истории (BR-001; ADR-0003, п.2).
- Прошлую сессию нужно найти и продолжить там же, где её начали (BR-8001).

## Context

Claude Code умеет сам уходить в отдельный worktree (`EnterWorktree`) и пишет журналы сессий в `~/.claude/projects`.
Cyborg не создаёт ветки и worktree сам (FR-1016), а историю сессий у него отнять не у кого, кроме журналов CLI.

## Decision

1. Каждой сессии при запуске (новой, из задачи или MR, продолженной) добавляется `--append-system-prompt` с инструкцией
   изоляции: «В этих репозиториях параллельно работают другие сессии. Перед первой правкой, сменой ветки или коммитом -
   EnterWorktree, дальше работа только в нём. Основной каталог - только чтение.» Решает модель: Cyborg ничего не создаёт и
   не блокирует. Используется `EnterWorktree`, а не `git worktree add`: он меняет cwd сессии, и дерево Cyborg переходит в
   worktree (ADR-0003, п.3-4).
2. Порядок аргументов: `--resume <id>` (если продолжение), `--append-system-prompt <текст>`, начальный промпт (если есть),
   `--add-dir <каталоги...>`. Промпт стоит до `--add-dir`: флаг вариадический и забрал бы промпт (ADR-0003, п.9).
3. История сессий читается из журналов Claude Code, своего хранилища у Cyborg нет. Каталог журналов репозитория -
   `~/.claude/projects/<путь репозитория, где всё кроме латинских букв и цифр заменено на «-»>`; сессии, ушедшие в worktree
   (`<репозиторий>/.claude/worktrees/<имя>`), лежат в каталоге с тем же именем и суффиксом `--claude-worktrees-<имя>` (FR-5008).
4. В список входят интерактивные сессии (запись `entrypoint: cli`) с заголовком: последний `custom-title`, иначе последний
   `ai-title`, иначе первый набранный запрос. Файл читается только с краёв (по 64 КБ), список ограничен 50 свежими.
5. Продолжение - `claude --resume <id>` в каталоге репозитория: Claude Code сам находит журнал, в том числе в каталоге
   worktree. Удаление - только выбранной сессии: файл `<id>.jsonl` и одноимённый каталог (вывод инструментов, субагенты).
   Идентификатор сессии проверяется как UUID, репозиторий - как репозиторий проекта (ADR-0002, п.5).
6. Проверка: тесты `claudeArgs` (порядок аргументов), списка, продолжения и удаления сессий, в том числе worktree;
   прогон на настоящем Claude Code 2.1.310: две параллельные сессии ушли в worktree, история показала обе, продолжение вернуло
   сессию в её worktree, удаление стёрло журнал.

## Consequences

- Positive: параллельные сессии в одних репозиториях реже затирают друг друга; история без второго хранилища.
- Negative: системный промпт сессии отличается от терминального запуска (отступление от нативности, п.1); формат журналов и
  имя каталога worktree - внутренности Claude Code, их смена ломает список.
- Risks: версия `claude` без `EnterWorktree` игнорирует инструкцию без эффекта (не проверялось); модель может не последовать
  инструкции - изоляция не гарантия.

## Alternatives Considered

- **Cyborg сам создаёт worktree перед запуском сессии.** Pros: изоляция гарантирована. Cons: Cyborg меняет репозиторий
  без запроса пользователя, вторая точка правды о каталоге сессии. Why rejected: FR-1016, ADR-0005.
- **Ничего не добавлять к запуску.** Pros: сессия строго нативна. Cons: параллельные сессии конфликтуют. Why rejected: проблема,
  ради которой собраны параллельные сессии.
- **Своё хранилище истории.** Pros: не зависит от формата журналов. Cons: дубль журнала CLI, расхождения. Why rejected: источник
  истины - Claude Code.
