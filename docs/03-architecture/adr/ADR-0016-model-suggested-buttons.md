# ADR-0016 Кнопки от модели: инструкция в системном промте, предложение в хвосте ответа, разбор по событию Stop, вставка без Enter

> Решения составителя по Issue #31 (2026-10-27), не согласованы: открытые решения - D-11..D-16, D-22 и D-23 фичи 12. Опирается на ADR-0015 (кнопки), ADR-0003
> (наблюдение за сессией через хуки) и ADR-0002 (изоляция интерфейса).

## Decision Drivers

- Часть действий ситуативна и заранее не записывается в набор (отзыв технического директора): подпись и текст кнопки знает только модель.
- Сессия остаётся нативной (BR-001): вывод терминала не разбирается и не оборачивается, Claude Code не подменяется.
- Ответ модели недоверенный: она могла прочитать файл с чужой инструкцией; предложенное не должно уходить одним нажатием.
- Новых зависимостей и процессов по возможности нет: хуки сессии уже подключены.
- Человек должен отличать заданные им кнопки от предложенных.

## Context

`SessionManager` (ADR-0003) запускает `claude` с `--settings` и хуками, которые кладут JSON событий в файл сессии; событие `Stop` несёт
`last_assistant_message` (проверено: поля события `Stop` Claude Code 2.1.311 - `session_id`, `transcript_path`, `cwd`, `prompt_id`, `permission_mode`,
`effort`, `hook_event_name`, `stop_hook_active`, `last_assistant_message`, `background_tasks`, `session_crons`). К системному промту уже дописывается
инструкция об изоляции (`--append-system-prompt`). Полоса кнопок и отправка текста - ADR-0015.

## Decision

1. Инструкция предложений (`SUGGEST_PROMPT`) дописывается к системному промту каждой сессии вместе с инструкцией об изоляции (`SESSION_PROMPT`):
   если следующие шаги понятны, в самом конце ответа, отдельной строкой, комментарий `<!-- cyborg-buttons: [{"label","text"}] -->` на 1-2 кнопки, с `"submit":true`, только если реплику можно отправить без правки; не
   очевидно - не писать. Проверка: `test/suggestions.test.ts` («инструкция сессии»), `test/history.test.ts`, `test/trackers.test.ts`, `test/mrs.test.ts`.
   Источник: Issue #31; D-12, D-16.
2. Главный процесс разбирает хвост `last_assistant_message` события `Stop` (`parseSuggestions`) и шлёт интерфейсу `session:suggest` с проверенным
   набором. Комментарий принимается только в самом конце сообщения (последний маркер), тело - JSON-массив до 20 000 знаков; ошибка разбора - не событие и
   не исключение. Проверка: `test/suggestions.test.ts`, `src/main/sessions.test.ts`. Источник: Issue #31; D-12.
3. Граница доверия: принимаются только `label`, `text`, `submit`, `description` с пределами кнопок файла (ADR-0015 п.8), не больше 2, без повторов подписи;
   сочетаний клавиш и отключения нет. Кнопка без `submit` вставляет текст, Enter нажимает человек; с `submit: true` один клик отправляет текст с Enter
   (нажимает по-прежнему человек, до клика отличие видно: рамка сплошная, а не пунктир, подсказка «нажатие отправит текст с Enter»); не булево
   `submit` отбрасывает кнопку. Реплика с «!» (Claude Code выполняет её командой оболочки без запроса разрешения) отбрасывается, с «/» только
   вставляется без Enter; управляющие символы C0, C1, U+2028/2029 и переопределения направления текста отвергают кнопку. Подстановки работают как у остальных. Проверка: `test/suggestions.test.ts`, `scripts/smoke.mjs` (две кнопки: одна
   отправила Enter, другая нет). Источник: D-13, D-22; ADR-0015 п.4.
4. Предложенные кнопки живут на полосе сессии до следующего запроса человека (`UserPromptSubmit`) либо нового предложения; не сохраняются между
   запусками; снимаются, когда модель снова работает без запроса человека (`PostToolUse`) либо стоит на вопросе или запросе разрешения (`Notification`,
   кроме `idle_prompt`). Проверка: `scripts/smoke.mjs`, `src/main/sessions.test.ts`. Источник: D-14, D-23.
5. Вид: заданные кнопки нейтральные, предложенные - оттенок акцента, маркер «✦» (рамка по `submit`, как у прочих), подсказка «Предложено моделью». Проверка:
   `scripts/smoke.mjs` (цвета различаются), снимки обеих тем. Источник: D-15.
6. Редактор кнопок открывает действующий набор целиком, встроенные кнопки получили описания, у кнопки появились `description` и `disabled`
   (дополнение к ADR-0015 п.1 и п.3; порядок полосы прежний). Проверка: `test/commands.test.ts`, `scripts/smoke.mjs`. Источник: Issue #31; D-11.

## Consequences

- Positive: ситуативные кнопки без заранее написанного набора и без новых процессов и зависимостей; ничего не уходит в сессию без нажатия человека, а без Enter - пока модель не попросила `submit`; различие заданных и предложенных видно сразу.
- Negative: Claude Code показывает комментарий как обычный текст, под ответом остаются 1-3 строки JSON; к системному промту добавляется несколько десятков
  токенов; возможность отключить инструкцию настройкой не предусмотрена; сохранённая из редактора копия встроенной кнопки лежит в файле явной записью
  и правок текста и описания встроенной в новых версиях не получает.
- Risks: прочитавшая недоверенный файл модель может предложить `submit: true` под безобидной подписью, и один клик отправит её текст (смягчение: подпись и подсказка с текстом, сплошная рамка, не больше 2 кнопок, нажимает человек); модель может не следовать инструкции (кнопок не будет) либо предлагать лишнее (тогда ужесточить формулировку); Claude Code может перестать
  отдавать `last_assistant_message` в `Stop` либо изменить показ комментариев (тогда канал заменить MCP-инструментом); при частичной потере кнопки
  теряются молча: набор предложений опционален по замыслу.

## Alternatives Considered

- **MCP-инструмент `suggest_buttons`, предложение читается из `tool_input` события `PostToolUse`.** Pros: структурный вызов без разбора текста; ответ
  не засоряется комментарием. Cons: нужны MCP-сервер (процесс и протокол), согласие на инструмент, его конфигурация в `--settings`; строка вызова
  инструмента в терминале видна так же. Why rejected: D-12; выбран путь без новых процессов, MCP остаётся запасным каналом, если комментарий мешает.
- **Модель пишет файл с предложением.** Pros: простой формат. Cons: каждая запись - запрос разрешения у человека, правка файла в проекте. Why rejected: D-12.
- **Разбор экрана терминала (`xterm`) или обёртка вывода.** Pros: не нужна инструкция. Cons: хрупко, нарушает нативность сессии (BR-001), разбор того, что
  человек видит. Why rejected: D-12.
- **Отдельный вызов `claude -p` за предложениями после хода.** Pros: чистый ответ в терминале. Cons: лишний запрос, расход и отдельный контекст без
  знания сессии. Why rejected: D-12.
- **Запретить `submit` модели совсем (первая редакция).** Pros: ничего не уходит в сессию без Enter человека. Cons: на очевидную реплику («да, продолжай»)
  нужны два действия. Why rejected: D-22; граница доверия сдвинута осознанно, риск описан в Consequences.
- **Комментарий из любого места ответа.** Pros: терпимее к форме. Cons: процитированный из файла или чужого ответа комментарий стал бы кнопкой. Why rejected: D-13.
- **Настройка отключения предложений в файле воркспейса.** Pros: тишина для тех, кому не нужно. Cons: ещё одно поле формата без сигнала спроса. Why rejected: D-16.
- **Только цвет для отличия предложенных.** Pros: проще стиль. Cons: не различимо при нарушении цветового зрения. Why rejected: D-15.
