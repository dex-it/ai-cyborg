# ADR-0022 Кнопки: одно окно-форма, слои по полям с сочетанием у верхнего слоя, свои кнопки запуска в prompts.json, один писатель файлов кнопок

> Решения по цели `unified-buttons` (запрос владельца 2026-11-18, ревизии 1-3): ответы оператора об одном окне, правиле по полям, сочетании, замене кнопки, подсказках, сохранении предложенной кнопки, инструментах и откате (D-28..D-32, D-34, D-35, D-38, D-39 фичи 12; D-29, D-31 фичи 15). Решения составителя, выведенные из кода правки, - D-33, D-36, D-37 фичи 12, D-30 фичи 15, не согласованы. Меняет подход ADR-0015 (замена кнопки целиком, правка JSON в Monaco), ADR-0016 п.6 и ADR-0017 п.5, п.6; их пункты помечены, номера не сдвинуты. Опирается на ADR-0002 (интерфейсу не доверяют).

## Decision Drivers

- Владелец: «два подменю с кнопками… это лишнее, должны быть просто кнопки» - одно место правки всех кнопок, без JSON.
- Правка общей кнопки должна доходить до воркспейса, который поменял у неё одно поле: копия кнопки целиком отрезала бы её от общего набора.
- Сочетание, заданное человеком в своём слое, действует без ошибки, а не проигрывает порядку на полосе.
- Кнопки пишут три пути - окно, меню кнопки полосы, инструменты сессий; безмолвной потери чужой правки нет (D-10 фичи 12), интерфейсу и модели не доверяют.
- Новых полей в файлах `commands` и `prompts.json` сверх ключа своих кнопок запуска нет; прежние файлы читаются без правки руками, откат - без миграции.

## Context

До правки кнопки полосы правились JSON-диалогом Monaco «Воркспейс → Кнопки команд…» по слою (ADR-0015 п.3, п.10), промпты кнопок запуска - вторым диалогом «Промпты кнопок…» (ADR-0017 п.6); одноимённая запись слоя заменяла нижнюю кнопку целиком, сочетание доставалось кнопке, стоящей раньше на полосе, а повтор сочетания между слоями был замечанием. Свои кнопки запуска сессий завести было нельзя: `prompts.json` знал только пять встроенных id. Писали файлы два канала (`commands:save`, `prompts:save`) без сверки с тем, что видел человек.

## Decision

1. Набор кнопок полосы строится слоями по полям: встроенные, общий слой всех воркспейсов, слой воркспейса - каждый поверх предыдущего, правило одно для обоих верхних слоёв. Запись с подписью кнопки нижнего слоя (без учёта регистра) меняет только названные поля, остальные берутся снизу; запись со своим `text` задаёт и `submit` (нет поля - только вставить, Enter снизу не наследуется); `"hotkey": null` снимает сочетание; `"disabled": false` верхнего слоя перекрывает выключение нижнего; запись без `text`, у которой ниже нет кнопки той же подписи, - замечание при чтении и отказ при записи; копия кнопки нижнего слоя ничего не меняет. Окно пишет в файл слоя только поля, отличные от нижнего слоя; запись правки, выключения и места считается в предел 30 записей слоя. Проверка: `test/commands.test.ts` («Кнопки: правило по полям», «Кнопки: сжатие слоя», «Кнопки: предел и проверка слоя»), `scripts/smoke.mjs` (общая кнопка с правкой поля в воркспейсе). Источник: ответ оператора (D-29 фичи 12); заменяет «заменяет нижнюю» ADR-0015 п.1 и п.10.
2. Сочетание принадлежит кнопке, чьё значение сочетания взято из самого верхнего слоя: она забирает его у нижней без ошибки, у нижней в этом слое сочетания нет, окно называет, кому оно отдано, и даёт вернуть; верхняя выключена, удалена или сняла сочетание - оно снова у нижней; выключенная кнопка сочетание освобождает. Повтор сочетания внутри одного слоя - отказ при записи и замечание при чтении. Проверка: `test/commands.test.ts` («Кнопки: владение сочетанием», «Повтор сочетания внутри слоя»), `scripts/smoke.mjs` (захват F4 и «Вернуть сочетание этой кнопке»). Источник: ответ оператора (D-30 фичи 12); заменяет отказ при повторе между слоями ADR-0015 п.6.
3. Подпись - ключ записи слоя: у унаследованной кнопки она не правится; другая кнопка на месте унаследованной - операция замены (исходная выключена в слое, новая встаёт на её место и получает её сочетание, подпись новой не совпадает с кнопками нижних слоёв). Повтор подписи в слое - замечание при чтении (действует первая запись) и отказ при записи. Новых полей файла для замены нет. Проверка: `test/buttons.test.ts` («Окно «Кнопки»: операции над слоем»), `test/commands.test.ts` («Кнопки: выключение»), `scripts/smoke.mjs` (замена «Сливай» с F1). Источник: ответ оператора, ревизия 3 (D-31 фичи 12).
4. Все кнопки - полосы и запуска сессий у MR, задачи и задачи Jira - правятся в одном окне «Кнопки» формой, без JSON-текста: пункт «Воркспейс → Кнопки…» (доступен без воркспейса, тогда слой воркспейса недоступен), ⚙ в конце полосы, «Изменить «X»…» в меню кнопки полосы, «Сохранить как кнопку…» у предложенной моделью кнопки (запись - только по «Сохранить» человека). Окно показывает каждую кнопку с происхождением и пометками выбранного слоя. Файлы по-прежнему правятся и руками. Проверка: `test/menu.test.ts` (««Кнопки…» одна на оба прежних пункта…»), `test/buttons.test.ts` («Окно «Кнопки»: вид», «Окно «Кнопки»: путь формы»), `scripts/smoke.mjs` (окно и меню полосы). Источник: ответ оператора (D-28, D-35 фичи 12); заменяет ADR-0015 п.3, ADR-0016 п.6, ADR-0017 п.6.
5. Окно правит черновик и сохраняет слой целиком; главный процесс сверяет файлы, какими окно их прочитало, с диском и отказывает при расхождении, файл не меняется. Внешнее изменение окно подхватывает при возврате фокуса, при несохранённой правке - после подтверждения; негодная запись файла видна в окне с причиной, и слой с ней не сохраняется, пока её не поправят или не удалят. Проверка: `test/buttons-service.test.ts` («Кнопки: запись из окна»), `test/buttons.test.ts` («негодная запись слоя видна строкой с причиной…»), `scripts/smoke.mjs` (внешняя правка при открытом окне). Источник: инженерный вывод (D-36 фичи 12).
6. Файлы кнопок (поле `commands` воркспейса, общий `commands.json`, `prompts.json`) пишет один писатель в главном процессе; все пути записи - окно, меню кнопки полосы, прежний текстовый канал слоя и инструменты сессий - проходят его одними проверками, интерфейс и модель ничего не решают; о записи интерфейс узнаёт событием и перечитывает набор. Отдельного канала записи промптов нет. Проверка: `test/buttons-service.test.ts` (все разделы), `test/commands-store.test.ts` («…saveText: запись текста слоя из редактора»), `test/remote-tools.test.ts` («инструменты кнопок»). Источник: инженерный вывод (D-37 фичи 12); ADR-0002 п.5; заменяет ADR-0017 п.5 в части канала записи.
7. Свои кнопки запуска сессий лежат в `prompts.json` под ключом `buttons` (массив `{place, label, text, description?, disabled?}`, не больше 30), действуют во всех воркспейсах и стоят после встроенных своего места; текст первого сообщения - одно правило для встроенных и своих (одна строка до 2000 знаков, не с «-», только подстановки своего места); встроенные кнопки запуска не выключаются. Негодная своя кнопка видна на карточке недоступной с причиной, не мешает встроенным и другим своим; при открытой по записи сессии - «К сессии», вторая сессия не открывается. У кнопок запуска - подсказка с описанием и промптом. Проверка: `test/prompts.test.ts` («Свои кнопки запуска: prompts.json», «Правило текста первого сообщения: одно для встроенных и своих кнопок»), `test/buttons-service.test.ts` («Кнопки: сбой prompts.json не мешает полосе», «Кнопки: происхождение кнопок запуска»), `scripts/smoke.mjs` (своя кнопка запуска). Источник: ответ оператора (D-32, D-34 фичи 12), инженерный вывод (D-33 фичи 12); дополняет ADR-0017 п.1.
8. Инструменты кнопок сессии пишут через того же писателя (п.6) одной операцией над одной записью одного слоя: слой воркспейса по умолчанию, все воркспейсы и кнопки запуска - только по слову человека, текст модели фильтруется строже предложений (ведущий «!» - отказ; у кнопки полосы «/» и «#» - без Enter; у кнопки запуска «#» - отказ). Устройство на стороне сервера - ADR-0019 п.10. Проверка: `test/buttons-service.test.ts` («Кнопки: инструменты сессии»), `test/buttons.test.ts` («Инструменты кнопок: форма аргументов»). Источник: ответ оператора (D-29, D-31 фичи 15), инженерный вывод (D-30 фичи 15).
9. Запись инструмента видна у полосы вызвавшей сессии уведомлением с «Отменить» и «Изменить…», кнопка помечена «новая», пока человек не наведёт на неё или не откроет её в окне. «Отменить» снимает только запись этого вызова; запись, изменённая после вызова, не снимается - отказ с причиной. Журнал отмены - в памяти главного процесса, до 50 вызовов, в файлы не пишется. Проверка: `test/buttons-service.test.ts` («Кнопки: отмена вызова»), `scripts/smoke.mjs` (add_button через MCP, уведомление, «Отменить»). Источник: ответ оператора (D-38 фичи 12).
10. Прежние файлы читаются без правки руками по новому правилу: полная запись над общей кнопкой наследует снизу сочетание и описание, повтор сочетания между слоями не замечание. Откат кода - возврат к прежней версии без миграции: она читает частичные записи и ключ `buttons` с замечанием и файлов не портит; частичные правки и свои кнопки запуска до правки руками не действуют. Проверка: `test/commands.test.ts` («прежние файлы читаются: полная запись над общей кнопкой, копия встроенной, {label} как место», «то же сочетание в разных слоях по-прежнему не замечание»); откат - осмотр. Источник: граница цели, ответ оператора (D-39 фичи 12).

## Consequences

- Positive: все кнопки правятся в одном окне без JSON; правка общей кнопки доходит до воркспейсов, поменявших у неё одно поле; сочетание человека действует без ошибки; свои кнопки запуска заводятся рядом со встроенными; сессия записывает кнопку по фразе человека, а человек видит и отменяет запись.
- Negative: прежний файл, где воркспейс держал полную копию общей кнопки, начинает наследовать её сочетание и описание; прежняя версия Cyborg не применяет частичные правки и свои кнопки запуска; журнал отмены пропадает с выходом Cyborg; окно - отдельный код формы, не общий редактор JSON.
- Risks: модель может назначить сочетание без слова человека - держат описание инструмента и подтверждение вызова; инструменты удалённой сессии могут писать в общий слой - держат подтверждение, уведомление и «Отменить» (D-31 фичи 15).

## Alternatives Considered

- **Два пункта меню с диалогами Monaco над JSON (прежние ADR-0015 п.3, ADR-0017 п.6).** Pros: меньше кода, файл виден как есть. Cons: два места правки, JSON для человека. Why rejected: D-28 фичи 12 (ответ оператора).
- **Кнопка «Открыть файлы как JSON» в окне.** Pros: путь для опытных. Cons: второй путь записи мимо проверок окна. Why rejected: D-28 фичи 12.
- **Одноимённая запись заменяет кнопку целиком (прежний ADR-0015 п.10).** Pros: проще правило. Cons: правка общей кнопки не доходит до воркспейса. Why rejected: D-29 фичи 12.
- **Сочетание по порядку на полосе.** Pros: прежнее поведение. Cons: сочетание, заданное в своём слое, молча проигрывает. Why rejected: D-30 фичи 12.
- **Поле `replaces` для замены кнопки.** Pros: явная связь. Cons: новое поле файла, граница цели. Why rejected: D-31 фичи 12.
- **Ключи `custom.<id>` в корне `prompts.json`.** Pros: формат прежних записей. Cons: порядок держится на порядке ключей, прежняя версия называла бы замечанием каждую кнопку. Why rejected: D-32 фичи 12.
- **Запись на каждое изменение поля; сохранение без сверки с диском.** Pros: нет черновика. Cons: нет отмены, запись инструмента при открытом окне терялась бы молча. Why rejected: D-36 фичи 12.
- **Отмена возвратом снимка слоя.** Pros: проще журнал. Cons: стирает правки, сделанные после вызова. Why rejected: D-38 фичи 12.
- **Миграция файлов в новый формат.** Pros: один формат. Cons: откат портит файлы. Why rejected: D-39 фичи 12.

## Расхождения с текущим кодом

Текст уведомления в коде - «Сессия добавила / изменила / выключила / включила кнопку…», в образце цели - «Добавлена кнопка…»; формулировка открыта на суд оператора (D-38 фичи 12), норма п.9 текста не задаёт. Иных расхождений нет.
