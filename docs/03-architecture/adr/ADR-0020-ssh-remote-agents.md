# ADR-0020 Удалённые сессии по SSH: демон на хосте, строки JSON по ssh, обратный туннель к MCP, чтение клонов без правки

> Решения по цели `ssh-remote-agents` (2026-11-09) и проектированию (D-01, D-02, D-04, D-06..D-12, D-14 фичи 17); решения составителя, выведенные из кода правки, - D-03, D-05, D-13 фичи 17, не согласованы. Опирается на ADR-0003 (сессия - нативный CLI, наблюдение через хуки), ADR-0019 (MCP-сервер сессий), ADR-0002 и ADR-0005 (границы интерфейса и git).

## Decision Drivers

- Удалённая сессия должна жить без канала и без окна Cyborg: `claude` держит не `ssh`, а процесс на хосте.
- Сессия остаётся нативной (ADR-0003): `claude` в pty, состояние по хукам.
- Ключи и параметры хостов разработчик уже держит в `~/.ssh/config`; новых npm-зависимостей нет.
- Порт MCP-сервера на `127.0.0.1` Cyborg и командная строка процесса не должны покидать машину и быть видны другим пользователям хоста.
- Работа агента на хосте не должна пропасть при закрытии: клон с незапушенным остаётся.

## Context

ADR-0003 запускает `claude` в pty на машине Cyborg; ADR-0019 даёт сессиям MCP-сервер на `127.0.0.1`. Цель требует сессий на серверах, переживающих обрыв связи и выход Cyborg, и инструментов оркестратора. Демон на хосте выбирает пути клонов, поэтому он же строит аргументы `claude` (отступление от ADR-0003 п.2, пункт 9).

## Decision

1. Хост - алиас из `~/.ssh/config`, список лежит в поле `hosts` проекта; Cyborg запускает системный `ssh` без оболочки, с `BatchMode`, `ConnectTimeout` и `--` перед алиасом, пароль не запрашивает; отказ `ssh` называется причиной. Проверка: `test/remote-args.test.ts` («sshArgs и classifySshError»). Источник: цель (D-01).
2. На хосте работает демон - бандл `dist/agentd.js` (Node 18+, без зависимостей): ставится скриптом через `sh -s` в `~/.cyborg/agentd/<16 hex sha256>/` с проверкой суммы до переименования, сокет - `~/.cyborg/run/agentd.sock` под замком, мост `connect.sh` соединяет stdio `ssh` с сокетом и поднимает демона; демон выходит после 10 мин без сессий и клиентов. Проверка: `test/remote-tools.test.ts` («установка агента и проверка хоста»), `test/remote-link.test.ts` («HostLink: проверка хоста и установка демона»). Источник: цель (D-02).
3. Протокол - строки JSON по каналу, версия `PROTO` в `hello`: демон другой версии без сессий останавливается и заменяется, с сессиями и той же `PROTO` остаётся, с сессиями и другой - отказ с числом сессий. Проверка: `test/remote-link.test.ts` («старая версия…», «несовместимый демон…»). Источник: инженерный вывод (D-03).
4. Демон клонирует на хост все репозитории проекта из `origin` локальных репозиториев (уточнение ADR-0003 п.6 для хоста), ветка - `git switch` либо `git switch -c` от HEAD клона; на хосте git меняет репозиторий только демон, Cyborg на машине разработчика по-прежнему только читает и переключает ветку (ADR-0005 п.3, п.5 не меняются). Вкладка несёт набор локальных каталогов проекта, соседство ADR-0019 п.3 не меняется. Проверка: `test/agentd.test.ts` («daemon: запуск сессии»), `test/remote-link.test.ts` («демон получает хост-независимый spawn…»). Источник: цель (D-04), инженерный вывод (D-05).
5. Состояние ведётся хуками (`events.jsonl` на хосте, чтение по росту файла, строки со смещением); при обрыве Cyborg переподключается с паузами 1..60 с, вывод и события берутся с отметок, кольцо вывода 1 МиБ, сессию подхватывает только экземпляр, который её открыл. Проверка: `test/agentd.test.ts` («daemon: события и вывод», «daemon: переподключение»), `test/remote-link.test.ts` («HostLink: обрыв связи и подхват»). Источник: цель (D-07, D-08).
6. MCP-сервер Cyborg виден хосту обратным туннелем `ssh -R <сокет хоста>:127.0.0.1:<порт>`; токен лежит в `mcp.json` 0600, в `claude` идёт адрес прокси демона; без Cyborg прокси отвечает на `tools/call` ошибкой инструмента, на прочее - 503. Проверка: `test/agentd.test.ts` («daemon: прокси MCP без Cyborg», токен не в аргументах и окружении), `test/remote-tools.test.ts` («McpServer: токены удалённых сессий»). Источник: цель (D-06).
7. Дерево, статус, ветка, чтение файла и сравнение с HEAD - запросы `fs` к демону, только чтение внутри клонов сессии (`realpath`, `..` и symlink наружу отвергаются); в главном процессе канал `remote:fs` пропускает операции из белого списка, интерфейс аргументам не доверен (ADR-0002 п.5). Проверка: `test/agentd.test.ts` («daemon: файлы сессии»); канал - осмотр `src/main/main.ts`. Источник: цель (D-12).
8. Лимиты держит демон: 4 живые сессии, задача агента 240 мин, простой в `working` 30 мин, таймеры только у сессий `spawn_agent` до `report_done`; закрытие убирает клон без изменений, коммитов вне `origin`, неотслеживаемых файлов и stash, остальные остаются с путём в ответе; `keep` оставляет всё; удалённые сессии не входят в `liveDirs`, `uses`, `count` и `killAll`. Проверка: `test/agentd.test.ts` («daemon: лимиты», «daemon: report и close»), `test/remote-link.test.ts` («killAll не трогает удалённые сессии…»). Источник: цель (D-09, D-10, D-14).
9. Инструменты `spawn_agent`, `close_agent` (у локальной сессии проекта с хостами) и `report_done` (у удалённой) добавлены к ADR-0019; удалённой сессии первые два недоступны; подтверждение - запрос разрешения Claude Code (ADR-0019 п.7). Демон сам строит `claudeArgs` с системным промптом удалённой сессии (D-13), естественный выход `claude` равен закрытию без `keep`. Проверка: `test/remote-tools.test.ts` («набор инструментов по виду сессии», «createSessionTools: удалённая часть»). Источник: цель (D-11), инженерный вывод (D-13).

## Consequences

- Positive: сессия переживает обрыв и выход Cyborg; хост не требует установки сверх `~/.cyborg`; токен не виден в списке процессов хоста; незапушенная работа не пропадает при закрытии.
- Negative: на хосте живёт процесс до 10 мин после последней сессии; закрыть удалённую вкладку без связи нельзя; просмотр удалённого файла без рендера Markdown и правки; сообщение, доставленное во время обрыва, ждёт в очереди.
- Risks: сервер SSH без пересылки сокетов оставляет сессию без MCP; смена формата событий хуков ломает состояние; старые версии `claude auth status` дают другую форму вывода, и вход сочтён отсутствующим.
- Откат: удалить `~/.cyborg` на хосте и убрать поле `hosts`; версия `proto` в `hello` меняется только вместе с форматом строк, старый демон остаётся до выхода своих сессий.

## Alternatives Considered

- **`tmux` или `screen` на хосте.** Pros: готовый держатель сессии. Cons: требует установки, вывод и размер идут через его экран. Why rejected: D-02.
- **`claude` напрямую под `ssh -tt`.** Pros: проще. Cons: обрыв канала убивает сессию. Why rejected: D-02, цель.
- **Библиотека SSH на Node.** Pros: без внешнего `ssh`. Cons: новая зависимость, свои разбор `~/.ssh/config` и ключей. Why rejected: D-01.
- **Порт MCP-сервера Cyborg наружу.** Pros: без туннеля. Cons: порт доступен по сети. Why rejected: D-06.
- **Перенос рабочего дерева с машины Cyborg.** Pros: нет клонирования. Cons: тяжело и ненадёжно. Why rejected: D-04.
- **Правка файлов клона из Cyborg.** Pros: удобство. Cons: ломает работу агента. Why rejected: D-12.
- **Удалять клоны безусловно.** Pros: хост чист. Cons: пропадает незапушенное. Why rejected: D-10.

## Расхождения с текущим кодом

- ADR-0003 п.2: аргументы `claude` удалённой сессии строит демон на хосте, а не главный процесс (пункт 9, D-13).
- ADR-0003 п.6: на хосте прочие репозитории проекта - клоны демона, подключённые `--add-dir` (пункт 4).
- ADR-0005 п.5 о командах git относится к машине Cyborg; `git clone`, `git switch -c` и уборку клонов на хосте выполняет демон (пункт 4).
