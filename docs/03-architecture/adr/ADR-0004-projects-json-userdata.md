# ADR-0004 Хранение проектов - JSON-файл в каталоге профиля приложения

> Реконструировано из кода, не согласовано.

## Decision Drivers

- Состояние мало: перечень проектов, их репозитории, последний выбранный проект (BRD, раздел 9).
- Один пользователь, один процесс - конкурентного доступа нет.
- Запись не должна оставлять файл обрезанным при сбое.

## Context

Проекты и включённые у них источники задач должны переживать перезапуск приложения. Других постоянных данных у
Cyborg нет.

## Decision

1. Проекты хранятся одним JSON-файлом в каталоге профиля приложения.
2. Запись атомарна: во временный файл рядом, затем переименование поверх.
3. Отсутствующий файл читается как пустой перечень.
4. Повреждённый файл не читается как пустой и не перезаписывается молча: пользователь узнаёт о повреждении,
   прежнее содержимое сохраняется (инженерный вывод).
5. Проверка: прерванная запись оставляет прежний файл целым; повреждённый файл не теряется после старта.
6. Источники задач - поле `trackers` каждого проекта в файле проектов: два boolean `github` и `gitlab`, без
   токенов; у нового проекта оба выключены. Проект без поля либо с полем не объектом при чтении получает значения
   прежнего общего `trackers.json` (однократно: поле ложится в файл проектов со следующим сохранением); нет либо
   нечитаем `trackers.json` - оба выключены; в объекте значение не `true` - «выключен». `trackers.json` только
   читается, не пишется и не удаляется, чтобы откат на прежнюю версию сохранил общие флаги (внешний источник:
   решение оператора 2026-10-24, цель `project-task-sources`). Проверка: после сохранения в поле два boolean;
   проект без поля получает флаги `trackers.json`; `trackers.json` не пишется.

## Consequences

- Positive: нет зависимости от СУБД; файл читается и правится руками.
- Negative: нет миграций формата - смена схемы требует ручной совместимости; поле `trackers` потребовало её в виде подстановки при чтении. Откат: прежняя версия читает проект насквозь и работает по `trackers.json`.
- Risks: молчаливая потеря проектов при повреждённом файле, если пункт 4 не соблюдён.

## Alternatives Considered

- **SQLite.** Pros: транзакции, запросы. Cons: нативный модуль, избыточно для перечня. Why rejected: данных мало.
- **localStorage интерфейса.** Pros: без IPC. Cons: данные в профиле движка, недоступны главному процессу. Why rejected: проекты нужны главному процессу.

- **Общий `trackers.json` для всех проектов (прежний п.6).** Pros: формат проектов не меняется. Cons: у двух проектов
  не может быть разных источников. Why rejected: оператор сделал источники свойством проекта (2026-10-24).
  Настройки трекеров полем в файле проектов выбраны вместо него.

## Расхождения с текущим кодом

- `src/main/projects.ts:22` - любая ошибка чтения, включая повреждённый JSON, даёт пустой перечень, а выбор
  проекта при старте сохраняет состояние поверх; пункт 4. Severity: medium.
