# ADR-0004 Хранение проектов - JSON-файл в каталоге профиля приложения

> Реконструировано из кода, не согласовано.

## Decision Drivers

- Состояние мало: перечень проектов, их репозитории, последний выбранный проект (BRD, раздел 9).
- Один пользователь, один процесс - конкурентного доступа нет.
- Запись не должна оставлять файл обрезанным при сбое.

## Context

Проекты и галочки включения трекеров задач должны переживать перезапуск приложения. Других постоянных данных у
Cyborg нет.

## Decision

1. Проекты хранятся одним JSON-файлом в каталоге профиля приложения.
2. Запись атомарна: во временный файл рядом, затем переименование поверх.
3. Отсутствующий файл читается как пустой перечень.
4. Повреждённый файл не читается как пустой и не перезаписывается молча: пользователь узнаёт о повреждении,
   прежнее содержимое сохраняется (инженерный вывод).
5. Проверка: прерванная запись оставляет прежний файл целым; повреждённый файл не теряется после старта.
6. Настройки трекеров задач хранятся отдельным JSON-файлом в том же каталоге профиля, с той же атомарной записью;
   файл несёт только флаги включения источников, без токенов. Отсутствующий либо нечитаемый файл читается как «все
   источники выключены»: потеря стоит одного повторного включения (инженерный вывод). Формат файла проектов не
   меняется (внешний источник: граница цели панели задач). Проверка: после сохранения в файле только два
   boolean-флага; повреждённый файл даёт выключенные источники.

## Consequences

- Positive: нет зависимости от СУБД; файл читается и правится руками.
- Negative: нет миграций формата - смена схемы требует ручной совместимости.
- Risks: молчаливая потеря проектов при повреждённом файле, если пункт 4 не соблюдён.

## Alternatives Considered

- **SQLite.** Pros: транзакции, запросы. Cons: нативный модуль, избыточно для перечня. Why rejected: данных мало.
- **localStorage интерфейса.** Pros: без IPC. Cons: данные в профиле движка, недоступны главному процессу. Why rejected: проекты нужны главному процессу.

- **Настройки трекеров полем в файле проектов.** Pros: один файл. Cons: меняет формат проектов. Why rejected:
  граница цели - формат не меняется (п.6).

## Расхождения с текущим кодом

- `src/main/projects.ts:22` - любая ошибка чтения, включая повреждённый JSON, даёт пустой перечень, а выбор
  проекта при старте сохраняет состояние поверх; пункт 4. Severity: medium.
