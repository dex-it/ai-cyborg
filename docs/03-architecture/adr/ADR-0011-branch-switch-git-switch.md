# ADR-0011 Смена ветки - единственная изменяющая команда git, `git switch` по явному действию

> Реконструировано из кода и прогона, не согласовано. Поправляет ADR-0005, п.3 и п.5.

## Decision Drivers

- Разработчик хочет сменить ветку репозитория из дерева, не уходя в терминал (BR-7001).
- Репозиторий может быть чужим: его конфиг способен запускать команды при выписывании файлов (ADR-0005, п.4).
- Веткой репозитория, в котором идёт сессия, управляет эта сессия (BRD, раздел 3: ветку MR переключает агент).

## Context

Cyborg читал git через CLI и ничего в репозитории не менял (ADR-0005). Смена ветки из дерева - первая и единственная
операция, меняющая рабочее дерево; без явных границ она открыла бы путь к исполнению команд из конфига чужого репозитория.

## Decision

1. Единственная команда git, которая меняет репозиторий, - `git switch <ветка>`, и только по действию пользователя в меню
   ветки. Коммит, создание, удаление и принудительная смена ветки не выполняются.
2. Имя ветки принимается, только если оно есть в списке веток репозитория (локальные и ветки remote без локальной копии) и
   не начинается с `-`; иначе ошибка «Ветки <имя> нет», `git switch` не запускается. Ветка remote заводит локальную с отслеживанием
   (поведение `git switch`).
3. Вызов идёт с `-c submodule.recurse=false`: подмодули со своим непроверенным конфигом `switch` не трогает, даже если
   репозиторий задал `submodule.recurse`.
4. Репозиторий, в конфиге которого (области `local`, `worktree`) задан `filter.*`, `extensions.partialclone` либо
   `remote.*.promisor`, не переключается: выписывание файлов запустило бы smudge-фильтр, а partial clone докачивает объекты
   транспортом из конфига; `GIT_NO_LAZY_FETCH` есть только с git 2.45. Отказ называет ключ и советует сменить ветку в терминале.
5. Канал `git:switch` принимает только репозиторий проекта и отказывает, если репозиторий - рабочий либо дополнительный
   каталог работающей сессии: веткой управляет она. Отказ приходит ответом `{error}`, а не исключением.
6. Незакоммиченные правки Cyborg не трогает: `git switch` переносит их сам либо отказывает, текст отказа (первая строка
   после команды, без префикса `error:`/`fatal:`) показывается в меню ветки.
7. Проверка: тест смены ветки (локальная, remote, чужое имя, конфликт с правками, `filter.*`, `extensions.partialclone`,
   `remote.*.promisor`: ветка не меняется, команда из фильтра не выполнена); осмотр `src/main/git.ts` - вызов `switch` один.

## Consequences

- Positive: смена ветки без терминала; защита от исполнения команд из чужого конфига теми же средствами, что у статуса.
- Negative: репозитории с фильтрами и partial clone переключаются только в терминале; Cyborg перестаёт быть «только читающим».
- Risks: правка списка запрещённых ключей отстаёт от новых ключей git, запускающих команды при `switch`.

## Alternatives Considered

- **Не менять ветку из Cyborg (прежний non-goal).** Pros: Cyborg строго читает. Cons: разработчик уходит в терминал за каждой
  сменой ветки. Why rejected: возможность уже в коде, на неё опираются README и сайт; владелец поручил решать по качеству.
- **`git checkout`.** Pros: знаком. Cons: делает много разного (ветки, файлы, отсоединённая HEAD). Why rejected: `switch` создан для смены ветки.
- **Разрешить создание и удаление веток, `--force`.** Pros: полная замена терминалу. Cons: необратимые операции, вне запроса.
  Why rejected: граница - смена на существующую ветку.
- **Вызывать `git switch` и в репозитории с фильтрами, обезвредив их ключами окружения (как статус).** Pros: переключается всё.
  Cons: докачку partial clone на git старше 2.45 перекрыть нечем, а перекрытие smudge-фильтров для `switch` не проверялось.
  Why rejected: отказ безопаснее и не требует проверки каждого ключа.
