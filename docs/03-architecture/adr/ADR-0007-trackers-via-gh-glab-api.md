# ADR-0007 Задачи и MR трекеров читаются через `gh api` и `glab api`

## Decision Drivers

- Своего токена Cyborg не хранит, токен берётся из залогиненных `gh`/`glab` (brief п.2; BRD продукта, раздел 11).
- Сеть - только к трекерам (BRD продукта, раздел 3).
- Открытые задачи и MR нужны полностью, со всех страниц (SRS фичи 01, FR-1003; SRS фичи 02, FR-2002).
- Новых npm-зависимостей нет (цель, граница); внешний CLI вместо библиотеки - как у git (ADR-0005 п.1).

## Context

Панель задач показывает issues GitHub и GitLab (в том числе самохостного) по remote репозиториев проекта, её вкладка
«MR/PR» - открытые pull requests GitHub и merge requests GitLab тех же remote.

## Decision

1. Задачи, MR и состояние входа читаются вызовом установленных `gh` и `glab` без оболочки; токен CLI берёт из своей
   конфигурации, Cyborg его не читает и не передаёт (внешний источник: brief п.2).
2. Список задач и список MR - один процесс на источник: `gh api --paginate --jq <фильтр>` (объект на строку; у
   задач без pull requests) и `glab api --paginate`; склеенные значения JSON разбираются однопроходным сканером
   (инженерный вывод). Пайплайн и апрувы MR - отдельными вызовами на MR по ADR-0008.
3. Вызываются только читающие запросы: без `-X`, без полей запроса, которые переключают CLI на запись, и без
   `graphql` (внешний источник: brief панели задач п.7, «Cyborg только читает»; brief вида MR/PR п.9).
4. Множество хостов GitLab берётся из `glab auth status`; хосты remote вне этого множества и вне `github.com` не
   опрашиваются (инженерный вывод из BRD, раздел 3).
5. Отказ `glab api` распознаётся по `HTTP NNN` в stderr либо объекту с `message`, а не по коду выхода (инженерный
   вывод: проба glab 1.36 - код 0 при HTTP 401/404).
6. Окружение вызова - окружение Cyborg плюс `GH_PROMPT_DISABLED=1` и `NO_COLOR=1`; рабочий каталог вне
   репозиториев, чтобы `glab` не выводил хост из текущего (инженерный вывод).
7. Проверка: тесты сервисов задач и MR на подставном запуске CLI видят только читающие аргументы, ни одного
   `graphql` и ни одного вызова `auth token`; в `src/` нет HTTP-клиента.

## Consequences

- Positive: авторизация, прокси и самохостные хосты - как у CLI пользователя; нет зависимости.
- Negative: процесс на источник, на каждую отслеживаемую задачу или MR вне списка и на детали MR (ADR-0008); формат `glab auth status` разбирается
  как текст.
- Risks: смена формата вывода `gh`/`glab` ломает чтение без изменения в Cyborg.

## Alternatives Considered

- **Свой HTTP-клиент с токеном из `gh auth token`.** Pros: без процесса на запрос. Cons: токен в памяти и коде
  Cyborg. Why rejected: противоречит п.1 и BRD, раздел 11.
- **`gh issue list --json`, `glab issue list`.** Pros: готовые команды. Cons: у `gh` обязательный `--limit`, `glab`
  выводит текст. Why rejected: нет «всех страниц».
- **Цикл процессов по `page=N`.** Pros: простая пагинация. Cons: процесс на страницу. Why rejected: `--paginate`
  даёт все страницы одним процессом.
- **`gh api --paginate --slurp`.** Pros: один массив. Cons: несовместим с `--jq`, тянет тела задач. Why rejected:
  объём вывода.
- **Опрос `glab api --hostname H user` по хостам remote.** Pros: находит GitLab без входа. Cons: запрос к
  произвольным хостам. Why rejected: сеть не к трекерам.

## Расхождения с текущим кодом

Расхождений нет.
