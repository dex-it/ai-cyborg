# ADR-0006 Сборка esbuild, Monaco своим загрузчиком, запуск из исходников

> Реконструировано из кода и конфигурации, не согласовано.

## Decision Drivers

- Три точки входа на разных платформах: главный процесс, preload, интерфейс (ADR-0001, ADR-0002).
- Monaco требует веб-воркеров, их бандлинг сложен.
- Нативный модуль терминала собирается под ABI Electron.
- Распространения сборкой не требуется (BRD, открытый вопрос 4).

## Context

Код на TypeScript надо превратить в файлы, которые загружает Electron, быстро и без сложной конфигурации.

## Decision

1. Сборка - esbuild: главный процесс и preload - CommonJS под Node, интерфейс - IIFE под браузер; каждый бандл с картой исходников.
2. Electron и нативный модуль терминала в бандл не входят.
3. Monaco не бандлится: его готовая min-сборка копируется в выход и грузится своим AMD-загрузчиком.
4. Проверка типов отделена от сборки: esbuild не проверяет типы, это делает `tsc --noEmit`.
5. После установки зависимостей нативный модуль терминала пересобирается под Electron.
6. Развёртывание - запуск из исходников: сборка в `dist/` и старт Electron; упаковки в установщик нет. Запуск - скрипт
   `./cyborg` на `sh` для macOS и Linux: проверяет git, Node 24+ и npm, ставит зависимости при смене
   `package-lock.json`, собирает и стартует Electron (фича `05-macos-support`, FR-5001).
7. Проверка: чистая установка и старт собирают и запускают приложение без ручных шагов.
8. Тесты - встроенный `node:test`; каждый тестовый файл собирает esbuild бандлом под Node во временный каталог,
   Electron и нативный модуль терминала в бандл не входят; запуск - `npm test`. Проверка типов охватывает и тесты
   (инженерный вывод: новых npm-зависимостей нет). Проверка: `npm test` проходит на чистой установке без
   установки тестового фреймворка.

## Consequences

- Positive: быстрая сборка, конфигурация в одном скрипте.
- Negative: ошибки типов не останавливают сборку без отдельного шага.
- Risks: без упаковки приложение есть только у тех, кто собирает из исходников.

## Alternatives Considered

- **Webpack или Vite с плагином Monaco.** Pros: бандлинг воркеров. Cons: сложная конфигурация. Why rejected: AMD-загрузка снимает задачу.
- **electron-builder или Electron Forge.** Pros: установщики и обновление. Cons: конфигурация упаковки. Why rejected: распространения не требуется.

- **vitest, jest или tsx для тестов.** Pros: готовый раннер. Cons: новая зависимость. Why rejected: п.8.
- **`node --experimental-strip-types`.** Pros: без сборки. Cons: не разрешает импорты без расширения. Why
  rejected: код импортирует модули без расширения.

## Расхождения с текущим кодом
