# ADR-0010 Детали задачи - по номеру выборки главного процесса; ссылка на задачу - системным браузером из главного процесса

## Decision Drivers

- Оператор видит детали задачи и открывает её ссылкой; описание грузится при раскрытии строки (цель
  `task-details-labels`, критерии «Ссылка», «Детали», «Описание загружается при раскрытии» - ответ оператора).
- Интерфейс показывает недоверенные данные трекера и не доверен главному процессу (ADR-0002 п.5; SRS фичи 01,
  FR-1017).
- Запрос описания идёт под входом `glab`/`gh`: его хост и путь не должны задаваться интерфейсом, иначе токен уходит
  на хост вне источников проекта (цель, критерий «Канал деталей принимает только задачу, которую главный процесс
  сам вернул в списке текущей выборки»).
- Только читающие вызовы CLI трекеров (ADR-0007; SRS фичи 01, FR-1016).

## Context

Список задач возвращает канал `tasks:list` (ADR-0007). Описание в список GitHub не входит, а оператор выбрал
загрузку описания при раскрытии (D-30 фичи 01). Канал деталей MR уже принимает только номер выборки, выданный
главным процессом (ADR-0008 п.8). Окно приложения не перехватывает навигацию и открытие новых окон.

## Decision

1. Ответ `tasks:list` несёт номер выборки; главный процесс запоминает ключи и ссылки задач каждой выборки и держит
   8 последних (инженерный вывод: образец ADR-0008 п.8, перекрывающиеся выборки при смене проекта во время
   «Обновить»). Проверка: девятая выборка вытесняет первую, детали по номеру первой - отказ без вызова CLI.
2. Канал `tasks:details` принимает номер выборки и ссылку на задачу; вызов CLI идёт, только если задача с тем же
   ключом есть в этой выборке, и хост с путём берутся из запомненной выборки, а не из аргумента (внешний источник:
   цель, критерий о канале деталей). Проверка: ссылка не из выборки - ни одного вызова `gh`/`glab`.
3. Описание - один читающий вызов одиночной задачи на раскрытие (внешний источник: цель, ответ оператора «грузится
   при раскрытии»; ADR-0007). Отказ - ответом канала с текстом причины по правилам списка, без исключения
   (инженерный вывод: исключение приходит в интерфейс с обёрткой Electron). Неверные типы аргументов - исключение,
   как у прочих каналов. Проверка: вызов без `-X`, `--input` и полей запроса; отказ CLI даёт текст, а не исключение.
4. Ссылка на задачу открывается каналом `tasks:open`: главный процесс проверяет ссылку (FR-1017), строит адрес тем
   же правилом, что URL задачи, и отдаёт его системному браузеру; интерфейс адреса не передаёт и сам не
   переходит (инженерный вывод: окно без перехвата навигации ушло бы по ссылке). Проверка: ссылка с чужим хостом
   отклоняется до вызова браузера; в интерфейсе нет элемента-ссылки на адрес задачи.
5. `tasks:open` принадлежности выборке не требует (рекомендация: токен трекера в открытии не участвует, а адрес
   строится только из проверенной ссылки). Отказ браузера - ответом канала с текстом причины. Проверка: открытие
   задачи вне выборки строит адрес; отказ открытия возвращает текст.

## Consequences

- Positive: интерфейс не может направить запрос под входом трекера на произвольный хост; деталям не нужен второй
  способ проверки, отличный от MR.
- Negative: после восьми выборок без перерисовки детали старой выборки требуют «Обновить»; описание GitLab
  запрашивается повторно, хотя список его уже содержит.
- Risks: ссылка на задачу у проверенного хоста, но несуществующая, открывается в браузере - браузер покажет ошибку
  трекера.

## Alternatives Considered

- **Ссылка без номера выборки, проверка по последнему списку.** Pros: проще аргумент. Cons: при перекрывающихся
  выборках итог зависит от порядка завершения. Why rejected: п.1, п.2.
- **Непрозрачный id на каждую задачу.** Pros: тот же контроль. Cons: лишняя карта id и рассинхрон с ключом
  раскрытия в интерфейсе. Why rejected: п.2.
- **Описание GitLab из ответа списка через хранилище выборки.** Pros: без вызова на раскрытие. Cons: отступление
  от ответа оператора, два способа по виду трекера. Why rejected: п.3.
- **Ссылка `<a href target=_blank>` в интерфейсе.** Pros: без канала. Cons: ссылка уводит окно Cyborg либо
  открывает окно Electron. Why rejected: п.4.
- **Требовать выборку и у `tasks:open`.** Pros: одно правило на оба канала. Cons: открытие ломается после
  вытеснения выборки. Why rejected: п.5.

## Расхождения с текущим кодом

Расхождений нет.
