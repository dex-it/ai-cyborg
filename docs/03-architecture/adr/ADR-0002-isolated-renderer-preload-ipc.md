# ADR-0002 Изолированный интерфейс и узкий API главного процесса через preload и IPC

> Реконструировано из кода, не согласовано.

## Decision Drivers

- Интерфейс показывает содержимое произвольных файлов и вывод сессий - недоверенные данные (BR-002, BR-003).
- Рекомендация Electron по безопасности: изоляция контекста, песочница, отключённая интеграция Node в интерфейсе.
- Граница между частями из ADR-0001 должна быть явной и типизированной.

## Context

Электрон даёт интерфейсу либо прямой доступ к Node, либо изоляцию с мостом. Интерфейс Cyborg отображает данные,
которые не контролирует.

## Decision

1. Окно интерфейса работает с изоляцией контекста, в песочнице и без интеграции Node.
2. Интерфейс получает один объект API, выставленный preload-скриптом; других путей к главному процессу нет.
3. Запрос с ответом идёт вызовом с промисом; поток без ответа (ввод в сессию, размер, завершение) - отправкой
   без ответа; события главного процесса (вывод, смена каталога, активность, выход сессии) - подпиской на канал.
4. Тип API выводится из самого preload-скрипта, интерфейс пользуется этим типом.
5. Главный процесс не доверяет аргументам из интерфейса: путь к файлу и каталогу принимается, только если он лежит
   в репозиториях проектов (инженерный вывод).
6. Проверка: в настройках окна изоляция, песочница и запрет Node включены; интерфейс компилируется без доступа к Node.

## Consequences

- Positive: код в интерфейсе не получает ОС напрямую; граница видна в одном файле.
- Negative: каждая новая возможность требует канала и метода моста.
- Risks: широкий метод моста (произвольный путь) сводит изоляцию на нет.

## Alternatives Considered

- **Интеграция Node в интерфейсе.** Pros: меньше кода. Cons: любой внедрённый скрипт получает ОС. Why rejected: интерфейс показывает недоверенные данные.
- **Локальный HTTP или WebSocket сервер.** Pros: независимость интерфейса от Electron. Cons: открытый порт и своя аутентификация. Why rejected: IPC уже даёт тот же канал без сети.

## Расхождения с текущим кодом

- `src/main/main.ts:89`, `src/main/main.ts:90` - чтение каталога и файла принимают любой путь из интерфейса, проверки
  принадлежности репозиториям проектов нет; пункт 5. Severity: medium.
- `src/main/main.ts:62` - `session:create` без задачи и MR принимает любой рабочий каталог; проверка по репозиториям
  проектов включена только для сессии из задачи либо MR (`src/main/main.ts:66`, решение D-15 фичи 01); пункт 5.
  Severity: low.
