# ADR-0015 Кнопки-команды сессии: набор в файле воркспейса, подстановки в интерфейсе, отправка одной записью

> Решения составителя по Issue #26 (2026-10-27), не согласованы: открытые решения - D-01..D-07, D-09, D-10 фичи 12; D-08 принято самим
> Issue. Дополнение п.9 - решение D-11 (Issue #31). Опирается на ADR-0014 (файл воркспейса) и ADR-0002 (изоляция интерфейса).

## Decision Drivers

- Типовые фразы и слеш-команды набираются руками каждый раз (Issue #26); кнопка должна уйти в видимую сессию одним нажатием.
- Сессия остаётся нативной (BR-001): Cyborg вводит текст тем же каналом, что клавиатура, и сам ничего не отправляет.
- Опасное действие не должно отправиться без человека: опечатка в файле не должна включать отправку.
- Набор у каждого свой и меняется чаще, чем версии: правка без перезапуска и без выхода из окна.
- Интерфейсу не доверяют (ADR-0002): всё, что пишется на диск, проверяет главный процесс; Cyborg по-прежнему не правит файлы репозиториев.
- Текст кнопки с веткой, PR и задачей попадает в запрос к модели: значения проверяются до отправки.

## Context

У окна есть канал `session:input` (ввод в pty сессии) и файл воркспейса `{projects, lastProjectId}` (ADR-0014), которым владеет
`ProjectStore`; просмотрщик Monaco только читает (BRD продукта, non-goals). О сессии интерфейс знает ветку (`git:branch`), ссылку PR/MR или
задачу, из которых она начата (`Session.mr`, `Session.task`, `Session.jira`), и список MR проекта (`mrs:list`). Issue #26 называет место
(полоса под терминалом), форму кнопки `{label, text, submit, hotkey}`, подстановки, канал `session:input`, набор «по умолчанию и из
файла воркспейса», правку «пунктом меню, открывающим JSON в Monaco», и четыре «Решено не делать».

## Decision

1. Набор кнопок - встроенный (`DEFAULT_COMMANDS`: «Сливай», «Сделай PR», «Мердж» без Enter, «Приберись») плюс поле `commands` файла воркспейса.
   Одноимённая кнопка воркспейса (без учёта регистра) заменяет встроенную на её месте, остальные идут следом; кнопок воркспейса не больше 30.
   Проверка: `test/commands.test.ts` («встроенные и из воркспейса»). Источник: Issue #26 («общий набор по умолчанию и дополнения из файла
   воркспейса»); D-01, D-03.
2. Файлом владеет `ProjectStore`: `loadCommands` и `saveCommands` читают и пишут только поле `commands`, запись проектов его сохраняет,
   прочие поля файла остаются, повреждённый и не прочитанный файл не затирается (ADR-0014 п.4). Интерфейс поле в своём состоянии проектов не
   держит: иначе запись проектов затёрла бы свежую правку кнопок. Каналы `commands:load` (поле как записано) и `commands:save` (текст
   редактора). Проверка: `test/commands-store.test.ts`. Источник: ADR-0014 п.1, п.4; D-04.
3. Правка - диалог с Monaco над JSON-массивом поля `commands` из меню «Воркспейс → Кнопки команд…» (недоступно без воркспейса). Главный
   процесс сам проверяет присланный текст (`saveCommandsText` -> `checkCommandsText`): не JSON, не массив, любая проблема набора (FR-12005) и
   повтор сочетания - отказ ответом, файл не меняется; интерфейсу доверия нет. Это единственная запись файла, которую Cyborg делает по
   действию человека помимо проектов; non-goal «правка файлов в Cyborg» названо с этим исключением. Проверка: `test/commands.test.ts`,
   `test/commands-store.test.ts` («saveCommandsText»), `test/menu.test.ts`, `scripts/smoke.mjs`. Источник: Issue #26 («пунктом системного
   меню, который открывает JSON в Monaco»); D-04.
4. Отправка: интерфейс пишет в сессию каналом `session:input` текст, а Enter (`\r`) - отдельной записью через 150 мс; пока Enter не ушёл, кнопка
   занята, завершившаяся за паузу сессия Enter не получает. Отдельный Enter не зависит от того, считает ли TUI пакет «текст и Enter» вставкой, где
   Enter - перевод строки: на Claude Code 2.1.311 через pty слеш-команда `/help` и обычная фраза отправляются и пакетом, и раздельно с паузой 150 мс.
   `submit` по умолчанию `false`: опечатка в имени поля (`submt`) оставляет кнопку без Enter, а не включает отправку; лишнее поле называется в
   замечаниях. Cyborg не блокирует кнопки, пока Claude работает, и не проверяет поле ввода (Issue). Проверка: `scripts/smoke.mjs` (`got:[сливай]`,
   вставка без Enter); опыт 2026-10-27 в pty на настоящем Claude Code. Источник: Issue #26 («Отправка», «Решено не делать»); D-02, D-06, D-08.
5. Подстановки считает интерфейс в момент нажатия (он знает сессию), за один проход, значения только для подстановок, которые есть в тексте:
   `{branch}` - ветка git корня сессии; `{pr}` - ссылка PR/MR, с которого начата сессия, иначе единственный открытый PR/MR (выборка
   `mrs:list` `all`) с веткой сессии в репозиториях проекта: свой приоритетнее чужого, несколько на одном уровне - отказ с номерами, PR/MR с одинаковой
   веткой источника и назначения (из форка) не берётся; `{task}` - ключ задачи Jira либо ссылка задачи трекера. Нет значения, оно
   неоднозначно или небезопасно (ветка вне `A-Za-z0-9._/-`, прочие значения с пробелом или управляющим знаком) - текст не уходит, причина
   названа у полосы; значение вместо литерала или пустой строки не подставляется. Проверка: `test/commands.test.ts` («подстановки»),
   `test/command-values.test.ts`, `scripts/smoke.mjs`. Источник: Issue #26 («Подстановки»); D-05.
6. Сочетания клавиш: `hotkey` разбирается в код клавиши и модификаторы (`parseHotkey`), сверяется по `event.code` и точному набору модификаторов,
   обрабатывается на уровне окна для видимой сессии (`handleKey`) и не срабатывает при вводе в поле, при открытом диалоге, под панелью задач
   и при повторе клавиши. Допустимо с Alt либо Cmd, либо Ctrl с Shift; занятые приложением сочетания и повторы отвергаются, кнопка остаётся без
   сочетания. Запись из редактора отклоняет и сочетание, не годящееся на другой системе: файл воркспейса переносят между macOS и Linux. Проверка: `test/commands.test.ts` («сочетания клавиш»), `scripts/smoke.mjs` (`Alt+B`). Источник: Issue #26 (`hotkey`, `Alt+S`); D-07.
7. Набор перечитывается при старте, после записи из редактора и при возврате фокуса окну; полоса перерисовывается, только если поле изменилось.
   Наблюдателя за файлом нет. Проверка: `scripts/smoke.mjs` (правка файла снаружи подхвачена). Источник: Issue #26 («подхватываются без
   перезапуска»); D-09.
8. Файл проверяется строго при записи (любая проблема - отказ) и терпимо при чтении (файл правят и руками): негодная кнопка пропускается,
   ошибка только в `hotkey` оставляет кнопку без сочетания, всё названо с номером кнопки в замечаниях у полосы и в диалоге; `text` - одна строка
   (перевод строки был бы Enter посреди фразы), без управляющих символов, до 2000 знаков; `label` до 40. Проверка: `test/commands.test.ts`
   («разбор commands»). Источник: инженерный вывод (безмолвных fallback нет); D-10.

9. Дополнено ADR-0016 (Issue #31): у кнопки поля `description` (до 200 знаков, подсказка) и `disabled` (скрыть кнопку, в том числе встроенную); диалог правки
   открывает действующий набор целиком (встроенные с описаниями и записи файла), сохранение пишет текст редактора как есть; порядок полосы прежний.
   Проверка: `test/commands.test.ts`, `scripts/smoke.mjs`. Источник: Issue #31; D-11.

## Consequences

- Positive: типовые команды и сочетания с веткой, PR и задачей отправляются одним нажатием; набор лежит в файле воркспейса, переносится и
  версионируется вместе с ним; опечатка не включает отправку опасного действия; негодный набор не записывается, а прочтённый руками - назван, а не
  молча урезан.
- Negative: Cyborg теперь записывает файл (поле `commands`), хотя до сих пор правил только проекты; в проекте с несколькими воркспейсами набор
  не общий (одна кнопка копируется в каждый файл); сочетания ограничены общим для macOS и Linux подмножеством.
- Risks: выборка `mrs:list` для `{pr}` идёт через `gh`/`glab` при нажатии и занимает секунды; Claude Code может изменить разбор ввода, и пауза 150 мс
  станет мала (тогда Enter снова склеится с текстом: smoke ловит это лишь на подставном `claude`); PR из форка с веткой источника, отличной от
  назначения, но совпавшей с веткой сессии, принимается за PR сессии, если своего PR нет.

## Alternatives Considered

- **Набор в отдельном файле `userData`, общем для воркспейсов.** Pros: одна правка для всех воркспейсов. Cons: второй формат и второе место
  правки; Issue называет файл воркспейса. Why rejected: D-03; общий набор остаётся открытым вопросом.
- **Открыть в Monaco весь файл воркспейса.** Pros: ничего нового в каналах. Cons: правка проектов в тексте спорит с их хранением в памяти окна, а
  следующая запись проектов затирает правку. Why rejected: D-04; пишется только поле `commands`.
- **Отдельная форма настройки кнопок.** Pros: меньше шансов на ошибку JSON. Cons: Issue: «отдельный диалог не нужен»; форма на каждое поле и
  сочетание. Why rejected: D-04.
- **Открыть файл внешним редактором (`shell.openPath`).** Pros: нет записи из Cyborg. Cons: Issue называет Monaco; внешняя правка без проверки в
  Cyborg. Why rejected: D-04.
- **Подстановки в главном процессе.** Pros: значения считаются рядом с git и `gh`. Cons: ветка, ссылка начала сессии и задача известны интерфейсу, а
  `session:input` и так принимает от него любой текст; главному процессу пришлось бы повторять состояние сессий. Why rejected: D-05.
- **Текст и Enter одной записью (`text\r`).** Pros: нет таймера и состояния. Cons: отправка зависит от того, считает ли Claude Code такой пакет
  вставкой; на 2.1.311 он отправляется, на следующей версии может не отправляться. Why rejected: D-06; проверено в pty, отдельный Enter работает.
- **`term.paste`.** Pros: вставка так же, как с клавиатуры. Cons: нужен режим bracketed paste, Enter всё равно отдельно. Why rejected: D-06.
- **`submit` по умолчанию `true`.** Pros: короче типовой файл. Cons: опечатка в имени поля включает отправку опасного действия. Why rejected: D-02.
- **Только свои PR/MR для `{pr}` (выборка «автор»).** Pros: нет чужих PR и путаницы с форками. Cons: PR коллеги на ветке сессии не находился. Why rejected: D-05;
  выбор среди всех PR/MR со своим приоритетом и отсевом PR из форка.
- **Подставлять пустую строку или оставлять `{pr}` как есть при отсутствии значения.** Pros: текст всегда уходит. Cons: «смерджи PR » без адресата.
  Why rejected: D-05.
- **`fs.watch` вместо перечитывания при фокусе.** Pros: мгновенный подхват. Cons: различия платформ, сброс событий при записи через переименование.
  Why rejected: D-09.
