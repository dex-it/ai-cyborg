# ADR-0014 Воркспейс - файл проектов по любому пути, один процесс на воркспейс

> Заменяет ADR-0004. Статус `review`: решение ждёт приёмки человеком.

## Decision Drivers

- Набор проектов должен задаваться файлом, который оператор кладёт куда хочет и открывает отдельным окном (ответ оператора: «это просто 2 разных инстанса с разными конфигами»).
- Прежние данные не теряются: `userData/projects.json` остаётся рабочим воркспейсом без миграции.
- Повреждение и недоступность файла по-прежнему не затирают проекты (ADR-0004, п.4).
- Один процесс держит одно окно и один `ProjectStore`: IPC-обработчики не переделываются под несколько окон (ответ оператора).

## Context

ADR-0004 хранил проекты одним файлом в каталоге профиля. Воркспейс обобщает его: тот же файл `{projects, lastProjectId}`, но по пути, который задаёт оператор.

## Decision

1. Воркспейс - JSON-файл `{projects, lastProjectId}` по любому абсолютному пути; формат и поля проекта прежние, пути репозиториев абсолютные (ADR-0004, п.1). Проверка: `test/workspaces.test.ts` («файл воркспейса»: `ProjectStore` читает и пишет файл вне `userData`, созданный файл проходит `validateProjectsState`). Источник: ответ оператора («Формат файла проектов не меняется»).
2. Запись атомарна: временный файл рядом с `<файл>.<pid>.tmp`, затем переименование поверх; pid в имени разводит два инстанса, пишущих общие файлы `userData`. Проверка: `test/stores.test.ts` («запись JSON»). Источник: инженерный вывод.
3. Отсутствующий файл читается как пустой перечень и сам не создаётся: файл появляется первым сохранением либо окном создания воркспейса. Проверка: `test/workspaces.test.ts`. Источник: ADR-0004, п.3.
4. Повреждённый файл не читается как пустой и не перезаписывается молча: копия байт `<файл>.corrupt-<UTC YYYYMMDDTHHMMSS>` рядом с файлом воркспейса, пустой перечень, окно называет причину, путь копии и фактический путь файла воркспейса. Не прочитанный файл не затирается. Замечание отдаёт канал `projects:problem`. Проверка: `test/workspaces.test.ts` (копия рядом с файлом), `test/workspace-text.test.ts` (текст называет путь файла). Источник: ADR-0004, п.4, п.5.
5. Прерванная запись оставляет прежний файл целым; повреждённый файл не теряется после старта. Проверка: `test/stores.test.ts`. Источник: ADR-0004, п.5.
6. Источники задач - поле `trackers` проекта, подстановка из прежнего `trackers.json` при чтении, `trackers.json` только читается. Проверка: `test/stores.test.ts`. Источник: ADR-0004, п.6 (решение оператора 2026-10-24).
7. Запуск: `--workspace <файл>` или `--workspace=<файл>` задаёт воркспейс, относительный путь разрешается от рабочего каталога процесса. Значение отсутствует либо путь - каталог: окно ошибки с причиной и выход, без отката на другой воркспейс. Без `--workspace` открывается последний свободный воркспейс из «Недавних»; «Недавние» пусты, но есть `userData/projects.json` - открывается он как есть, без миграции; иначе окно первого запуска. Понятия «воркспейс по умолчанию» нет. Проверка: `test/workspaces.test.ts` (`parseWorkspaceArg`, `resolveStartup`). Источник: ответ оператора («Последний воркспейс»); тихий откат подсунул бы чужой набор проектов и позволил бы записать в него (инженерный вывод).
8. Один процесс на воркспейс. «Открыть в новом окне…», «Создать…» и «Недавние» запускают отдельный независимый процесс Cyborg с `--workspace=<файл>` и общим `--user-data-dir`; он живёт после выхода породившего, его закрытие завершает только его сессии. Неупакованный запуск передаёт путь приложения первым аргументом. Сбой запуска - окно ошибки. Инстанс без воркспейса (отмена окна первого запуска) открывает выбранный файл в своём окне, не порождая процесс. Проверка: `test/workspaces.test.ts` (`launchArgs`, `launchInstance`, открытие из меню). Источник: ответ оператора («Отдельный процесс»).
9. Замок: файл `<файл>.lock` рядом с воркспейсом, содержимое - pid. Захват создаёт его с флагом `wx`; замок мёртвого процесса перехватывается переименованием в служебное имя со сверкой pid (чужой свежий замок возвращается на место, перехват не отнимает его),  свежий файл без pid (не старше 2 с) считается занятым. Файл, открытый живым инстансом (в том числе текущим), второй раз не открывается: «Воркспейс уже открыт», процесс не запускается; запуск `--workspace` на занятый файл - отказ окном и выход. Каталог без записи замка не даёт, воркспейс открывается без него. Замок снимается при выходе, только если в нём свой pid. Прежний `projects.json` блокируется так же. Проверка: `test/workspaces.test.ts` («замок открытого воркспейса»), `scripts/smoke.mjs` (замок с pid живого процесса, снят после SIGTERM). Источник: ответ оператора («Не открывать второй раз»); реюз pid чужим процессом даёт ложный отказ, сообщение называет файл замка для ручного удаления (инженерный вывод).
10. «Недавние»: `userData/recent-workspaces.json` вида `{"recent": [пути]}`, общий для инстансов, до 10 канонических путей, последний открытый сверху; недоступный для записи список открытие не блокирует. Пропавший файл при старте пропускается и остаётся в списке, при клике по нему называется ошибкой и убирается из списка. Проверка: `test/workspaces.test.ts` («Недавние»). Источник: ответ оператора («Файл в userData»); поведение пропавшего пути - практика «Недавних» настольных приложений.
11. Настройки интерфейса (`localStorage`) каждого воркспейса живут в своей сессии Chromium `userData/workspaces/<первые 16 знаков sha256 канонического пути файла>`; у прежнего `projects.json` сессия прежняя (по умолчанию), чтобы настройки не потерялись; окно без воркспейса - сессия в памяти. Перенос файла теряет только настройки интерфейса. Проверка: `test/workspaces.test.ts` (`sessionDirOf`), `scripts/smoke.mjs` (настройки пережили перезапуск воркспейса). Источник: ответ оператора («настройки переживают перезапуск»).
12. Окно первого запуска создаёт воркспейс: имя, файл (по умолчанию `~/<имя>.cyborg.json`) и первый проект с хотя бы одним репозиторием; существующий файл не перезаписывается (`wx`), окно предлагает открыть его. Проверка: `test/workspaces.test.ts` (создание), `test/workspace-text.test.ts`, `scripts/smoke.mjs` (первый запуск). Источник: ответ оператора («Имя, место и проект»; «автоматом сохранить»); отказ от перезаписи - ADR-0004, п.4.

## Consequences

- Positive: набор проектов переносится и версионируется как файл; два воркспейса работают одновременно без общего состояния окна.
- Negative: на воркспейс уходит процесс Electron; перенос файла сбрасывает настройки интерфейса; общий `userData` (`claude-hooks.json`, `trackers.json`, кэш входа) пишут все инстансы.
- Risks: pid замка, повторно выданный чужому процессу, даёт ложный отказ; два инстанса, стартующие одновременно, пишут в `recent-workspaces.json` без блокировки - выигрывает последний, одна вставка может потеряться, файл остаётся целым.

## Alternatives Considered

- **Несколько окон в одном процессе.** Pros: один процесс. Cons: IPC-обработчики держат одно окно и один `ProjectStore`. Why rejected: ответ оператора («2 разных инстанса»).
- **Воркспейс по умолчанию в `userData`.** Pros: всегда есть что открыть. Cons: лишнее понятие. Why rejected: ответ оператора («Последний воркспейс», у умолчания нет имени).
- **Миграция `projects.json` в файл воркспейса.** Pros: единый путь. Cons: запись без действия оператора, потеря настроек интерфейса. Why rejected: прежний файл открывается как есть (ответ оператора).
- **Замок в `userData` по хешу пути.** Pros: рядом с файлом ничего не лежит. Cons: замок не виден тому, кто смотрит на файл, и не переживает перенос. Why rejected: оператор выбрал замок рядом с файлом.
