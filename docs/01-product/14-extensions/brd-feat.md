# BRD фичи 14 - окно «Расширения»: магазины, плагины, скиллы, MCP и хабы

Источник: Issue #59 (2026-10-30): «посмотреть все подключённые магазины и их скиллы, а также установленные скиллы и подключённые MCP, удобное меню, согласованное с областью ответственности проектов, пространств и прочего»; дополнения владельца: «скачивание с подключённых магазинов и удаление плагинов, поиск магазинов и подключение самих магазинов по известным хабам, хабы тоже можно подключать и отключать»; «разберись и реши сам». Решения составителя - `decision-log.md`, исход «открыто» до подтверждения владельцем.

## 1. BRS overview

Сессия Claude Code берёт скиллы, плагины и серверы MCP из нескольких мест: настроек пользователя, организации, репозитория и каталогов `--add-dir`. Разработчик не видит, что именно получит сессия в этом репозитории и что общее для всех его проектов, а ставит и убирает плагины командами в терминале. Фича даёт окно «Расширения»: оно показывает магазины, плагины, скиллы, команды, агентов и серверы MCP в границах воркспейса, проекта и сессии, устанавливает и удаляет плагины, подключает и отключает магазины и ищет магазины в хабах. Адресована владельцу продукта и составителям SRS.

## 2. Business purpose

Видеть и менять набор расширений Claude Code так, как устроен Cyborg: общее для пользователя отдельно от того, что относится к проекту, репозиторию и текущей сессии; не выходя из окна и не держа команды в голове.

## 3. Business scope

Внутри границы: меню «Расширения» и окно с вкладками «Магазины», «Установленные», «MCP», «Хабы»; области «Сессия», «Проект», «Везде»; чтение магазинов, плагинов, скиллов, команд, агентов и серверов MCP; проверка связи серверов MCP по просьбе; установка и удаление плагина, подключение и отключение магазина через `claude plugin`; хабы - списки магазинов (встроенный и свои по https), их подключение, отключение, удаление и поиск магазина в них.

`non-goals`:

- включение и выключение плагинов, правка и добавление серверов MCP;
- вставка вызова скилла в промпт сессии (окно не пишет в терминал сессии);
- запись в файлы Claude Code напрямую: любое изменение - вызов `claude plugin ...`;
- подтверждение чужой команды установки, которую объявляет магазин;
- публикация плагинов и магазинов.

## 7. Mission, goals and objectives

### BR-14001 Видеть и менять расширения Claude Code в границах воркспейса, проекта и сессии

- **Требование:** разработчик из меню приложения открывает окно, в котором видны подключённые магазины плагинов с их плагинами, скиллами, командами и агентами, установленные плагины и скиллы и серверы MCP, разложенные по областям (общее для пользователя, репозиторий проекта, репозиторий сессии); устанавливает плагин из подключённого магазина и удаляет установленный, подключает магазин по адресу либо из хаба и отключает его; ведёт список хабов.
- **traced from:** BR-001.
- **rationale:**
  - reason: что получит сессия, определяют несколько файлов настроек, и из терминала это не видно целиком; установка плагинов командами требует знать область и синтаксис;
  - assumptions: состав и области определяет Claude Code (`claude plugin list`, файлы настроек); хаб - понятие Cyborg (D-07);
  - relationships: BR-001 (параллельные сессии, у каждой свой репозиторий и доп. каталоги), фича `13-file-search` (окно и вкладки того же вида), ADR-0005 (читающие команды), ADR-0018;
  - design constraints: чтение без секретов MCP, запись только вызовом `claude plugin` и по подтверждению в окне, ADR-0002 (проверка аргументов и путей каналов).
- **MOE:** по окну можно сказать, какие скиллы, плагины и серверы MCP получит сессия в этом репозитории и какие из них общие для всех проектов; плагин ставится и убирается, магазин подключается и отключается без терминала (качественная).
