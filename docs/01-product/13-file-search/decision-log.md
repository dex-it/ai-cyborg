# decision-log фичи 13 - окно поиска

Решения прогона по Issue #55 (2026-10-29). Исход «принято» - ответ владельца продукта на вопрос Issue; «открыто» - допущение, принятое за постановщика, подтверждает либо меняет владелец.

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | «Дифф» - то, чем оперирует Cyborg: изменения рабочего дерева против HEAD, как их показывает просмотр файла | дифф ветки против базы MR, поиск по истории `git log -S/-G` | ответ владельца на вопрос 1 Issue #55 | принято |
| D-02 | Постоянное поле «Найти файл» над деревом (PR #54) убрано; поиск по имени живёт в окне поиска | оставить поле скрытым за `Cmd/Ctrl+F` в дереве | ответ владельца на вопрос 2 | принято |
| D-03 | Окно вызывается отдельным верхним пунктом меню «Поиск»: «Найти файл…» с `Cmd+P` на macOS и `Ctrl+Shift+P` на Linux; для содержимого и изменений - `Cmd/Ctrl+Shift+F` (следующие шаги) | `Cmd/Ctrl+Shift+N` как в JetBrains: занят новой сессией; `Ctrl+P` на Linux: клавиша readline в терминале | ответ владельца на вопрос 3 («устраивают») | принято |
| D-04 | Запрос - подстрока; переключатель «.*» включает регулярное выражение. В режиме «Файлы» это `RegExp` JavaScript, в режиме «Текст» - `git grep -P` (PCRE2), в режиме «Изменения» - `RegExp` JavaScript в главном процессе под `vm` с таймаутом 2 с. От зависания защищают: предел 200 знаков, в «Файлах» и «Изменениях» отказ для выражений с квантором над группой с квантором (`(a+)+`), строки диффа до 1000 знаков, таймаут `git` 15 с, у PCRE2 лимит перебора | `git grep -E`: ERE системной библиотеки не знает `\b` и `\w` (проверено на macOS); разбор выражения в отдельном потоке с таймаутом: тяжелее, чем нужно для окна поиска | ответ владельца на вопрос 4; проверка 2026-10-29 | открыто: отказ по виду выражения не ловит все патологические случаи (в «Файлах» других защит нет) |
| D-05 | Ищется по корням дерева: корни активной сессии, без сессии - репозитории проекта | только корень сессии; все репозитории проекта независимо от дерева | ответ владельца на вопрос 5 | принято |
| D-06 | Режим «Файлы» ищет в имени, не в пути; вперёд идут имена, начинающиеся с совпадения, затем короткие пути, затем по алфавиту; показаны первые 500 результатов и число найденного; запрос и переключатели помнятся до закрытия приложения | нечёткое совпадение; поиск по пути; показ всех результатов (DOM не потянет) | перенос поведения PR #54 (подстрока без регистра, 500) и практика поиска файла в редакторах | открыто: владелец подтверждает подстроку вместо нечёткого поиска, предел и порядок |
| D-07 | На Linux окно вызывается `Ctrl+Shift+P`, и сочетание не проверено живьём: Linux-сборка прогонялась только смоуком | `Ctrl+P` | D-03; проверки на Linux живьём не было | открыто |
| D-08 | Один и тот же запрос-выражение разбирают два движка: `git grep -P` (PCRE2) и `RegExp` JavaScript. Их синтаксис в основном общий (`\d`, `\w`, `\b`, группы, просмотр вперёд и назад), но различается в редких местах (`(?i)` внутри выражения, `\h`, именованные группы и др.); негодное для одного движка выражение показывается его причиной | один движок для всех видов: `-P` по строкам диффа потребовал бы временных файлов и новых процессов, JavaScript в `git grep` невозможен | выбор по возможностям: `git grep -E` не знает `\b` и `\w` (проверено на macOS) | открыто: владелец принимает расхождение движков |
| D-09 | Сочетания: «Найти в файлах…» - `Cmd/Ctrl+Shift+F`, «Найти в изменениях…» - `Cmd/Ctrl+Shift+D` | `Ctrl+Shift+F` для изменений: занято содержимым; `Cmd/Ctrl+Shift+G`: в Monaco это «найти предыдущее» | `Cmd/Ctrl+Shift+F` предложено в Issue #55 и принято владельцем (D-03); `Shift+D` выбран постановщиком (D от diff), свободен в приложении | открыто: владелец подтверждает `Cmd/Ctrl+Shift+D` |
| D-10 | Поиск по изменениям берёт `git diff HEAD` (рабочее дерево и индекс против HEAD, без контекста, без переименований, подмодули не входят) и новые неигнорируемые файлы как целиком добавленные: не больше 300 файлов, каждый до 1 МиБ, двоичные и не обычные файлы пропускаются | `git diff` без `HEAD`: пропустил бы добавленное в индекс; обход подмодулей: чужие репозитории со своим конфигом; все новые файлы без предела: каталог сборки на тысячи файлов | D-01; предел защищает окно от каталога вне `.gitignore` | открыто: пределы |
| D-11 | Результат-удаление ведёт к месту удаления в рабочем файле (строка, перед которой стояла удалённая), результат-добавление - к самой строке; просмотр - диф-редактор, где удалённая строка видна рядом | открыть версию из HEAD: просмотр показывает рабочую версию | диф-редактор Monaco в инлайн-режиме не даёт перейти к удалённой строке по номеру | открыто |
| D-12 | «Целое слово»: совпадение не примыкает к `\w`, латинице с диакритикой и кириллице в «Файлах» и «Изменениях» (JavaScript); в «Тексте» работает `git grep -w` (знаки слова - буквы, цифры и `_` по локали git) | `\b` JavaScript: не знает кириллицу | практика русскоязычных репозиториев | открыто: возможно расхождение границ слова между видами поиска на не ASCII тексте |
