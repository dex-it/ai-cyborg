# SRS фичи 13 - окно поиска по файлам, содержимому и изменениям

## 1. SRS overview

Требования к окну поиска: меню «Поиск», три вида поиска (по имени файла, по содержимому файлов, по изменениям), запрос подстрокой и регулярным выражением, переход к найденной строке, каналы поиска главного процесса. Вход - BRD фичи (`brd-feat.md`, BR-13001), код `src/renderer/search-dialog.ts`, `src/renderer/search-model.ts`, `src/shared/search-pattern.ts`, `src/main/menu.ts`, `src/main/git-search.ts`, `src/main/search-args.ts`, `src/main/search-run.ts`, `src/main/files.ts`, `src/main/git.ts`. Основания решений - `decision-log.md` (D-NN).

## 2. Purpose

Задать наблюдаемое поведение поиска так, чтобы правка проверялась по требованию, а не по коду.

## 3. Scope

Окно поиска, меню «Поиск», виды «Файлы», «Текст» и «Изменения», переключатели регистра, целого слова и регулярного выражения, переход к строке в просмотре, каналы `fs:files`, `search:text`, `search:changes`. Вне фичи: замена по найденному, история коммитов, дифф ветки против базы MR, индексация, поиск по выводу терминала (`brd-feat.md`, раздел 3).

## 4. Product perspective

Окно поверх интерфейса (`<dialog>`), вызывается из меню приложения; файлы открываются тем же путём, что клик в дереве (вкладка сессии либо просмотр без сессии). Список файлов и поиск по содержимому и изменениям делает главный процесс читающими командами git (ADR-0005, ADR-0002).

## 5. Product functions

Вызов окна; поиск файла по части имени; поиск строки по содержимому и среди изменений; подстрока и регулярное выражение; открытие найденного и переход к строке; список файлов корня; каналы поиска.

## 6. User characteristics

`inherited`: BRD продукта, раздел 5.

## 7. Limitations

Только чтение; git - только читающие команды. Новых npm-зависимостей нет.

## 8. Assumptions and dependencies

Допущения D-04, D-06..D-12 открыты до подтверждения владельцем. Регулярное выражение в виде «Текст» требует git с PCRE2 (`git grep -P`); в сборке без PCRE окно говорит об этом, а подстрока работает.

## 9. Apportioning of requirements

Интерфейс: FR-13001..FR-13004, FR-13009. Главный процесс: FR-13005 (список файлов), FR-13006 (поиск по содержимому), FR-13007 (поиск по изменениям), FR-13008 (каналы), FR-13001 (меню).

## 10. Specified requirements

Общие атрибуты, если у требования не сказано иное: `feature: 13-file-search`; приоритет - обязательно; основание - Issue #55 (`brd-feat.md`); уровень верификации - модуль (`npm test`) для испытания, собранное приложение (`npm run smoke`) для демонстрации.

## 11. External interfaces

## 12. Functions

### FR-13001 Окно поиска вызывается из меню и сочетанием, на экране его нет

- **Требование:** в меню приложения есть пункт верхнего уровня «Поиск» с тремя пунктами: «Найти файл…» (`Cmd+P` на macOS, `Ctrl+Shift+P` на остальных системах), «Найти в файлах…» (`Cmd/Ctrl+Shift+F`) и «Найти в изменениях…» (`Cmd/Ctrl+Shift+D`). Пункты доступны, когда выбран проект; каждый открывает окно поиска в своём виде («Файлы», «Текст», «Изменения»). Пока окно не вызвано, на экране нет ни окна, ни поля поиска (над деревом поля нет). `Esc` и клик по затемнению закрывают окно, фокус возвращается туда, где он был. Повторный вызов при открытом окне ставит фокус в поле и выделяет набранное. Запрос помнится до закрытия приложения, вид и переключатели - между запусками.
- **traced from:** BR-13001.
- **источник:** Issue #55 («не показывался сразу, а вызывался стандартным хоткеем или из меню»); D-02, D-03, D-07, D-09.
- **rationale:** reason - постоянное поле занимает место; assumptions - D-03, D-07, D-09; relationships - FR-4006 (дерево с клавиатуры); design constraints - сочетание `Ctrl+P` в терминале Linux принадлежит readline, поэтому там `Ctrl+Shift+P`; `Cmd/Ctrl+Shift+N` занято новой сессией.
- **verification:** испытание - `test/menu.test.ts` («меню «Поиск»»); демонстрация - `scripts/smoke.mjs` (окно закрыто без вызова, каждый пункт меню открывает окно в своём виде).
- **класс:** Functions. **origin:** source.

### FR-13002 Поиск файла по части имени

- **Требование:** в виде «Файлы» окно показывает файлы, в имени которых есть набранный запрос; ищется в имени файла, не в пути. Область поиска - корни дерева: корни активной сессии, а без сессии - репозитории проекта (D-05), включая свёрнутые корни и нераскрытые каталоги; игнорируемые `.gitignore` файлы не входят (FR-13005). Порядок: имена, начинающиеся с совпадения, затем короткие пути, затем по алфавиту. Строка результата - имя с подсвеченной совпавшей частью и каталог (при нескольких корнях - с именем корня) серым. Показываются первые 500 результатов; подпись под полем: «Найдено N» либо «Найдено N, показаны первые 500»; без совпадений - «Нет совпадений»; пустой запрос - число файлов; нет проекта - «Нет проекта с репозиториями». `Enter` и клик открывают файл: вкладкой активной сессии, а без сессии - просмотром, и закрывают окно.
- **traced from:** BR-13001.
- **источник:** Issue #55; перенос поведения поля из PR #54; D-05, D-06.
- **rationale:** reason - найти файл, не раскрывая дерево; assumptions - D-06; relationships - FR-13003, FR-13005, FR-4001 (дерево), BR-003 (просмотр файла); design constraints - предел 500 строк DOM без задержки на нажатие.
- **verification:** испытание - `test/search-model.test.ts` («compileMatcher: подстрока», «matchFiles», «resultSummary и moveActive»); демонстрация - `scripts/smoke.mjs` (часть имени без учёта регистра, подсветка, «нет совпадений», `Enter` открывает файл).
- **класс:** Functions. **origin:** source.

### FR-13003 Запрос: подстрока, регистр, целое слово, регулярное выражение

- **Требование:** по умолчанию запрос - подстрока без учёта регистра. Переключатели в окне, общие для всех видов поиска: «Aa» - учитывать регистр, «W» - целое слово (совпадение не примыкает к буквам, цифрам и `_`, в том числе кириллице), «.*» - запрос как регулярное выражение. Состояние переключателей видно (`aria-pressed`) и действует сразу на показанный результат. Негодное выражение не бросает исключение: поле помечено `aria-invalid`, подпись называет причину («Выражение не разобрано: …»), список пуст. Запрос длиннее 500 знаков (выражение - 200), с переводом строки или NUL не принимается. Выражение с квантором над группой, внутри которой тоже квантор (`(a+)+`, `(.*)*`), отклоняется в видах «Файлы» и «Изменения»: у `RegExp` JavaScript нет таймаута.
- **traced from:** BR-13001.
- **источник:** просьба владельца добавить поиск регулярным выражением (Issue #55); D-04, D-08, D-12.
- **rationale:** reason - искать по шаблону и по слову; assumptions - D-04: отказ по виду выражения не ловит все патологические случаи; D-08, D-12; relationships - FR-13002, FR-13006, FR-13007; design constraints - `RegExp` не прерывается по таймауту.
- **verification:** испытание - `test/search-model.test.ts` («compileMatcher: подстрока», «целое слово», «регулярное выражение»), `test/git-search.test.ts` («validateSearchRequest и SearchRunner»); демонстрация - `scripts/smoke.mjs` (выражение находит файл, `(` называет ошибку, целое слово в виде «Текст»).
- **класс:** Functions. **origin:** source.

### FR-13004 Окно поиска управляется с клавиатуры

- **Требование:** поле запроса - `combobox` (`aria-controls` на список, `aria-activedescendant` на активную строку), список - `listbox` с подписью по виду поиска, строка - `option` с `aria-selected`; переключатели - кнопки с `aria-pressed` и подписью; виды поиска - `tablist` «Вид поиска» с `tab` («Файлы», «Текст», «Изменения»): стрелки, `Home`, `End` переводят фокус, `Enter` и пробел выбирают вид. Фокус при открытии стоит в поле. `ArrowDown` и `ArrowUp` переводят активную строку по кругу, активная прокручивается в видимую часть, `Enter` открывает её; сочетания с `Ctrl`, `Alt` и `Cmd` поле не перехватывает.
- **traced from:** BR-13001.
- **источник:** Issue #55 («с клавиатуры»); практика WAI-ARIA combobox с `aria-activedescendant` и tablist (`src/renderer/tabs.ts`).
- **rationale:** reason - фокус должен оставаться в поле, пока набирается запрос; assumptions - нет; relationships - FR-13002, FR-4006; design constraints - `<dialog>` с `aria-labelledby` (как другие окна).
- **verification:** испытание - `test/search-model.test.ts` («moveActive»), `test/tabs.test.ts`, `test/static-guards.test.ts` (подпись окон); демонстрация - `scripts/smoke.mjs` (`Enter` на активной строке, вкладки видов).
- **класс:** Functions. **origin:** source.

### FR-13005 Список файлов корня

- **Требование:** канал `fs:files` отдаёт пути файлов под корнем относительно него. В git-корне это `git ls-files -z --cached --others --exclude-standard` (отслеживаемые и новые, без игнорируемых `.gitignore`), вне git - обход каталога без `.git` не больше чем по 50 000 файлов. Путь корня проверяется так же, как в других каналах `fs:*`: корень вне репозиториев проектов и каталогов живых сессий отклоняется.
- **traced from:** BR-13001.
- **источник:** Issue #55; перенос канала из PR #54; ADR-0002, ADR-0005.
- **rationale:** reason - окну нужен весь набор файлов корня, а не раскрытые каталоги; assumptions - нет; relationships - FR-13002, FR-1017 (проверка путей); design constraints - git только читающей командой, обход ограничен.
- **verification:** испытание - `test/file-list.test.ts` (`gitFiles`, `walkFiles`), `test/allowed-paths.test.ts` (канал вне разрешённых путей).
- **класс:** Functions. **origin:** source.

### FR-13006 Поиск по содержимому файлов

- **Требование:** в виде «Текст» окно ищет строки, содержащие запрос, в файлах всех корней дерева. В git-корне поиск идёт по отслеживаемым и новым файлам без игнорируемых `.gitignore`, вне git - по каталогу целиком; двоичные файлы пропускаются. Подстрока ищется как есть (`git grep -F`), регулярное выражение - `git grep -P` (PCRE2); без учёта регистра по умолчанию (`-i`), «Aa» это снимает, «W» даёт `-w`. Запрос, начинающийся с дефиса, остаётся запросом, а не флагом git. Строка результата: текст строки без отступа (до 300 знаков) с подсвеченным совпадением и `файл:строка` (при нескольких корнях - с именем корня). Показываются первые 500 результатов; подпись: «Найдено N», «Показаны первые 500, уточните запрос» либо «Нет совпадений». Запрос уходит в git после паузы в наборе 250 мс; новый запрос отменяет прежний. Негодное выражение и git без PCRE называются причиной («Выражение не разобрано: …», «Регулярные выражения недоступны: этот git собран без PCRE»), таймаут git (15 с) - «Поиск не уложился в 15 с».
- **traced from:** BR-13001.
- **источник:** Issue #55 («поиск по содержимому»); проверка `git grep` 2026-10-29 (`-E` не знает `\b`, `-P` знает); D-04, D-06, D-08.
- **rationale:** reason - найти место в коде по тексту, а не по имени файла; assumptions - D-04, D-08, D-12; relationships - FR-13003, FR-13008, FR-13009; design constraints - ADR-0005: только читающая команда с `SAFE_CONFIG`.
- **verification:** испытание - `test/git-search.test.ts` («gitGrep»: подстрока, регистр, целое слово, выражение PCRE, негодное выражение, запрос с дефисом, вне git, предел 500, длинная строка, отмена); демонстрация - `scripts/smoke.mjs` (поиск в файлах: подсветка, целое слово, выражение, ошибка выражения).
- **класс:** Functions. **origin:** source.

### FR-13007 Поиск по изменениям

- **Требование:** в виде «Изменения» окно ищет запрос в добавленных (`+`) и удалённых (`-`) строках изменений каждого git-корня: рабочее дерево и индекс против HEAD (`git diff HEAD -U0 --no-ext-diff --no-textconv --no-renames --ignore-submodules=all`) и новые неигнорируемые файлы как целиком добавленные (не больше 300 файлов по 1 МиБ, двоичные пропускаются). Неизменённые строки не ищутся. Результат несёт знак `+` либо `-`, текст строки и `файл:строка`; у `+` номер - строка рабочего файла, у `-` - место удаления в нём. Команда `git diff` выполняется с теми же перекрытиями ключей фильтров репозитория, что `git status` (ADR-0005): внешний diff, textconv и clean-фильтр из конфига репозитория не запускаются. Выражение и «целое слово» сравниваются с строками `RegExp` JavaScript под `vm` с таймаутом 2 с: тяжёлое выражение называется причиной «Выражение слишком тяжёлое: не уложилось в 2 с», строки сравниваются обрезанными до 1000 знаков. Не git-репозиторий - «Не git-репозиторий», нет коммита HEAD - «Нет коммита HEAD для сравнения». Предел, подпись и порядок - как в FR-13006.
- **traced from:** BR-13001.
- **источник:** Issue #55 («поиск по содержимому диффа»); D-01, D-04, D-10, D-11; проверка 2026-10-29: `git diff` без `--no-ext-diff --no-textconv` запускает команды из конфига репозитория.
- **rationale:** reason - найти строку в изменениях, в том числе удалённую, которой уже нет в файле; assumptions - D-10, D-11; relationships - FR-13003, FR-13008, FR-13009, ADR-0005; design constraints - конфиг репозитория не доверенный (ADR-0005), у `RegExp` нет таймаута.
- **verification:** испытание - `test/git-search.test.ts` («parseDiff», «gitDiffSearch»: строки `+` и `-`, новые и добавленные в индекс файлы, неизменённое мимо, выражение и слово, тяжёлое выражение, не git и без коммитов, внешний diff и textconv и clean-фильтр не запускаются; «matchLines»); демонстрация - `scripts/smoke.mjs` (знак `+`, неизменённое не находится).
- **класс:** Functions. **origin:** source.

### FR-13008 Каналы поиска проверяют аргументы, отменяют устаревшее и ограничены

- **Требование:** каналы `search:text` и `search:changes` принимают запрос вида `{root, query, options}`: корень - строка из разрешённых путей (как в других каналах `fs:*`), запрос - непустая строка в пределах FR-13003 без перевода строки и NUL, переключатели - три булевых; иное отклоняется ошибкой «Некорректные аргументы поиска» до запуска git. Новый запрос того же вида и того же корня отменяет прежний и его процесс git; отменённый отвечает `cancelled`. Вывод git ограничен 16 МиБ (больше - обрыв, совпадения из прочитанного отдаются с признаком обрезки), время - 15 с.
- **traced from:** BR-13001.
- **источник:** Issue #55; ADR-0002, п.5 (проверка аргументов каналов); D-04.
- **rationale:** reason - запрос идёт аргументом git, а набор в окне порождает поток запросов; assumptions - нет; relationships - FR-13006, FR-13007, FR-1017; design constraints - ADR-0002, ADR-0005.
- **verification:** испытание - `test/git-search.test.ts` («validateSearchRequest и SearchRunner»), `test/allowed-paths.test.ts` («каналы поиска»).
- **класс:** Functions. **origin:** source.

### FR-13009 Переход к найденной строке

- **Требование:** `Enter` и клик по результату поиска по содержимому или изменениям открывают файл (вкладкой активной сессии либо просмотром без сессии; уже открытый файл показывается, а не открывается второй раз) и ставят просмотр на найденную строку: строка в центре окна редактора, курсор на ней, подсветка на 2 секунды, фокус в редакторе. У файла, изменённого против HEAD, просмотр - диф-редактор, переход идёт в рабочей версии; для удалённой строки - к месту удаления (D-11). Номер за пределом файла сводится к последней строке.
- **traced from:** BR-13001.
- **источник:** Issue #55; D-11.
- **rationale:** reason - результат поиска по строке бесполезен без перехода к ней; assumptions - D-11; relationships - FR-13006, FR-13007, BR-003; design constraints - просмотр только читает файл.
- **verification:** демонстрация - `scripts/smoke.mjs` (`Enter` на результате «Текст» ставит курсор Monaco на строку 2).
- **класс:** Functions. **origin:** source.
