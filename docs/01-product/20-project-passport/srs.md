# SRS фичи 20 - паспорт проекта

## 1. SRS overview

Требования к паспорту проекта: перечень способностей и файлов, пробел по файлам и метки, проверка файлов без нажатия, точка в строке проекта, окно «Паспорт проекта», проба агента, проверка источника и подтверждение смысловых способностей, отказ «Не нужно», проект из нескольких репозиториев, исправление пробела сессией и повторная проба, поручение начальным промптом, кандидаты в скиллы, работа без `claude`. Вход - BRD фичи (`brd-feat.md`, BR-20001), BR-013 и сценарий 19 раздела 17 BRD продукта, журнал решений фичи (`decision-log.md`, D-01..D-49). Кода и тестов у фичи пока нет: это требования следующего шага разработки. Основания решений - `decision-log.md` (D-NN).

## 2. Purpose

Задать наблюдаемое поведение паспорта проекта так, чтобы код писался по требованию, а не по догадке о поведении.

## 3. Scope

Проверка файлов паспорта в `.cyborg/passport/` репозиториев проекта, точка в строке проекта и окно «Паспорт проекта», проба агента и проверка её источника, подтверждение смысловых способностей человеком, отказ «Не нужно», главный репозиторий проекта из нескольких репозиториев, исправление пробела сессией по слову разработчика и повторная проба, поручение сессии и кандидаты в скиллы. Вне фичи (D-14, D-15, D-17, D-23): набор способностей, зашитый под процесс dex-auto, проверка только по наличию файлов, индикатор внутри карточки «Статус», кнопка на полосе сессий; профиль-переопределение набора и таблицы средств, автопроверки по таймеру, проекты по SSH, правка паспорта в окне; запись содержимого паспорта и выдача разрешений Claude Code самим Cyborg. Способ пробы, формат записи состояния и место локальных данных - решение следующего ADR (D-22), не этот документ.

## 4. Product perspective

Часть окна Cyborg рядом со списком проектов и сессиями. Исправление - обычная нативная сессия Claude Code (BR-001, ADR-0003), порядок работы сессии и worktree - ADR-0012. Кандидаты в скиллы берутся оттуда же, откуда окно «Расширения» (фича 14, ADR-0018). Окно показывает недоверенные данные по ADR-0002.

## 5. Product functions

Перечень способностей и файлов; пробел по файлам и метки; проверка файлов без нажатия; точка в строке проекта; окно с четырьмя группами; проба агента; проверка источника и подтверждение человеком; отказ «Не нужно»; главный репозиторий; исправление сессией и повторная проба; поручение начальным промптом; кандидаты в скиллы; работа без `claude`.

## 6. User characteristics

`inherited`: BRD продукта, раздел 5 (разработчик; Claude Code CLI).

## 7. Limitations

Проекты по SSH вне первой версии (D-15). Числовых пределов времени и размера файлов нет: базы измерения нет (D-20). Cyborg содержимое паспорта не пишет, состояние паспорта записывает по нажатию разработчика и не коммитит, разрешений Claude Code не выдаёт (D-17, D-23, D-46). Новых зависимостей требования не называют.

## 8. Assumptions and dependencies

Проба и исправление требуют `claude` (FR-20013); проверка файлов его не требует. Допущения D-18..D-26, D-31..D-45 и D-47..D-49 - допущения составителя, исход «открыто»: владелец продукта подтверждает или меняет. Ответы оператора на шаге SRS - D-29 (точка видна всегда, вход - клик по ней, при нуле галочка), D-30 (куда сессия пишет исправление, решает пользователь) и D-46 (состояние паспорта лежит в репозитории, Cyborg записывает его по нажатию разработчика), исход «принято владельцем». Имена способностей и файлов взяты из таблицы сессии «Организация процесса» и подтверждены владельцем не отдельно (D-21).

## 9. Apportioning of requirements

Главный процесс: проверка файлов и хранение статуса (FR-20002, FR-20003, FR-20006..FR-20009), проверка источника (FR-20007), текст поручения и сбор кандидатов (FR-20011, FR-20012), определение `claude` (FR-20013). Интерфейс: точка и окно (FR-20004, FR-20005), кнопки действий (FR-20007..FR-20010), NFR-20001 и NFR-20002. Отложено, а не отвергнуто (D-15): профиль-переопределение набора, автопроверки по таймеру, проекты по SSH, правка паспорта в окне.

## 10. Specified requirements

Общие атрибуты, если у требования не сказано иное: `feature: 20-project-passport`; приоритет - обязательно; основание - BR-20001 (`brd-feat.md`); уровень верификации - осмотр и демонстрация собранного приложения: кода и тестов у фичи нет, испытание автотестом - следующий шаг.

### FR-20002 Пробел по файлам и метки «⚠» и «≈»

- **Требование:** пробел по файлам у способности - любое из: файла способности нет; файл пуст либо в нём одни пробельные знаки; в файле осталась метка «⚠»; в файле стоит метка «≈», и разработчик её не подтвердил; в файле нет рабочей ссылки на документ проекта: Markdown-ссылки на существующий файл или каталог внутри репозитория, путь от каталога паспорта либо от корня репозитория (не адрес сети, не сам каталог паспорта, не выход за репозиторий; `#якорь` отбрасывается) (D-52). «⚠» значит «не найдено, нужен человек»; «≈» значит «черновик по коду, нужно подтвердить» (D-06: метки стоят в самом файле). Подтверждение «≈» разработчик даёт в окне «Паспорт проекта» кнопкой «Подтвердить черновик»; подтверждение Cyborg записывает в состояние паспорта в репозитории, файл способности не меняется (D-46, D-23). Подтверждение снимается, если файл изменился после него. Причина пробела в окне названа словами: «файла нет», «файл пуст», «есть ⚠», «≈ не подтверждено», «нет ссылки на документ проекта». Если в файле и «⚠», и «≈» - это один пробел, названы обе причины. Знак «≈» внутри цитаты кода в файле тоже метка: различения нет (D-32, исход открыто).
- **traced from:** BR-20001 (сценарий 19 раздела 17 BRD продукта: проверка файлов показывает число пробелов); BR-013
- **источник:** BR-20001, второй пункт «Требование» (проверка файлов); D-04, D-06, D-23, D-46; смысл меток и условия пробела - D-32, допущение составителя, исход открыто (источники называют метки, но не их смысл и не условия пробела)
- **rationale:** reason - дешёвая проверка файлов должна давать один и тот же ответ на один и тот же каталог; без названного смысла меток число пробелов нельзя ни посчитать, ни проверить; assumptions - D-32: что считается пробелом по файлам и что значат метки - допущение составителя; владелец подтверждает или меняет; relationships - FR-20001, FR-20003, FR-20004, FR-20005, FR-20007; design constraints - метки живут в файлах (D-06), подтверждение - в состоянии паспорта рядом с файлами (D-46): файл способности пишет сессия, не Cyborg (D-23).
- **verification:** осмотр - текст окна: у способности с пробелом названа причина одной из четырёх формулировок; демонстрация - проект с каталогом паспорта, где один файл отсутствует, другой пуст, третий содержит «⚠», четвёртый «≈»: в окне четыре пробела с названными причинами; подтвердить «≈» - пробел исчез, файл способности не изменился, git status показывает изменение только в `.cyborg/passport/` (запись подтверждения); изменить файл - пробел вернулся; испытание автотестом - следующий шаг, кода пока нет.
- **класс:** External interfaces. **origin:** source; условия пробела и снятие подтверждения - derived (D-32).

### FR-20011 Поручение способности начальным промптом

- **Требование:** сессия исправления пробела получает встроенное поручение своей способности начальным промптом (D-10, D-16). Поручение есть у каждой из двенадцати способностей (FR-20001); текст строит главный процесс, интерфейс передаёт только способность и проект. Поручение содержит: вопрос способности; файл паспорта и репозиторий, где он лежит (главный либо свой, FR-20009); требование держать паспорт указателем со ссылками на документы проекта и не писать в него описания, требования, решения, результаты проверок и регламенты; требование найти в проекте документ с ответом либо помочь его собрать, положив сам документ в проект по раскладке корпуса (скиллами по документации, если они есть), и только потом сослаться на него из паспорта, решения и ответы человека по ходу записывая в документы проекта (D-52); требование сначала выдать план (что выяснить, какие документы создать или править, что будет в паспорте, какие скиллы выбраны и почему) и до подтверждения разработчика файлы не править; перечень кандидатов в скиллы, если он есть (FR-20012). Скиллы поручение только усиливают и не заменяют: без них сессия исполняет встроенное поручение. FR обязывает Cyborg к тексту поручения, а не гарантирует поведение модели: сессия остаётся нативной (BR-001), Cyborg не блокирует правки до подтверждения; подтверждение плана - диалог разработчика с сессией, Cyborg его не отслеживает (D-35, исход открыто). Поручение не просит коммитить и сливать: Cyborg этого не делает сам, а как правки доходят до PR, определяет разработчик (открытый вопрос D-28).
- **traced from:** BR-20001 (сценарий 19 раздела 17 BRD продукта: по пробелу разработчик запускает исправление: сессия предлагает план); BR-013
- **источник:** BR-20001, четвёртый пункт «Требование» (поручение способности идёт начальным промптом, D-16); D-09, D-10, D-16; требование плана до правок и роль подтверждения - D-35, допущение составителя, исход открыто
- **rationale:** reason - разработчик нажал «Исправить» и ждёт, что сессия знает, что именно исправлять; план до правок оставляет решение за человеком; assumptions - D-35: подтверждение плана даёт человек в сессии; модель следует поручению, но риск, что нет, остаётся (ADR-0012: изоляция и порядок работы модели - не гарантия); relationships - FR-20010, FR-20012, FR-20001, FR-20009, ADR-0003; design constraints - поручение начальным промптом расширяет перечень добавок к CLI (D-16, ADR-0003 п.9 других добавок к CLI не допускает); правку текста ADR делает шаг ADR, а не этот документ.
- **verification:** осмотр - текст встроенного поручения у каждой из двенадцати способностей: вопрос, файл и его место, требование плана до правок, перечень кандидатов; демонстрация - «Исправить» у способности с пробелом открывает сессию, чьё первое сообщение - поручение этой способности; у проекта без скиллов оно то же, без перечня кандидатов; у проекта из нескольких репозиториев оно называет репозиторий файла; испытание автотестом - следующий шаг, кода пока нет.
- **класс:** External interfaces. **origin:** source; состав поручения - derived (D-35).

## 12. Functions

### FR-20003 Проверка файлов паспорта без нажатия

- **Требование:** проверку файлов (FR-20002) Cyborg запускает сам: при выборе проекта и при открытии окна «Паспорт проекта». Таймера нет, наблюдения за файлами нет. `claude` для проверки не нужен. Новый запуск проверки того же проекта заменяет прежний, остаётся результат последнего запуска. Результат проверки хранит Cyborg у себя, не в репозитории: он считается из файлов и состояния паспорта, это последний известный результат проекта, он остаётся и после перезапуска (D-47, D-31). Изменение файлов и состояния паспорта на диске, в том числе слияние PR с исправлением или смена ветки, точка узнаёт при следующем выборе проекта или открытии окна (D-25, D-31, исход открыто). Пока проверка идёт, точка показывает «…» (FR-20004). У проекта без каталога `.cyborg/passport/` пробелами считаются все способности, подлежащие проверке (FR-20009).
- **traced from:** BR-20001 (сценарий 19 раздела 17 BRD продукта: разработчик открывает проект без паспорта: точка показывает число пробелов по проверке файлов); BR-013
- **источник:** BR-20001, второй пункт «Требование»; раздел 11 BRD продукта (момент проверки); D-04, D-15 (автопроверки по таймеру вне первой версии); D-25, допущение составителя, исход открыто; последний результат у невыбранного проекта - D-31, допущение составителя, исход открыто
- **rationale:** reason - число пробелов должно быть перед глазами, не требуя нажатия, и не должно стоить ни сети, ни токенов; assumptions - D-25: моменты проверки - выбор проекта и открытие окна; D-31: слияние PR точка узнаёт с этих же моментов; relationships - FR-20002, FR-20004, FR-20013, NFR-20001; design constraints - способ чтения файлов и хранения результата - вне требования (D-22).
- **verification:** осмотр - в тексте поведения нет ни таймера, ни наблюдения за каталогом; демонстрация - выбрать проект без паспорта - точка показывает число без нажатий; поправить файл паспорта на диске, проект не выбирать - точка не изменилась; выбрать проект заново либо открыть окно - изменилась; отключить `claude` - число по файлам всё равно показывается; испытание автотестом - следующий шаг, кода пока нет.
- **класс:** Functions. **origin:** source; хранение последнего результата - derived (D-31).

### FR-20004 Точка в строке проекта

- **Требование:** у каждого проекта в списке проектов в строке слева стоит точка, отдельно от кнопки «Статус» (D-13, D-14). ### FR-20006 Проба агента по кнопке

- **Требование:** в окне «Паспорт проекта» есть кнопка «Проверить агентом». Без нажатия проба не идёт никогда. Проба задаёт агенту вопрос каждой способности (FR-20001) по рабочей копии проекта, и у каждой способности получается исход: «нашёл с источником», «выдумывает» либо «не знает» (D-04). Исходы Cyborg записывает в состояние паспорта в репозитории по окончании пробы (D-46, D-48); исход повторной пробы по дереву исправления Cyborg хранит у себя, в репозиторий он не пишется и исходов пробы проекта не меняет (D-47, FR-20010). Файлы способностей проба не меняет, меняется только состояние паспорта; Cyborg не коммитит. Проба идёт по всем способностям, кроме снятых «Не нужно» (FR-20008); пробу одной способности даёт только повторная проба после исправления (FR-20010). У проекта одна проба за раз, и повторная проба по одной способности (FR-20010) - тоже проба в этом правиле: пока идёт любая проба проекта, общая либо повторная, «Проверить агентом» и «Повторить пробу» у всех его способностей отключены, кнопка пробы подписана «Проба идёт…», у «Повторить пробу» названа причина «Идёт проба»; пробы разных проектов идут независимо. Прерванная или упавшая проба оставляет прежние исходы: общая - исходы пробы проекта, повторная - прежнюю строку «по дереву исправления»; причина названа в окне. Закрыли окно либо сменили проект - проба идёт до конца, исход пишется к проекту, для которого она запущена. Исход «нашёл с источником» у способности с пробелом по файлу пробел по файлу не снимает (FR-20002). До первой пробы исхода нет. Способ запуска агента и место пробы - вне этого требования (D-22).
- **traced from:** BR-20001 (сценарий 19 раздела 17 BRD продукта: проба отмечает каждую способность: нашёл с источником, выдумывает либо не знает); BR-013
- **источник:** BR-20001, второй пункт «Требование» (проба по кнопке с тремя исходами); D-04, D-22, D-46; одна проба за раз, прерывание, объём пробы - D-40, допущение составителя, исход открыто
- **rationale:** reason - проба стоит времени и токенов подписки разработчика, поэтому идёт только по его слову и не больше одной на проект; исход по каждой способности показывает, где агент выдумывает; assumptions - D-40: одна проба на проект, все способности, прерывание статус не меняет; вопрос к владельцу - нужна ли проба по одной способности и параллельные пробы; relationships - FR-20001, FR-20004, FR-20007, FR-20010, FR-20013; design constraints - способ запуска агента и место его работы - решение шага ADR (D-22), а не требование.
- **verification:** осмотр - текст окна: у каждой способности один из трёх исходов, у снятой «Не нужно» исхода нет; демонстрация - нажать «Проверить агентом» на проекте с паспортом: у каждой способности исход; пока проба идёт, кнопка отключена и подписана «Проба идёт…»; пока идёт повторная проба одной способности, «Проверить агентом» и «Повторить пробу» у любой способности отключены, вторая проба не стартует; оборвать пробу - прежние исходы на месте; после пробы git status показывает изменения только в `.cyborg/passport/` (запись исходов), файлы способностей и прочий репозиторий не изменены, после оборванной пробы git status не меняется; нет `claude` - кнопка отключена; испытание автотестом - следующий шаг, кода пока нет.

### FR-20007 Проверка источника и подтверждение смысловых способностей

- **Требование:** механическая проверка источника: источник, названный агентом (файл репозитория, при желании со строкой), есть в рабочей копии, лежит внутри неё и не указывает на каталог, а строка не выходит за конец файла. Источник разрешился - исход «нашёл с источником»; источника нет либо он не разрешается - «выдумывает»; агент отвечает, что не знает, - «не знает» (D-05). Смысловые способности - те, чей ответ знает только человек: «Зачем и для кого», «Что значит «готово»», «Границы автономии», «Грабли среды», «Кому и когда эскалировать», «Актуализация». У них исход «нашёл с источником» ждёт человека: в окне видны ответ агента (текстом, NFR-20002) и источник, разработчик выбирает «Подтвердить» либо «Не то». До подтверждения способность считается пробелом и подписана «ждёт подтверждения»; «Не то» ставит исход «выдумывает». Подтверждение Cyborg записывает в состояние паспорта в репозитории, файлы способностей не меняет (D-46, D-23); новая проба проекта (FR-20006) подтверждение снимает, повторная проба по дереву исправления (FR-20010) его не снимает и не ставит. У прочих способностей разрешившийся источник - достаточное подтверждение, человек их не подтверждает.
- **traced from:** BR-20001 (сценарий 19 раздела 17 BRD продукта: смысловую способность проба подтвердить не может - её подтверждает разработчик); BR-013
- **источник:** BR-20001, второй пункт «Требование» (источник проверяется механически где возможно, смысловые способности подтверждает человек); D-05, D-23, D-46; какие способности смысловые и что значит «источник проверен» - D-33, допущение составителя, исход открыто (источники этого не называют; основа - порода «интервью» у шести файлов в таблице сессии «Организация процесса»)
- **rationale:** reason - агент может сослаться на реальный файл, который ничего не доказывает; механика отсекает выдуманные ссылки, а смысл ответа о намерениях людей судит только человек; assumptions - D-33: перечень смысловых способностей и условие «источник проверен» - допущение составителя, владелец подтверждает или меняет; relationships - FR-20002, FR-20004, FR-20006, FR-20005, NFR-20002; design constraints - подтверждение пишется в состояние паспорта, а не в файл способности (D-46, D-23).
- **verification:** осмотр - текст окна: у смысловой способности ответ агента и источник, «Подтвердить» и «Не то»; у прочих кнопок подтверждения нет; демонстрация - проба, где агент сослался на несуществующий файл, - «выдумывает»; смысловая способность найдена с источником - «ждёт подтверждения» и пробел в точке, после «Подтвердить» пробела нет, после «Не то» - «выдумывает»; механическая способность с разрешившимся источником пробелом не считается без подтверждения; испытание автотестом - следующий шаг, кода пока нет.

### FR-20009 Проект из нескольких репозиториев и главный репозиторий

- **Требование:** технические способности (группа «техника») проверяются в каждом репозитории проекта; проектные (группы «продукт», «работа» и «актуализация») - только в главном, а в каждом из остальных репозиториев в `.cyborg/passport/index.md` должен быть указатель на главный. Указатель - Markdown-ссылка в любом месте файла, чей путь, отсчитанный от каталога этого `index.md`, разрешается в `.cyborg/passport/index.md` главного репозитория, отмеченного в проекте; пример верного при главном `backend`, лежащем рядом: `[Паспорт проекта](../../../backend/.cyborg/passport/index.md)`. Нет такой ссылки - пробел этого репозитория: текст без ссылки, ссылка в несуществующий путь, ссылка на другой файл (например, на `README.md` главного) либо на репозиторий, не отмеченный главным. Пока главный не отмечен, сверять не с чем: указатель не проверяется ни на наличие, ни на цель (D-07, D-38, D-45). Пока главный не отмечен, проектные способности не проверяются и проба по ним не идёт, а окно показывает «Отметьте главный репозиторий» со списком репозиториев проекта; точка показывает технические пробелы, а при нуле - «–», не «✓» (FR-20004). У проекта из одного репозитория он и есть главный, отметки не нужно, указатель не нужен. Число пробелов - сумма по репозиториям: технические пробелы каждого, проектные пробелы главного и неглавные репозитории без верного указателя (когда главный отмечен). Исход пробы технической способности - свой у каждого репозитория; в окне она показана строкой по каждому репозиторию с названием репозитория, и кнопки строки действуют на этот репозиторий. ### FR-20010 Исправление пробела сессией и повторная проба

- **Требование:** кнопка «Исправить» у способности с пробелом открывает сессию Claude Code проекта (вкладку по BR-001) с поручением этой способности (FR-20011). Поручение требует от сессии сначала план, правок до подтверждения разработчика не делать; подтверждает разработчик в самой сессии (D-09, D-35). Куда сессия пишет исправление, решает пользователь, Cyborg это не навязывает (D-30, ответ оператора, принято владельцем): по умолчанию сессия по ADR-0012 сама уходит в worktree (D-09, D-27), но если разработчик вёл сессию в текущей ветке, она пишет в неё. Дерево исправления - то, где работала сессия: её worktree либо, если вели в текущей ветке, рабочая копия проекта (у технической способности проекта из нескольких репозиториев - дерево репозитория нажатой строки); Cyborg хранит дерево исправления по способности у себя, не в репозитории, и оно остаётся после закрытия сессии и перезапуска Cyborg (D-44, исход открыто). После правок разработчик запускает повторную пробу этой способности кнопкой «Повторить пробу» в окне. Кнопка доступна, пока у способности есть дерево исправления, оно существует на диске, ни одна проба проекта, общая либо повторная, не идёт (FR-20006) и есть `claude` (FR-20013); иначе она отключена, и названа причина: «Исправление не запускали», «Дерево исправления убрано», «Идёт проба» либо причина по FR-20013 (D-44). Повторная проба идёт по дереву исправления (D-27, D-30) и касается одной исправляемой способности (FR-20006). Вторая сессия исправления той же способности не открывается: пока первая жива, «Исправить» переводит к её вкладке; после закрытия «Исправить» открывает новую сессию, и её дерево заменяет прежнее (D-44). Исход повторной пробы виден в окне у способности отдельной строкой «по дереву исправления»: «нашёл с источником», «выдумывает» либо «не знает». Он хранится у Cyborg отдельно от исходов пробы проекта, записанных в репозиторий (FR-20006, D-47), в подсчёт точки не входит (FR-20004) и подтверждения смысловой способности (FR-20007) не заменяет и не требует; после «выдумывает» либо «не знает» «Повторить пробу» можно нажать снова (D-34, исход открыто). Содержимое паспорта Cyborg не пишет (правит сессия), не коммитит и не сливает (D-23, D-27, раздел 3 BRD продукта); состояние паспорта он записывает по FR-20006..FR-20008 в рабочую копию проекта, а не в worktree исправления (D-48); PR разработчик сливает как обычно. Точка в строке проекта смотрит на репозиторий проекта (D-27): пробел по файлам исчезает при следующей проверке файлов (FR-20003) после слияния либо, если сессия писала в текущую ветку, без слияния; пробел по пробе - при новой пробе проекта (FR-20006) после слияния либо правки в текущей ветке. Если worktree убран без слияния, точка не меняется. Worktree исправления остаётся, пока его не уберёт разработчик или сама сессия: Cyborg worktree не создаёт и не убирает (FR-1016), ADR-0012 пути уборки не описывает. Как окно показывает остальное по способности, исправленной, но не слитой, и кто коммитит правки и открывает PR - открытый вопрос D-28, этим требованием он не решается. Без `claude` кнопки «Исправить» и «Повторить пробу» отключены (FR-20013).
- **traced from:** BR-20001 (сценарий 19 раздела 17 BRD продукта: по пробелу разработчик запускает исправление: сессия предлагает план, после подтверждения правит файлы, затем повторная проба; разработчик сливает PR как обычно); BR-013
- **источник:** BR-20001, четвёртый пункт «Требование» (исправление сессией: план, подтверждение, повторная проба); D-09, D-23, D-27, раздел 3 BRD продукта (non-goals); ответ оператора (запись D-30, принято владельцем): «Предлагаю вообще этот момент оставить. Пусть пользователь сам решает, куда ему писать. Если он вызвал в текущей ветке, значит в текущую ветку Cyborg пишет»; исход повторной пробы, кроме «нашёл с источником», и его отдельное хранение - D-34, допущение составителя, исход открыто; подтверждение плана в сессии и уборка worktree - D-35, допущение составителя, исход открыто; доступность «Повторить пробу», дерево исправления и вторая сессия по той же способности - D-44, допущение составителя, исход открыто (источники называют «worktree сессии», но не то, что видно, когда сессия закрыта, Cyborg перезапущен либо worktree убран)
- **rationale:** reason - пробел закрывается работой, которую выполняет сессия по слову человека; повторная проба показывает, нашёл ли агент теперь ответ с источником; assumptions - D-30: умолчание D-09 и D-27 (worktree) не обязательно; D-34, D-35: исходы повторной пробы, их отдельное хранение и подтверждение плана - допущения составителя; D-44: доступность повторной пробы и дерево исправления - допущение составителя, вопрос владельцу - те же; риск (ADR-0012): модель может не уйти в worktree и не дождаться подтверждения плана, Cyborg этого не блокирует, сессия нативная (BR-001); relationships - FR-20003, FR-20004, FR-20006, FR-20007, FR-20011, FR-20012, FR-20013, ADR-0012; design constraints - отдельной меры о записи в рабочую копию нет: слов «worktree обязателен» требование не содержит (D-30); Cyborg не коммитит и не сливает (D-23, D-27).
- **verification:** осмотр - текст поручения сессии исправления: требует план до правок (FR-20011); в тексте требования нет обязательного worktree, нет коммита и слияния от Cyborg; демонстрация - «Исправить» открывает сессию, она начинается с плана и до подтверждения файлов не правит; после правок «Повторить пробу» идёт по дереву сессии и показывает исход у способности отдельной строкой; способность с пробелом только по пробе, исправленная в worktree и найденная повторной пробой с источником при не слитом PR, - число в точке прежнее, убрать worktree без слияния - прежнее, слить PR и запустить пробу проекта - число уменьшилось; пока идёт повторная проба, «Повторить пробу» у любой способности и «Проверить агентом» отключены с причиной «Идёт проба»; у смысловой способности повторная проба подтверждения не требует и не заменяет; до «Исправить» и после удаления worktree «Повторить пробу» отключена с названной причиной; закрыть сессию и перезапустить Cyborg - кнопка доступна и идёт по тому же worktree; «Исправить» при живой сессии той же способности переводит к её вкладке, второй сессии нет; сессия, которую вели в текущей ветке, - повторная проба по рабочей копии; пробу «не знает» можно повторить, пробел остаётся; журнал коммитов ветки сессии содержит только коммиты сессии либо разработчика; испытание автотестом - следующий шаг, кода пока нет.

### NFR-20002 Содержимое из репозитория и ответ пробы не исполняют кода и не грузят сеть

- **Требование:** классификация данных: файлы паспорта, ответ агента, пути источников и названия репозиториев - недоверенные данные репозитория и сессии, только локально. Всё, что из них попадает в окно «Паспорт проекта» (FR-20005), показывается текстом, без разметки и HTML: скрипты, обработчики событий и ссылки не исполняются и сами не открываются, картинки и сеть не грузятся. Модель авторизации: субъект - интерфейс окна; права записи в файлы способностей паспорта и в настройки Claude Code у окна нет (D-17, D-23); состояние паспорта записывает главный процесс по нажатию кнопки, окно только передаёт действие (D-46).
- **traced from:** BR-20001
- **источник:** ADR-0002 (интерфейс показывает недоверенные данные); образец - требование к документу из репозитория в SRS фичи 16 (NFR-16001); BR-20001, пункты о пробе агента и подтверждении человеком; D-17, D-23, D-46
- **rationale:** reason - ответ агента и файлы паспорта пишет сессия или чужой коммит, и разметка в них иначе исполнилась бы в окне с доступом к возможностям Cyborg; assumptions - D-36: окно не показывает содержимого файлов паспорта; но ответ агента и источник у смысловых способностей показываются, и именно они под этой мерой; relationships - FR-20005, FR-20007, NFR-16001, ADR-0002; design constraints - вывод текстом - ограничение интерфейса по ADR-0002: недоверенные данные не попадают в разметку.
