# BRD фичи 20 - паспорт проекта: готовность к агентской разработке видна и закрывается из Cyborg

Источник: сессия «Организация процесса» (2026-11-20): «Cyborg проверяет готовность проекта к агентской разработке («Паспорт проекта») и помогает закрыть пробелы». Сводка согласована владельцем; решения - `decision-log.md`, исход «принято владельцем» (D-01..D-17), допущения составителя - исход «открыто» (D-18..D-27).

## 1. BRS overview

Агент Claude Code выдумывает или не находит то, что из кода не выводится: зачем продукт, как работает команда, что устарело. Cyborg об этом разработчику не говорит. Фича проверяет двенадцать способностей проекта в четырёх группах (продукт, техника, работа, актуализация), показывает число пробелов точкой в строке проекта и окном «Паспорт проекта», пробой агента выясняет, находит ли он ответ с источником, и по слову разработчика закрывает пробел сессией. Адресована владельцу продукта и составителям SRS.

## 2. Business purpose

Разработчик видит, готов ли проект к работе агента, и закрывает пробелы, не составляя перечень проверок руками; повторная проба подтверждает, что агент теперь находит ответ с источником.

## 3. Business scope

Внутри границы: двенадцать способностей в четырёх группах, каждая задана вопросом к проекту (D-02, D-03); дешёвая проверка файлов паспорта в `.cyborg/passport/` без нажатия и проба агента по кнопке с исходом по каждой способности (D-04, D-05, D-06); паспорт проекта из нескольких репозиториев с главным репозиторием, который отмечает разработчик (D-07, D-24); статус проверок и отказы «Не нужно» в данных Cyborg (D-08); исправление пробела сессией в worktree с планом, подтверждением и повторной пробой (D-09, D-23); встроенное поручение начальным промптом (D-10, D-16); сбор кандидатов в скиллы и установка по решению человека (D-11, D-12, D-17, D-26); индикатор-точка с числом пробелов в строке проекта слева и окно «Паспорт проекта» (D-13).

`non-goals`:

- набор способностей, зашитый под процесс dex-auto, проверка только по наличию файлов, индикатор внутри карточки «Статус», кнопка на полосе сессий: отвергнуто (D-14);
- профиль-переопределение набора и таблицы средств, автопроверки по таймеру, проекты по SSH, правка паспорта в окне: вне первой версии, отложено, а не отвергнуто (D-15);
- запись паспорта и выдача разрешений Claude Code самим Cyborg: исправляет сессия по слову разработчика, разрешение на установку скилла даёт человек в штатном запросе Claude Code (D-17, D-23).

## 7. Mission, goals and objectives

### BR-20001 Паспорт проекта: проба агента находит невыводимое из кода, пробел закрывает сессия по слову разработчика

- **Требование:** разработчик видит у проекта готовность к агентской разработке и закрывает пробелы:
  - Cyborg проверяет двенадцать способностей в четырёх группах (продукт, техника, работа, актуализация); способность задана вопросом к проекту, а не форматом документа; паспорт - фиксированный список файлов по способностям и `index.md` в `.cyborg/passport/`; поимённый перечень способностей и файлов - в SRS следующего шага (D-21);
  - проверка файлов идёт без нажатия, при выборе проекта и при открытии окна (D-25); проба агента - по кнопке, с исходом по каждой способности: нашёл с источником, выдумывает, не знает; где возможно, источник ответа проверяется механически, смысловые способности подтверждает человек;
  - точка с числом пробелов в строке проекта и окно «Паспорт проекта» с четырьмя группами и пробелами по цепочке; отказ «Не нужно» снимает способность с пробелов и хранится у Cyborg;
  - пробел закрывает сессия в worktree: сначала план, правки после подтверждения разработчика, затем повторная проба; по какому дереву она идёт и кто переносит правки из worktree в рабочую копию проекта - открыто (D-27); поручение способности идёт начальным промптом сессии (D-16); Cyborg файлы паспорта не пишет (D-23);
  - кандидатов в скиллы собирает Cyborg из установленных плагинов и подключённых магазинов, сессия выбирает и объясняет выбор в плане; установку скилла разрешает человек в окне «Расширения» либо в штатном запросе Claude Code (D-12, D-17).
- **traced from:** BR-013.
- **rationale:**
  - reason: BR-013; агент не выводит из кода продукт, технику, работу и актуализацию, и без паспорта выдумывает либо не находит их;
  - assumptions: D-21, D-22, D-24, D-25, D-26, D-27;
  - relationships: BR-013, BR-005, BR-008 (фича `14-extensions`), сценарий 19 раздела 17, ADR-0003, ADR-0018, ADR следующего шага;
  - design constraints: поручение начальным промптом расширяет перечень добавок к CLI (D-16); разрешений Claude Code Cyborg не выдаёт и настроек не пишет (D-17); файлы паспорта пишет сессия, не Cyborg (D-23); способ пробы и хранение статуса - ADR следующего шага (D-22).
- **MOE:** после закрытия пробела проект проходит повторную пробу по этой способности с источником, а пробелы видны точкой, не открывая окна (качественная).

### Открытые вопросы

- Принял: имена двенадцати способностей и файлов паспорта и смысл меток «⚠» и «≈» - в SRS следующего шага, потому что сводка называет число и группы, но не имена (D-21).
- Принял: способ пробы агента, хранение статуса и граница паспорта в репозитории - ADR следующего шага, потому что это выбор механизма, а не наблюдаемое поведение (D-22).
- Принял: проверка файлов идёт при выборе проекта и открытии окна, потому что сводка исключает таймер, но момент не называет (D-25).
- Принял: у проекта из нескольких репозиториев без отмеченного главного проектные способности не проверяются, потому что сводка поведение без отметки не задаёт (D-24).
- Принял: в режиме разрешений сессии без запроса установку скилла решает настройка разработчика, потому что Cyborg режим не меняет (D-26).
- Не решено, ответ даёт владелец продукта: по какому дереву идёт повторная проба после исправления пробела (рабочая копия проекта или worktree сессии) и кто переносит правки паспорта из worktree в рабочую копию (сессия по слову разработчика, сам разработчик либо иначе); варианта нет, потому что сводка дерева и переноса не называет, а Cyborg не коммитит и не сливает (D-27).
