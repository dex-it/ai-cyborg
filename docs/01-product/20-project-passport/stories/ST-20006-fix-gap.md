# ST-20006 Пробел закрывает сессия по слову разработчика

Как разработчик, я хочу по нажатию запустить сессию, которая исправит пробел паспорта по плану, и проверить результат повторной пробой, чтобы закрыть пробел, не составляя тексты руками.

## Acceptance Criteria

- **AC-1.** Дано: у способности пробел и есть `claude`. Когда я нажимаю «Исправить». Тогда открывается сессия проекта с поручением этой способности, она начинается с плана (что выяснить, какие файлы править, какие скиллы и почему), и до моего подтверждения в сессии файлы не правятся. [FR-20010] [FR-20011]
- **AC-2.** Дано: поручение есть у каждой из двенадцати способностей. Когда я нажимаю «Исправить» у любой из них. Тогда первое сообщение сессии - встроенное поручение своей способности; у проекта без скиллов оно то же, без перечня кандидатов; у проекта из нескольких репозиториев оно называет репозиторий файла. [FR-20011]
- **AC-3.** Дано: сессия ушла в worktree. Когда я после правок нажимаю «Повторить пробу». Тогда проба идёт по worktree сессии и показывает исход у способности. [FR-20010]
- **AC-4.** Дано: я вёл сессию в текущей ветке. Когда я нажимаю «Повторить пробу». Тогда проба идёт по рабочей копии, Cyborg запись не навязывает; точка меняется при следующем выборе проекта либо открытии окна, без слияния. [FR-20010]
- **AC-5.** Дано: повторная проба дала «не знает» либо «выдумывает». Когда я смотрю окно. Тогда пробел остаётся, «Повторить пробу» можно нажать снова. [FR-20010]
- **AC-6.** Дано: исправление готово. Когда я смотрю историю git ветки сессии. Тогда в ней только коммиты сессии либо мои, Cyborg не коммитит и не сливает; PR я сливаю как обычно. [FR-20010]
- **AC-7.** Дано: нет `claude`. Когда я смотрю «Исправить» и «Повторить пробу». Тогда они отключены с названной причиной. [FR-20010] [FR-20013]
