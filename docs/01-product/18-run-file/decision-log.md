# decision-log фичи 18 - запуск файла из просмотра в системном терминале

Решения по формулировке оператора (2026-11-15): «при клике на файл который можно запустить в терминале - предлагать запуск в терминале, предупредить об опасности запуска, если пользователь одобрит - сохранить одобрение и хэш файла, дальше додумай» и по цели `run-file-in-terminal`. Ответы оператора и допущения цели, принятые им («по всем допущениям - ок», 2026-11-15), - исход «принято оператором»; выведенные составителем из кода правки - «принято составителем» до подтверждения владельцем; неизвестное - «открыто».

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | Запуск предлагает кнопка «▶ Запустить в терминале» в шапке просмотра перед «Открыть в системе»; клик по строке дерева открывает просмотр, как раньше | модальный вопрос на клик по строке дерева | ответ оператора «Кнопка в шапке просмотра»; BR-003 | принято оператором |
| D-02 | Запускаемый файл и его команда определяются по порядку: бит исполнения у текущего пользователя - сам файл; иначе shebang первой строки - интерпретатор из него; иначе расширение из таблицы; прочее и каталог не запускаются. Запускаемость не зависит от того, показывает ли файл просмотр | только бит исполнения; только расширения | ответ оператора «Бит, shebang и расширения»; двоичные файлы чаще всего несут именно бит | принято оператором |
| D-03 | Таблица «расширение - интерпретатор» зашита в код: `.sh` - `bash`, `.py` - `python3`, `.js`, `.mjs`, `.cjs` - `node`. Это техдолг: целевое - брать соответствие из реестра ОС либо из настроек приложения; чей ответ - владелец продукта | - | ответ оператора: «.cjs запускается через node. - по хорошему это д.б. реестр ОС или в приложении.. пока пометим как техдолг» | открыто |
| D-04 | Файл запускается в окне системного терминала ОС; терминал, транскрипт и pty сессии Claude Code не меняются | свой терминал или pty внутри окна Cyborg | ответ оператора «Системный терминал»; BRD продукта, раздел 11 (сессия не оборачивается) | принято оператором |
| D-05 | Одобрение: ключ - физический путь файла, значение - SHA-256 содержимого и команда запуска; новое одобрение пути заменяет прежнее, возврат к старому содержимому спрашивает снова | история одобренных хэшей пути; одобрение только по хэшу без команды | формулировка оператора «сохранить одобрение и хэш файла»; команда добавлена проверкой безопасности после трека: снятый или выставленный бит исполнения меняет команду, а не хэш, и человек одобрял показанную команду | путь и хэш - принято оператором; команда в одобрении - принято составителем |
| D-06 | Команду и хэш считает главный процесс по файлу на диске в момент нажатия; одобряется показанное предупреждением; после согласия путь, команда и хэш считаются заново, расхождение - отказ «Файл изменился, пока вы решали: запуск отменён» без запуска и без сохранения | хэш и команда от интерфейса; хэш при проверке запускаемости (время по размеру на открытие каждого файла); предел размера файла для хэша (большие двоичные стали бы незапускаемыми) | ADR-0002: решения о доступе в главном процессе; практика против подмены между проверкой и использованием | принято оператором; отвергнутые варианты - принято составителем |
| D-07 | Остаточный риск принят: файл может смениться между последней сверкой хэша и исполнением в эмуляторе | исполнение копии файла либо передача открытого дескриптора: меняют `$0` и каталог файла | окно в сотни миллисекунд; закрыть его можно только сменой того, что видит запущенный файл | принято составителем |
| D-08 | Каталог и команда доходят до оболочки аргументами постоянного скрипта, а не подстановкой в текст команды; эмулятору команда передаётся по элементам | временный скрипт-файл с путём в тексте (подстановка, уборка, гонка за файл); формы эмуляторов с командой одной строкой (строку они разбирают сами); строка для Terminal.app, собранная кодом Cyborg | имя файла с пробелом, кавычкой, `$` и `;` обязано запускать этот файл, а не текст из имени; так же запускается сессия | принято оператором (критерий); способ - принято составителем |
| D-09 | Shebang разбирается по правилам ядра Linux на обеих ОС: интерпретатор и один необязательный аргумент - остаток строки; интерпретатор - абсолютный путь; строка с управляющими символами, не UTF-8 либо без конца в первых 256 байтах негодна. Файл с негодным shebang не запускается и по расширению | относительный интерпретатор (разрешился бы от каталога файла, внутри репозитория); откат к таблице расширений при негодном shebang (явный shebang молча подменялся бы) | показанная команда должна совпадать с тем, что исполнило бы ядро | принято составителем |
| D-10 | Linux: эмулятор - первый найденный из `$TERMINAL`, `x-terminal-emulator`, `gnome-terminal`, `konsole`, `xfce4-terminal`, `kitty`, `alacritty`, `wezterm`, `foot`, `xterm`; `PATH` и `TERMINAL` берутся из окружения Cyborg; ни одного - сообщение с перечнем и подсказкой про `TERMINAL` | `PATH` и `TERMINAL` из логин-оболочки; кэш найденного эмулятора (PATH меняется, проверка дешёвая) | допущение цели: сначала выбор пользователя и системы, затем распространённые эмуляторы | перечень и порядок - принято оператором; источник окружения - принято составителем |
| D-11 | macOS: окно открывает Terminal.app через `osascript` с постоянным сценарием; Cyborg ждёт `osascript` и показывает его ошибку. На настоящей macOS не проверено; чей ответ - владелец продукта | выбор другого эмулятора macOS | допущение цели: Terminal.app есть в каждой системе | Terminal.app - принято оператором; проверка на macOS - открыто |
| D-12 | Окно терминала после завершения файла не закрывается: код выхода и ожидание Enter; Ctrl-C завершает файл, но не оболочку окна | закрывать окно по завершении (вывод короткого скрипта не прочитать); игнорировать сигнал прерывания (игнор унаследовал бы запущенный файл) | допущение цели | окно и код выхода - принято оператором; Ctrl-C - принято составителем |
| D-13 | Запуск и проверка запускаемости судят символьную ссылку по цели: цель вне разрешённых каталогов - отказ; бит, хэш и ключ одобрения - у файла-цели, две ссылки на один файл делят одобрение | проверка по строке пути, как у каналов чтения (ссылка внутри репозитория на программу системы прошла бы) | критерий цели о ссылке; граница записи Markdown по раскрытым путям (D-03 фичи 16) | критерий - принято оператором; общая проверка с записью - принято составителем |
| D-14 | Одобрения лежат в `run-approvals.json` каталога данных приложения, один файл на все воркспейсы, запись атомарная; отсутствующий либо повреждённый файл читается как пустой; сбой записи не мешает запуску; хранится не больше 1000 одобрений, самое давнее вытесняется | файл одобрений на воркспейс; хранилище без предела (читается на каждое нажатие) | допущения цели по образцу общих промптов и хабов; предел - по образцу хранилища номеров дочерних разговоров | хранилище - принято оператором; предел - принято составителем |
| D-15 | Логин-оболочка не семейства sh (`fish`, `tcsh`, `csh`, `nu`, `xonsh`, `elvish`, `pwsh` по имени из `$SHELL`) - отказ до предупреждения с именем оболочки, на Linux и macOS | запускать и не сообщать: окно закрывалось сразу, файл не исполнялся, Cyborg сообщал об успехе; свой текст скрипта под каждую оболочку | команда оператора: «почини F4: проверяй $SHELL до запуска и отказывай с сообщением для fish/tcsh/csh»; скрипт запуска написан на POSIX sh, а читает его логин-оболочка | принято оператором; `nu`, `xonsh`, `elvish`, `pwsh` в перечне - принято составителем |
| D-16 | macOS: каталог либо слово команды с обратной косой чертой - отказ до предупреждения | пропускать такой путь: кавычение Terminal.app рассчитано на sh, и иная логин-оболочка разобрала бы его иначе - текст после кавычки исполнился бы | проверка безопасности после трека | принято составителем |
| D-17 | Оболочка и эмулятор проверяются до хэша и предупреждения | проверка после согласия: одобрение, после которого запустить нечем | критерий цели «ни одного нет - сообщение, запуска нет» | принято составителем |
| D-18 | Повторное нажатие кнопки, пока идёт запуск того же файла, ничего не делает | второе предупреждение поверх первого | один вопрос - одно решение человека | принято составителем |
| D-19 | Не делаем: удалённые сессии, запуск по ссылке-пути из вывода сессии, аргументы и переменные окружения запуска, выбор интерпретатора человеком, настройку эмулятора в интерфейсе, список одобрений с отзывом в интерфейсе, Windows | - | граница цели, принятая оператором | принято оператором |
| D-20 | Правки корпуса вне фичи. Род - расширение области: BRD продукта (BR-011, разделы 3, 9, 11, 12, сценарий 18 раздела 17, заметка в шапке), ADR-0002 п.3, п.5 и последствия (каналы `file:runnable`, `file:run`), FR-1015 фичи 01 (одобрения запуска среди того, что главный процесс пишет на диск). Род - уточнение формулировки: FR-16004 фичи 16 (порядок проверок записи: граница каталогов раньше расширения и `.git`). Зависимые места найдены поиском по корпусу: «пишет на диск», «прочее чтение», `fs:write`, `path:open` | новые единицы рядом с задетыми | один предмет - одна единица | принято составителем |
| D-21 | Историй с AC (`stories/`) и сценариев (`02-use-cases/`) у фичи нет: поведение проверяют автотесты, названные в верификации требований | нарезка историй с критериями приёмки | у фичи один BR и линейный сценарий; сценарии в корпусе не заведены ни у одной фичи | принято составителем |
