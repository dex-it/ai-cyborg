# SRS фичи 18 - запуск файла из просмотра в системном терминале

## 1. SRS overview

Требования к кнопке запуска в шапке просмотра, к правилу запускаемости файла и его команде, к предупреждению и одобрению, к хранилищу одобрений, к выбору эмулятора терминала и к тому, что происходит в его окне, к отказам запуска и к каналам `file:runnable` и `file:run`. Вход - BRD фичи (`brd-feat.md`, BR-18001), формулировка оператора 2026-11-15 и цель `run-file-in-terminal`, код `src/main/run-file.ts`, `src/main/run-terminal.ts`, `src/main/run-approvals.ts`, `src/main/allowed-paths.ts`, `src/main/main.ts`, `src/main/preload.ts`, `src/renderer/run-button.ts`, `src/renderer/app.ts`. Основания решений - `decision-log.md` (D-NN).

## 2. Purpose

Задать наблюдаемое поведение запуска файла так, чтобы правка проверялась по требованию, а не по коду.

## 3. Scope

Файл, открытый в просмотре вкладки локальной сессии либо в просмотре без сессии, на Linux и macOS; каналы `file:runnable` и `file:run`; файл `run-approvals.json`. Вне фичи: удалённые сессии, ссылки-пути в выводе сессии, аргументы и окружение запуска, выбор интерпретатора и эмулятора в интерфейсе, отзыв одобрений, Windows (`brd-feat.md`, раздел 3).

## 4. Product perspective

Кнопка - часть шапки просмотра файла в интерфейсе (ADR-0001, ADR-0002); всё решение о запуске - в главном процессе (ADR-0021). Внешние соединения: эмулятор терминала ОС (Linux), `osascript` и Terminal.app (macOS), логин-оболочка пользователя. С pty сессий Claude Code фича не соединена.

## 5. Product functions

Кнопка запуска; правило запускаемости и команда; предупреждение; одобрение и повторная сверка; хранилище одобрений; окно системного терминала; исполнение в окне; отказы с причиной; каналы главного процесса.

## 6. User characteristics

`inherited`: BRD продукта, раздел 5.

## 7. Limitations

Эмулятор терминала - внешняя программа: Cyborg узнаёт только о сбое её старта (Linux) либо об ошибке `osascript` (macOS), а не о том, что произошло в окне. Скрипт запуска написан на POSIX sh и читается логин-оболочкой пользователя (D-15). Новых npm-зависимостей нет.

## 8. Assumptions and dependencies

Допущения цели приняты оператором (`decision-log.md`). D-05 (команда в одобрении), D-07, D-09, D-16..D-18 - решения составителя до подтверждения владельцем. Таблица расширений - техдолг (D-03). Интерпретаторы таблицы (`bash`, `python3`, `node`) ищет оболочка окна терминала по своему `PATH`: их отсутствие видно в окне, Cyborg его не проверяет.

## 9. Apportioning of requirements

Интерфейс: FR-18001. Главный процесс: FR-18002..FR-18009, NFR-18001. В будущие версии отложено: соответствие «расширение - интерпретатор» из реестра ОС либо настроек приложения (D-03).

## 10. Specified requirements

Общие атрибуты, если у требования не сказано иное: `feature: 18-run-file`; приоритет - обязательно; основание - формулировка оператора 2026-11-15 и цель `run-file-in-terminal` (`brd-feat.md`); уровень верификации - модуль (`npm test`). Сценариев (`UC`) у фичи нет (D-21), поэтому правила трассируются на BR-18001 напрямую.

## 11. External interfaces

### FR-18009 Каналы file:runnable и file:run принимают только путь и решают всё в главном процессе

- **Требование:** интерфейс получает два метода моста. `runnable(file)` (канал `file:runnable`) отвечает `true` либо `false`: запускается ли файл на этой платформе (FR-18002); команду и хэш интерфейс не получает. `runFile(file)` (канал `file:run`) запускает файл и ничего не возвращает: предупреждение, одобрение и сообщения об отказе показывает главный процесс. Единственный аргумент обоих - путь; он проходит проверку каналов чтения (FR-1027 фичи 01), затем раскрывается до физического пути: файла нет - «Файл не найден»; физический путь вне раскрытых разрешённых каталогов - «Путь вне репозиториев проектов и каталогов сессий». Символьная ссылка судится по цели: запускаемость, команда, хэш и ключ одобрения берутся у файла, на который она указывает. Отказ проверки пути `file:runnable` отдаёт ошибкой канала (кнопки нет, FR-18001), `file:run` - окном «Файл не запущен» с причиной (FR-18008). На платформе, кроме macOS и Linux, `runnable` отвечает `false`.
- **traced from:** BR-18001.
- **источник:** цель, критерии 7 и 11; ADR-0002 п.5; D-06, D-13.
- **rationale:** reason - интерфейсу не доверяют, а канал запуска программы - самый опасный из его каналов; assumptions - нет; relationships - FR-1027 фичи 01, FR-16004 фичи 16 (та же граница по раскрытым путям), ADR-0002 п.3 и п.5, ADR-0021 п.1, п.2; design constraints - проверка по строке пути, как у чтения, пропустила бы ссылку внутри репозитория на программу вне его (D-13).
- **verification:** испытание - `test/run-file.test.ts` («путь вне разрешённых и ссылка наружу - отказ без диалога и запуска», «ссылка внутри репозитория: ключ - цель, одобрение общее», «runnable: boolean, бит не нужен для .sh, нет для .ts, каталог - false», «win32: runnable false, run - ошибка», «регистрирует file:runnable и file:run, каждому свой обработчик с одним аргументом-путём», «main.ts: каналы регистрирует registerRunChannels, платформу выбирает launcherFor»).
- **класс:** External interfaces. **origin:** source; сообщения отказов и форма ответа - derived.

## 12. Functions

### FR-18001 Кнопка «▶ Запустить в терминале» в шапке просмотра запускаемого файла

- **Требование:** клик по файлу дерева открывает его просмотр, как раньше; вопроса о запуске на клик нет. В шапке просмотра - во вкладке локальной сессии и в просмотре без сессии - у запускаемого файла (FR-18002) перед кнопкой «Открыть в системе» стоит кнопка «▶ Запустить в терминале» с подсказкой «Запустить файл в системном терминале». Кнопка появляется после ответа `true` канала `file:runnable`; при ответе `false` и при ошибке канала кнопки нет. Кнопка есть и у запускаемого файла, который просмотр показать не может (двоичный, больше 5 МБ). В просмотре файла удалённой сессии кнопки нет, канал не запрашивается. Нажатие отправляет путь файла в `file:run`; интерфейс ответа не ждёт и сам ничего не показывает.
- **traced from:** BR-18001.
- **источник:** формулировка оператора («предлагать запуск в терминале»); ответ оператора «Кнопка в шапке просмотра» (D-01); цель, критерии 1 и 3, граница (D-19).
- **rationale:** reason - запуск предлагается там, где файл читают, и не мешает открытию просмотра; assumptions - нет; relationships - BR-003 BRD продукта, FR-18002, FR-18009, фича `17-ssh-remote-agents` (удалённый просмотр без кнопки); design constraints - запускаемость решает главный процесс, интерфейс получает только признак (ADR-0021 п.1).
- **verification:** испытание - `test/run-file.test.ts` («запускаемый файл локальной сессии: кнопка перед «Открыть в системе», клик запускает», «незапускаемый файл и отказ канала: кнопки нет», «удалённая сессия: канал не вызывается, кнопки нет», «app.ts: кнопка добавляется в общей шапке с признаком remote, openFile передаёт !!s.remote», «двоичный файл больше 5 МБ с битом - запускаемый, без бита - нет»); осмотр - вид кнопки в окне: дымового сценария нет.
- **класс:** Functions. **origin:** source; подсказка и поведение при ошибке канала - derived.

### FR-18002 Запускаемый файл и команда его запуска: бит исполнения, shebang, расширение

- **Требование:** запускаемость и команду определяет главный процесс по физическому пути обычного файла, по порядку: (а) у текущего пользователя есть право исполнения - команда: сам файл; (б) права нет, файл начинается с `#!` - команда: интерпретатор из shebang, его аргумент, если есть, и файл; (в) права и shebang нет, расширение имени без учёта регистра из таблицы - `.sh`: `bash`, `.py`: `python3`, `.js`, `.mjs`, `.cjs`: `node` - команда: интерпретатор и файл. Иначе файл не запускаемый; каталог, файл с управляющим символом в пути, несуществующий и нечитаемый без права исполнения - тоже. Shebang читается только из первой строки в пределах первых 256 байт: интерпретатор - слово до первого пробела, обязан быть абсолютным путём; остаток строки без крайних пробелов - один аргумент. Строка с управляющим символом (в том числе с возвратом каретки), не UTF-8, с относительным либо пустым интерпретатором или без конца строки в 256 байтах при большем файле негодна: файл с негодным shebang не запускаемый, расширение для него не смотрится. Файл с правом исполнения запускается по (а), каким бы ни было его расширение.
- **traced from:** BR-18001.
- **источник:** ответ оператора «Бит, shebang и расширения» (D-02); ответ оператора о `.cjs` и техдолге (D-03); цель, критерии 2 и 10; D-09.
- **rationale:** reason - человек должен видеть команду, которая исполнится, а не догадку; assumptions - интерпретаторы таблицы есть в `PATH` оболочки окна; relationships - FR-18001, FR-18003, FR-18004; design constraints - разбор shebang как в ядре Linux, чтобы показанная команда совпадала с исполняемой; относительный интерпретатор разрешился бы внутри репозитория (D-09); таблица зашита в код временно (D-03).
- **verification:** испытание - `test/run-file.test.ts` («бит исполнения: запускается сам файл», «бит и shebang: исполняет ядро, argv - сам файл», «без бита, shebang: интерпретатор из shebang», «shebang с аргументами - один аргумент, как в Linux», «shebang из одной строки без перевода строки», «негодный shebang: относительный, пустой, управляющие символы, не UTF-8, длинный», «вторая строка с #! не читается», «без бита и shebang - по расширению», «.ts, .txt, без расширения и каталог - не запускаются», «имя с переводом строки - не запускаемый»); тесты с битом исполнения под root пропускаются.
- **класс:** Functions. **origin:** source; разбор shebang и негодные случаи - derived.

### FR-18003 Предупреждение перед запуском неодобренного файла

- **Требование:** нажатие кнопки по файлу, чьи нынешние содержимое и команда не одобрены (FR-18004), показывает окно-предупреждение «Запустить файл в терминале?» с подробностями: «Файл: <физический путь>», «Каталог: <каталог файла>», «Команда: <команда>» и текст «Файл выполнится с правами вашего пользователя и может изменить или удалить ваши данные. Запускайте только файл, которому доверяете.». Команда показана словами через пробел; слово не из букв, цифр и знаков `_@%+=:,./-` взято в одинарные кавычки. Если у пути есть прежнее одобрение с другим содержимым либо другой командой, подробности начинаются строкой «Файл изменён с прошлого одобрения: содержимое либо команда запуска уже не те.». Кнопки - «Отмена» и «Запустить»; по умолчанию и по Esc - «Отмена». «Отмена» ничего не запускает и ничего не сохраняет. Повторное нажатие кнопки запуска, пока идёт запуск того же файла, второго окна не открывает и ничего не делает (D-18).
- **traced from:** BR-18001.
- **источник:** формулировка оператора («предупредить об опасности запуска»); цель, критерии 4 и 6; D-18.
- **rationale:** reason - человек одобряет конкретный файл и конкретную команду, зная риск; assumptions - нет; relationships - FR-18002, FR-18004; design constraints - окно показывает главный процесс: интерфейс текст предупреждения не формирует (ADR-0021 п.1); показанная команда - только показ, к исполнению строка не идёт (NFR-18001).
- **verification:** испытание - `test/run-file.test.ts` («путь, точная команда, права пользователя и риск изменения или удаления», «изменённый файл помечен», «displayCommand: простые элементы без кавычек», «true только при «Запустить»; «Отмена» и Esc - false; по умолчанию и по Esc «Отмена»», «отмена: ни запуска, ни файла одобрений», «повторное нажатие, пока идёт запуск того же файла - один диалог»).
- **класс:** Functions. **origin:** source; строка каталога, кавычение показа и замок повторного нажатия - derived.

### FR-18004 Одобрение относится к содержимому и команде и сверяется перед запуском

- **Требование:** по нажатию главный процесс считает команду (FR-18002) и SHA-256 содержимого файла на диске. Одобрение пути с тем же хэшем и той же командой есть - файл запускается без предупреждения. Нет одобрения, другой хэш либо другая команда при том же хэше (выставлен или снят бит исполнения) - предупреждение (FR-18003). После «Запустить» путь, команда и хэш определяются заново: физический путь, команда и хэш те же, что показаны, - одобрение сохраняется (FR-18005) и файл запускается; иначе, в том числе когда файл удалён либо перестал запускаться, - отказ «Файл изменился, пока вы решали: запуск отменён», запуска и сохранения нет. Возврат файла к прежде одобренному содержимому спрашивает снова: хранится одно одобрение на путь.
- **traced from:** BR-18001.
- **источник:** формулировка оператора («если пользователь одобрит - сохранить одобрение и хэш файла»); цель, критерии 5-7; D-05, D-06.
- **rationale:** reason - одобрение относится к тому, что человек видел, а не к имени файла; assumptions - остаточный риск смены файла между сверкой и исполнением принят (D-07); relationships - FR-18002, FR-18003, FR-18005, ADR-0021 п.3, п.4; design constraints - снятый бит меняет команду, а не хэш, поэтому команда входит в одобрение (D-05); хэш считается потоком без предела размера и только на нажатие (D-06).
- **verification:** испытание - `test/run-file.test.ts` («неодобренный: предупреждение, одобрение сохранено, запуск с cwd и чистым env», «тот же хэш - без предупреждения», «другой хэш - предупреждение с пометкой об изменении; возврат к старому спрашивает снова», «хэш тот же, команда другая (после одобрения выставлен бит): спрашивает снова с новой командой», «файл переписан, пока открыт диалог: отказ, без запуска и одобрения», «содержимое то же, команда другая (снят бит): отказ, без запуска и одобрения»).
- **класс:** Functions. **origin:** source; команда в одобрении и состав повторной сверки - derived.

### FR-18006 Окно системного терминала: эмулятор на Linux, Terminal.app на macOS

- **Требование:** Linux: эмулятор - первый найденный исполняемый файл по порядку: значение `TERMINAL`, `x-terminal-emulator`, `gnome-terminal`, `konsole`, `xfce4-terminal`, `kitty`, `alacritty`, `wezterm`, `foot`, `xterm`. Имя без `/` ищется по абсолютным каталогам `PATH` окружения Cyborg по порядку; значение `TERMINAL` с `/` принимается только абсолютным путём; ненайденное пропускается. Команда передаётся эмулятору по элементам: `gnome-terminal` - после `--`, `xfce4-terminal` - после `-x`, `kitty` и `foot` - сразу, `wezterm` - после `start --`, прочие - после `-e`; для `x-terminal-emulator` форма выбирается по имени программы, на которую он ссылается. Эмулятор запускается отдельным процессом, не зависящим от Cyborg, в каталоге файла; сбой его старта - отказ с причиной (FR-18008). Ни одного эмулятора нет - отказ «Не найден эмулятор терминала. Искали в PATH: $TERMINAL, x-terminal-emulator, …, xterm. Задайте переменную окружения TERMINAL с именем или путём вашего терминала и перезапустите Cyborg.» (заданное значение `TERMINAL` названо в скобках). macOS: окно открывает Terminal.app по команде `osascript`; Cyborg ждёт завершения `osascript` не дольше 120 с, его ошибка (например, отказ в разрешении управлять Terminal) - отказ с текстом его stderr.
- **traced from:** BR-18001.
- **источник:** ответ оператора «Системный терминал» (D-04); цель, критерий 8; D-08, D-10, D-11.
- **rationale:** reason - запуск идёт в терминале, которым разработчик уже пользуется; assumptions - `TERMINAL`, заданный только в файле настроек оболочки, Cyborg, запущенный из меню приложений, не видит (D-10); relationships - FR-18007, FR-18008, ADR-0021 п.5, п.6; design constraints - формы эмуляторов с командой одной строкой не используются: строку эмулятор разбирает сам (D-08).
- **verification:** испытание - `test/run-file.test.ts` («первый найденный по порядку перечня», «$TERMINAL первым, по имени и по абсолютному пути; ненайденный пропускается», «относительные и пустые каталоги PATH пропускаются», «ни одного: сообщение с перечнем и подсказкой про TERMINAL», «форма передачи команды по эмулятору, argv поэлементно», «x-terminal-emulator - ссылка: форма по имени цели, не по имени ссылки», «darwin: скрипт AppleScript постоянен, каталог и файл - отдельными элементами», «darwin ждёт osascript и не зовёт отрыв; linux отрывает и не зовёт osascript», «stderr процесса попадает в ошибку, успех - пустой ответ», «эмулятора нет: сообщение, без диалога»); настоящий эмулятор и Terminal.app автотест не запускает.
- **класс:** Functions. **origin:** source; формы передачи команды и ожидание `osascript` - derived.

### FR-18007 В окне терминала: каталог файла, окружение логин-оболочки без маркеров сессии, код выхода

- **Требование:** в окне терминала файл исполняется командой FR-18002 без дополнительных аргументов; рабочий каталог - каталог файла. Linux: скрипт запуска читает логин-оболочка пользователя (`$SHELL -lc`, при незаданном `SHELL` - `/bin/bash`); macOS: логин-оболочка окна Terminal.app исполняет `/bin/sh` со скриптом запуска. Из окружения сняты маркеры сессии Claude Code и переменные Cyborg, которые достались бы от сессии, запустившей Cyborg (`CLAUDECODE`, `CLAUDE_CODE_*`, `CYBORG_CWD`, `CYBORG_MCP`, `CYBORG_PLUGIN`, `CYBORG_EVENTS`, `CYBORG_SETTINGS` и прочие маркеры сессии). После завершения файла окно не закрывается: пустая строка, «[Код выхода N] Нажмите Enter, чтобы закрыть окно» и ожидание Enter. Ctrl-C завершает файл, но не оболочку окна: код выхода (130) и приглашение показаны. Каталог файла недоступен к моменту запуска - «Каталог недоступен: <каталог>», ожидание Enter, файл не исполняется.
- **traced from:** BR-18001.
- **источник:** цель, критерий 9; D-12.
- **rationale:** reason - вывод короткого скрипта иначе не прочитать, а файл, запущенный с маркерами сессии, вёл бы себя как её потомок; assumptions - логин-оболочка семейства sh (D-15); relationships - FR-18006, FR-18008, NFR-18001; design constraints - перехват, а не игнор сигнала прерывания: игнор унаследовал бы запущенный файл (D-12).
- **verification:** испытание - `test/run-file.test.ts` («unset всех переменных сессии», «код выхода и приглашение; переменные сессии вычищены; каталог - каталог файла», «Ctrl-C завершает файл, но не оболочку: код 130 и ожидание Enter (под pty)» - пропускается без `python3`, «каталога нет - сообщение, не запуск», «SHELL не задан - /bin/bash», «неодобренный: предупреждение, одобрение сохранено, запуск с cwd и чистым env»).
- **класс:** Functions. **origin:** source; Ctrl-C и недоступный каталог - derived.

### FR-18008 Запуск невозможен - окно «Файл не запущен» с причиной, до предупреждения

- **Требование:** отказ `file:run` главный процесс показывает окном ошибки «Файл не запущен» с причиной; отмена предупреждения и успешный запуск окна не дают. Проверки идут в порядке: путь (FR-18009); платформа, кроме macOS и Linux, - «Запуск в терминале есть на macOS и Linux»; файл есть, но перестал запускаться - «Файл больше не запускается: <путь>» (удалённый файл отсекает проверка пути, FR-18009); имя логин-оболочки из `SHELL` - `fish`, `tcsh`, `csh`, `nu`, `xonsh`, `elvish` либо `pwsh` - «Логин-оболочка <имя> не разбирает скрипт запуска (нужна оболочка семейства sh: bash, zsh, dash, ksh). Запустите файл из своего терминала.», на Linux и macOS, эмулятор при этом не ищется; на macOS каталог либо слово команды с обратной косой чертой - «Путь или команда с обратной косой чертой на macOS не запускаются»; на Linux нет эмулятора (FR-18006); содержимое не прочитано - «Файл не прочитан: <код ошибки>». Все эти отказы наступают до предупреждения: окна-вопроса, сохранения одобрения и запуска нет. После согласия отказом кончаются расхождение при повторной сверке (FR-18004) и сбой старта эмулятора либо ошибка `osascript` (FR-18006).
- **traced from:** BR-18001.
- **источник:** команда оператора «почини F4: проверяй $SHELL до запуска и отказывай с сообщением для fish/tcsh/csh» (D-15); цель, критерии 7 и 8; D-16, D-17.
- **rationale:** reason - при логин-оболочке не семейства sh окно терминала закрывалось сразу, файл не исполнялся, а Cyborg об этом не сообщал; одобрение, после которого запустить нечем, бессмысленно; assumptions - оболочка определяется по имени файла из `SHELL` окружения Cyborg; незаданный `SHELL` отказа не даёт; relationships - FR-18004, FR-18006, FR-18007, FR-18009, ADR-0021 п.7; design constraints - на macOS кавычение Terminal.app рассчитано на sh: при иной логин-оболочке текст после обратной косой черты и кавычки исполнился бы (D-16).
- **verification:** испытание - `test/run-file.test.ts` («логин-оболочка не семейства sh - отказ с её именем на обеих ОС, эмулятор не ищется», «darwin: обратная косая черта в каталоге или команде - отказ, linux её пропускает», «win32 - не поддерживается», «удалённый, ставший незапускаемым файл: ошибка без запуска», «бит есть, права чтения нет: «Файл не прочитан», без диалога, запуска и одобрения», «эмулятора нет: сообщение, без диалога», «ошибка запуска эмулятора возвращается», «ошибка ответа и исключение показываются окном, успех и отмена - нет»).
- **класс:** Functions. **origin:** source; отказ по обратной косой черте, порядок проверок и тексты сообщений - derived.

## 15. Logical database requirements

### FR-18005 Хранилище одобрений run-approvals.json

- **Требование:** одобрения лежат в файле `run-approvals.json` каталога данных приложения, одном на все воркспейсы, и переживают перезапуск Cyborg. Запись - объект JSON: ключ - физический абсолютный путь файла, значение - `{sha256, command}`: `sha256` - 64 шестнадцатеричных знака в нижнем регистре, `command` - непустой массив строк. Новое одобрение пути заменяет прежнее. Запись файла атомарная. Хранится не больше 1000 одобрений: при превышении вытесняется одобренное раньше всех. Файл отсутствует, не разбирается либо не объект - одобрений нет; запись с неабсолютным ключом либо значением иной формы пропускается. Запись на диск не удалась - запуск идёт, а следующий запуск того же файла спрашивает снова. Значения переменных окружения, содержимое файла и вывод запуска в хранилище не попадают.
- **traced from:** BR-18001.
- **источник:** формулировка оператора («сохранить одобрение и хэш файла»); цель, критерии 5 и 12; D-05, D-14.
- **rationale:** reason - согласие не должно спрашиваться заново при каждом запуске и после перезапуска; assumptions - повреждённый файл безопаснее считать пустым: худший исход - лишний вопрос; relationships - FR-18004, FR-1015 фичи 01 (перечень того, что главный процесс пишет на диск); design constraints - файл читается на каждое нажатие, без предела он рос бы без границы (D-14).
- **verification:** испытание - `test/run-file.test.ts` («нет записи, тот же хэш, другой хэш заменяет прежний», «переживает пересоздание», «битый файл, не объект, плохие записи - пусто», «сбой записи: false, не бросает», «предел 1000 записей вытесняет самую давнюю», «сбой записи одобрения: запуск идёт, в следующий раз спросят снова»), `test/static-guards.test.ts` (перечень пишущих файлов).
- **класс:** Logical database requirements. **origin:** source; форма записи, предел и разбор повреждённого файла - derived.

## 18. Software system attributes

### NFR-18001 Имя файла, его каталог и shebang не исполняются как текст команды

- **Требование:** классификация данных: путь файла, его содержимое и первая строка - недоверенные данные репозитория (их пишут сессии и чужие коммиты), только локально; одобрение - локальные данные пользователя. Каталог файла и слова команды доходят до оболочки отдельными аргументами постоянного скрипта запуска и исполняются как `"$@"`: файл с пробелом, кавычкой, `$` и `;` в своём имени либо в имени каталога запускается как этот файл, текст из имени не исполняется. Текст скрипта запуска и сценарий для Terminal.app не зависят от файла. Строка команды из предупреждения к исполнению не идёт. Интерпретатор берётся только из первой строки файла и только абсолютным путём (FR-18002). Модель авторизации: субъект - разработчик за окном Cyborg; право запуска даёт только его «Запустить» в окне главного процесса либо действующее одобрение тех же содержимого и команды; интерфейс права решать не имеет - он передаёт путь, который главный процесс проверяет заново (FR-18009).
- **traced from:** BR-18001.
- **источник:** цель, критерий 10; ADR-0002 (интерфейс показывает недоверенные данные); D-08.
- **rationale:** reason - имя файла в репозитории выбирает не разработчик, и подстановка его в строку команды дала бы исполнение текста из имени; assumptions - нет; relationships - FR-18002, FR-18006, FR-18007, FR-18008, ADR-0021 п.5; design constraints - временный скрипт с путём в тексте и формы эмуляторов с командой одной строкой отвергнуты (D-08).
- **verification:** испытание - `test/run-file.test.ts` («имя файла и каталога со спецсимволами: исполняется этот файл, текст из имени - нет», «darwin: скрипт AppleScript постоянен, каталог и файл - отдельными элементами», «форма передачи команды по эмулятору, argv поэлементно», «displayCommand, shellQuote и shQuote дают одно кавычение», «негодный shebang: относительный, пустой, управляющие символы, не UTF-8, длинный»).
- **класс:** Software system attributes. **origin:** source; модель авторизации - derived.
