## 1. BRS overview

Документ фиксирует назначение Cyborg, его стороны и границу. Проблема: разработчик, который ведёт несколько
сессий Claude Code сразу, держит их в разрозненных терминалах и отдельно открывает файлы и git-изменения,
которых коснулась сессия. Решение: настольное рабочее место, где каждая нативная сессия Claude Code идёт со своим
деревом файлов, git-статусом и просмотром файлов (`package.json:5`). Ожидаемая выгода: состояние каждой сессии
видно в одном окне без переключения между инструментами. Документ адресован владельцу продукта и составителям
требований и архитектуры.

## 2. Business purpose

Дать разработчику одно место, где видно, что каждая из его параллельных сессий Claude Code делает с
репозиториями проекта, при этом сама сессия остаётся нативной: Cyborg не подменяет Claude Code и не меняет то,
как тот пишет свою историю (`src/main/sessions.ts:43`, `src/main/sessions.ts:126`).

## 3. Business scope

Внутри границы:

- проекты как именованные наборы локальных репозиториев с описанием;
- запуск, ввод, изменение размера и завершение интерактивных сессий Claude Code в выбранном репозитории проекта,
  остальные репозитории проекта подключаются к сессии как дополнительные каталоги;
- дерево файлов сессии с ветками и git-статусом каждого репозитория, следующее за рабочим каталогом сессии, с
  раскрытием по каждому каталогу независимо (фича `04-session-tree`);
- просмотр текстовых файлов с подсветкой синтаксиса; изменённый файл открывается сравнением с версией в HEAD; Markdown - отрендеренным
  документом с переключением на сравнение, исходник которого правится по кнопке «Править» и сохраняется в файл (фича `16-markdown-view`);
- окно поиска, вызываемое меню «Поиск»: файл по имени, строка по содержимому файлов и по изменениям (рабочее дерево против HEAD), подстрока либо регулярное выражение, переход к строке в просмотре (фича `13-file-search`);
- окно «Расширения», вызываемое меню «Расширения»: магазины плагинов и их содержимое, установленные плагины, скиллы, команды и агенты, серверы MCP в областях «Сессия», «Проект», «Везде»; установка и удаление плагина, подключение и отключение магазина вызовом `claude plugin`; хабы - списки магазинов для поиска и подключения (фича `14-extensions`, ADR-0018);
- смена ветки репозитория из дерева командой `git switch` по существующей ветке (фича `07-branch-switch`, ADR-0011);
- прошлые сессии проекта: список, продолжение `claude --resume`, удаление (фича `08-session-history`, ADR-0012);
- инструкция изоляции в каждой сессии: параллельные сессии уходят каждая в свой worktree (фича `09-session-isolation`, ADR-0012);
- размер шрифта, запоминание фильтров и сортировки панелей, порядок репозиториев, `Shift+Enter`, воркспейс, проект и версия в заголовке окна, уведомление рабочего стола, когда сессия ждёт человека, ссылки в выводе сессии: путь и адрес открываются по клику (фича `10-ui-preferences`);
- воркспейс: файл проектов по любому пути, один процесс на воркспейс, «Недавние», окно первого запуска, смена воркспейса в этом окне пунктом «Воркспейс → Открыть…» (фича `01-tasks-panel`, FR-1028..FR-1030, FR-1033, ADR-0014);
- запуск и работа на macOS и Linux, запуск одной командой `./cyborg` (фича `05-macos-support`);
- README и сайт документации (фича `06-docs-site`);
- светлая и тёмная тема по системной настройке;
- открытые задачи GitHub и GitLab по remote репозиториев текущего проекта и старт сессии Claude Code по задаче
  (фича `01-tasks-panel`); источник подключается в свойствах проекта, авторизация - залогиненные `gh` и `glab`;
- открытые MR GitLab и PR GitHub тех же remote во вкладке «MR/PR» панели задач и сессия ревью чужого либо доработки
  своего MR (фича `02-mr-view`);
- абсолютный путь строки дерева либо файла из файлового менеджера ОС в промпт сессии перетаскиванием на её
  терминал (фича `03-path-drop`);
- кнопка «Статус»: упавшие пайплайны и замечания к своим MR, MR на моём ревью и открытые задачи Jira на мне с индикатором, деталями
  задачи Jira и запуском сессии по слову разработчика (фича `11-status-hub`, ADR-0013); Jira читается через `jira-cli`;
- кнопки-команды под терминалом активной сессии: нажатие или сочетание клавиш отправляет заданный текст в сессию, подстановки
  `{branch}`, `{pr}`, `{task}`; набор - встроенные кнопки, общий набор всех воркспейсов (`commands.json` в userData) и поле `commands` файла воркспейса, правка JSON в Monaco из меню; кнопки, которые предлагает модель; промпты кнопок запуска сессий в общем `prompts.json` (фича `12-command-buttons`, ADR-0015, ADR-0016, ADR-0017);
- MCP-сервер Cyborg, подключённый к каждой сессии: сессия открывает новую вкладку своего проекта с заданием (`open_session`), видит вкладки проекта
  с состоянием и хвостом ответа (`list_sessions`) и пишет другой вкладке - сразу, если та ждёт сообщения, иначе после конца её хода (`send_to_session`), и закрывает вкладку проекта (`close_session`)
  (фича `15-session-mcp`, ADR-0019).

`non-goals` (выведены из отсутствия в коде, подтверждаются владельцем):

- правка файлов в Cyborg: код и прочие файлы просмотрщик только читает; исключения - Markdown, который разработчик правит по кнопке «Править» (фича `16-markdown-view`, D-01, D-02), и JSON кнопок-команд (поле `commands` файла воркспейса и общий `commands.json`) и промптов (`prompts.json`), которые разработчик правит в диалогах Cyborg (фича `12-command-buttons`, D-04, D-25, D-26);
- git-операции, меняющие репозиторий, кроме смены ветки на существующую (`git switch`, ADR-0011): коммит, создание, удаление и
  принудительная смена ветки, слияние;
- собственный клиент модели или обёртка над API: работа идёт только через CLI `claude`; настройки Claude Code Cyborg сам не пишет, плагины и магазины меняет вызовом `claude plugin` по подтверждению в окне (фича `14-extensions`, ADR-0018);
- удалённые машины и многопользовательская работа: все пути и процессы локальные, сеть Cyborg использует только
  для обращения к трекерам задач и к хабам магазинов по https: файл хаба, поиск GitHub по теме и каталоги найденных магазинов (фича `14-extensions`),
  и слушает только `127.0.0.1` - MCP-сервер для своих сессий, по токену сессии (фича `15-session-mcp`) (brief панели задач, «Расхождения с BRD», §3);
- запись в трекер задач, включая Jira: статус задачи меняет агент сессии, Cyborg его только читает; MR Cyborg не апрувит, не
  комментирует и не меняет, ветку MR переключает агент сессии;
- сессия, начатая без слова разработчика: Cyborg по событиям трекеров сессий сам не запускает (фича `11-status-hub`, D-05); вкладку по `open_session`,
  сообщение по `send_to_session` и закрытие по `close_session` Cyborg открывает, пишет и закрывает только по вызову инструмента, который разработчик подтвердил запросом разрешения
  Claude Code в вызывающей сессии, своего подтверждения у Cyborg нет (D-11 фичи 15);
- кнопки-команды сами ничего не отправляют: без нажатия или сочетания разработчика текст в сессию не уходит; не блокируются, пока
  Claude работает (он ставит ввод в очередь сам), не проверяют, пусто ли поле ввода, не бывают контекстными и не шлют одну команду в
  несколько сессий (фича `12-command-buttons`, D-08, Issue #26);
- автоматическое восстановление сессий после перезапуска Cyborg: процессы и вкладки не переживают закрытие окна, прошлую сессию
  разработчик продолжает вручную из вкладки «Сессии» (фича `08-session-history`).

## 4. Business overview

Сегодня разработчик запускает `claude` в эмуляторе терминала, по окну на сессию, а файлы и изменения смотрит в
редакторе или через git отдельно. Связь «какая сессия что меняет» держится в голове. Нет данных о том, как
постановщик видит процесс сейчас - открытый вопрос 1.

## 6. Business environment

Внешние силы: Claude Code CLI и его механизм хуков, на который Cyborg опирается целиком, - смена формата событий
или флагов CLI ломает продукт без изменения в нём; git как источник статуса; трекеры задач и их CLI `gh`/`glab` -
смена API либо формата вывода CLI ломает панель задач, вид MR/PR и сводку статуса; формат вывода `jira-cli` (`--raw`) у Cyborg
проверен на Jira Server 9.2, Cloud и Data Center вживую не проверялись (фича `11-status-hub`, D-11); Electron и нативный модуль
терминала, привязанные к версии рантайма. Регулятора и юрисдикции у предмета не выявлено.

## 7. Mission, goals and objectives

### BR-001 Параллельные нативные сессии в одном окне

- **Требование:** разработчик ведёт несколько сессий Claude Code одновременно в одном окне, каждую в контексте
  выбранного проекта и его репозитория.
- **traced from:** Business purpose; сторона «разработчик».
- **rationale:**
  - reason: цель продукта - собрать параллельные сессии в одном месте (`package.json:5`);
  - assumptions: сессия - нативный процесс `claude`, а не встроенный клиент;
  - relationships: сценарий 1 раздела 17;
  - design constraints: нативность сессии задана - транскрипт и поведение Claude Code не должны отличаться от
    запуска в терминале (`src/main/sessions.ts:43`), кроме инструкции изоляции (фича `09-session-isolation`, D-02).
- **MOE:** разработчик переключается между своими сессиями и видит вывод каждой, не открывая другой терминал
  (качественная).

### BR-002 Видимость изменений сессии

- **Требование:** для каждой сессии разработчик видит файлы её рабочего каталога и других репозиториев проекта с
  текущей веткой и git-статусом, обновляющимися по ходу работы сессии.
- **traced from:** Business purpose; сторона «разработчик».
- **rationale:**
  - reason: связь «сессия - что она меняет» сейчас держится в голове (раздел 4);
  - assumptions: изменения сессии отражаются в git-статусе рабочих деревьев;
  - relationships: сценарий 2 раздела 17;
  - design constraints: нет.
- **MOE:** после действия сессии над файлами разработчик видит изменённый файл отмеченным в дереве этой сессии
  без ручного обновления (качественная).

### BR-003 Просмотр файла на месте

- **Требование:** разработчик открывает файл из дерева сессии и читает его с подсветкой синтаксиса, Markdown - отрендеренным
  документом, который по кнопке правит и сохраняет, не покидая рабочего места.
- **traced from:** BR-002.
- **rationale:**
  - reason: увидев изменённый файл, разработчик хочет прочитать его там же, а документацию - в виде, в котором её читают другие;
  - assumptions: правку кода ведёт сессия или внешний редактор, Cyborg его только показывает; в Cyborg правится только Markdown (фича `16-markdown-view`);
  - relationships: сценарий 2 раздела 17; BR-16001;
  - design constraints: запись - только Markdown по действию разработчика, граница non-goals раздела 3.
- **MOE:** файл, открытый из дерева, показывает актуальное содержимое с диска при каждом показе (качественная).

### BR-004 Задача либо MR трекера в работу сессией, не покидая Cyborg

- **Требование:** разработчик видит открытые задачи и MR трекеров по репозиториям текущего проекта и начинает по
  задаче либо MR сессию Claude Code, не покидая Cyborg.
- **traced from:** Business purpose; сторона «разработчик»; brief панели задач («Расхождения с BRD», новый BR);
  brief вида MR/PR п.1, п.6.
- **rationale:**
  - reason: задача либо MR, по которым идёт сессия, сегодня ищутся в браузере трекера и пересказываются сессии
    руками;
  - assumptions: задачи и MR проекта ведутся в GitHub или GitLab, разработчик залогинен в их CLI;
  - relationships: сценарии 4 и 5 раздела 17; фичи `01-tasks-panel`, `02-mr-view`;
  - design constraints: сессия остаётся нативной (BR-001); Cyborg в трекер не пишет (non-goals раздела 3).
- **MOE:** разработчик начинает сессию по задаче либо MR проекта из Cyborg, и сессия получает ссылку на задачу либо
  MR без ручного ввода (качественная).

### BR-005 Состояние работы по проекту перед глазами, реакция агента по слову разработчика

- **Требование:** разработчик одним взглядом на кнопку и одним нажатием видит, что по проекту требует его внимания: упавшие
  пайплайны и замечания к его MR/PR, MR на его ревью и открытые задачи Jira на нём со статусом и деталями; по любой записи он одним
  действием запускает сессию Claude Code, которая разберёт упавший пайплайн, замечания либо задачу. Cyborg ничего не пишет ни в
  трекеры, ни в Jira и сам сессий не запускает.
- **traced from:** Business purpose; сторона «разработчик»; запрос владельца 2026-10-26 («кнопка как в Discord: статус из
  GitLab/GitHub и Jira, смотреть задачу в Jira, реагировать агентом»).
- **rationale:**
  - reason: состояние работы по проекту узнаётся сегодня обходом браузера (CI, MR, Jira) и пересказывается сессии руками;
  - assumptions: разработчик залогинен в `gh`, `glab` и `jira-cli` (по нужным ему источникам);
  - relationships: сценарий 10 раздела 17; BR-004; фича `11-status-hub`; ADR-0013;
  - design constraints: сессия остаётся нативной (BR-001); Cyborg в трекеры не пишет и без слова разработчика сессию не
    запускает (non-goals раздела 3).
- **MOE:** индикатор кнопки называет худшее состояние проекта, карточка по нажатию показывает записи, требующие внимания, и по
  каждой можно начать сессию без ручного ввода ссылки (качественная).

### BR-006 Типовые команды сессии одним нажатием

- **Требование:** разработчик отправляет в видимую сессию Claude Code типовую команду («сливай», «сделай PR», «смерджи PR {pr}»,
  слеш-команду скилла) нажатием кнопки под терминалом либо сочетанием клавиш, без набора руками; текст может нести ветку, PR и задачу
  сессии, а опасное действие вставляется без Enter и отправляется человеком; набор кнопок разработчик правит под себя в файле воркспейса
  без перезапуска. Cyborg сам ничего в сессию не отправляет.
- **traced from:** Business purpose; сторона «разработчик»; Issue #26 (2026-10-27).
- **rationale:**
  - reason: типовые команды Claude Code набираются руками каждый раз, а текст с веткой и номером PR приходится дописывать;
  - assumptions: разработчик знает свои фразы и скиллы, кнопка лишь экономит набор (D-01, D-03);
  - relationships: сценарий 11 раздела 17; BR-001; фича `12-command-buttons`; ADR-0014;
  - design constraints: сессия остаётся нативной (BR-001): Cyborg вводит текст тем же каналом, что клавиатура; без нажатия разработчика
    ничего не уходит (non-goals раздела 3).
- **MOE:** типовая команда уходит в видимую сессию одним нажатием, подстановки раскрыты, а при отсутствии значения текст не уходит и
  причина названа (качественная).

### BR-007 Найти файл и место в коде, не раскрывая дерево

- **Требование:** разработчик по команде с клавиатуры или из меню находит файл по части имени, строку по содержимому файлов и строку среди изменений рабочего дерева против HEAD (подстрокой либо регулярным выражением) и переходит к ней в просмотре.
- **traced from:** Business purpose; BR-003; Issue #55 (2026-10-29).
- **rationale:**
  - reason: в большом репозитории нужный файл не найти раскрытием каталогов, а постоянное поле поиска занимает место;
  - assumptions: корни и файлы те же, что видит дерево сессии (фича `13-file-search`, D-05);
  - relationships: сценарий 12 раздела 17; BR-003; фича `13-file-search`; ADR-0005;
  - design constraints: поиск только читает, git только читающими командами (non-goals раздела 3); переход к строке Markdown открывает его правку (фича `16-markdown-view`).
- **MOE:** нужный файл или строка открываются из окна поиска, вызванного с клавиатуры, без раскрытия каталогов (качественная).

### BR-008 Расширения Claude Code в границах сессии, проекта и всех проектов

- **Требование:** разработчик видит магазины плагинов, установленные плагины, скиллы, команды, агентов и серверы MCP по областям «Сессия», «Проект», «Везде», устанавливает и удаляет плагины, подключает и отключает магазины вызовом `claude plugin` и ищет магазины в хабах.
- **traced from:** Business purpose; BR-001; Issue #59 (2026-10-30).
- **rationale:**
  - reason: что получит сессия, решают несколько файлов настроек Claude Code и каталог запуска, а смотреть это приходится в терминале командами;
  - assumptions: Claude Code остаётся источником истины о включённом, Cyborg сам его файлы не пишет (ADR-0018);
  - relationships: сценарий 13 раздела 17; BR-001; фича `14-extensions`;
  - design constraints: сессия остаётся нативной (BR-001); любое изменение - вызов `claude plugin` по подтверждению в окне (non-goals раздела 3).
- **MOE:** из окна «Расширения» видно, какие плагины, скиллы и серверы MCP действуют в выбранной области, и плагин ставится и удаляется без терминала (качественная).

### BR-009 Сессии проекта поручают работу друг другу

- **Требование:** сессия Claude Code во вкладке Cyborg с подтверждения разработчика открывает новую вкладку своего проекта с заданием, видит вкладки проекта с состоянием и итогом, пишет другой вкладке, не попадая в её вопрос или запрос разрешения, и закрывает вкладку, закончившую работу.
- **traced from:** Business purpose; BR-001; цель `mcp-session-tools` (2026-11-07).
- **rationale:**
  - reason: параллельные сессии проекта работают рядом (BR-001), но задания и итоги между ними переносит только разработчик;
  - assumptions: состояние сессии Cyborg знает только по хукам (ADR-0003, D-12 фичи 15);
  - relationships: сценарий 16 раздела 17; BR-001; фича `15-session-mcp`; ADR-0019;
  - design constraints: сессия остаётся нативной (BR-001): инструменты - через механизм MCP Claude Code, ввод - вставкой, как с клавиатуры; подтверждает разработчик запросом разрешения Claude Code (D-11 фичи 15).
- **MOE:** сессия раздаёт части работы вкладкам проекта и собирает их итог, а разработчик не переносит текст между вкладками руками (качественная).

## 11. Business operational policies and rules

- Сессия Claude Code не оборачивается: Cyborg добавляет к ней только свои хуки, каталоги репозиториев проекта, начальный промпт
  (сессия, начатая из задачи либо MR, получает первым сообщением ссылку на задачу либо MR; решение владельца 2026-10-23) и
  в системный промпт (`--append-system-prompt`) инструкцию изоляции (фича `09-session-isolation`) и инструкцию кнопок от модели:
  предлагать после ответа 1-2 следующих шага комментарием в конце ответа (фича `12-command-buttons`, ADR-0016, D-12, D-16), а также конфиг
  своего MCP-сервера (`--mcp-config`, фича `15-session-mcp`, ADR-0019). Транскрипт CLI не
  меняется; поведение отличается этими инструкциями - решение владельца об отступлении от нативности открыто (D-02 фичи 09, D-16 фичи 12).
- Репозиторий Cyborg меняет единственной командой - `git switch` по действию пользователя в дереве (ADR-0011) - и записью Markdown-файла,
  который разработчик сам правит и сохраняет: только существующий файл, не в `.git`, изменённый на диске - только с согласия (фича `16-markdown-view`); прочее чтение.
- В другую сессию Cyborg пишет только по вызову `send_to_session` и только когда она ждёт сообщения: сессии, стоящей на вопросе,
  разрешении или лимите, ничего не уходит; слэш-команды, «!» и «#» в чужую сессию не отправляются (фича `15-session-mcp`, D-07, D-10).
- Своего токена трекера Cyborg не хранит: доступ к трекеру идёт под входом пользователя в `gh`/`glab`.
- Каждая сессия - изолированное рабочее пространство: дерево, раскрытые каталоги и вкладки файлов не делятся с
  другими сессиями (`src/renderer/app.ts:49`).

## 12. Business operational constraints

- Работа требует установленного CLI `claude`, доступного из логин-оболочки пользователя, и `git`; панель задач
  и вид MR/PR требуют установленного и залогиненного `gh` либо `glab`.
- Файл больше 5 МБ и двоичный файл не показываются (`src/main/files.ts:9`).

## 16. High-level operational concept

Cyborg для разработчика - пульт поверх его собственных сессий Claude Code: сессии работают как в терминале, а
Cyborg добавляет контекст - проект, дерево, статус, просмотр.

## 17. High-level operational scenarios

1. Разработчик выбирает проект и запускает сессию в репозитории; при нескольких репозиториях выбирает один, прочие
   подключаются к сессии дополнительными каталогами. Альтернатива: у проекта нет репозиториев - запуск недоступен.
2. Сессия меняет файлы; дерево сессии отмечает изменения, разработчик открывает файл и читает его; Markdown читает отрендеренным
   документом, по кнопке «Править» правит исходник и сохраняет его. Альтернатива: сессия сменила рабочий каталог - дерево переходит к
   новому корню; файл изменён на диске после начала правки - Cyborg спрашивает, перезаписать ли его (фича `16-markdown-view`).
3. Разработчик закрывает сессию либо окно; процессы сессий завершаются.
4. Разработчик открывает панель задач проекта, выбирает задачу и начинает по ней сессию; сессия получает ссылку на
   задачу первым сообщением, заголовок сессии показывает номер, название и статус задачи. Альтернатива: по задаче
   уже открыта сессия - Cyborg переключает на неё; источник не включён или вход не выполнен - панель показывает,
   что сделать.
5. Разработчик открывает вкладку «MR/PR» панели задач, выбирает MR и открывает по нему сессию: по чужому MR -
   ревью, по своему - доработку; сессия получает ссылку на MR и действие первым сообщением, заголовок сессии
   показывает номер, название, статус и пайплайн MR. Альтернатива: по MR уже открыта сессия - Cyborg переключает
   на неё; пайплайн либо апрувы MR не получены - строка остаётся с «—».
6. Разработчик перетаскивает строку дерева сессии либо файлы из файлового менеджера ОС на терминал сессии или её
   вкладку «Claude»; в промпт вставляются абсолютные пути, путь с пробелом - в одинарных кавычках. Альтернатива:
   сессия завершена либо бросок мимо терминала и вкладки - ничего не вставляется, окно остаётся на месте.
7. Разработчик нажимает на ветку в строке репозитория в дереве, ищет ветку по имени и выбирает её; ветка меняется, дерево
   обновляется. Альтернатива: в репозитории работает сессия либо конфиг репозитория запускает команды (`filter.*`, partial
   clone) - ветка не меняется, причина названа.
8. Разработчик открывает вкладку «Сессии» (вверху боковой колонки), видит прошлые интерактивные сессии проекта, свежие первыми, и
   продолжает выбранную в том же репозитории либо удаляет её. Альтернатива: прошлых сессий нет - список пуст; сессия ушла в
   worktree - она в списке и продолжается оттуда.
9. Несколько сессий работают параллельно в одних репозиториях: каждой передана инструкция уйти в свой worktree перед первой
   правкой, и дерево каждой сессии следует за её каталогом. Альтернатива: сессия в worktree не ушла - Cyborg её не блокирует.
10. Разработчик нажимает кнопку «Статус»: индикатор уже показал худшее состояние проекта, карточка перечисляет открытые задачи Jira
    на нём (со статусом, связанными MR и пайплайном), его MR/PR с упавшим пайплайном либо замечаниями и MR, ждущие его ревью;
    по записи он раскрывает детали задачи Jira и начинает сессию («Начать», «Разобрать пайплайн», «Доработать», «Ревью»).
    Альтернатива: источник недоступен (нет `jira-cli`, вход не выполнен) - карточка называет причину и команду, остальное
    остаётся; по записи уже открыта сессия - кнопка ведёт к ней.
11. Разработчик закончил работу и нажимает под терминалом «Сделай PR», затем «Сливай» (или `Alt+S`): текст уходит в видимую сессию и
    отправляется; «Мердж» вставляет без Enter просьбу открыть PR, если его нет, и слить его, и разработчик нажимает Enter сам. Альтернатива: у ветки нет
    открытого PR/MR либо сессия завершилась - текст не уходит, причина названа у полосы. Свои кнопки разработчик добавляет в меню
    «Воркспейс → Кнопки команд…» (JSON в Monaco: слой «Общие» для всех воркспейсов либо «Этот воркспейс», действующий набор, встроенные кнопки с описаниями тоже), полоса обновляется без перезапуска.
    Ситуативные кнопки предлагает сама модель по ходу работы: они выделены цветом и маркером, вставляют текст (с Enter только по `submit` от модели и клику) и исчезают после следующего
    запроса разработчика. Промпты кнопок запуска сессий («Ревью», «Доработать», «CI», «Взять в работу», задача Jira) разработчик правит там же
    («Воркспейс → Промпты кнопок…»); в промпт попадают только проверенные ссылка и ключ.

12. Разработчик вызывает «Поиск → Найти файл…» (`Cmd+P`, на Linux `Ctrl+Shift+P`), «Найти в файлах…» или «Найти в изменениях…», набирает часть имени
    либо строку (подстрока или регулярное выражение, регистр и целое слово переключаются), стрелками выбирает результат и по `Enter` открывает файл:
    для поиска по содержимому и по изменениям просмотр встаёт на найденную строку. Альтернатива: проекта нет - пункты недоступны; выражение не
    разобрано либо git собран без PCRE - окно называет причину; результатов больше 500 - показаны первые 500 (фича `13-file-search`).
13. Разработчик открывает «Расширения → Магазины…» (`CmdOrCtrl+Shift+X`), «Установленные плагины и скиллы…», «Серверы MCP…» или «Хабы магазинов…», выбирает область
    «Сессия», «Проект» или «Везде», фильтром находит плагин либо скилл, ставит плагин из подключённого магазина (форма называет область и последствия) либо подключает
    магазин по адресу или из хаба. Альтернатива: `claude` не найден - окно показывает файлы настроек и причину; магазин объявляет команду установки - установка
    отказывает, подтверждение остаётся за терминалом (фича `14-extensions`).
14. Разработчик выбирает «Воркспейс → Открыть…» и файл воркспейса: если сессии работают, Cyborg предупреждает, что они будут завершены; после согласия воркспейс открывается
    в этом окне. Альтернатива: файл тот же, что открыт, - ничего не происходит; файл пропал либо открыт другим экземпляром Cyborg - причина названа до вопроса, сессии не
    трогаются; «Открыть в новом окне…» и «Недавние» запускают отдельный процесс (фича `01-tasks-panel`, FR-1029, FR-1033).
15. В выводе сессии разработчик кликает по абсолютному пути либо адресу `http(s)`: файл или каталог открывается приложением системы, адрес - браузером. Альтернатива:
    путь не существует либо это исполняемый файл - окно сообщения называет причину (фича `10-ui-preferences`).
16. Сессия решает поручить часть работы: разработчик подтверждает запрос разрешения на `open_session`, и в фоне открывается вкладка того же проекта с заданием
    первым сообщением; позже сессия по `list_sessions` видит, что вкладка ждёт, читает хвост её ответа и по `send_to_session` дописывает ей. Альтернатива:
    вкладка работает - сообщение ждёт в очереди Cyborg конца её хода; вкладка стоит на вопросе или разрешении - сообщение не уходит, причина названа;
    окно не открыло вкладку за 20 с - ошибка инструмента (фича `15-session-mcp`).
