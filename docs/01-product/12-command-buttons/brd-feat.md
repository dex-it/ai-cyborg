# BRD фичи 12 - кнопки-команды под терминалом сессии

Источник: Issue #26 (2026-10-27): «Типовые команды Claude Code («сливай», «сделай PR», «смерджи», «приберись») сейчас каждый раз
набираются руками. Нужна панель настраиваемых кнопок в быстром доступе: нажатие отправляет заданный текст в активную сессию».
Решения, принятые составителем там, где Issue молчит, - `decision-log.md` (исход «открыто»). Фича опирается на файл воркспейса
(ADR-0014) и канал ввода в сессию (`session:input`).

## 1. BRS overview

Разработчик одинаково часто отправляет сессии одни и те же фразы и слеш-команды. Фича даёт под терминалом активной сессии полосу кнопок:
нажатие или сочетание клавиш отправляет заданный текст в видимую сессию, текст может нести ветку, PR и задачу сессии, а набор кнопок -
встроенный и из файла воркспейса - правится в Monaco из меню без перезапуска. Адресована владельцу продукта и составителям SRS и архитектуры.

## 2. Business purpose

Убрать набор типовых команд руками и дописывание к ним ветки и номера PR, не нарушая нативность сессии (BR-001) и оставляя решение об
отправке опасного действия человеку.

## 3. Business scope

Внутри границы: полоса кнопок под терминалом активной сессии; отправка текста в сессию с Enter либо без него; подстановки `{branch}`,
`{pr}`, `{task}`; необязательное сочетание клавиш у кнопки; встроенный набор и поле `commands` файла воркспейса; пункт меню «Воркспейс →
Кнопки команд…» с правкой JSON в Monaco и проверкой при сохранении; подхват правок без перезапуска.

`non-goals`:

- блокировка и приглушение кнопок, пока Claude работает: Claude Code сам ставит ввод в очередь (D-08);
- проверка, пусто ли поле ввода сессии: набранный текст останется, текст кнопки допишется к нему; надёжная проверка требует разбора экрана
  xterm (различать серую подсказку-заглушку по `isDim()`), это отложено (D-08);
- контекстные кнопки (например, «Мердж» только при открытом PR) (D-08);
- отправка одной команды в несколько сессий (D-08);
- отдельная форма настройки кнопок: правка идёт в JSON (D-04);
- общий для всех воркспейсов пользовательский набор вне файла воркспейса (D-03).

## 7. Mission, goals and objectives

### BR-12001 Типовая команда в видимую сессию одним нажатием

- **Требование:** под терминалом активной сессии есть полоса кнопок; нажатие кнопки либо её сочетания клавиш отправляет текст кнопки в
  видимую сессию (с Enter либо только вставкой), раскрыв `{branch}`, `{pr}`, `{task}` из того, что Cyborg знает о сессии и проекте; если
  значения нет, текст не уходит, а причина названа у полосы; сами кнопки ничего не отправляют.
- **traced from:** BR-006.
- **rationale:**
  - reason: типовые команды и ветка с номером PR набираются руками каждый раз;
  - assumptions: фразы и скиллы разработчик знает сам, кнопка лишь экономит набор (D-01, D-05);
  - relationships: сценарий 11 BRD продукта; ADR-0015; канал `session:input`;
  - design constraints: нативность сессии (BR-001): текст вводится тем же каналом, что клавиатура (D-06); опасное действие по умолчанию
    не отправляется само (D-02).
- **MOE:** по кнопке или сочетанию текст с раскрытыми подстановками оказывается в видимой сессии, при неразрешимой подстановке не уходит
  ничего и причина видна (качественная).

### BR-12002 Набор кнопок под себя без перезапуска

- **Требование:** кнопки берутся из встроенного набора и из поля `commands` файла воркспейса; разработчик правит JSON в Monaco из меню,
  ошибка файла называет кнопку и поле и не даёт записать негодный набор; правка файла - в Cyborg либо снаружи - подхватывается без
  перезапуска.
- **traced from:** BR-006.
- **rationale:**
  - reason: набор команд у каждого свой и меняется чаще, чем выходят версии;
  - assumptions: файл воркспейса - естественное место набора, он уже переносится и версионируется (D-03, ADR-0014);
  - relationships: сценарий 11; ADR-0015; фича `10-ui-preferences` (меню «Воркспейс»);
  - design constraints: запись в файл воркспейса не теряет проекты (D-04).
- **MOE:** добавленная в Monaco кнопка появляется на полосе без перезапуска, а негодная запись отклоняется с причиной (качественная).
