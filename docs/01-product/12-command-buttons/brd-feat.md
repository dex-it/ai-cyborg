# BRD фичи 12 - кнопки-команды под терминалом сессии

Источник: Issue #26 (2026-10-27): «Типовые команды Claude Code («сливай», «сделай PR», «смерджи», «приберись») сейчас каждый раз
набираются руками. Нужна панель настраиваемых кнопок в быстром доступе: нажатие отправляет заданный текст в активную сессию».
Дополнение: Issue #31 (2026-10-27) по отзыву технического директора - описания и все кнопки (в том числе встроенные) видны и правятся в конфиге,
ситуативные кнопки предлагает сама модель, промпты остальных кнопок запуска сессий (ревью, доработка, CI, задача) тоже в конфиге. Решения, принятые составителем там, где Issue молчит, - `decision-log.md` (исход «открыто»). Фича опирается на файл воркспейса
(ADR-0014) и канал ввода в сессию (`session:input`).

## 1. BRS overview

Разработчик одинаково часто отправляет сессии одни и те же фразы и слеш-команды. Фича даёт под терминалом активной сессии полосу кнопок:
нажатие или сочетание клавиш отправляет заданный текст в видимую сессию, текст может нести ветку, PR и задачу сессии, а набор кнопок -
встроенный и из файла воркспейса - правится в Monaco из меню без перезапуска. Адресована владельцу продукта и составителям SRS и архитектуры.

## 2. Business purpose

Убрать набор типовых команд руками и дописывание к ним ветки и номера PR, не нарушая нативность сессии (BR-001) и оставляя решение об
отправке опасного действия человеку.

## 3. Business scope

Внутри границы: полоса кнопок под терминалом активной сессии; отправка текста в сессию с Enter либо без него; подстановки `{branch}`,
`{pr}`, `{task}`; необязательные сочетание клавиш и описание у кнопки; встроенный набор и поле `commands` файла воркспейса, отключение кнопки
(`disabled`); пункт меню «Воркспейс → Кнопки команд…» с правкой действующего набора (встроенные и свои кнопки) в Monaco и проверкой при
сохранении; подхват правок без перезапуска; кнопки, которые по ходу работы предлагает модель (вставляются без Enter), и их отличие от заданных
заранее; поле `prompts` файла воркспейса с промптами кнопок «Ревью», «Доработать», «CI», «Взять в работу» и сессии по задаче Jira, пункт меню «Воркспейс →
Промпты кнопок…» с правкой в Monaco.

`non-goals`:

- блокировка и приглушение кнопок, пока Claude работает: Claude Code сам ставит ввод в очередь (D-08);
- проверка, пусто ли поле ввода сессии: набранный текст останется, текст кнопки допишется к нему; надёжная проверка требует разбора экрана
  xterm (различать серую подсказку-заглушку по `isDim()`), это отложено (D-08);
- кнопки, видимые только при условии (например, «Мердж» только при открытом PR) (D-08); ситуативные кнопки предлагает модель (BR-12003);
- подсказки с описаниями промптов на самих кнопках списков MR и задач (D-20);
- сохранение предложенной кнопки в набор одним нажатием, сочетания клавиш у предложенных кнопок, отключение инструкции предложений настройкой
  (D-16);
- отправка одной команды в несколько сессий (D-08);
- отдельная форма настройки кнопок: правка идёт в JSON (D-04);
- общий для всех воркспейсов пользовательский набор вне файла воркспейса (D-03).

## 7. Mission, goals and objectives

### BR-12001 Типовая команда в видимую сессию одним нажатием

- **Требование:** под терминалом активной сессии есть полоса кнопок; нажатие кнопки либо её сочетания клавиш отправляет текст кнопки в
  видимую сессию (с Enter либо только вставкой), раскрыв `{branch}`, `{pr}`, `{task}` из того, что Cyborg знает о сессии и проекте; если
  значения нет, текст не уходит, а причина названа у полосы; сами кнопки ничего не отправляют.
- **traced from:** BR-006.
- **rationale:**
  - reason: типовые команды и ветка с номером PR набираются руками каждый раз;
  - assumptions: фразы и скиллы разработчик знает сам, кнопка лишь экономит набор (D-01, D-05);
  - relationships: сценарий 11 BRD продукта; ADR-0015; канал `session:input`;
  - design constraints: нативность сессии (BR-001): текст вводится тем же каналом, что клавиатура (D-06); опасное действие по умолчанию
    не отправляется само (D-02).
- **MOE:** по кнопке или сочетанию текст с раскрытыми подстановками оказывается в видимой сессии, при неразрешимой подстановке не уходит
  ничего и причина видна (качественная).

### BR-12002 Набор кнопок под себя без перезапуска

- **Требование:** кнопки берутся из встроенного набора и из поля `commands` файла воркспейса; разработчик правит JSON в Monaco из меню,
  ошибка файла называет кнопку и поле и не даёт записать негодный набор; правка файла - в Cyborg либо снаружи - подхватывается без
  перезапуска.
- **traced from:** BR-006.
- **rationale:**
  - reason: набор команд у каждого свой и меняется чаще, чем выходят версии;
  - assumptions: файл воркспейса - естественное место набора, он уже переносится и версионируется (D-03, ADR-0014);
  - relationships: сценарий 11; ADR-0015; фича `10-ui-preferences` (меню «Воркспейс»);
  - design constraints: запись в файл воркспейса не теряет проекты (D-04).
- **MOE:** добавленная в Monaco кнопка появляется на полосе без перезапуска, а негодная запись отклоняется с причиной (качественная).

### BR-12003 Ситуативные кнопки предлагает модель

- **Требование:** сессия получает инструкцию предлагать кнопки, когда следующие шаги понятны; предложенные моделью кнопки появляются на полосе отдельной
  группой и отличаются от заданных заранее цветом и маркером; нажатие вставляет текст в поле ввода, а Enter модель может попросить только полем `submit`
  (одна нажатая человеком кнопка отправляет текст), отличие видно до нажатия; предложения устаревают, как только человек задал следующий запрос.
- **traced from:** BR-006.
- **rationale:**
  - reason: часть действий ситуативна и заранее не пишется (отзыв технического директора, Issue #31), их подпись и текст знает только модель;
  - assumptions: модель следует короткой инструкции, а хук `Stop` отдаёт конец ответа целиком (D-12);
  - relationships: сценарий 11 BRD продукта; ADR-0016; ADR-0003 (хуки сессии); BR-12001, BR-12002;
  - design constraints: нативность сессии (BR-001): вывод терминала не разбирается и не оборачивается; ответ модели недоверенный (D-13).
- **MOE:** после ответа модели с предложением на полосе появляются её кнопки, нажатие вставляет текст (с Enter только у кнопки с `submit`), а следующий запрос человека их убирает (качественная).

### BR-12004 Промпты остальных кнопок запуска сессий в конфиге

- **Требование:** первое сообщение сессии, которую запускают кнопки «Ревью», «Доработать», «CI», «Взять в работу» и сессия по задаче Jira, берётся из поля `prompts`
  файла воркспейса, а без записи - встроенный текст (прежний); разработчик видит действующие тексты с описаниями и правит их в Monaco из меню; в
  текст попадают только проверенные значения (ссылка MR или задачи, ключ Jira), чужой текст (название, ветки, автор) - нет; негодная запись не
  заменяется встроенной молча и не записывается.
- **traced from:** BR-006.
- **rationale:**
  - reason: отзыв технического директора «для любых кнопок писать промпт», «описания и кнопки видеть в конфиге» (Issue #31): эти промпты были зашиты в код;
  - assumptions: файл воркспейса - то же место настроек, что у кнопок команд (D-17, D-20);
  - relationships: сценарии 4, 5, 10, 11 BRD продукта; ADR-0017; BR-12002;
  - design constraints: чужой текст в промпт не попадает (D-18); проверка и запись в главном процессе (ADR-0002).
- **MOE:** правка текста промпта в редакторе меняет первое сообщение следующей сессии, а негодная запись названа и не отправляется модели (качественная).
