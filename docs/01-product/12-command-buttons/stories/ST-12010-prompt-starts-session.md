# ST-12010 Правка промпта доходит до первого сообщения сессии

Как разработчик, я хочу, чтобы сессия по кнопке начиналась с моего промпта, и чтобы в него не попадал чужой текст.

## Acceptance Criteria

- **AC-1.** Дано: файл воркспейса без поля `prompts`. Когда я запускаю сессию кнопкой («Ревью», «Доработать», «CI», «Взять в работу», задача Jira). Тогда первое сообщение то же, что было до появления поля. [FR-12009]
- **AC-2.** Дано: для `jira.start` записан текст `Работай над {jira_key}`. Когда я начинаю сессию по задаче Jira DEX-12. Тогда первое сообщение `Работай над DEX-12`, без перезапуска Cyborg. [FR-12009]
- **AC-3.** Дано: в тексте `mr.review` подстановка `{mr_url}`. Когда я начинаю ревью MR. Тогда подставлена ссылка на MR; название MR, ветки и автор в сообщение не попадают. [FR-12009]
- **AC-4.** Дано: у `task.start` подстановки `{task_url}` и `{status_command}`. Когда я беру в работу задачу GitHub (GitLab). Тогда подставлены ссылка на задачу и `gh issue edit` (`glab issue update`). [FR-12009]
- **AC-5.** Дано: в файле, правленном руками, негодная запись `mr.review` (текст начинается с «-»). Когда я нажимаю «Ревью». Тогда сессия не стартует, окно сообщения называет промпт и причину (без служебной обёртки Electron) и отправляет в меню «Промпты кнопок…»; встроенный текст молча не подставлен. [FR-12009]
- **AC-6.** Дано: та же негодная запись `mr.review`. Когда я начинаю «Доработать» или сессию по задаче. Тогда они стартуют: чужая запись не мешает. [FR-12009]
- **AC-7.** Дано: файл с повреждённым JSON. Когда я сохраняю промпты. Тогда файл не затирается, причина названа. [FR-12009]
