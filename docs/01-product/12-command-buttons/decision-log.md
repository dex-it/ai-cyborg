# decision-log фичи 12 - кнопки-команды под терминалом сессии

Решения и допущения по Issue #26 (2026-10-27) и Issue #31 (D-11..D-21, 2026-10-27). Исход «открыто» - допущение составителя там, где Issue молчит; подтверждает либо меняет
владелец продукта. Решения, названные в Issue прямо («Решено не делать»), помечены исходом «принято».

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | Встроенный набор - «Сливай» (`сливай`), «Сделай PR» (`сделай PR`), «Мердж» (`смерджи PR {pr}`, без Enter) и «Приберись» (`приберись`) как обычные фразы с сочетаниями F1-F4 по порядку | слеш-команда `/cleanup-merged-branches` из примера Issue: скилла у разработчика может не быть, и Claude Code ответит «неизвестная команда»; встроенные сочетания с буквой: зависят от раскладки, а F-клавиши - нет; встроенные без сочетаний (прежняя редакция): владелец попросил сочетания | Issue #26, перечень «типовых команд» и примеры | открыто |
| D-02 | `submit` по умолчанию `false`: кнопка без поля только вставляет текст, Enter нажимает человек | по умолчанию `true`: опечатка в имени поля (`submt`) включила бы отправку опасного действия; проверка в файле называет лишнее поле, но кнопка остаётся | Issue #26: «`submit: false` - только вставить (для опасных действий)» | открыто |

| D-04 | Правка - диалог с Monaco на поле `commands` из меню «Воркспейс → Кнопки команд…»; главный процесс проверяет текст и пишет только это поле (`commands:save`), проекты и чужие поля файла остаются; запись проектов поле сохраняет. Это единственное место, где Cyborg правит файл, и non-goal BRD «правка файлов» названо с этим исключением | открыть в Monaco весь файл воркспейса: правка проектов в нём спорила бы с их хранением в памяти окна и затирала бы чужие правки; отдельная форма кнопок (Issue: «отдельный диалог не нужен»); открыть файл внешним редактором: Issue называет Monaco | Issue #26: «пунктом системного меню, который открывает JSON в Monaco»; ADR-0015 | открыто |
| D-05 | `{branch}` - ветка git корня сессии в момент нажатия; `{pr}` - ссылка PR/MR, с которого начата сессия, иначе ссылка открытого PR/MR с этой веткой источника в репозиториях проекта среди всех PR/MR (выборка `all`): свой приоритетнее чужого, чужой берётся, если своего нет; несколько на одном уровне - отказ с перечнем номеров; PR/MR с одинаковой веткой источника и назначения (из форка) не берётся; `{task}` - ключ задачи Jira либо ссылка задачи трекера, из которых начата сессия. Нет значения (нет ветки, у ветки нет PR либо их несколько, сессия не из задачи) или оно небезопасно - текст не уходит, причина названа у полосы; чужие `{...}` остаются как есть | номер вместо ссылки в `{pr}`: в проекте с несколькими репозиториями номер двусмыслен; подстановка пустой строки или литерала при отсутствии значения: «смерджи PR » ушёл бы без адресата; только свои PR/MR (выборка «автор»): PR коллеги на ветке сессии не находился; любой PR с совпавшей веткой: PR из форка со своей `main` принимался бы за PR ветки сессии `main` | Issue #26: подстановки «из того, что Cyborg уже знает о сессии и проекте»; доработка PR #28 (PR с чужим автором) | открыто |
| D-06 | Текст уходит в сессию каналом `session:input` одной записью, Enter (`\r`) - отдельной записью через 150 мс; пока Enter не ушёл, кнопка занята, а завершившаяся за это время сессия Enter не получает. Проверено на живом Claude Code 2.1.311 через pty: слеш-команда `/help` и обычная фраза отправляются и пакетом `текст` с `\r`, и раздельно с паузой 150 мс | пакет «текст и Enter» одной записью: отправляется на 2.1.311, но зависит от того, считает ли TUI такой пакет вставкой, где Enter - перевод строки; `term.paste`: то же и нужен режим bracketed paste | Issue #26: «через существующий канал `session:input`»; опыт 2026-10-27; доработка PR #28 (риск версии Claude Code) | открыто |
| D-07 | Сочетание кнопки обрабатывается на уровне окна для видимой сессии по `event.code`; допустимо с Alt либо Cmd, либо Ctrl с Shift (чистый Ctrl+буква - управляющие символы терминала); сочетания, занятые приложением, и повторы отвергаются; при записи из редактора сочетание должно годиться и на другой системе (файл переносят между macOS и Linux: `CmdOrCtrl+K` годится на macOS, но не на Linux); при вводе в поле (не терминал) и открытом диалоге не срабатывает | глобальное сочетание, пока окно не в фокусе: вне границы окна; Ctrl+буква без Shift: отнимает у сессии Ctrl+C и другие; проверка только на своей системе: перенесённый файл получал замечание | Issue #26: необязательный `hotkey`, пример `Alt+S`; поведение xterm с Option на macOS (ß вместо s); доработка PR #28 | открыто |
| D-08 | Не блокировать и не приглушать кнопки, пока Claude работает; не проверять, пусто ли поле ввода сессии (набранное останется, текст кнопки допишется); без контекстных кнопок; без отправки одной команды в несколько сессий | блокировка по «Claude занят»: Claude Code сам ставит ввод в очередь; разбор экрана xterm с `isDim()`: надёжность и объём, отложено | Issue #26, раздел «Решено не делать (пока)» | принято |
| D-09 | Файл кнопок перечитывается при возврате фокуса окну и после записи из редактора, без наблюдателя за файлом; перерисовка - только если поле изменилось | `fs.watch`: платформенные различия и сброс событий при атомарной записи через переименование; опрос по таймеру: лишняя работа ради редкой правки | Issue #26: «изменения подхватываются без перезапуска» | открыто |
| D-10 | Пределы: не больше 30 кнопок, `label` до 40 знаков, `text` до 2000 знаков и в одну строку (перевод строки в тексте был бы нажатием Enter посреди фразы), без управляющих символов; негодная кнопка пропускается с причиной и номером, ошибка только в `hotkey` оставляет кнопку без сочетания, лишнее поле называется; при сохранении любая проблема - отказ | подставлять значения по умолчанию молча: опечатка прошла бы незамеченной; многострочный `text`: Enter нельзя отличить от отправки | инженерный вывод: безмолвных fallback нет | открыто |
| D-11 | Редактор открывает **действующий набор целиком**: встроенные кнопки (с описаниями) и записи файла как они есть, в порядке полосы (встроенные на своих местах, затем свои); сохранение пишет текст редактора как есть. У кнопки поле `description` (до 200 знаков, одна строка, необязательное): подсказка кнопки и строка редактора; поле `disabled: true` скрывает кнопку, в том числе встроенную, и освобождает её сочетание. Записи файла в редакторе берутся без разбора, чтобы негодную запись можно было поправить, а не потерять. Встроенным кнопкам добавлены описания, их тексты не менялись | показывать в редакторе только свои кнопки (как было): встроенные и их описания не видны, «в конфиге» их нет; сохранять только отличия от встроенных: файл снова скрывал бы встроенные, а видимый в редакторе набор не совпадал бы с записанным; порядок как в файле: изменил бы полосу у воркспейсов, где записана одна замена встроенной; отдельный реестр встроенных кнопок в файле: второй формат | Issue #31; отзыв технического директора: «описания и кнопки видеть в конфиге», «для любых кнопок писать промпт» | открыто |
| D-12 | Канал предложений модели: к системному промту сессии (`--append-system-prompt`, вместе с инструкцией об изоляции) добавляется инструкция: если следующие шаги понятны, в самом конце ответа дописать комментарий `<!-- cyborg-buttons: [{"label","text"}] -->` на 1-4 кнопки, иначе не писать; главный процесс разбирает такой хвост из `last_assistant_message` события `Stop` (хуки уже подключены, ADR-0003) и шлёт интерфейсу `session:suggest` | MCP-инструмент `suggest_buttons` с вызовом в `PostToolUse`: нужны сервер, согласие на инструмент и его настройка, строка вызова инструмента видна так же; запись файла моделью: запрос разрешения на каждую запись; разбор экрана терминала либо обёртка вывода: нарушает нативность сессии (BR-001); отдельный вызов `claude -p` за предложениями: лишний запрос и контекст | опыт 2026-10-27, Claude Code 2.1.311: `claude -p` с такой инструкцией дописал комментарий в конец ответа, хук `Stop` отдал его целиком в `last_assistant_message`; в pty терминал показывает комментарий как обычный текст (1-3 строки JSON под ответом) | открыто |
