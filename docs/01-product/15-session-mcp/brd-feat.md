# BRD фичи 15 - MCP-сервер Cyborg: сессия открывает вкладки проекта, видит их и пишет им

Источник: цель `mcp-session-tools` (2026-11-07): «Cyborg поднимает MCP-сервер, через который сессия Claude Code в вкладке Cyborg управляет другими вкладками своего проекта»; решения оператора по подтверждению и остаточному риску - D-11, D-12; закрытие вкладки - просьба оператора 2026-11-09 (D-18..D-21). Источник требований выше цели оператор не назвал. Решения составителя - `decision-log.md`, исход «принято составителем» до подтверждения владельцем.

## 1. BRS overview

Разработчик ведёт в Cyborg несколько сессий Claude Code одного проекта, но поручить работу соседней вкладке, узнать её состояние и дописать ей может только он сам, переключаясь между вкладками. Фича даёт сессии четыре инструмента MCP-сервера Cyborg: открыть новую вкладку проекта с заданием, перечислить вкладки проекта с состоянием и хвостом ответа, отправить сообщение другой вкладке, закрыть вкладку проекта. Адресована владельцу продукта и составителям SRS.

## 2. Business purpose

Сессия раздаёт части работы параллельным сессиям того же проекта и собирает их результат без того, чтобы человек переносил задания и ответы между вкладками руками; каждое действие сессии человек подтверждает запросом разрешения Claude Code в ней самой.

## 3. Business scope

Внутри границы: MCP-сервер в главном процессе Cyborg, подключаемый к каждой сессии, которую запускает Cyborg; инструменты `open_session` (новая вкладка в том же проекте, первое сообщение - задание), `list_sessions` (вкладки проекта, их состояние и хвост последнего ответа), `send_to_session` (сообщение в другую вкладку, очередь для работающей), `close_session` (закрытие вкладки проекта, в том числе своей).

`non-goals`:

- подтверждение отправки в интерфейсе Cyborg: подтверждает Claude Code запросом разрешения в вызывающей сессии (D-11);
- вкладки и сессии чужих проектов и сессии, запущенные не из Cyborg;
- слэш-команды, команды оболочки (`!`) и запись в память (`#`) в чужую сессию (D-10);
- ответ на вопрос, разрешение или лимит, на которых стоит другая сессия: такую сессию инструменты не трогают, закрыть её можно только явным `force` (D-18);
- хранение очереди сообщений между запусками Cyborg (D-12);
- доступ к серверу не из сессии Cyborg: с другой машины, из браузера, из процесса без токена сессии.

## 7. Mission, goals and objectives

### BR-15001 Сессия поручает работу другим вкладкам проекта, видит их и пишет им

- **Требование:** сессия Claude Code во вкладке Cyborg по решению модели и с подтверждения человека открывает новую вкладку в том же проекте с самодостаточным заданием первым сообщением, видит открытые вкладки проекта с их состоянием (запускается, работает, ждёт сообщения, ждёт человека) и хвостом последнего ответа и отправляет другой вкладке сообщение - сразу, если та ждёт, или после конца её хода; в сессию, которая ждёт человека, ничего не уходит; закрывает вкладку проекта, закончившую работу, и свою.
- **traced from:** BR-009.
- **rationale:**
  - reason: параллельные сессии проекта уже есть (BR-001, фича `09-session-isolation`), но связывает их только человек;
  - assumptions: состояние вкладки известно только по хукам Claude Code, запрос разрешения может появиться раньше своего события (D-12);
  - relationships: BR-009 BRD продукта (сценарий 16 раздела 17), BR-001, фича `09-session-isolation` (каждая сессия в своём worktree), фича `12-command-buttons` (ввод тем же каналом, что клавиатура), ADR-0003, ADR-0019;
  - design constraints: сессия остаётся нативной (BR-001): Cyborg пишет в чужую вкладку только вставкой, как человек; подтверждение - запросом разрешения Claude Code (D-11).
- **MOE:** сессия открывает вкладку проекта с заданием, узнаёт, что та закончила, читает её итог и дописывает ей, а человек не переносит текст между вкладками; Enter, отправленный Cyborg, не подтверждает чужой запрос разрешения (качественная).
