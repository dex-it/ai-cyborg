# SRS фичи 15 - MCP-сервер Cyborg и инструменты сессий

## 1. SRS overview

Требования к MCP-серверу Cyborg и четырём его инструментам: подключение сессии к серверу, протокол, доступ, `open_session`, `list_sessions`, `send_to_session`, `close_session`, состояние сессии по хукам и очередь сообщений, каналы передачи и закрытия вкладки в интерфейсе. Вход - BRD фичи (`brd-feat.md`, BR-15001), цель `mcp-session-tools`, просьба оператора о закрытии сессии (2026-11-09, D-18), код `src/main/mcp.ts`, `src/main/session-tools.ts`, `src/main/sessions.ts`, `src/main/main.ts`, `src/main/preload.ts`, `src/renderer/app.ts`. Основания решений - `decision-log.md` (D-NN) и ADR-0019.

## 2. Purpose

Задать наблюдаемое поведение сервера и инструментов так, чтобы правка проверялась по требованию, а не по коду.

## 3. Scope

MCP-сервер в главном процессе, конфиг `--mcp-config` сессии, инструменты `open_session`, `list_sessions`, `send_to_session`, `close_session`, состояние сессии для инструментов, очередь сообщений, каналы `session:handoff`, `session:handoffFailed`, `session:close`, `session:release` и старт `{handoff}` канала `session:create`. Вне фичи: подтверждение отправки в интерфейсе Cyborg, сессии чужих проектов и запущенные не из Cyborg, ответ за человека на вопрос или разрешение, хранение очереди на диске (`brd-feat.md`, раздел 3).

## 4. Product perspective

Сервер - часть главного процесса, рядом с менеджером сессий; клиент - Claude Code в каждой сессии, запущенной Cyborg (ADR-0003). Вкладку новой сессии открывает интерфейс тем же путём, что вкладку из панели задач (`session:create`), а закрывает - тем же путём, что крестик вкладки; ввод в другую сессию идёт в её pty, как ввод с клавиатуры (ADR-0019).

## 5. Product functions

Подключение сессии к серверу; протокол MCP поверх HTTP; доступ по токену сессии; открытие вкладки по заданию; перечень вкладок проекта; сообщение другой вкладке; очередь для работающей; закрытие вкладки проекта; состояние сессии по хукам; передача вкладки интерфейсу.

## 6. User characteristics

`inherited`: BRD продукта, раздел 5. Пользователь инструментов - модель в сессии Claude Code; человек подтверждает каждый вызов запросом разрешения Claude Code (D-11).

## 7. Limitations

Транспорт - Streamable HTTP только на `127.0.0.1` (D-01). Промпт и сообщение - до 100 000 байт UTF-8: промпт уходит одним аргументом `claude`, а Linux ограничивает аргумент 128 КиБ (D-10). Новых npm-зависимостей нет.

## 8. Assumptions and dependencies

Состояние сессии известно только по событиям хуков Claude Code (ADR-0003); запрос разрешения может появиться раньше своего `Notification`, и в этом окне `send_to_session` сочтёт сессию ждущей - риск принят оператором (D-12). Клиент MCP Claude Code не шлёт заголовок `Origin` (D-03). Допущения D-04, D-06, D-14, D-15, D-18..D-20, D-27, D-28 - решения составителя до подтверждения владельцем.

## 9. Apportioning of requirements

Главный процесс: FR-15001, FR-15002, FR-15004..FR-15008, FR-15010, FR-15011, NFR-15001. Интерфейс и главный процесс: FR-15003 (интерфейс - вкладка в фоне и сверка каталога с проектом, главный процесс - выдача промпта по ключу), FR-15009 (главный процесс - проверка и срок закрытия своей вкладки, интерфейс - снятие вкладки).

## 10. Specified requirements

Общие атрибуты, если у требования не сказано иное: `feature: 15-session-mcp`; приоритет - обязательно; основание - цель `mcp-session-tools` (`brd-feat.md`); уровень верификации - модуль (`npm test`).

## 11. External interfaces

### FR-15001 Сессия, запущенная Cyborg, подключена к его MCP-серверу своим конфигом

- **Требование:** при старте Cyborg главный процесс поднимает MCP-сервер на `127.0.0.1`, порт выдаёт ОС. Каждая сессия, запущенная после того, как сервер слушает, получает конфиг `{"mcpServers":{"cyborg":{"type":"http","url":"http://127.0.0.1:<порт>/mcp","headers":{"Authorization":"Bearer <токен>"}}}}` с новым токеном: файл `<pid>-<номер>.mcp.json` с правами 0600 в каталоге файлов событий, путь - переменная окружения `CYBORG_MCP`, запуск - `claude --settings "$CYBORG_SETTINGS" --mcp-config "$CYBORG_MCP" …`. При выходе сессии файл удаляется, токен отзывается. При старте Cyborg конфиги и файлы событий экземпляров, чей процесс не жив, удаляются. Сервер не поднялся либо ещё не слушает - сессия запускается без `--mcp-config` и без `CYBORG_MCP`, как до фичи. При закрытии окон сервер закрывается.
- **traced from:** BR-15001.
- **источник:** цель, «Что сделано» п.1 («каждая сессия получает свой Bearer-токен в файле конфига 0600 рядом с файлом событий, путь - через --mcp-config "$CYBORG_MCP"; токен отзывается и файл удаляется при выходе сессии, файлы убитого экземпляра убираются при старте»); D-02, D-15.
- **rationale:** reason - инструменты должны знать, какая сессия их вызвала, а токен не должен лежать в командной строке; assumptions - D-15: без сервера сессия прежняя; relationships - NFR-15001, FR-15002, ADR-0003 п.7 и п.9; design constraints - токен в файле, а не в аргументе: командную строку процесса видят все пользователи машины (D-02, ADR-0019).
- **verification:** испытание - `src/main/sessions.test.ts` («SessionManager с MCP: конфиг сессии в файле 0600, ключ --mcp-config, на выходе файл удалён и токен отозван», «SessionManager без MCP запускает claude без --mcp-config», «SessionManager убирает конфиги MCP убитого экземпляра вместе с его событиями»), `test/mcp.test.ts` («конфиг - http на 127.0.0.1 с токеном в заголовке»), `test/static-guards.test.ts` (перечень пишущих файлов).
- **класс:** External interfaces. **origin:** source; запуск без сервера и сессии до `listen` - derived.

### FR-15002 Протокол: JSON-RPC в POST /mcp без потока SSE

- **Требование:** сервер принимает `POST /mcp` с одним сообщением JSON-RPC 2.0 и отвечает JSON. `initialize` отвечает версией протокола клиента, если она из `2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`, иначе `2025-11-25`, возможностью `tools` (`listChanged: false`) и `serverInfo` `{name: "cyborg", version: <версия Cyborg>}`; `ping` - `{}`; `tools/list` - инструменты вызывающей сессии (FR-15004, FR-15006, FR-15007, FR-15009); `tools/call` - `content` с одним текстом, ошибка выполнения инструмента - тот же ответ с `isError: true` и причиной текстом. Уведомление и ответ клиента (без `id`) - 202 без тела. Неизвестный инструмент - ошибка `-32602`, неизвестный метод - `-32601`, сообщение не объект - `-32600` с HTTP 400, тело не JSON - `-32700` с HTTP 400. `GET` и другие методы - 405 с `Allow: POST`, путь не `/mcp` - 404, тело больше 1 МиБ - 413.
- **traced from:** BR-15001.
- **источник:** цель, «Что сделано» п.1 («Streamable HTTP на 127.0.0.1, случайный порт, JSON-RPC без SSE (initialize, ping, tools/list, tools/call)»); D-01.
- **rationale:** reason - клиент Claude Code говорит по Streamable HTTP, а сервер ничего не запрашивает у клиента, поэтому поток SSE не нужен; assumptions - клиент SDK отвергает версию протокола вне своего списка, поэтому ответ - его же версия; relationships - FR-15001, NFR-15001; design constraints - D-01, ADR-0019.
- **verification:** испытание - `test/mcp.test.ts` («handleRpc»: initialize, уведомления, tools/list, tools/call, неизвестный метод; «McpServer»: «GET - 405, чужой путь - 404, не JSON - 400, тело больше предела - отказ»).
- **класс:** External interfaces. **origin:** source; коды ошибок и предел тела - derived.

### FR-15003 Передача вкладки интерфейсу по одноразовому ключу

- **Требование:** `open_session` (FR-15004) отправляет интерфейсу событие `session:handoff` `{hid, from, repo}` - одноразовый ключ, номер вызывающей сессии и каталог - без промпта. Интерфейс находит вкладку вызывающей сессии и её проект; вкладки нет - `session:handoffFailed` с причиной «вкладка передавшей сессии не найдена», каталог больше не входит в проект - с причиной «каталог … больше не входит в проект …». Иначе интерфейс открывает вкладку сессии в этом каталоге (остальные каталоги проекта - `--add-dir`, как у всякой сессии) вызовом `session:create` со стартом `{handoff: hid}`: главный процесс выдаёт промпт, только если ключ ждёт и каталог совпадает с выбранным моделью, ключ гаснет при выдаче; иначе отказ «Переданная задача не найдена или устарела». Отказ `session:create` (каталог вне проектов, ошибка запуска) возвращается и в `session:handoffFailed`, и модели. Новая вкладка открывается в фоне: активная вкладка остаётся активной, панель задач, если открыта, остаётся открытой; без активной вкладки новая становится активной; вкладка другого проекта, чем выбранный сейчас, скрыта до выбора проекта. Причина отказа обрезается до 500 знаков.
- **traced from:** BR-15001.
- **источник:** цель, «Что сделано» п.2 («Вкладка открывается в фоне»); D-04, D-05, D-14.
- **rationale:** reason - интерфейсу не доверяют, а промпт уходит аргументом `claude`; assumptions - D-04; relationships - FR-15004, FR-1017 фичи 01, ADR-0002 п.3 и п.5; design constraints - промпт держит главный процесс (D-04, ADR-0019).
- **verification:** испытание - `test/session-tools.test.ts` («Handoffs»: интерфейс получает ключ без промпта, `take` по ключу и каталогу отдаёт промпт один раз; отказ интерфейса, закрытое окно и истёкшее ожидание); осмотр - `src/renderer/app.ts` (обработчик `session:handoff`, открытие в фоне): автотеста у интерфейсной части нет.
- **класс:** External interfaces. **origin:** source; ключ вместо промпта и причины отказа интерфейса - derived.

## 12. Functions

### FR-15004 open_session открывает вкладку в том же проекте с заданием первым сообщением

- **Требование:** инструмент `open_session {prompt, repo}`: `repo` - один из каталогов запуска вызывающей сессии (перечень - `enum` схемы инструмента), он становится рабочим каталогом новой сессии, остальные каталоги проекта подключаются `--add-dir`, новая сессия получает проект вызывающей (D-27); `prompt` с обрезанными краями - первое сообщение новой сессии, может начинаться со слэш-команды. Ответ - «Открыта вкладка сессии N в <repo>.» с номером новой сессии. Отказ ошибкой инструмента с причиной: `prompt` не строка либо пустой; начинается (после пробелов) с «-» или «!»; длиннее 100 000 байт UTF-8; `repo` вне перечня. Интерфейс не открыл вкладку за 20 с - «интерфейс Cyborg не открыл вкладку за 20 с»; окна нет - «окно Cyborg закрыто»; отказ интерфейса - его причина (FR-15003).
- **traced from:** BR-15001.
- **источник:** цель, «Что сделано» п.2 («open_session {prompt, repo}: открывает новую вкладку в том же проекте, repo - один из каталогов проекта (перечень в схеме), остальные каталоги идут --add-dir; prompt - первое сообщение… Ответ - номер новой сессии. Отказ: пустой prompt, ведущие «-» и «!», больше 100000 байт, repo вне проекта; интерфейс не открыл вкладку за 20 с - ошибка»); D-06, D-10, D-14, D-27.
- **rationale:** reason - сессия раздаёт часть работы новой вкладке, и та должна получить задание целиком и остаться видна открывшей; assumptions - D-06: `repo` - из каталогов запуска вызывающей; D-27: проект сессии - ключ проекта воркспейса, у дочерней - проект открывшей; relationships - FR-15003, FR-15006, FR-15007; design constraints - «-» claude примет за ключ, «!» выполнится как команда оболочки без запроса разрешения, предел - аргумент Linux 128 КиБ (D-10).
- **verification:** испытание - `test/session-tools.test.ts` («validateOpenSession», «createSessionTools»: «open_session передаёт задачу интерфейсу и называет номер новой сессии»), `src/main/sessions.test.ts` («SessionManager: проект сессии - ключ проекта; дочерняя - только в проекте открывшей, в том числе удалённая»), `test/mcp.test.ts` («tools/list отдаёт инструменты вызывающей сессии с её каталогами в схеме»).
- **класс:** Functions. **origin:** source.

### FR-15005 Состояние сессии для инструментов - по событиям хуков

- **Требование:** главный процесс ведёт состояние каждой сессии: `starting` - от запуска до первого `SessionStart` (Claude Code грузится или стоит на доверии к каталогу); `working` - после `UserPromptSubmit` и после `PreToolUse`, `PostToolUse` и `PostToolUseFailure` главной модели (событие с `agent_id` субагента состояния не меняет); `waiting` - после `SessionStart` из `starting` и после `Stop` без `background_tasks` и `session_crons`; `Stop` с ними оставляет `working` в паузе: ход закончен, Claude Code принимает ввод, а сессия проснётся сама, когда задача закончится или сработает пробуждение; пауза снимается событием, которое меняет состояние; `asking` с причиной - после `Notification` из списка ожиданий человека (ADR-0003 п.4); `exited` с кодом выхода - процесс локальной сессии завершился, а её вкладка открыта (FR-15011), событий у неё больше нет; событие вне перечня состояния не меняет. `SessionStart` посреди хода (сжатие контекста) состояния не меняет. Событие перечня, кроме `Notification` ожидания, снимает причину. `Stop` сохраняет последний ответ (`last_assistant_message`) без комментария `cyborg-buttons` в конце. Состояние `waiting` объявляется сразу по `Stop`, без 30-секундной выдержки уведомлений (FR-15008 даёт свою выдержку). Кроме состояния, главный процесс ведёт вызовы инструментов в полёте: `PreToolUse` добавляет вызов по `tool_use_id`, в том числе вызов субагента, кроме внешних вызовов `REPL`, `Poll`, `Agent` и `Task`; `PostToolUse` и `PostToolUseFailure` с тем же `tool_use_id` его снимают; `Stop` и `UserPromptSubmit` снимают вызовы главной модели, `SubagentStop` - вызовы своего субагента (`agent_id`), `Stop` без `background_tasks` - все.
- **traced from:** BR-15001.
- **источник:** цель, «Что сделано» п.3 (состояния starting/working/waiting/asking (+reason)) и п.4 («Stop с background_tasks или session_crons - сессия всё ещё working»); D-09, пауза - D-25, вызовы в полёте - D-26, `exited` - D-28.
- **rationale:** reason - писать в сессию можно, только зная, что она ждёт сообщения либо работает без вызова инструмента, а не стоит на вопросе человеку; assumptions - D-12: запрос разрешения может опередить свой `Notification`, но не `PreToolUse` своего вызова; вложенные вызовы `REPL` и инструменты субагента дают свои `PreToolUse` (D-26); ручной отказ в разрешении и прерывание Esc `Post*` не дают - зависший вызов снимает конец хода; хуки сессия получает файлом `claude-hooks-<хеш содержимого>.json` в каталоге данных, общем у экземпляров Cyborg, - экземпляр другой версии не подменяет ей набор событий; команда хука выходит с кодом 0, даже если файл событий недоступен, - код 2 у `PreToolUse` запретил бы вызов; relationships - FR-15006, FR-15007, FR-15008, ADR-0003 п.3 и п.4; design constraints - состояние только по хукам, вывод терминала не разбирается (ADR-0003).
- **verification:** испытание - `src/main/sessions.test.ts` («SessionManager: состояние сессии и хвост ответа для list_sessions, соседи - сессии того же проекта при любых каталогах», «упавший инструмент - работа: после запроса разрешения сессия снова working, хук подписан на все инструменты», «SessionManager.say: работающей сессии без вызова инструмента - сразу, без тишины; вызов держит очередь до своего Post*», «SessionManager.say: вызов субагента держит очередь до его SubagentStop, внешние REPL, Poll и Agent - нет», «SessionManager.say: вызов без Post* (отказ в разрешении, Esc) снимают Stop и UserPromptSubmit, вызов фонового субагента - только Stop без фоновых задач», «SessionManager: файл хуков назван по содержимому - экземпляр другой версии с тем же userData его не затирает», «хук не запрещает вызов инструмента, когда файл событий недоступен: код 2 у PreToolUse - запрет»).
- **класс:** Functions. **origin:** source; правила `SessionStart`, субагента и вызовов в полёте - derived.

### FR-15006 list_sessions перечисляет вкладки проекта с состоянием и хвостом ответа

- **Требование:** инструмент `list_sessions {}` отдаёт JSON-массив вкладок сессий того же проекта, что вызывающая (D-27), при любых их каталогах запуска, её саму тоже, и вкладок, чей процесс завершился (FR-15011): `id`, `tab` (`CC<id>`), `self: true` у вызывающей, `repo` (каталог запуска), `cwd` (текущий каталог), `state` (FR-15005), `reason` - только у `asking`, `exit_code` - только у `exited`, `queued` - только если очередь не пуста (FR-15008), `last_answer` - только если ответ был: 1500 последних знаков с «…» впереди, если ответ длиннее; `parent` - номер сессии, открывшей эту `open_session` или `spawn_agent`, только у таких сессий (у удалённой вкладки, подхваченной после перезапуска Cyborg, его нет); `child: true` - только у сессий, чей `parent` - вызывающая. У завершённой вызывающей инструментов нет.
- **traced from:** BR-15001.

### FR-15007 send_to_session пишет вставкой и Enter, когда запись не попадёт в чужой диалог

- **Требование:** инструмент `send_to_session {id, message}`. Сообщение очищается: `\r\n` и `\r` - перевод строки, управляющие символы, кроме перевода строки и табуляции (`\x00-\x08`, `\x0b-\x1f`, `\x7f-\x9f`), удаляются, края обрезаются. Отказ ошибкой инструмента с причиной: пустое после очистки; начинается с «!», «/» или «#»; длиннее 100 000 байт UTF-8; `id` - вызывающая сессия; `id` нет среди сессий FR-15006; цель в `starting` («ещё запускается»), `asking` («ждёт человека (<причина>)») либо `exited` («сессия N завершилась: её вкладку закрывает close_session»). Цель принимает ввод: локальная - в `waiting` либо в `working` без вызовов в полёте (FR-15005); удалённая - в `waiting` либо в паузе `working`. Если цель принимает ввод, очередь пуста, а удалённая к тому же 2 с без событий, сообщение уходит сразу: в pty пишется `ESC[200~<текст>ESC[201~`, через 150 мс - `\r`; ответ «Сообщение отправлено сессии N.», цели в `working` вне паузы - «Сообщение отправлено сессии N: она работает, Claude Code передаст его после текущего вызова инструмента.». Перед вставкой и перед Enter правило перепроверяется, у локальной - по событиям, дочитанным из файла в этот момент: вызов начат до вставки - сообщение встаёт в очередь первым; между вставкой и Enter - у локальной Enter пишется, когда вызов закончится, и до того сообщение считается в `queued`, у удалённой Enter не пишется, ошибка «сессия N начала ход: текст вставлен в её ввод, Enter не отправлен»; сессия завершилась - «сессия N завершилась». Подтверждения отправки в интерфейсе Cyborg нет: вызов подтверждает человек запросом разрешения Claude Code в вызывающей сессии.

### FR-15009 close_session закрывает вкладку проекта, не обрывая без force работу и вопрос соседки

- **Требование:** инструмент `close_session {id, force?}`: `id` - сессия из перечня FR-15006, в том числе вызывающая; `force` - логическое, по умолчанию `false`. Соседке в `waiting` или `exited` и с `force: true` в любом состоянии главный процесс отправляет интерфейсу событие `session:close {id}`, отметив, что вкладку закрывает вызывающая (FR-15011), интерфейс снимает вкладку как крестиком, но без окна подтверждения: процесс сессии завершается, вкладка и её файлы закрываются, активной становится соседняя вкладка проекта; ответ «Вкладка сессии N закрыта.». Интерфейс не нашёл вкладку либо окна нет - главный процесс завершает процесс сессии и убирает её запись сам. Вызывающая сессия закрывается в любом состоянии, через 1 с после ответа «Эта вкладка закроется через секунду.». Дочерняя вызывающей (`child: true`, FR-15006) закрывается в любом состоянии без `force`. Отказ ошибкой инструмента с причиной: `force` не логическое («force - true или false»); `id` нет среди сессий FR-15006; соседка без `force` в `working` («работает»), `asking` («ждёт человека (<причина>)») либо `starting` («ещё запускается») - с припиской «закрытие оборвёт её, закрыть всё же - force: true». - **rationale:** reason - вкладка, отдавшая итог, остаётся открытой, пока человек не закроет её крестиком; assumptions - D-18: правило состояний заменяет окно подтверждения крестика; relationships - FR-15005, FR-15006, FR-15008, FR-15004 (закрытие вкладки, открытой по `open_session`); design constraints - вызов подтверждает человек запросом разрешения Claude Code (D-11), вкладку убирает интерфейс (D-20), своя вкладка закрывается после ответа (D-19).

## 13. Usability requirements

Описания инструментов говорят модели, что новая сессия диалога не видит (задание - самодостаточное), что получатель `send_to_session` не знает отправителя (свой номер называют в тексте) и что сообщение допишется к вводу, если человек набирает текст в той вкладке; описание `close_session` называет, что закрытие обрывает работу соседки и что её итог стоит прочитать в `list_sessions` до закрытия; описание `report_done` локальной дочерней просит закоммитить работу до вызова (FR-15010); требований сверх FR-15004, FR-15006, FR-15007, FR-15009, FR-15010 нет.

## 14. Performance requirements

Пределы поведения - 20 с ожидания вкладки (FR-15004), 150 мс до Enter (FR-15007), 1 с до закрытия своей вкладки (FR-15009), 2 с тишины перед доставкой из очереди (FR-15008), 1 МиБ тела запроса (FR-15002). Измеримых целей по задержке постановка не задаёт.

## 15. Logical database requirements

## 18. Software system attributes

### NFR-15001 Сервер принимает вызовы только от сессий Cyborg по их токену

- **Требование:** классификация данных: токен сессии - секрет (даёт право открывать, закрывать вкладки и писать в сессии проекта от имени этой сессии); промпт, сообщения и хвосты ответов - данные пользователя, только локально. Модель авторизации: субъект - сессия Cyborg, удостоверение - токен из её конфига (32 случайных байта, base64url), право - инструменты над сессиями того же проекта, что у неё (D-27), включая их закрытие (FR-15009). Сервер слушает только `127.0.0.1`; удалённым сессиям он виден обратным туннелем `ssh` (FR-17007, ADR-0020), порт наружу не открывается. Запрос с заголовком `Origin` - 403 до проверки токена; без `Authorization: Bearer <токен>`, с неизвестным либо отозванным токеном - 401. Токен не попадает в командную строку процесса: только в файл 0600 (FR-15001). Токен сессии отзывается при её завершении: дальше её запросы - 401.
- **traced from:** BR-15001.
- **источник:** цель, «Что сделано» п.1 («Каждая сессия получает свой Bearer-токен… Запрос с заголовком Origin - 403, без токена - 401»); D-02, D-03.
- **rationale:** reason - порт на `127.0.0.1` открыт всем пользователям машины и страницам браузера, а инструменты пишут в терминалы сессий; assumptions - D-03: клиент Claude Code не шлёт `Origin`; relationships - FR-15001, FR-15002; design constraints - D-02, ADR-0019.
- **verification:** испытание - `test/mcp.test.ts` («без токена, с чужим токеном и после disconnect - 401; с Origin браузера - 403», «конфиг - http на 127.0.0.1 с токеном в заголовке; по токену отвечает за его сессию»), `src/main/sessions.test.ts` (файл 0600; на выходе сессии токен отозван).
- **класс:** Software system attributes. **origin:** source; классификация данных и модель авторизации - derived.
