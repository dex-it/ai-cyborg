# decision-log фичи 15 - MCP-сервер Cyborg и инструменты сессий

Решения по цели `mcp-session-tools` (2026-11-07): «Cyborg поднимает MCP-сервер, через который сессия Claude Code в вкладке Cyborg управляет другими вкладками своего проекта». Источник требований оператор не назвал; решения из описания сделанного в цели - исход «принято в цели», решения оператора - «принято оператором», выведенные из кода правки - «принято составителем» до подтверждения владельцем. D-18..D-21 - по просьбе оператора 2026-11-09 «Научи киборга закрывать сессию» (инструмент `close_session`, FR-15009).

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | MCP-сервер живёт в главном процессе Cyborg: Streamable HTTP на `127.0.0.1`, порт выдаёт ОС, `POST /mcp` с одним сообщением JSON-RPC (`initialize`, `ping`, `tools/list`, `tools/call`); поток SSE сервер не держит, `GET` получает 405 | поток SSE для запросов сервера к клиенту | сервер ничего не запрашивает у клиента; спецификация разрешает 405 на `GET` | принято в цели |
| D-02 | Каждая сессия получает свой Bearer-токен: конфиг `--mcp-config` лежит файлом 0600 рядом с файлом событий сессии, путь к нему - переменная `CYBORG_MCP`; при выходе сессии токен отзывается и файл удаляется, файлы убитого экземпляра убираются при старте, как файлы событий | токен в аргументе командной строки | командную строку процесса видят все пользователи машины, порт на `127.0.0.1` - тоже; вызывающую сессию называет только токен | принято в цели |
| D-03 | Запрос с заголовком `Origin` - 403, без токена либо с чужим и отозванным - 401 | проверка только токена | страница в браузере дотягивается до `127.0.0.1` и всегда шлёт `Origin`, клиент Claude Code его не шлёт | принято в цели |
| D-04 | `open_session` передаёт интерфейсу только одноразовый ключ, номер вызывающей сессии и каталог; промпт хранит главный процесс и отдаёт его `session:create` по ключу и совпавшему каталогу | промпт в событии интерфейсу и обратно в `session:create` | интерфейсу не доверяют (ADR-0002 п.5): текст модели дошёл бы до аргументов `claude` через недоверенный канал | принято составителем |
| D-05 | Новая вкладка открывается в фоне: активная вкладка остаётся активной; без активной вкладки новая становится активной | переключение на новую вкладку | вызывающая сессия и человек работают в своей вкладке, человек переключается сам | принято в цели |
| D-06 | Проект сессии для инструментов - набор её каталогов запуска: соседи - работающие сессии с тем же набором каталогов; `repo` у `open_session` - один из каталогов вызывающей сессии, перечень стоит в схеме инструмента | проект по данным интерфейса | главный процесс проектов сессий не знает; интерфейс при открытии вкладки сверяет каталог с проектом вызывающей вкладки | принято составителем; соседство пересмотрено D-27 |
| D-07 | `send_to_session` пишет только в сессию в состоянии `waiting`: вставкой (bracketed paste) и Enter отдельной записью через 150 мс; состояние перепроверяется перед вставкой и перед Enter, начавшийся ход отменяет Enter с ошибкой | запись в работающую сессию; текст и Enter одной записью | Enter в открытый запрос разрешения ответил бы на него «Да»; перевод строки в тексте без вставки TUI принял бы за Enter; пауза - как у кнопок команд (D-06 фичи 12) | принято в цели; для локальной сессии пересмотрен D-26 |
| D-08 | Работающей сессии сообщение ставится в очередь главного процесса и отдаётся по одному, когда сессия в `waiting` и 2 с нет её событий; сессии в `waiting`, у которой событие свежее 2 с либо очередь не пуста, сообщение тоже идёт в очередь | отказ работающей сессии; доставка сразу по `Stop` | чужой Stop-хук может продолжить ход; очередь не обгоняет саму себя | принято в цели; для локальной сессии пересмотрен D-26 |
| D-09 | `Stop` с `background_tasks` или `session_crons` оставляет сессию в `working` | `Stop` - всегда конец хода | сессия проснётся сама, ввод извне попал бы в её ход | принято в цели; запрет ввода в паузе пересмотрен D-25 |
| D-10 | Отказы: `open_session` - пустой промпт, ведущие «-» и «!», больше 100 000 байт, каталог вне перечня; `send_to_session` - себе, сессии вне соседей, в `starting` и `asking`, ведущие «!», «/», «#», больше 100 000 байт; управляющие символы, кроме перевода строки и табуляции, вычищаются из сообщения. Промпт `open_session` может начинаться со слэш-команды | одни правила для обоих инструментов | «-» claude примет за ключ; «!» Claude Code выполнит как команду оболочки без запроса разрешения; «/» и «#» в чужой сессии правят её настройки и память в обход её разрешений; ESC закрыл бы вставку и пустил текст клавишами; предел - запас до 128 КиБ одного аргумента Linux (`MAX_ARG_STRLEN`); первое сообщение новой сессии - её собственное задание | принято в цели |
| D-11 | Подтверждения отправки `send_to_session` в интерфейсе Cyborg нет: человек подтверждает вызов инструмента запросом разрешения Claude Code в вызывающей сессии | окно подтверждения Cyborg перед отправкой | ответ оператора | принято оператором |
| D-12 | Остаточный риск принят: состояние сессии известно только по хукам, запрос разрешения может появиться раньше своего `Notification`; очередь живёт в памяти и пропадает с вкладкой и с выходом Cyborg | очередь на диске; распознавание запроса разрешения по выводу терминала | ответ оператора; разбор вывода отвергнут ADR-0003 | принято оператором |
| D-13 | `list_sessions` отдаёт хвост последнего ответа - 1500 последних знаков с «…» впереди, без комментария `cyborg-buttons` в конце | ответ целиком; начало ответа | итог работы обычно в конце ответа; комментарий кнопок служебный (фича 12) | принято в цели |
| D-14 | Интерфейс не открыл вкладку за 20 с либо окна нет - ошибка инструмента с причиной; отказ интерфейса (вкладки вызывающей сессии нет, каталог больше не в проекте, `session:create` отказал) возвращается модели текстом до 500 знаков | ожидание без предела | вызов инструмента не должен висеть, пока окно не отвечает | принято в цели (20 с), причины отказа - принято составителем |
| D-15 | Сервер не поднялся (порт не дан) - сессии работают без MCP Cyborg и без `--mcp-config`; сессии, запущенные до того, как сервер слушает, остаются без него | отказ запуска сессий | сессии создаёт окно, а оно грузится дольше, чем поднимается сервер; инструменты - добавка, без них сессия остаётся прежней | принято составителем |
| D-16 | Правки корпуса вне фичи, род - расширение области: BRD продукта (BR-009, разделы 3, 5, 9, 11, 17, заметка в шапке), ADR-0002 п.3 и п.5 (каналы `session:handoff`, `session:handoffFailed`, старт `{handoff}`), ADR-0003 п.7 и п.9 (`--mcp-config`, удаление конфига), FR-1015 (пишущие файлы) и FR-1017 (формы старта `session:create`) фичи 01; зависимые единицы найдены поиском по номерам и формам старта | новые единицы рядом с задетыми | один предмет - одна единица (unit-identity) | принято составителем |
| D-17 | Историй с AC (`stories/`) у фичи нет: поведение проверяют автотесты, названные в верификации FR-15001..FR-15008 и NFR-15001 | нарезка историй с критериями приёмки | ответ оператора | принято оператором |
| D-18 | `close_session {id, force?}` закрывает вкладку сессии проекта, как крестик: соседку в `waiting` - сразу, в `working`, `asking` и `starting` - только с `force: true`, иначе ошибка с причиной и подсказкой о `force`; очередь закрытой сессии пропадает | закрытие любой соседки без условия; запрет закрывать работающую и ждущую человека без обхода | крестик спрашивает «Сессия ещё работает. Завершить её?», а у модели окна нет: правило состояний не даёт оборвать ход или вопрос человеку по ошибке, `force` оставляет снять зависшую соседку; вызов подтверждает человек запросом разрешения (D-11) | принято составителем |
| D-19 | Вызывающая сессия закрывает свою вкладку в любом состоянии, через 1 с после ответа инструмента | закрытие сразу; запрет закрывать себя | в своём ходу сессия всегда `working`, и правило D-18 запретило бы ей закрыться; сразу закрытая сессия не получила бы результат вызова, и он пропал бы из возобновлённого диалога | принято составителем |
| D-20 | Вкладку снимает интерфейс по событию `session:close {id}` тем же путём, что крестик, без окна подтверждения; окна нет или вкладка не найдена - главный процесс завершает процесс сессии сам | завершение процесса только из главного процесса | вкладка завершённой сессии осталась бы с пометкой «завершена», и человеку пришлось бы закрывать её руками; главный процесс вкладок не знает (D-06) | принято составителем |
| D-21 | Правки корпуса вне SRS фичи, род - расширение области: BRD фичи (разделы 1, 3, BR-15001), BRD продукта (раздел 3: перечень функций и non-goal о сессиях без слова разработчика; BR-009), ADR-0002 п.3 (событие `session:close`), ADR-0019 (п.7 и новый п.9) | новые единицы рядом с задетыми | один предмет - одна единица (unit-identity), как D-16 | принято составителем |
| D-22 | `list_sessions` называет у сессии, открытой инструментом, `parent` - номер открывшей, а у дочерних вызывающей - `child: true`; у вызывающей перечня детей нет | поле `children` у вызывающей; связь только в памяти модели | после сжатия контекста модель теряет номера своих дочерних, а закрывать их должна она; `child: true` даёт их без сравнения номеров | ответ оператора 2026-11-15 |
| D-23 | `report_done` получает и локальная сессия с `parent`: тот же круг, текст и отказ повтора, что у удалённой (FR-17009), доставка - очередь открывшей, без неё - уведомление; без пометки вкладки «итог сдан» | итог свободным текстом через `send_to_session` с номером открывшей в задании | одинаковый итог у локальной и удалённой, номер в задании не нужен; пометка вкладки цели не служит | ответ оператора 2026-11-15 |
| D-24 | `close_session` закрывает дочернюю вызывающей в любом состоянии без `force`; чужую в `working`, `asking`, `starting` - по-прежнему только с `force` | `force` для всех; закрытие дочерних только в `waiting` | отработавших закрывает открывшая, а `force` остаётся признаком чужой вкладки | ответ оператора 2026-11-15 («отработанные сессии - закрывает родитель») |
| D-25 | `working` после `Stop` с `background_tasks` или `session_crons` - пауза: `send_to_session` и очередь пишут в неё, как в `waiting`; `close_session` без `force` её по-прежнему не закрывает, `list_sessions` показывает `working`; тишину перед доставкой сбивают и события фонового субагента (`agent_id`): в паузе он работает и может открыть запрос разрешения, чей `Notification` опоздает. Правки FR-15005, FR-15007, FR-15008, описания `list_sessions` и `send_to_session` | новое состояние для паузы: менялись бы закрытие соседки и усыпление на хосте, где пауза должна считаться работой; доставка только после пробуждения - сессия, которая ждёт фонового агента, не получала сообщений, пока он не закончит | жалоба оператора 2026-11-16: «клод ожидает фонового агента - киборг думает что он занят и не передает ему сообщение»; в паузе Claude Code принимает ввод, итог фоновой задачи он ставит в свою очередь | принято составителем |
| D-26 | Локальной сессии `send_to_session` и очередь пишут и посреди хода: в `working` без вызовов инструментов в полёте, которые Cyborg ведёт по `PreToolUse` и `Post*` (`tool_use_id`); внешние вызовы `REPL`, `Poll`, `Agent`, `Task` не в счёт - их вложенные вызовы дают свои `PreToolUse`; зависший вызов (отказ в разрешении, Esc) снимают `Stop`, `UserPromptSubmit` и `SubagentStop`; перед вставкой и Enter события дочитываются из файла; вызов, начатый между вставкой и Enter, откладывает Enter до своего конца; тишина 2 с остаётся только у удалённой. Пересматривает D-07 и D-08 для локальной сессии. Правки FR-15005, FR-15007, FR-15008, ADR-0019 п.5 и п.6, описаний `list_sessions` и `send_to_session` | очередь до конца хода (D-07, D-08) - итог дочерней шёл до 2 мин; запись в `working` без учёта вызовов - Enter попал бы в запрос разрешения; разбор вывода терминала - ADR-0003 | просьба оператора 2026-11-17: «сообщения должны инжектироваться а не ждать конца хода»; ввод посреди хода Claude Code ставит в свою очередь и передаёт модели после текущего вызова (interactive-mode, «Queue messages while Claude works»); `PreToolUse` приходит до запроса разрешения (hooks); вложенные вызовы `REPL` дают свои хуки (`tool_use_id` с `repl_` в событиях сессий). Остаточный риск: диалог без `PreToolUse` («Press enter to continue» после лимита) | принято составителем |
| D-27 | Проект сессии - id проекта воркспейса, который интерфейс называет в `session:create` и `session:resume`; главный процесс принимает каталоги только из репозиториев этого проекта; дочерняя (`open_session`, `spawn_agent`) - только в проекте открывшей, иначе отказ; соседи для инструментов - сессии того же проекта при любых каталогах запуска; хосты `spawn_agent` - хосты проекта вызывающей. Пересматривает соседство D-06; `repo` у `open_session` по-прежнему из каталогов вызывающей | набор каталогов запуска (D-06) | случай 2026-11-17: в проект добавили репозиторий, открытая после этого дочерняя получила три каталога, открывшая осталась с двумя - они перестали видеть друг друга, `close_session` отвечал «сессии 8 нет среди открытых вкладок проекта», а старым сессиям пропали хосты `spawn_agent`; воркспейс в окне один, при его смене сессии завершаются, поэтому id проекта однозначен | принято составителем |
| D-28 | Вкладка локальной сессии, чей процесс вышел, остаётся в перечне `list_sessions` в состоянии `exited` с кодом выхода, пока интерфейс не сообщит о снятии вкладки (`session:release`); `send_to_session` ей отказывает, `close_session` закрывает без `force`; открывшей уходит сообщение о выходе дочерней или о том, кто закрыл её вкладку, кроме закрытия самой открывшей и завершения всех сессий Cyborg | запись удаляется с выходом процесса | случай 2026-11-17: процесс CC8 вышел, вкладка осталась, CC6 не видела её и не могла закрыть, а о выходе не узнала и ждала итога | принято составителем |
