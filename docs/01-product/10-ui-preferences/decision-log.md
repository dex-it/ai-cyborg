# decision-log фичи 10 - настройки окна

Решения и допущения прогона по Issue #10 (2026-10-26). Исход «открыто» - допущение, принятое за постановщика без владельца
(рекомендации Issue #10, владелец поручил решать по качеству); подтверждает либо меняет владелец продукта.

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | Настройки окна хранятся в `localStorage` окна, а не в файле воркспейса и не в отдельном файле; хранилище недоступно - значение действует до закрытия окна | файл настроек в профиле: ещё один формат и путь записи без нужды; `projects.json`: настройки интерфейса не свойство проекта (кроме выбора меток, D-32 фичи 01) | код `prefs.ts`; Issue #10, вопрос 4 (отдельная фича) | открыто |
| D-02 | Размер шрифта 8..32 с шагом 1, по умолчанию 13, один для терминалов, просмотра файлов и дерева; дерево масштабируется свойством `zoom`, а не размером шрифта | размер на каждое окно сессии: разнобой; `font-size` дерева: высоты строк и бейджи заданы в px и не масштабировались бы | код `font-size.ts`, `zoomTree`; комментарий в `app.ts` | открыто |
| D-03 | Сохранённое значение вне допустимого набора (в том числе вариант, снятый в новой версии) читается как значение по умолчанию | падение на неизвестном значении; перенос старого значения | код `readChoice`, `parseFontSize` | открыто |
| D-04 | `Shift+Enter` в терминале сессии вводит `ESC` и `CR` - перевод строки Claude Code; событие `keypress` гасится, иначе xterm отправил бы ещё и `CR`, и запрос ушёл бы | оставить `Shift+Enter` как `Enter`: многострочный запрос в Claude Code не набрать | код `createTerminal`; прогон 26.10.2026: в процесс дошли `ESC` и перевод строки, у обычного Enter - только перевод строки | открыто |
| D-05 | Порядок репозиториев меняется перетаскиванием строки в диалоге проекта (при двух и более репозиториях) и сохраняется в проекте; порядок задаёт меню выбора репозитория и порядок корней дерева | кнопки «вверх» и «вниз»: вне образца интерфейса | код `moveItem`, `renderDraftRepos` | открыто |
| D-06 | В заголовке окна - «Проект - Cyborg v.версия+хеш коммита»; версия и хеш подставляет сборка (`__APP_VERSION__`), заголовок задаёт интерфейс через `document.title`; без `.git` хеша нет | читать версию в рантайме через `app.getVersion()` и IPC: лишний канал ради строки; заголовок только в `BrowserWindow`: он перебивается заголовком страницы | PR #24; код `windowTitle`, `scripts/build.mjs` | открыто |
| D-07 | Уведомление о ждущей сессии несёт короткую фразу по типу события, не содержимое: ни ответа Claude, ни сообщения запроса; о законченном ходе - через 30 секунд тишины сессии | начало последнего ответа (до 200 знаков): видно в центре уведомлений и на заблокированном экране, в ответе бывают пути и секреты; уведомление сразу по `Stop`: чужой Stop-хук продолжает ход, уведомление ложное | PR #22; ADR-0003, п.4; решение владельца 2026-10-26 (превью не нужно) | принято |
| D-08 | Заголовок окна с воркспейсом (цель `project-workspaces`): «<проект> - <воркспейс> - Cyborg v.версия», воркспейс - имя файла без `.cyborg.json`, иначе без расширения; прежний `userData/projects.json` и пустой Cyborg без воркспейса имени не несут, FR-10005 для них прежний | имя из поля «имя воркспейса» окна создания: файл можно переименовать, имя разошлось бы с файлом; «Default» для прежнего файла: оператор ответил, что у умолчания нет имени | ответ оператора «Имя файла, у умолчания нет»; допущение цели, п.12 | принято |
| D-09 | Управление проектами - в системном меню «Воркспейс» (пять пунктов), а не во всплывающем меню проекта на панели; выбор проекта остаётся на панели, удаление - в диалоге; строка меню на Linux видна всегда; требование ведёт BR-10001, потому что у фичи нет другого BR | оставить меню проекта на панели рядом с меню «Воркспейс»: два места для одного действия; скрытая строка меню (`autoHideMenuBar`): пункты воркспейса не нашли бы без Alt | ответы оператора «Показывать меню всегда», «Выбор проекта остаётся на панели»; допущение цели, п.4-6 | принято |
