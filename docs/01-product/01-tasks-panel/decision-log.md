# decision-log фичи 01 - панель задач

Решения и допущения прогона цели `tasks-panel` (2026-10-23). Исход «открыто» - допущение, принятое за постановщика
без оператора; подтверждает либо меняет владелец продукта.

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | Панель открывается кнопкой «Задачи» в полосе сессий рядом с «+ CC» и занимает рабочую область вместо сессии, пока открыта | отдельное окно `BrowserWindow`: второй канал событий preload и синхронизация проектов; раздел боковой панели | цель, критерий 2 (допущение) | открыто: где живёт панель |
| D-02 | Фильтр «Назначено мне» - переключатель, по умолчанию включён; выключенный показывает все открытые задачи тех же remote | фильтр всегда включён | цель, критерий 3 (допущение) | открыто |
| D-03 | Сортировка по умолчанию - дата обновления, новые сверху | - | цель, критерий 4; практика трекеров | принято |
| D-04 | Источник - каждый fetch-remote каждого репозитория проекта, не только `origin`; GitLab-хост признаётся, только если он есть в `glab auth status` | опрос `glab api --hostname H user` по каждому хосту remote: запрос ушёл бы к произвольным хостам, это сеть не к трекерам | цель, критерий 5 (допущение); прогон, решение «хосты из glab auth status» | открыто: все remote или только `origin` |
| D-05 | Открытые задачи выбираются со всех страниц выдачи | `gh issue list --limit`: ограничение числа | цель, критерий 6 | принято |
| D-06 | Галочки GitHub и GitLab по умолчанию выключены; хранятся отдельным JSON в профиле (ADR-0004 п.6) | включать источник сразу при залогиненном CLI; поле в `projects.json` (формат не меняется - граница цели) | цель, критерий 8 (допущение) | открыто: включать ли сразу |
| D-07 | Задача опознаётся парой «репозиторий трекера + номер»; сессия задачи с завершённым процессом и открытой вкладкой считается открытой; реестр сессий задач ведётся в разрезе проекта | ключ только по задаче: общий remote у двух проектов смешивал сессии (находка ревью F3) | цель, критерий 20 (допущение); прогон, F3 | открыто: считается ли завершённая сессия открытой |
| D-08 | Статус задачи - open/closed трекера, у GitLab дополнительно scoped-метки `workflow::…` | поле Status GitHub Projects | цель, критерий 21 (допущение) | открыто: что считать статусом |
| D-09 | Сессия из задачи получает первое сообщение начальным позиционным аргументом `claude`; BRD продукта, раздел 11, расширен до «хуки и начальный промпт» (ADR-0003 п.9) | ввод в терминал после старта; сборка текста в интерфейсе (произвольный текст в аргументах CLI); промпт после `--add-dir` (вариадичный флаг забрал бы промпт) | решение владельца 2026-10-23 (цель, «Решения») | принято |
| D-10 | Задачи читаются `gh api --paginate --jq` и `glab api --paginate` без оболочки (ADR-0007) | свой HTTP-клиент с токеном из `gh auth token`; `gh issue list`/`glab issue list`; цикл процессов по `page=N`; `gh api --slurp` | прогон, дизайн | принято |
| D-11 | Фильтр «назначено мне» применяется на стороне трекера (`assignee`, `assignee_username`); логин GitHub берётся `gh api user`, при невходе источник даёт ошибку, фильтр вслепую не применяется | клиентский фильтр по полной выборке: каждое обновление тянуло бы все открытые задачи | прогон, дизайн | принято |
| D-12 | GitHub 410 (задачи в репозитории отключены) - пометка источника, не ошибка; `www.github.com` и `ssh.github.com` считаются `github.com`; порт ssh-URL отбрасывается; ssh-алиасы `~/.ssh/config` не разрешаются, такой remote пропускается | - | прогон, исход, о котором вход молчит | принято |
| D-13 | Список рисуется целиком, без виртуализации; десятки тысяч задач рисуются медленно | виртуализация списка | прогон, дизайн | открыто: вопрос 1 BRD фичи |
| D-14 | Окно настроек сохраняет галочки кнопкой «Сохранить», «Отмена» их не меняет | сохранение по клику на галочку: окно «Свойства проекта» работает через Сохранить/Отмена | прогон, дизайн | принято |
| D-15 | Проверка каталогов `session:create` по репозиториям проектов включена только для сессии с задачей; запуск «+ CC» прежний | проверка для всех сессий: меняла бы поток «+ CC» и сохранения проектов | прогон, дизайн; ADR-0002, расхождение п.5 | принято |
| D-16 | Статусы в заголовках сессий другого проекта обновляются, только когда обновляется панель их проекта | - | прогон: `tasks:list` работает по одному проекту | принято |
| D-17 | Смена проекта во время загрузки и сохранение настроек запускают новую выборку сразу, ответ прежней отбрасывается; «второй запрос не запускается» относится к повторному «Обновить» | ожидание старой выборки | прогон; находка ревью F4 | принято |
| D-18 | Тесты - встроенный `node:test`, файлы собирает esbuild во временный каталог, `npm test` (ADR-0006 п.8) | vitest/jest/tsx - новая зависимость; `node --experimental-strip-types` - не разрешает импорты без расширения | прогон; граница «новых npm-зависимостей нет» | принято |
| D-19 | Правила панели (выбор действия «Начать», одиночный полёт обновления с токеном, реестр сессий задач) - модуль без DOM под тестами | логика в DOM-модулях без шва | прогон; находка ревью F5 | принято; связка закрытия панели с DOM осталась без шва |
| D-20 | Отказ `glab api` распознаётся по `HTTP NNN` в stderr либо объекту с `message`, а не по коду выхода | код выхода: glab 1.36 выходит с 0 при HTTP 401/404 | прогон, проба CLI | принято |
| D-21 | Правки по цели `mr-view` (2026-10-23), род - расширение области: FR-1001 - панель несёт вкладки «Задачи» и «MR/PR», первой открыта «Задачи», выбор держится до перезапуска; FR-1006 - обновление по открытию и переходу относится к вкладке «Задачи», смена проекта и настроек обновляет активную вкладку; FR-1016 - запрет `graphql` и checkout, старт MR; FR-1017 - старт `session:create` объектом `{task}` либо `{mr, intent}`; BRD фичи, раздел 3 - вид MR/PR вынесен в фичу 02. Зависимые единицы, найденные по номерам, - SRS и decision-log фичи 02 | отдельная панель MR/PR; второй канал старта сессии | цель `mr-view`, критерии 1, 10, 20, 22; D-01, D-22 фичи 02 | открыто: вкладка по умолчанию (D-01 фичи 02) |
| D-22 | Проверка входа (`glab auth status`, `gh api user`) - один результат главного процесса на задачи и MR, переиспользуемый между выборками без срока жизни; проверка включённых трекеров запускается один раз при старте приложения | проверка перед каждой выборкой: около 1 с на критическом пути (brief perf, «Замер»); отказ от прогрева как фоновой активности - прогрев однократный, не опрос (FR-1006 не задет); `glab auth status --hostname <хост>` по хостам remote: классификация remote строится по всем хостам входа, и вид «нет remote / вход не выполнен» сменился бы | цель `panel-load-perf`, критерии 13, 15, 20; решение владельца 2026-10-23 (а) | принято |
| D-23 | «Обновить» и сохранение настроек сбрасывают результат проверки входа, но выборка идёт по прежнему результату параллельно с новой проверкой; изменились хосты с входом, пользователи либо состояние входа - выборка выполняется заново, изменился только текст ошибки - нет; без прежнего результата выборка ждёт проверку | ждать новую проверку перед выборкой: 1,8 с после «Обновить» не держится | цель `panel-load-perf`, критерий 21; решение владельца 2026-10-23 (б) | принято |
| D-24 | Сброс при сохранении настроек делает главный процесс в обработчике `trackers:save`; «Обновить» передаёт признак новой проверки аргументом `tasks:list` и `mrs:list` | отдельный канал `trackers:recheck` перед списком: два вызова и опора на их порядок | прогон, дизайн; ADR-0009 | принято |
| D-25 | Правки по цели `panel-load-perf` (2026-10-23): FR-1006 - расширение области (сброс проверки входа по «Обновить» и сохранению); FR-1016 - смена ограничения (допущен читающий `glab api graphql` деталей MR); FR-1017 - расширение области (признак новой проверки у `tasks:list`); новые FR-1019, NFR-1004; BRD фичи, раздел 14 и открытый вопрос 1 - требование времени загрузки задано. Зависимые единицы по номерам - SRS и decision-log фичи 02, ADR-0007, ADR-0009 | - | brief perf, «Требования» п.1, п.4; цель `panel-load-perf` | принято |
