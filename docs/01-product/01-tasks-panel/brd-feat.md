# BRD фичи 01 - панель задач из трекеров

Источник: бриф владельца `Cyborg-tasks-panel.brief.md` (2026-10-23), цель трека `tasks-panel`.

## 1. BRS overview

Разработчик берёт задачу трекера в работу, переключаясь в браузер трекера и пересказывая задачу сессии руками.
Фича даёт панель открытых задач GitHub и GitLab по remote репозиториев текущего проекта и кнопку «Начать», которая
открывает сессию Claude Code со ссылкой на задачу первым сообщением. Адресован владельцу продукта и составителям
SRS и архитектуры.

## 2. Business purpose

Сократить путь от задачи трекера до работающей по ней сессии до одного действия в Cyborg, сохранив нативность
сессии (BR-001) и не давая Cyborg права менять трекер.

## 3. Business scope

Внутри границы: панель задач (вкладка «Задачи» панели, общей с видом MR/PR фичи 02); окно настроек с источниками GitHub, GitLab и заглушкой Jira; старт и повторный старт
сессии по задаче; номер, название и статус задачи в заголовке сессии; обновление по открытию панели и кнопке.

`non-goals`:

- вид MR/PR - фича `02-mr-view` (brief, «Смежное: вид MR/PR»); общая с ней - только вкладочная шапка панели;
- подключение Jira - только заглушка в настройках (brief п.2);
- действия по задаче кроме «Начать», например «сразу фиксить» (brief п.4);
- запись в трекер, в том числе смена статуса задачи (brief п.7);
- создание ветки или worktree при старте задачи (brief п.4);
- фоновый опрос трекеров (brief п.3);
- восстановление привязки задачи к сессии после перезапуска Cyborg (BRD продукта, non-goals).

## 7. Mission, goals and objectives

### BR-1001 Задачи текущего проекта в Cyborg

- **Требование:** разработчик видит открытые задачи включённых трекеров только по remote репозиториев текущего
  проекта, с фильтром «назначено мне» и сортировкой по дате обновления, дате создания и номеру.
- **traced from:** BR-004.
- **rationale:**
  - reason: задача проекта ищется сегодня вне Cyborg (brief п.1);
  - assumptions: задачи ведутся в issues GitHub либо GitLab тех же репозиториев, что remote проекта;
  - relationships: сценарий 4 BRD продукта;
  - design constraints: токен берётся из залогиненных `gh`/`glab`, своего токена Cyborg не хранит (brief п.2).
- **MOE:** в панели проекта видны его открытые задачи и не видны задачи других проектов (качественная).

### BR-1002 Сессия по задаче одним действием

- **Требование:** разработчик одной кнопкой начинает по задаче сессию Claude Code в репозитории задачи; сессия
  первым сообщением получает ссылку на задачу и подсказку сменить её статус; повторное действие возвращает к уже
  открытой сессии задачи; заголовок сессии показывает номер, название и статус задачи.
- **traced from:** BR-004, BR-001.
- **rationale:**
  - reason: пересказ задачи сессии руками (brief п.4-п.7);
  - assumptions: агент сессии сам меняет статус задачи CLI трекера;
  - relationships: сценарий 4 BRD продукта;
  - design constraints: начальный промпт - единственная добавка к CLI сверх хуков (BRD продукта, раздел 11;
    решение владельца 2026-10-23); git Cyborg не меняет.
- **MOE:** сессия, начатая из задачи, без ручного ввода содержит ссылку на задачу, а вкладка сессии - её номер и
  статус (качественная).

## 11. Business operational policies and rules

- Cyborg ничего не пишет в трекер; статус задачи меняет агент сессии.
- Сеть - только к трекерам; токен трекера Cyborg не читает и не хранит.

## 12. Business operational constraints

- Нужен установленный и залогиненный `gh` (GitHub) либо `glab` (GitLab, в том числе самохостный).

## 14. Business operational quality

Время загрузки задано владельцем (brief perf, 2026-10-23): на проекте Upcore задачи открываются не дольше 0,8 с при
прогретом входе и не дольше 1,8 с при первом открытии после запуска и после «Обновить»; вход в трекеры не
проверяется заново при каждом обновлении (SRS фичи, NFR-1004, FR-1019). Требований к числу задач нет - открытый
вопрос 1.
