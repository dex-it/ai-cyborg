# SRS фичи 01 - панель задач из трекеров

## 1. SRS overview

Требования системы к панели задач GitHub и GitLab, разделу источников задач в диалоге проекта и старту сессии Claude Code из задачи.
Вход - BRD фичи (`brd-feat.md`, BR-1001, BR-1002), цель трека `tasks-panel` и её критерии «готово» 1-24; метки,
фильтр по меткам, детали и открытие задачи в браузере - цель `task-details-labels` (D-34).
Основания решений и допущений - `decision-log.md` (D-NN).

## 2. Purpose

Задать наблюдаемое поведение панели, раздела источников диалога проекта и старта задачи так, чтобы правка проверялась по требованию, а
не по коду.

## 3. Scope

Специфицируется часть Cyborg: чтение задач трекеров через `gh`/`glab`, их показ, настройки источников, старт
сессии из задачи. Вне продукта: сами трекеры и CLI `gh`/`glab`, их вход; запись в трекер; вид MR/PR (фича
`02-mr-view`, кроме общей вкладочной шапки панели - FR-1001); Jira
(границы - `brd-feat.md`, раздел 3).

## 4. Product perspective

Главный процесс Cyborg запускает `gh` и `glab` без оболочки и читает remote репозиториев `git remote -v`;
интерфейс получает результат через preload-API (ADR-0002). Внешние соединения - только API трекеров через их CLI
(NFR-1002, ADR-0007).

## 5. Product functions

Панель задач проекта с фильтром, сортировкой и фильтром по комбинации меток; метки, детали задачи и открытие её в
системном браузере; раздел «Источники задач» диалога проекта (источники и их авторизация); «Начать» и «К сессии» у
задачи; заголовок сессии задачи со статусом; обновление по открытию и кнопке.

## 6. User characteristics

`inherited`: BRD продукта, раздел 5 (разработчик, ведущий сессии Claude Code).

## 7. Limitations

- Новых npm-зависимостей нет; API трекеров - через установленные `gh`/`glab` (цель, граница).
- Источники задач - поле `trackers` проекта в `projects.json` (ADR-0004 п.6); прочие поля проекта не меняются (ADR-0004 п.1).
- Git - только читающие команды (ADR-0005 п.3).

## 8. Assumptions and dependencies

- `gh` 2.74 и `glab` 1.36: формат вывода снят пробами прогона; смена формата `glab auth status` ломает FR-1009 и
  FR-1002 (D-20).
- Допущения цели D-01, D-02, D-04, D-06, D-07, D-08 открыты до подтверждения владельцем.

## 9. Apportioning of requirements

Главный процесс: FR-1002, FR-1003, FR-1004, FR-1007, FR-1010, FR-1012, FR-1016, FR-1017, FR-1019, FR-1020, FR-1024,
NFR-1001..1004; FR-1025 - построение адреса и открытие браузера.
Интерфейс: FR-1001, FR-1005, FR-1006, FR-1008, FR-1009, FR-1011, FR-1013, FR-1014, FR-1015, FR-1018, FR-1021,
FR-1022, FR-1023; FR-1025 - кнопки и показ отказа.
Отложено: Jira, прочие действия по задаче, комментарии задачи. Вид MR/PR - SRS фичи `02-mr-view`.

## 10. Specified requirements

Общие атрибуты, если у требования не сказано иное: `feature: 01-tasks-panel`; приоритет - обязательно; основание -
несценарное требование (сценарии фичи в `02-use-cases/` не заведены, поведение выводится из `BR` и критерия цели);
уровень верификации - модуль (`npm test`) для испытания и собранное приложение для демонстрации.

## 11. External interfaces

### FR-1002 Источники задач по remote проекта

- **Требование:** источник задач - каждый fetch-remote каждого репозитория текущего проекта (не только `origin`,
  remote частичного клона с суффиксом `[...]` после `(fetch)` тоже). Remote с хостом `github.com` (а также
  `www.github.com`, `ssh.github.com`) и путём ровно `owner/repo` - источник GitHub; remote с хостом, который
  перечисляет `glab auth status`, и путём из двух и более сегментов - источник GitLab. Схемы кроме `http`,
  `https`, `ssh`, `git` и scp-формы, локальные пути, иные хосты и ssh-алиасы пропускаются; порт ssh-URL
  отбрасывается. Задача, пришедшая через два remote, показывается один раз: ключ - вид трекера, хост, путь в
  нижнем регистре и номер.
- **traced from:** BR-1001.
- **источник:** цель, критерий 5 («каждый remote репозитория (не только `origin`) с хостом GitHub … либо хостом
  GitLab, на который залогинен `glab`»); D-04, D-12.
- **rationale:** reason - только задачи текущего проекта (brief п.1); assumptions - remote указывает на трекер
  задач; relationships - сценарий 4 BRD продукта; design constraints - хосты GitLab не опрашиваются (NFR-1002).
- **verification:** испытание - `test/trackers.test.ts` (`parseRemote`, `classifyRemote`, «берёт все remote»,
  «пропускает чужие хосты», «GitLab: самохостный»), `test/stores.test.ts` (`gitRemotes`).
- **класс:** External interfaces. **origin:** source; исходы D-12 - derived.

### FR-1003 Выборка открытых задач со всех страниц

- **Требование:** в список входят только открытые issues (`state=open` GitHub, `state=opened` GitLab), без
  pull/merge requests, со всех страниц выдачи API, по 100 на страницу.
- **traced from:** BR-1001.
- **источник:** цель, критерии 1 и 6; brief п.1 («открытые задачи»).
- **rationale:** reason - «открытые задачи» не ограничены числом; assumptions - нет; relationships - сценарий 4;
  design constraints - одним процессом CLI с `--paginate` (ADR-0007).
- **verification:** испытание - `test/trackers.test.ts` («запрашивает issues без PR», «источник с задачами сверх
  одной страницы отдаёт все», `splitJsonValues`).
- **класс:** External interfaces. **origin:** source.

### FR-1004 Фильтр «Назначено мне» на стороне трекера

- **Требование:** при включённом фильтре выборка идёт с `assignee=<логин>` (GitHub, логин - `gh api user`) либо
  `assignee_username=<пользователь хоста из glab auth status>` (GitLab); при выключенном - без него. Логин GitHub
  не получен - источник GitHub отдаёт ошибку, выборка без фильтра не подменяет отфильтрованную.
- **traced from:** BR-1001.
- **источник:** цель, критерий 3; brief п.1 («Фильтр: «назначено мне»»); D-02, D-11.
- **rationale:** reason - фильтр брифа; assumptions - D-02; relationships - сценарий 4; design constraints -
  серверный фильтр (D-11).
- **verification:** испытание - `test/trackers.test.ts` («фильтр «назначено мне»», «без залогиненного gh фильтр
  не применяется вслепую»).
- **класс:** External interfaces. **origin:** source; способ (серверный фильтр, отказ без логина) - derived.

### FR-1007 Отказ источника не скрывает остальные

- **Требование:** отказ одного источника показывается строкой «<источник>: <причина>», задачи остальных остаются
  видны. Причины: CLI не установлен; трекер не ответил за 120 с; ответ больше 64 МБ; `gh` с кодом 4 - «gh не
  залогинен»; иной ненулевой код либо `HTTP NNN` (NNN ≥ 400) в stderr, либо объект с `message` без `iid` у
  GitLab - первая строка сообщения; ответ не разобран. GitHub 410 - не отказ, а пометка «задачи в репозитории
  отключены». Remote хоста, который `glab` перечисляет без подтверждённого входа, - источник с причиной: при
  невходе - команда `glab auth login --hostname <хост>`, при сбое проверки - её текст; выборки по нему нет.
- **traced from:** BR-1001.
- **источник:** цель, критерий 15; BRD продукта, раздел 13; D-12, D-20; находка ревью F2.
- **rationale:** reason - деградация показывает причину (BRD §13); assumptions - нет; relationships - сценарий 4,
  альтернатива; design constraints - отказ `glab` распознаётся по stderr (D-20).
- **verification:** испытание - `test/trackers.test.ts` («отказ одного источника показан его сообщением»,
  «glab: HTTP-ошибка при коде 0», «HTTP 410 у GitHub», «хост glab без подтверждённого входа»).
- **класс:** External interfaces. **origin:** source; перечень причин, 410 и пределы - derived.

### FR-1016 Только чтение трекера и git

- **Требование:** Cyborg вызывает у `gh`/`glab` только читающие запросы (`api` без `-X` и `--input`, `auth status`),
  у git - только `remote -v`; при старте задачи либо MR не создаёт ветку, worktree и не делает checkout. Поля
  запроса (`-f`) и `graphql` допускаются только у `glab api graphql` деталей MR: строка запроса постоянна, без
  `mutation`, путь проекта и курсор страницы - переменными через `-f`, а не вставкой в текст (FR-2003, ADR-0007 п.3).
- **traced from:** BR-1002; BR-2002.
- **источник:** цель, критерии 19 и 22; brief п.4 («С git Cyborg ничего не делает»), п.7 («Cyborg его только
  читает»); цель `mr-view`, критерий 20, brief вида MR/PR п.9; цель `panel-load-perf`, критерий 7, D-28 фичи 02;
  цель `task-details-labels`, критерий «Запросы к трекеру только читающие» (запрос описания, FR-1024).
- **rationale:** reason - non-goals BRD фичи; assumptions - `-f` передаёт строку без чтения `@файл` (в отличие от
  `-F`); relationships - сценарий 4; design constraints - ADR-0005 п.3, ADR-0007 п.3.
- **verification:** испытание - `test/trackers.test.ts` («ни одного изменяющего запроса и ни одного обращения к
  токену»), `test/task-details.test.ts` («GitHub: gh api с --jq {body} и путём issues/N, только чтение»),
  `test/mrs.test.ts` («только читающие вызовы: ни -X, ни --input, ни токена; graphql - только постоянные
  запросы через -f», «GraphQL только читает»); осмотр - вызовы `git` в `src/main/git.ts`.
- **класс:** External interfaces. **origin:** source.

### FR-1017 Проверка аргументов каналов главным процессом

- **Требование:** главный процесс отклоняет ошибкой: ссылку на задачу, у которой вид не `github`/`gitlab`, хост не
  домен, путь с сегментом вне `[A-Za-z0-9._-]` либо `.`/`..`, GitHub не `github.com` с двумя сегментами, номер не
  целое 1..2^31; `tasks:list` с проектом не строкой, фильтром не boolean, отслеживаемыми задачами не массивом
  либо больше 200, признаком новой проверки входа (FR-1019) не boolean; `projects:save` с состоянием не объектом, с `projects` не массивом, с элементом `projects` не объектом либо с полем
  источников какого-либо проекта не объектом из двух boolean `github` и `gitlab` - файл проектов при отказе не
  пишется, лишние ключи поля источников при записи отбрасываются; отказ `projects:save` интерфейс показывает
  сообщением при любом сохранении, в том числе при смене проекта, состояние в памяти не откатывается;
  `session:create`, у которого старт не `{task}` либо `{mr, intent}` (правила старта с MR - FR-2016), и
  `session:create` со стартом, если рабочий либо дополнительный каталог не входит в репозитории проектов. `session:create` без старта работает как раньше (D-15).
  `tasks:details` с номером выборки не целым либо меньше 1 или со ссылкой на задачу не по правилам выше;
  `tasks:open` со ссылкой не по правилам выше - лишние поля ссылки отбрасываются, адрес строится из проверенных
  (FR-1024, FR-1025).
- **traced from:** BR-1002; ADR-0002 п.5.
- **источник:** цель, граница («главный процесс проверяет аргументы новых каналов»); цель `mr-view`, критерий 22,
  D-22 фичи 02; цель `panel-load-perf`, критерий 14 (признак новой проверки входа - derived); цель
  `project-task-sources`, критерий 11 (проверка `projects:save`; отказ при `projects` не массиве и сообщение при
  любом сохранении - решения прогона, D-26); цель `task-details-labels`, критерий «аргументы нового канала деталей
  и открытия ссылки проверяет главный процесс» (D-34).
- **rationale:** reason - интерфейс показывает недоверенные данные (ADR-0002); assumptions - нет; relationships -
  нет; design constraints - D-15.
- **verification:** испытание - `test/trackers.test.ts` («валидация аргументов каналов», `saveProjectsState`: поле
  источников не из двух boolean и `projects` не массив - ошибка, файл не пишется; `validateOpenArgs`),
  `test/mrs.test.ts` (`validateSessionStart`, «задача - прежний путь»), `test/task-details.test.ts`
  (`validateTaskDetailsArgs`, «tasks:list и tasks:details отклоняют неверные аргументы до запроса», «tasks:open
  строит адрес из проверенной ссылки и отклоняет чужой хост»).
- **класс:** External interfaces. **origin:** source; границы значений - derived.

### FR-1020 Метки, автор и исполнители в запросе списка

- **Требование:** метки задачи с цветом, автор и исполнители приходят в том же запросе списка, что задачи
  (FR-1003), без дополнительных вызовов CLI: у GitLab запрос несёт `with_labels_details=true`, у GitHub отбираются
  имя и цвет каждой метки, логин автора и логины исполнителей. Метка, пришедшая строкой (у GitHub по схеме, у
  одиночного запроса задачи вне списка GitLab, FR-1014), - метка без цвета. Цвет принимается из 3 либо 6
  шестнадцатеричных цифр с `#` или без и приводится к `#rrggbb` нижним регистром; иное значение - метка без цвета.
  Повтор имени метки у одной задачи отбрасывается.
- **traced from:** BR-1001.
- **источник:** цель `task-details-labels`, критерии «Метки», «Загрузка списка задач укладывается в пределы
  NFR-1004: метки и цвета приходят в том же запросе списка», «Автор и исполнители приходят в том же запросе списка»,
  «GitLab отдаёт цвета в том же запросе списка (`with_labels_details=true`), GitHub - полем `labels[].color`».
- **rationale:** reason - метки видны без запроса на задачу (NFR-1004); assumptions - у одиночного эндпоинта задачи
  GitLab параметра цветов нет, поэтому метки-строки допускаются (D-34); relationships - FR-1021, FR-1022;
  design constraints - ADR-0007, только читающие запросы (FR-1016).
- **verification:** испытание - `test/trackers.test.ts` («GitHub: цвет без # нормализуется, метки-строки получают
  color null, автор и исполнители из jq», «GitLab: запрос списка с with_labels_details, метки объектами, workflow из
  имён, автор и исполнители», «GitLab tracked: метки строками, цвет null», `normalizeColor`).
- **класс:** External interfaces. **origin:** source; метки-строки, приведение цвета и повтор имени - derived.

### FR-1024 Описание задачи только по задаче текущей выборки

- **Требование:** ответ `tasks:list` несёт номер выборки, выданный главным процессом; главный процесс держит
  задачи 8 последних выборок. `tasks:details` с номером выборки и ссылкой на задачу запрашивает описание, только
  если задача с тем же ключом (FR-1002) есть в этой выборке: одним читающим вызовом одиночной задачи - `gh api` у
  GitHub, `glab api` на хосте задачи выборки у GitLab. Задачи нет в выборке либо выборка вытеснена - отказ «задача
  не из текущей выборки: нажмите «Обновить»» без вызова CLI. Отказ трекера - текст по правилам FR-1007, при этом
  GitHub 410 - отказ, а не пометка. Отказы возвращаются ответом канала, а не исключением.
- **traced from:** BR-1001; ADR-0002 п.5.
- **источник:** цель `task-details-labels`, критерии «Описание загружается при раскрытии одним читающим запросом к
  трекеру», «Канал деталей принимает только задачу, которую главный процесс сам вернул в списке текущей выборки»;
  D-29, D-30.
- **rationale:** reason - токен `glab` не уходит на хост вне источников проекта; assumptions - нет; relationships -
  FR-1023, FR-1017; design constraints - ADR-0010 п.1-3.
- **verification:** испытание - `test/task-details.test.ts` (`TaskDetailsService`: «remember выдаёт растущий номер и
  держит не больше 8 выборок», «GitHub: gh api с --jq {body} и путём issues/N, только чтение», «GitLab: glab api на
  хосте выборки, единственный вызов - issues/N», «ссылка не из выборки: CLI не запускается», «отказ CLI - текст как
  у interpret», «GitLab: {message} без iid - отказ; HTTP 410 - ошибка, не пометка»; `createTaskHandlers`:
  «tasks:list отдаёт результат с номером выборки, по которому details находит задачу»).
- **класс:** External interfaces. **origin:** source; предел 8 выборок, 410 как отказ и отказ ответом - derived.

## 12. Functions

### FR-1001 Панель задач в рабочей области

- **Требование:** кнопка «Задачи» в полосе сессий рядом с «+ CC» открывает и закрывает панель; открытая панель
  занимает рабочую область вместо сессии; переход к сессии закрывает панель. Панель несёт вкладки «Задачи» и
  «MR/PR» (вид MR/PR - SRS фичи 02); при первом открытии активна «Задачи», выбранная вкладка держится до
  перезапуска; открытие панели и переход на вкладку обновляют её вид. Кнопок «Задачи» и «MR/PR» нет без выбранного
  проекта и у проекта, у которого не включён ни GitHub, ни GitLab; открытая панель в этом случае закрывается, видимость
  пересчитывается при смене проекта и после сохранения его свойств (решение оператора 2026-10-24). Без репозиториев
  в проекте панель показывает то же пояснение, что пустая рабочая область.
- **traced from:** BR-1001; BR-2001.
- **источник:** цель, критерий 2 (допущение D-01); brief п.1 («Отдельная панель»); цель `mr-view`, критерий 1
  (допущение D-01 фичи 02).
- **rationale:** reason - отдельная панель брифа; assumptions - D-01; relationships - сценарий 4; design
  constraints - нет.
- **verification:** демонстрация - собранное приложение.
- **класс:** Functions. **origin:** source.

### FR-1005 Сортировка

- **Требование:** сортировка выбирается из «Обновлена» (по умолчанию), «Создана», «Номер»; во всех трёх большее
  значение сверху; при равенстве порядок по ключу задачи, чтобы список не менялся между обновлениями.
- **traced from:** BR-1001.
- **источник:** цель, критерий 4; brief п.1 («Сортировка: дата обновления, дата создания, номер»); D-03.
- **rationale:** reason - бриф; assumptions - D-03; relationships - сценарий 4; design constraints - нет.
- **verification:** испытание - `test/model.test.ts` (`sortTasks`).
- **класс:** Functions. **origin:** source; порядок при равенстве - derived.

### FR-1006 Обновление по открытию и кнопке

- **Требование:** список и статусы обновляются при открытии панели на вкладке «Задачи», при переходе на неё и
  кнопкой «Обновить»; фонового опроса нет. Во время загрузки фильтр, сортировка и «Обновить» недоступны, повторное

### FR-1019 Проверка входа в трекеры переиспользуется между выборками

- **Требование:** проверка входа (`glab auth status`, `gh api user`) общая для выборок задач и MR (FR-2001) и
  переиспользуется между ними: при прогретом результате выборка не вызывает ни `auth status`, ни `api user`;
  одновременные выборки при пустом результате ждут одну проверку в полёте. Переиспользуется любой исход - вход,
  «не залогинен», отказ, - без срока жизни.
  - Проверка трекеров, включённых хотя бы у одного проекта, запускается один раз при старте приложения, не дожидаясь открытия панели; открытие
    после её завершения проверки не ждёт. Повтора по таймеру нет (FR-1006).
  - Сбрасывают результат «Обновить» на вкладках «Задачи» и «MR/PR» и сохранение проектов (`projects:save`), изменившее
    источники хотя бы у одного проекта (новый либо удалённый проект с обоими выключенными источниками их не меняет);
    результат проверки, начатой до сброса, не сохраняется. Открытие панели,
    переход на вкладку, смена фильтра, смена проекта и прочие сохранения состояния результат не сбрасывают.
  - После сброса выборка идёт по прежнему результату (хосты с входом, их пользователи, логин `gh`) параллельно с новой
    проверкой. Новая проверка изменила хосты с входом, пользователей либо состояние входа - выборка выполняется заново
    по ней и её ответ заменяет первый; изменился только текст ошибки - первый ответ остаётся. Прежнего результата нет
    (до прихода первой проверки) - выборка ждёт проверку.
  - Диалог проекта проверяет вход заново при каждом открытии (FR-1009) и результат выборок не трогает: вход,
    выполненный в терминале, списки видят после «Обновить».
  Тексты отказа («нет remote», «вход не выполнен», FR-1007) не меняются.
- **traced from:** BR-1001; BR-2001.
- **источник:** цель `panel-load-perf`, критерии 13-16, 20, 21; brief perf, «Требования» п.4; D-22, D-23 (решения
  владельца 2026-10-23).
- **rationale:** reason - `glab auth status` стоит около 1 с и шёл последовательно перед каждой выборкой (brief perf,
  «Замер»); assumptions - сравнение результатов без текста ошибки (D-23); relationships - NFR-1004, NFR-2002;
  design constraints - ADR-0009.
- **verification:** испытание - `test/trackers.test.ts` («второе обновление не зовёт auth status и api user;
  «Обновить» (recheck) зовёт снова», `warmAuth`, «список стартует до завершения новой auth status», «новая проверка
  изменила пользователя GitLab: выборка перестроена», «изменился только текст ошибки - не перестраивается»,
  «saveProjectsState: сброс кэша только при изменении источников»), `test/flow.test.ts` («кэш входа сбрасывает только «Обновить»»).
- **класс:** Functions. **origin:** source; общая проверка в полёте, отсечение результата до сброса и сравнение без
  текста ошибки - derived.

### FR-1022 Фильтр по комбинации меток

- **Требование:** над списком задач полоса «Метки:» показывает метки загруженного списка и сохранённого фильтра по
  алфавиту; метка определяется точным именем (регистр различается), одноимённые метки разных источников проекта -
  одна запись. Клик по метке полосы переключает её: не выбрана → обязательная (+) → исключённая (−) → не выбрана.
  В списке остаются задачи, у которых есть все обязательные метки и нет ни одной исключённой; «✕» сбрасывает
  фильтр. Фильтр применяется к загруженному списку и запросов к трекеру не делает; с «Назначено мне» и сортировкой
  сочетается. Выбор хранится у каждого проекта отдельно и переживает перезапуск; сохранённая метка, которой нет в
  загруженном списке, остаётся видна в полосе и снимается «✕»; повреждённое сохранённое значение даёт пустой
  фильтр. Во время загрузки полоса показывает метки прежнего списка и недоступна; смена проекта очищает её. Полосы
  нет, если меток нет ни в списке, ни в фильтре.
- **traced from:** BR-1001.
- **источник:** цель `task-details-labels`, критерии «Фильтр меток над списком», «Фильтр работает по загруженному

  источников проекта», «Клик по метке в фильтре переключает её» (допущения, D-34); хранение у проекта - решение
  прогона D-32.
- **rationale:** reason - оператор фильтрует по тегам и их комбинациям; assumptions - D-34; relationships -
  FR-1008, FR-1021, FR-1004; design constraints - D-31.
- **verification:** испытание - `test/model.test.ts` (фильтр меток: «И по обязательным и НЕ по исключённым»,
  «только исключённые оставляют и задачи без меток», «cycleLabel: + -> − -> снята», «сохранение: круг и
  повреждённые значения», «availableLabels: одноимённые метки в одну запись, сохранённая без задач остаётся, регистр
  различается»), `test/tasks-view.test.ts` («пока идёт загрузка, полоса меток остаётся с прежними метками и цветом,

### FR-1025 Открытие задачи в системном браузере

- **Требование:** номер задачи `#N` в строке открывает страницу задачи в системном браузере; окно Cyborg остаётся на месте, не переходит по адресу и нового окна не открывает. Адрес
  строит главный процесс из проверенной ссылки на задачу (FR-1017) по тому же правилу, что URL задачи в промпте
  (FR-1012); принадлежность текущей выборке не требуется. Браузер не открылся - строка раскрывается, и в деталях
  виден текст «Браузер не открылся: <причина>».
- **traced from:** BR-1001.
- **источник:** цель `task-details-labels`, критерий «Ссылка» (ответ оператора; адрес из главного процесса -

- **rationale:** reason - «должна работать ссылка на задачу»; assumptions - D-34; relationships - FR-1012, FR-1017;
  design constraints - ADR-0010 п.4, п.5.
- **verification:** испытание - `test/task-details.test.ts` («tasks:open строит адрес из проверенной ссылки и
  отклоняет чужой хост», «tasks:open: отказ браузера возвращается текстом»); демонстрация - клик по номеру.

### NFR-1004 Время загрузки панели задач

- **Требование:** на проекте Upcore (3 репозитория GitLab на `git.dextechnology.com`) задачи загружаются не дольше
  0,8 с при прогретой проверке входа (FR-1019) и не дольше 1,8 с при открытии после завершения проверки при старте и
  при «Обновить» с прежним результатом проверки. Открытие без прежнего результата и без проверки при старте предела
  не несёт и печатается справочно. Предел судится по медиане 5 прогонов замера.
- **traced from:** BR-1001.
- **источник:** brief perf, «Требования» п.1, п.4; цель `panel-load-perf`, критерии 2 и 22; D-31 фичи 02.
- **rationale:** reason - на Upcore задачи открывались 1,6 с, из них 1,0 с - `glab auth status` перед списками
  (brief perf, «Замер»); assumptions - разброс сети между прогонами до 2×, поэтому медиана (D-31 фичи 02);
  relationships - FR-1019; design constraints - ADR-0009. Классификация данных и авторизация - NFR-1001.
- **verification:** анализ - `npm run measure` (`scripts/measure.mjs`) на Upcore печатает время до списка задач по
  сценариям «после проверки при старте», «Обновить» и справочную строку; замер владельца 2026-10-23 (медиана из 5:
  1,00 с и 1,04 с) - `decision-log` фичи 02, D-31.
- **класс:** Performance. **origin:** source.

## 18. Software system attributes

### NFR-1001 Токен трекера не проходит через Cyborg

- **Требование:** Cyborg не читает, не хранит и не передаёт токен трекера: `gh`/`glab` берут его из своей
  конфигурации; токена нет в файлах Cyborg, в логе и в окружении сессий Claude Code; `gh auth token` не
  вызывается.
- **traced from:** BR-1001; BRD продукта, раздел 11.
- **источник:** цель, критерий 9; brief п.2 («своего токена Cyborg не хранит»).
- **rationale:** reason - токен - секрет пользователя; assumptions - пользователь залогинен в CLI; relationships -
  нет; design constraints - ADR-0007. Классификация данных: токен - секрет, задачи - данные пользователя под его
  авторизацией в трекере; модель авторизации - права входа пользователя в `gh`/`glab`.
- **verification:** испытание - `test/trackers.test.ts` («ни одного … обращения к токену»); осмотр - окружение
  процесса сессии.
- **класс:** Security. **origin:** source.

### NFR-1002 Сеть только к трекерам

- **Требование:** Cyborg обращается к сети только к API трекеров через `gh` (хост `github.com`) и `glab` (хосты из
  `glab auth status`); хосты remote, которых нет среди трекеров, не опрашиваются; своего HTTP-клиента нет.
- **traced from:** BR-1001; BRD продукта, раздел 3.
- **источник:** цель, критерий 10; brief, «Расхождения с BRD», §3.
- **rationale:** reason - граница продукта; assumptions - нет; relationships - нет; design constraints - ADR-0007,
  D-04.
- **verification:** испытание - `test/trackers.test.ts` («пропускает чужие хосты», «выключенные источники»);
  осмотр - нет `fetch`/`http` в `src/`.
- **класс:** Security. **origin:** source.
