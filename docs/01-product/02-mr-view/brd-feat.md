# BRD фичи 02 - вид MR/PR в панели задач

Источник: бриф владельца `Cyborg-mr-view.brief.md` (2026-10-23), цель трека `mr-view`. Фича идёт после
`01-tasks-panel` и опирается на её источники, свойства проекта и механизм действий со стартом сессии.

## 1. BRS overview

Разработчик ревьюит чужие MR и дорабатывает свои, открывая их в браузере трекера и пересказывая сессии Claude Code
руками. Фича даёт в панели задач вкладку «MR/PR» с открытыми MR GitLab и PR GitHub репозиториев текущего проекта и
действие, которое открывает по MR сессию: ревью чужого MR либо доработку своего. Адресован владельцу продукта и
составителям SRS и архитектуры.

## 2. Business purpose

Сократить путь от открытого MR до сессии, которая его ревьюит либо дорабатывает, до одного действия в Cyborg,
сохранив нативность сессии (BR-001) и не давая Cyborg права менять трекер и git.

## 3. Business scope

Внутри границы: вкладка «MR/PR» рядом с «Задачи» в той же панели; строка MR с номером, названием, автором, ветками,
пометкой черновика, пайплайном и апрувами; фильтр и сортировка; действия «Ревью» и «Доработать» со стартом сессии;
возврат к открытой сессии MR; номер, название, статус и пайплайн MR в заголовке сессии; обновление по открытию
вкладки и кнопке.

`non-goals`:

- запись в трекер: Cyborg не апрувит, не комментирует, не меняет статус MR (brief п.9; BRD продукта, non-goals);
- checkout ветки MR, создание ветки или worktree: это делает агент сессии (brief п.9);
- отдельные галочки источников и отдельная авторизация для MR - источники общие с задачами (brief п.2);
- фоновый опрос трекеров (brief п.5);
- Jira (фича `11-status-hub`);
- восстановление привязки MR к сессии после перезапуска Cyborg (BRD продукта, non-goals).

## 7. Mission, goals and objectives

### BR-2001 Открытые MR текущего проекта в Cyborg

- **Требование:** разработчик видит открытые MR GitLab и PR GitHub только по remote репозиториев текущего проекта,
  с автором, ветками, пометкой черновика, статусом пайплайна и апрувами, с фильтром «назначено мне» и «я ревьюер» и
  сортировкой по дате обновления, дате создания и номеру.
- **traced from:** BR-004.
- **rationale:**
  - reason: MR проекта ищется сегодня в браузере трекера (brief п.1, п.3, п.4);
  - assumptions: MR ведутся в тех же репозиториях GitHub либо GitLab, что remote проекта;
  - relationships: сценарий 5 BRD продукта;
  - design constraints: источники и авторизация - общие с панелью задач (brief п.2; BR-1001).
- **MOE:** во вкладке «MR/PR» проекта видны его открытые MR с пайплайном и апрувами и не видны MR других проектов
  (качественная).

### BR-2002 Сессия ревью или доработки MR одним действием

- **Требование:** разработчик одной кнопкой открывает по чужому MR сессию ревью, по своему - сессию доработки, в
  репозитории MR; сессия первым сообщением получает ссылку на MR и команду ревью либо просьбу разобрать замечания;
  повторное действие возвращает к уже открытой сессии MR; заголовок сессии показывает номер, название, статус и
  пайплайн MR.
- **traced from:** BR-004, BR-001.
- **rationale:**
  - reason: пересказ MR сессии руками (brief п.6-п.8);
  - assumptions: агент сессии сам переключается на ветку MR (brief п.9); команда `/dex-auto:auto review`
    установлена у пользователя;
  - relationships: сценарий 5 BRD продукта;
  - design constraints: начальный промпт - единственная добавка к CLI сверх хуков, каталогов и инструкции изоляции (BRD продукта,
    раздел 11, ADR-0012; решение владельца 2026-10-23); git Cyborg не меняет.
- **MOE:** сессия, открытая из MR, без ручного ввода содержит ссылку на MR и нужное действие, а вкладка сессии -
  номер, статус и пайплайн MR (качественная).

## 11. Business operational policies and rules

- Cyborg ничего не пишет в трекер и в git; ветку MR переключает агент сессии.
- Сеть - только к трекерам; токен трекера Cyborg не читает и не хранит (как у фичи 01, NFR-1001, NFR-1002).

## 12. Business operational constraints

- Нужен установленный и залогиненный `gh` (GitHub) либо `glab` (GitLab, в том числе самохостный); источник включён
  в свойствах проекта (фича 01).
- Действие «Ревью» опирается на установленную у пользователя команду Claude Code `/dex-auto:auto`.

## 14. Business operational quality

Время загрузки задано владельцем (brief perf, 2026-10-23): на проекте Upcore вкладка MR/PR показывает список не
дольше 2 с, пайплайн и апрувы - не дольше 3 с; список виден сразу после выборки, детали дописываются следом (SRS
фичи, NFR-2002, FR-2006, FR-2009). Требований к числу MR нет - открытый вопрос 1.
