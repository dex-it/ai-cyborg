# decision-log фичи 02 - вид MR/PR

Решения и допущения прогона цели `mr-view` (2026-10-23). Исход «открыто» - допущение, принятое за постановщика
без оператора; подтверждает либо меняет владелец продукта.

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | Вкладки «Задачи» и «MR/PR» в одной панели; при первом открытии активна «Задачи», выбранная вкладка держится до перезапуска | - | цель, критерий 1 (допущение) | открыто: какая вкладка по умолчанию |
| D-02 | Номер MR - нотация трекера: GitHub `#N`, GitLab `!N` | - | цель, критерий 5 (допущение) | открыто |
| D-03 | Ветка PR из форка (в том числе удалённого) - `<владелец форка>:<ветка>` по `head.label` GitHub; ветка своего репозитория - как есть | - | цель, критерий 5 (допущение) | открыто |
| D-04 | Значения пайплайна - «успешен» / «упал» / «идёт» / «ожидает» / «отменён» / прочее статусом трекера / «нет пайплайна»; у GitHub - сводка check runs и commit statuses головного коммита, хотя бы один упавший - «упал»; у GitLab - `head_pipeline` MR. Апрувы - «апрувов: N», у GitLab при заданном числе обязательных - «апрувов: N из M» | - | цель, критерий 5 (допущение) | открыто: какие значения пайплайна и апрувов показывать |
| D-05 | Фильтр - выбор одного из «Все» (по умолчанию), «Назначено мне», «Я ревьюер»; «Я ревьюер» у GitHub - ревью запрошено лично (`requested_reviewers`), PR с уже отправленным ревью в фильтр не входит | два независимых фильтра | цель, критерий 7 (допущение) | открыто: форма, умолчание, смысл «Я ревьюер» у GitHub |
| D-06 | Статус MR в заголовке - «открыт» / «черновик» / «влит» / «закрыт»; «закрыт» (закрыт без вливания) добавлен к перечню брифа, GitLab `locked` показывается «закрыт» | - | цель, критерий 17 (допущение); прогон, решение за молчащий вход | открыто |
| D-07 | Первое сообщение «Ревью» - `/dex-auto:auto review <URL MR>`: ссылка входит в команду, перед командой не стоит (slash-команда распознаётся только в начале сообщения); «Доработать» - «Разбери замечания к MR <URL MR>: переключись на его ветку и доработай её по замечаниям ревью.» | ссылка отдельной строкой перед командой | цель, критерии 12, 13 (допущение); brief п.6 | открыто |
| D-08 | URL MR - канонические адреса трекеров: `https://github.com/<owner>/<repo>/pull/<N>`, `https://<хост>/<путь>/-/merge_requests/<N>` | - | цель, критерий 15 (допущение) | открыто |
| D-09 | Открытые MR читаются со всех страниц; сбой любой страницы, таймаут, переполнение и HTTP 410 - отказ источника целиком, а не пометка (у задач 410 - пометка «задачи отключены», D-12 фичи 01) | усечённый список; пометка 410, как у задач | цель, критерий 4; код `src/main/mrs-service.ts:120-125` | принято |
| D-10 | Фильтр применяется в главном процессе по одной полной выборке `pulls` / `merge_requests` до запроса деталей; смена фильтра - новый запрос | search API GitHub (`is:pr review-requested:`): 30 запросов в минуту, своя пагинация до 1000, `pulls` всё равно нужен для веток и головного коммита; фильтр в интерфейсе: аргумент фильтра проверяет главный процесс, а фильтр до деталей сокращает число вызовов | прогон, дизайн; цель, граница («на усмотрение реализации») | принято |
| D-11 | GraphQL `gh api graphql` не используется | один запрос на статус, ревью и checks: требует полей запроса, запрещённых ADR-0007 п.3 | цель, граница | принято |
| D-12 | Пайплайн и апрувы запрашиваются у 200 самых свежих по `updated_at` MR после фильтра по всем источникам; MR с открытой сессией получают детали сверх предела (не больше 200); остальные строки показывают «—» | детали по всем MR: 2000 открытых PR дали бы 6000 вызовов `gh` при лимите REST GitHub 5000 в час и сломали бы и вид задач; вытеснять свежие MR ради MR с сессией | прогон, дизайн; находка ревью F2 | принято: открытый вопрос 1 BRD фичи |
| D-13 | Одновременно обрабатываются не больше 6 MR, вызовы CLI одного MR идут подряд: процессов `gh`/`glab` не больше 6 плюс число источников | `Promise.all` внутри MR: до 18 процессов `gh` при пуле в 6 MR | прогон, дизайн; находка ревью F1 | принято |
| D-14 | Пайплайн GitLab берётся одиночным запросом MR (`head_pipeline`): список MR GitLab его не несёт; тот же вызов обслуживает MR с сессией вне списка | - | прогон, документация GitLab API | принято |
| D-15 | Апрувы GitHub - число пользователей, у которых последнее ревью среди APPROVED / CHANGES_REQUESTED / DISMISSED - APPROVED; COMMENTED и PENDING не сбрасывают апрув | «последнее ревью любого вида» из критерия 5: COMMENTED после APPROVED снимал бы апрув, который GitHub показывает | прогон, неверное во входе | принято |
| D-16 | «Нет пайплайна» у GitHub - ноль commit statuses (`total_count = 0`) и ни одного check run, а не `state` сводки: у пустой сводки `state = pending` | признак по `state` | прогон, неверное во входе | принято |
| D-17 | Статус пайплайна GitLab вне пяти известных (`created`, `manual`, `skipped` и прочие) показывается как есть; `canceled` - «отменён» | - | прогон, неверное во входе (перечень критерия 5 неполон) | принято |
| D-18 | Логин `gh` не получен: при фильтре «Все» список отдаётся, у всех PR действие «Ревью» (только читающее); при «Назначено мне» и «Я ревьюер» - отказ источника, выборка без фильтра не подменяет отфильтрованную | отказ источника и при «Все» | прогон, решение за молчащий вход; FR-1004 | принято |
| D-19 | Головной коммит из ответа трекера проверяется как hex SHA до подстановки в путь `api`; не прошёл - пайплайн «—» без вызова CLI | - | прогон, решение за молчащий вход: данные трекера не доверены | принято |
| D-20 | Процессы устаревшей выборки (смена проекта, сохранение настроек) не прерываются, их ответ отбрасывается | отмена процессов: в репозитории её нет и у задач | прогон, решение за молчащий вход; D-17 фичи 01 | принято |
| D-21 | Сессии задач и MR - один реестр в разрезе проекта; ключи различаются разделителем (`#` у задачи, `!` у MR), поэтому сессия MR GitLab `!N` и задачи `#N` того же репозитория - разные | отдельный реестр сессий MR: повтор реестра задач | прогон, дизайн | принято |
| D-22 | Аргумент старта `session:create` - размеченное объединение `{task}` либо `{mr, intent}` с одной точкой проверки в главном процессе; прежняя форма (голая ссылка на задачу) снята, интерфейс шлёт `{task}` | пятый позиционный аргумент для MR: два необязательных параметра дают невалидное сочетание задача+MR | прогон, дизайн | принято |
| D-23 | Разбор источников (remote, хосты `glab auth status`, логин `gh`) - общий для задач и MR | копия разбора в выборке MR | прогон, дизайн | принято |
| D-24 | Не полученный пайплайн (`null`, вызов не удался) не затирает прежний пайплайн в заголовке сессии; легитимное отсутствие приходит значением «нет пайплайна» | заменять заголовок на «—» при каждом сбое | прогон; находка ревью F2 | принято |
| D-25 | Для MR с сессией вне списка запрашиваются статус и пайплайн, апрувы - нет: в заголовке их нет | - | прогон, дизайн | принято |
| D-26 | Строка MR показывает не полученное как «пайплайн: —» и «апрувов: —» | - | прогон; цель, критерий 6 | принято |
| D-27 | Правки корпуса вне фичи, род - расширение области: BR-004 BRD продукта - «задача либо MR трекера», сценарий 5 раздела 17 и разделы 3, 5, 6, 9-13 о виде MR/PR; ADR-0007 - чтение MR тем же способом, запрет `graphql` в п.3; ADR-0003 п.9 - начальный промпт сессии MR; правки фичи 01 - D-21 фичи 01 | новый BR продукта рядом с BR-004: тот же предмет (работа с трекером в Cyborg), другое ограничение | brief п.1, п.6, «Старт сессии» («BRD §11 расширен») | принято |
