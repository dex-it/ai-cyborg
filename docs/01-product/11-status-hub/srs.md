# SRS фичи 11 - кнопка «Статус»: GitHub, GitLab и Jira в одной карточке

## 1. SRS overview

Требования к кнопке «Статус», её карточке, чтению Jira через `jira-cli` и запуску сессий по записям карточки. Вход - BRD фичи
(`brd-feat.md`, BR-11001..BR-11003) и код `src/main/jira.ts`, `src/main/jira-service.ts`, `src/renderer/status.ts`,
`src/renderer/status-model.ts`. Основания решений - `decision-log.md` (D-NN).

## 2. Purpose

Задать наблюдаемое поведение сводки статуса так, чтобы правка проверялась по требованию, а не по коду.

## 3. Scope

Кнопка и карточка, настройка Jira проекта, каналы `jira:status`, `jira:list`, `jira:details`, `jira:open`, расширение `session:create`
(задача Jira, намерение `ci`). Вне фичи: запись в Jira и трекеры, JQL по выбору, панели «Задачи» и «MR/PR» (`brd-feat.md`, раздел 3).

## 4. Product perspective

Часть окна Cyborg рядом с панелью трекеров (фичи `01-tasks-panel`, `02-mr-view`): выборка MR - та же (`mrs:list`, `mrs:details`), старт
сессий - тот же механизм (`session:create`). Jira читается отдельным процессом `jira` (ADR-0013).

## 5. Product functions

Настройка Jira проекта; кнопка и индикатор; сбор и обновление данных; уровень и счётчик; список задач Jira; детали задачи; списки MR/PR;
сессия по задаче Jira; сессия по упавшему пайплайну; границы безопасности; отказы `jira-cli`.

## 6. User characteristics

`inherited`: BRD продукта, раздел 5.

## 7. Limitations

- Jira читается только командами `jira version`, `jira me`, `jira issue list`, `jira issue view`, `jira open --no-browser` (ADR-0013, п.1).
- Новых npm-зависимостей нет.

## 8. Assumptions and dependencies

- Для Jira нужен установленный и настроенный `jira-cli` с работающим входом (`jira me` называет пользователя); для MR/PR - `gh` и
  `glab` под входом, как у вкладки «MR/PR»; допущения D-01..D-13 открыты до подтверждения владельцем.

## 9. Apportioning of requirements

Главный процесс: FR-11001 (хранение и проверка настроек), FR-11005, FR-11006, FR-11010, FR-11011 (чтение Jira), FR-11008, FR-11009 (старт
сессии). Интерфейс: FR-11002, FR-11003, FR-11004, FR-11005..FR-11009 (вид).

## 10. Specified requirements

Общие атрибуты, если у требования не сказано иное: `feature: 11-status-hub`; приоритет - обязательно; основание - запрос владельца
(`brd-feat.md`); уровень верификации - модуль (`npm test`) для испытания, собранное приложение (`npm run smoke`) для демонстрации.

## 11. External interfaces

Внешний интерфейс - командная строка `jira-cli` (ADR-0013): формат `--raw` списка и просмотра у `jira-cli` не версионируется; сверен на
версии 1.7.0 (D-11).

## 12. Functions

### FR-11001 Jira в свойствах проекта

- **Требование:** в разделе «Источники задач» диалога проекта Jira - рабочая галочка и поле «Ключ проекта» (пусто - проект, сохранённый
  `jira init`); при открытии диалога под галочкой показан итог проверки: `jira-cli` не установлен, не настроен, не вошёл либо
  «вход выполнен: <пользователь> (jira-cli <версия>)». Настройка хранится в проекте полем `jira: {enabled, project}`; проект без поля
  читается как «Jira выключена». Ключ проекта принимается, только если он пуст либо состоит из букв, цифр и «_» и начинается с буквы:
  иначе сохранение отклоняется (в диалоге - подсветка поля и отказ формы, в канале `projects:save` - ошибка), в файл ничего не
  пишется. Поле `jira` не влияет на `trackers` и на кнопки «Задачи» и «MR/PR».
- **traced from:** BR-11002.
- **источник:** запрос владельца; код `readJira`, `validateJira`, `initSourcesSection`; D-02, D-04.
- **rationale:** reason - включить Jira для проекта без правки файла; assumptions - D-04; relationships - FR-1010 (источники GitHub и
  GitLab), ADR-0004 (файл проектов); design constraints - ключ проекта попадает в аргумент `-p`, форма проверяется (FR-11010).
- **verification:** испытание - `test/jira.test.ts` («Jira: настройки проекта»: чтение из файла, проверка при сохранении, лишние поля не
  переносятся, неверный ключ отклоняет сохранение); демонстрация - диалог проекта на стенде.
- **класс:** Functions. **origin:** source.

### FR-11002 Кнопка «Статус» и карточка

- **Требование:** в полосе сессий у проекта, у которого включён хотя бы один источник (GitHub, GitLab либо Jira), есть кнопка «Статус» с
  индикатором (цвет по FR-11004) и счётчиком записей, требующих внимания; у проекта без источников кнопки нет, и открытая карточка
  закрывается при смене проекта. Нажатие открывает карточку под кнопкой, повторное нажатие, клик снаружи и Escape закрывают её; клик
  внутри карточки, перерисовавший её, не закрывает. При открытии фокус переходит в карточку (Escape не перехватывается терминалом).
  Заголовок карточки - имя проекта с индикатором, время последнего обновления и кнопка «Обновить».
- **traced from:** BR-11001.
- **источник:** запрос владельца («как в Discord»); код `StatusHub`; D-01.
- **rationale:** reason - сводка видна мельком и не занимает рабочую область; assumptions - D-01; relationships - FR-11003, FR-11004;
  design constraints - строки карточки строятся через `textContent` (запрет `innerHTML`, `test/static-guards.test.ts`).
- **verification:** испытание - `scripts/smoke.mjs` (кнопка у проекта с источником и её отсутствие у проекта без; открытие, закрытие
  кликом снаружи и Escape; клик внутри с перерисовкой не закрывает); осмотр - `tabindex` и фокус карточки в `src/renderer/status.ts`;
  демонстрация - карточка в обеих темах на стенде.
- **класс:** Usability. **origin:** source.

### FR-11003 Сбор и обновление данных

- **Требование:** данные карточки собираются при выборе проекта, при открытии карточки, если они старше минуты, по «Обновить» и по таймеру
  раз в 5 минут (и при возврате окна на экран, если данные старше 5 минут), пока окно на виду; свёрнутое окно не опрашивается.
  Собираются: открытые MR/PR автора (`mrs:list` с фильтром «автор») и MR на ревью («рецензент») с пайплайном, апрувами и признаком замечаний -
  по очереди (сначала автор, затем рецензент), каждая списком и вторым вызовом деталей (`mrs:details`); задачи Jira - параллельно, если Jira включена. Недоступный источник называется в карточке
  причиной (нет входа, нет remote, ответ не получен), остальные показываются; если ни у одного репозитория проекта нет remote GitHub или
  GitLab с ответом, карточка говорит об этом. Данные прежнего проекта после смены проекта отбрасываются, запоздавший ответ не
  применяется. «Обновить» заново проверяет вход трекеров и снимает остановку опроса Jira (FR-11011).
- **traced from:** BR-11001.
- **источник:** код `StatusHub.refresh`; D-06.
- **rationale:** reason - индикатор нужен без нажатия, но не должен нагружать CLI; assumptions - D-06; relationships - FR-11002, FR-11011;
  design constraints - общий пул процессов деталей MR (ADR-0008).
- **verification:** осмотр - `REFRESH_MS`, `FRESH_MS`, порядок вызовов в `StatusHub.refresh` (`src/renderer/status.ts`); демонстрация -
  стенд с подставными `gh` и `jira`: индикатор и карточка после запуска без нажатия; `scripts/smoke.mjs` (карточка называет причину
  отсутствия данных о MR). Таймер отдельным тестом не покрыт (интерфейсный код без DOM-стенда).
- **класс:** Functions. **origin:** source.

### FR-11004 Индикатор и счётчик

- **Требование:** уровень индикатора - по MR/PR с ответившим источником: «красный» (bad) - у своего открытого MR пайплайн «упал»;
  «янтарный» (attention) - у своего открытого MR есть замечания либо открытый не-черновик другого автора ждёт моего ревью; «синий» (wait) -
  у своего открытого MR пайплайн «идёт» или «ожидает»; «зелёный» (ok) - данные есть, ничего из перечисленного; «серый» (unknown) - ни один
  источник кода не ответил. Источник не считается ответившим без единого репозитория, ответившего без ошибки (нет входа, нет remote).
  Счётчик - число MR, требующих внимания (свой MR с упавшим пайплайном и замечаниями - один; MR из обоих списков - один раз); от 100 - «99+».
  Закрытые и влитые MR и черновики чужих внимания не просят. Jira в уровень не входит.
- **traced from:** BR-11001.
- **источник:** код `levelOf`, `attentionOf`, `usable`; D-10.
- **rationale:** reason - индикатор отвечает на «что горит»; assumptions - D-10; relationships - FR-11002, FR-11007; design constraints -
  слова пайплайна задаёт главный процесс (`mrs.ts`: «упал», «идёт», «ожидает», «успешен»).
- **verification:** испытание - `test/status-model.test.ts` (тон пайплайна, причины внимания и их порядок, уровни, когда по MR можно судить);
  демонстрация - индикатор «красный» со счётчиком 3 на стенде (упавший пайплайн, замечания, ревью).
- **класс:** Functions. **origin:** source.

### FR-11005 Задачи Jira на мне: список и связь с MR

- **Требование:** раздел «Jira · на мне: N» (N - число задач, «+» при пределе 50) показывает открытые задачи Jira, назначенные на
  пользователя `jira-cli`, свежие первыми: ключ, название, статус, приоритет, давность обновления, метки связанных MR с их пайплайном
  (`#12 ✓`, `✕`, `…`). Группы: «В работе» (категория статуса «In Progress» - вторым запросом ключей) и «Остальные открытые»; пустая группа
  не показывается. MR связан с задачей, если ключ задачи стоит в названии либо ветке MR целым словом (`DEX-1` не находится в `DEX-12` и
  `XDEX-1`), регистр не важен. Нет задач - «Открытых задач на вас нет.»; ошибка источника - её причина.
- **traced from:** BR-11002.
- **источник:** код `parseIssues`, `jiraListArgs`, `groupIssues`, `mrsOfIssue`; D-07, D-08.
- **rationale:** reason - видеть свои задачи рядом с их MR и CI; assumptions - D-08; relationships - FR-11006, FR-11008; design constraints -
  `jira issue list -q <JQL> --raw --order-by updated --paginate 0:50 [-p <проект>]` и запрос ключей (`--plain --columns key`) (ADR-0013, п.1).
- **verification:** испытание - `test/jira.test.ts` (разбор записи списка и тела просмотра, пустая выборка, битые записи, запросы и аргументы,
  категория «в работе», предел), `test/status-model.test.ts` (связь по ключу, группы); `scripts/smoke.mjs` (задача в карточке);
  демонстрация - стенд с подставным `jira`.
- **класс:** Functions. **origin:** source.

### FR-11006 Детали задачи Jira и открытие в браузере

- **Требование:** клик по ключу задачи раскрывает под строкой детали, повторный сворачивает: тип, статус, приоритет, исполнитель, автор,
  метки, описание (документ ADF Jira Cloud приводится к тексту, вики-разметка Server остаётся как написана, не длиннее 20 000 знаков) и
  последние три комментария («последние N из M») с автором и давностью; пока детали грузятся - «Загрузка…», при отказе - его причина.
  Кнопка «Открыть в Jira» открывает адрес из `jira open <ключ> --no-browser` в браузере (только `http` и `https`); отказ называется в
  деталях. Детали и адрес запрашиваются только по задаче из последнего списка проекта; «Обновить» сбрасывает загруженные детали.
- **traced from:** BR-11002.
- **источник:** код `parseDetails`, `JiraService.details`, `JiraService.url`; D-03.
- **rationale:** reason - прочитать задачу, не открывая браузер; assumptions - D-02; relationships - FR-11005, FR-11010; design constraints -
  чужой текст рисуется через `textContent`, управляющие коды вычищены (FR-11010).
- **verification:** испытание - `test/jira.test.ts` (детали: ADF, упоминание, комментарии без номера, число комментариев; сервис: детали и адрес
  только по задаче из списка, чужой и неверный ключ до `jira` не доходят, адрес только `http(s)`); `scripts/smoke.mjs` (детали с описанием и
  комментарием); демонстрация - раскрытая задача на стенде.
- **класс:** Functions. **origin:** source.

### FR-11008 Сессия по задаче Jira

- **Требование:** кнопка «Начать» у задачи открывает сессию Claude Code в репозитории проекта, первым сообщением которой Cyborg отдаёт
  `Задача Jira <ключ>: прочитай её (jira issue view <ключ> --comments 5), разберись в постановке и предложи план работ. Код не правь, пока я не
  подтвержу план.`; название и описание задачи в сообщение не попадают. Канал `session:create` принимает `{jira: {key}}`, ключ - по форме
  `ABC-12` (иначе отказ), источник старта один. Репозиторий: у связанного MR - его репозиторий проекта, иначе единственный репозиторий
  проекта, иначе меню выбора. Карточка закрывается, вкладка сессии называется `CC<n> · <ключ> <название>`. Повторное действие по задаче с
  открытой сессией («К сессии») возвращает к ней и новую не открывает; двойной клик не создаёт вторую сессию.
- **traced from:** BR-11003.
- **источник:** код `jiraPrompt`, `validateSessionStart`, `startJira`; D-05, D-09.
- **rationale:** reason - от задачи до сессии одним действием; assumptions - D-09; relationships - FR-11005, FR-11010; design constraints -
  сессия нативна (BR-001), первое сообщение строится в главном процессе из проверенного ключа (ADR-0003, п.9).
- **verification:** испытание - `test/jira.test.ts` («Jira: старт сессии»: промпт по ключу, ключи не по форме и два источника старта - отказ);
  `scripts/smoke.mjs` (вкладка сессии с ключом, промпт в аргументах `claude`, «К сессии» возвращает без новой вкладки); демонстрация -
  сессия в репозитории связанного MR на стенде.
- **класс:** Functions. **origin:** source.

### FR-11009 Сессия по упавшему пайплайну, доработке и ревью из карточки

- **Требование:** у своего открытого MR с упавшим пайплайном кнопка «Разобрать пайплайн» открывает сессию с сообщением

  «Доработать», у чужого - «Ревью» (сообщения - как у вкладки «MR/PR»). Если по MR открыта сессия, вместо кнопок по причинам одна кнопка
  «К сессии» (у MR одна сессия на все намерения). Канал `session:create` принимает намерение `ci` наравне с `review` и `rework`.
- **traced from:** BR-11003.
- **источник:** код `mrPrompt`, `StatusHub.mrRow`; D-13.
- **rationale:** reason - реагировать на красный пайплайн одним действием; assumptions - D-05, D-13; relationships - FR-11004, фича
  `02-mr-view`; design constraints - первое сообщение строится из проверенной ссылки MR.
- **verification:** испытание - `test/jira.test.ts` («намерение ci»: промпт, `session:create`, прочие намерения прежние); демонстрация - кнопки
  «Разобрать пайплайн», «Доработать», «Ревью» на стенде.
- **класс:** Functions. **origin:** source.

### FR-11010 Только чтение и безопасность аргументов

- **Требование:** Cyborg вызывает `jira` только командами `version`, `me`, `issue list`, `issue view`, `open --no-browser`, аргументами
  массива (без оболочки), и ничего не пишет в Jira. Конфиг и токен `jira-cli` не читаются и не передаются. Ключ задачи в вызовах и в
  `session:create` - по форме `^[A-Z][A-Z0-9_]*-\d+$`, ключ проекта - `^[A-Za-z][A-Za-z0-9_]*$`; детали, адрес и старт принимают ключ только
  из последнего списка проекта (старт - по форме). Чужой текст (названия, описание, комментарии, ошибки) очищен от цветовых и управляющих
  кодов и рисуется через `textContent`; ответ `jira` ограничен по времени (120 с) и размеру (64 МБ, как у `gh` и `glab`). Адрес для
  браузера - только `http` и `https`.
- **traced from:** BR-11002.
- **источник:** код `createCliRunner`, `JiraService`, `KEY_RE`, `clean`; ADR-0013, п.1-4; D-02, D-03.
- **rationale:** reason - не дать ключу, названию или ответу сервера стать командой, кодом терминала или схемой URL; assumptions - D-02;
  relationships - FR-11006, FR-11008, ADR-0002 (рендерер не доверяет); design constraints - ADR-0013, п.3-4.
- **verification:** испытание - `test/jira.test.ts` (форма ключей: `--raw`, `DEX-1; ls`, перевод строки отклонены; чужой ключ до `jira` не
  доходит; адрес `file:` и `javascript:` отклонён; очистка управляющих кодов), `test/static-guards.test.ts` (нет `innerHTML`); осмотр - список
  вызовов в `src/main/jira.ts` (`jiraListArgs`, `jiraViewArgs`, `jiraOpenArgs`).
- **класс:** Security. **origin:** source.

### FR-11011 Отказы `jira-cli` и защита учётной записи

- **Требование:** нет бинаря `jira` - «jira-cli не установлен: brew tap ankitpokhrel/jira-cli && brew install jira-cli»; нет настройки -
  причина и «jira init»; вход не принят - причина и подсказка про `JIRA_API_TOKEN`; прочий отказ, таймаут, переполнение вывода и ответ не
  в JSON - своя причина одной строкой, без падения интерфейса. После отказа входа запросы списка по таймеру и открытию карточки не
  выполняются (`jira` не вызывается), пока человек не нажал «Обновить»; проверка входа в диалоге проекта успешным ответом снимает остановку.
  Пустая выборка («No result found») - не ошибка. Отказ не по входу опрос не останавливает.
- **traced from:** BR-11002.
- **источник:** код `JiraService`, `problemOf`, `problemText`; D-12.
- **rationale:** reason - сервер, видящий неверные учётные данные раз в 5 минут, блокирует учётную запись; assumptions - D-12; relationships -
  FR-11003, FR-11001; design constraints - ADR-0013, п.5.
- **verification:** испытание - `test/jira.test.ts` («Jira: отказы jira-cli», «Jira: сервис»: нет бинаря, таймаут, переполнение, не JSON,
  отказ входа - один вызов за серию опросов и повтор после recheck, отказ не по входу не блокирует, пустая выборка, проверка входа).
- **класс:** Reliability. **origin:** source.
