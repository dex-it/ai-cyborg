# BRD фичи 11 - кнопка «Статус»: GitHub, GitLab и Jira в одной карточке

Источник: запрос владельца в чате (2026-10-26): «кнопка как в Discord: нажимаешь, а там статус из GitLab/GitHub и Jira, можно смотреть
задачу в Jira, статус, реагировать агентом как-то; продумать». Решения, принятые составителем за владельца, - `decision-log.md`
(исход «открыто»). Фича идёт после `01-tasks-panel` и `02-mr-view` и опирается на их источники, выборку MR и старт сессии.

## 1. BRS overview

Состояние работы по проекту разработчик узнаёт обходом трёх мест: CI и замечания - в MR/PR на GitHub или GitLab, задачи - в Jira.
Фича даёт кнопку «Статус» в полосе сессий: индикатор называет худшее состояние проекта, карточка по нажатию перечисляет задачи Jira
на разработчике, его MR/PR с упавшим пайплайном либо замечаниями и MR на его ревью, раскрывает детали задачи Jira и по слову
разработчика запускает сессию Claude Code. Адресована владельцу продукта и составителям SRS и архитектуры.

## 2. Business purpose

Дать разработчику ответ «что у меня горит» без выхода из Cyborg и сократить путь от красного пайплайна, замечаний или задачи до сессии,
которая их разбирает, до одного действия, не нарушая нативность сессии (BR-001) и не давая Cyborg права писать в трекеры и Jira.

## 3. Business scope

Внутри границы: кнопка «Статус» в полосе сессий проекта с индикатором и счётчиком; карточка со списком открытых задач Jira на
разработчике (статус, связанные MR и их пайплайн), детали задачи Jira (описание, поля, последние комментарии) и открытие её в
браузере; списки «Мои MR/PR» и «Ждут моего ревью» с пайплайном, апрувами и причиной внимания; действия «Начать» (по задаче Jira),
«Разобрать пайплайн», «Доработать» и «Ревью», запускающие сессию; настройка Jira проекта (включение, выбор проектов Jira из списка, подсказки по веткам) и проверка входа
`jira-cli` в свойствах проекта; обновление при выборе проекта, открытии карточки, по кнопке и по таймеру.

`non-goals`:

- запись в Jira и трекеры: смена статуса, назначение, комментарий, «взять в работу», «сдать» (BRD продукта, non-goals; D-03);
- автоматический запуск сессии по событию (упал пайплайн, назначена задача): сессию запускает только слово разработчика (D-05);
- Jira в панели «Задачи» и как вид трекера задач (D-04);
- собственный JQL, задачи чужих исполнителей, спринты и доски (D-07);
- хранение токена и чтение конфига `jira-cli` (D-02);
- уведомления вне окна (тосты ОС, звук) и история изменений Jira.

## 7. Mission, goals and objectives

### BR-11001 Сводка статуса проекта в одной карточке

- **Требование:** разработчик видит у проекта кнопку «Статус» с индикатором худшего состояния (упал пайплайн своего MR, замечания
  либо ревью ждут его, пайплайны идут, всё спокойно, данных нет) и счётчиком записей, требующих внимания; по нажатию - карточку с
  задачами Jira на нём, его открытыми MR/PR и MR на его ревью; данные обновляются при выборе проекта, открытии карточки, по кнопке
  и по таймеру, пока окно на виду; недоступный источник назван в карточке с причиной, остальные показываются.
- **traced from:** BR-005.
- **rationale:**
  - reason: CI, замечания и задачи проверяются обходом трёх сайтов;
  - assumptions: проект ведёт MR в GitHub либо GitLab, задачи - в Jira, разработчик залогинен в нужные CLI (D-01, D-06);
  - relationships: сценарий 10 BRD продукта; ADR-0013; фичи `01-tasks-panel`, `02-mr-view` (источники и выборка MR);
  - design constraints: источники кода - те же, что у вкладки «MR/PR» (D-04); Jira - через `jira-cli` (D-02).
- **MOE:** индикатор после обновления отражает худшее состояние MR/PR проекта, карточка показывает записи, из-за которых он такой,
  и называет недоступные источники (качественная).

### BR-11002 Задачи Jira на разработчике и их детали в Cyborg

- **Требование:** разработчик видит открытые задачи Jira, назначенные на него, по статусу («В работе» и остальные) и со связанными
  MR; раскрывает детали задачи (поля, описание, последние комментарии) и открывает её в браузере; Cyborg в Jira ничего не пишет.
- **traced from:** BR-005.
- **rationale:**
  - reason: описание и комментарии задачи читаются в браузере и пересказываются сессии руками;
  - assumptions: в Jira задача и MR связаны ключом в названии либо ветке MR (D-08);
  - relationships: сценарий 10; ADR-0013;
  - design constraints: чтение только через `jira-cli` (D-02, D-03); запрос фиксирован (D-07).
- **MOE:** в карточке видны мои открытые задачи Jira с деталями, без записи в Jira (качественная).

### BR-11003 Реакция агента по слову разработчика

- **Требование:** по записи карточки разработчик одним действием запускает сессию Claude Code: по задаче Jira - прочитать её и
  предложить план, по своему MR с упавшим пайплайном - разобрать падение, с замечаниями - доработать, по чужому MR - ревью;
  повторное действие возвращает к уже открытой сессии записи; без действия разработчика Cyborg сессию не запускает.
- **traced from:** BR-005.
- **rationale:**
  - reason: от красного сигнала до сессии, которая его разбирает, сегодня несколько ручных шагов;
  - assumptions: человек остаётся в петле (D-05); первое сообщение сессии строит Cyborg из проверенной ссылки либо ключа (D-09);
  - relationships: BR-004; сценарий 10; фича `02-mr-view` (действия «Ревью» и «Доработать»);
  - design constraints: нативность сессии (BR-001); первое сообщение не несёт названия и описания записи.
- **MOE:** по каждой записи карточки есть действие, и сессия получает первым сообщением ссылку либо ключ записи без ручного ввода
  (качественная).
