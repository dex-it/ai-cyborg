# decision-log фичи 11 - кнопка «Статус»

Решения и допущения по запросу владельца (2026-10-26: «кнопка как в Discord: статус из GitLab/GitHub и Jira, смотреть задачу в Jira,
реагировать агентом, продумать»). Исход «открыто» - допущение составителя, принятое за владельца («Делай качественно и как хотел бы
автор доков, если спорно, продумай, как лучше для наших целей»); подтверждает либо меняет владелец продукта.

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | Кнопка «Статус» в полосе сессий с индикатором и счётчиком; по нажатию - карточка поверх окна (закрывается кликом снаружи и Escape), не вкладка и не панель | вкладка панели рядом с «Задачи»: занимает рабочую область, а сводку надо видеть мельком; раздел боковой колонки: колонка занята деревом | запрос владельца («кнопка как в Discord, нажимаешь - там статус»); прогон на стенде | принято |
| D-02 | Jira читается только через `jira-cli` (`jira me`, `jira issue list/view`, `jira open --no-browser`), как мод dex-jira-tracker; Cyborg не читает конфиг и токен и не хранит их | REST Jira напрямую: свой секрет в Cyborg и второй способ входа; MCP Atlassian: у Cyborg нет клиента модели | ADR-0013, п.1-2; мод dex-jira-tracker; ADR-0007 (трекеры через CLI) | открыто |
| D-03 | Cyborg читает Jira и не пишет: смена статуса, назначение, комментарий, «взять в работу» остаются сессии и её инструментам | кнопки записи как у мода (`/jira work`): запись в Jira вне границы продукта | BRD продукта, non-goals («запись в трекер задач»); запрос владельца называет «смотреть задачу, статус» | открыто |
| D-04 | Jira - отдельный модуль со своими каналами `jira:*`; `TrackerKind`, панели «Задачи» и «MR/PR» не меняются; Jira включается полем проекта `jira`, не флагом `trackers` | Jira третьим видом трекера: ссылки задач (хост, путь, номер), ключи и фильтры панелей перестраивались бы целиком | форма данных `jira-cli` (ключ `ABC-12`, проект) не ложится в `TaskRef`; код `trackers.ts` | открыто |
| D-05 | Реакция агента - кнопка в строке записи, сессию запускает человек; автоматического запуска по событиям нет | автозапуск сессии при падении пайплайна или назначении задачи: агент без слова человека правил бы репозиторий | BRD продукта, BR-001 и non-goals; запрос владельца («как-то реагировать агентом, продумать») | открыто |
| D-06 | Данные обновляются при выборе проекта, при открытии карточки (если старше минуты), по «Обновить» и по таймеру раз в 5 минут, пока окно на виду; это отменяет для сводки «без фонового опроса» вида MR/PR (brief п.5) | только по нажатию: индикатор без данных бесполезен; период короче: нагрузка на `gh`, `glab`, `jira` и лимиты их серверов | сценарий 10 BRD продукта; ADR-0013, п.6 | открыто |
| D-07 | Запрос Jira фиксирован: открытые задачи на мне (`assignee = currentUser() AND statusCategory != Done`), 50 свежих; проект - по ключу в свойствах проекта, пусто - проект из `jira init` | произвольный JQL в настройках: ломкая настройка (jira-cli дописывает свой ORDER BY); задачи всего проекта: сводка «что у меня» тонет | мод dex-jira-tracker (`scope.ts`); ADR-0013, п.1 | открыто |
| D-08 | Задача Jira связывается с MR/PR по ключу в названии либо ветке MR (целое слово, регистр не важен): рядом с задачей видны номер MR и его пайплайн, репозиторий сессии берётся у MR | связь по ссылке в описании MR: нужны детали MR; связь по dev-панели Jira: через `jira-cli` недоступна | практика веток `DEX-12-fix`; код `mrsOfIssue` | открыто |
| D-09 | Первое сообщение сессии по задаче Jira строится в главном процессе из ключа: прочитать задачу (`jira issue view`), разобраться и предложить план, код не править до подтверждения; название и описание в него не попадают | промпт с текстом задачи: чужой текст в первом сообщении; вызов `/jira work` мода: запись в Jira и зависимость от плагина | ADR-0003 (начальный промпт), D-03; код `jiraPrompt` | открыто |
| D-10 | Индикатор и счётчик считаются по MR/PR: упал пайплайн своего открытого MR - красный, замечания либо ревью - янтарный, пайплайн идёт - синий, спокойно - зелёный, нет данных - серый; Jira в уровень не входит | учёт задач Jira: по списку не видно ни событий, ни сроков - «внимание» было бы выдумкой | код `levelOf`, `attentionOf` | открыто |
| D-11 | Формы ответов `jira-cli` (`--raw` списка и просмотра) взяты из мода dex-jira-tracker (jira-cli 1.7.0, Jira Server 9.2) и подставного `jira` в тестах; живой вход Cyborg в Jira не проверялся (Cloud и Data Center - тем более) | отложить фичу до проверки на живой Jira: у составителя нет доступа | `test/jira.test.ts`; `scripts/smoke.mjs` | открыто |
| D-12 | Отказ входа (`jira-cli` не вошёл) останавливает опрос по таймеру и повторные запросы до «Обновить»: сервер, снова и снова видящий неверные учётные данные, блокирует учётную запись | повторять запрос по таймеру: капча и блокировка учётной записи Jira Server | мод dex-jira-tracker (`backend.ts`, `JiraAuthError`); `test/jira.test.ts` | открыто |
| D-13 | У MR три намерения сессии: ревью (чужой), доработка (свой с замечаниями), разбор упавшего пайплайна (свой; `ci`) | разбор пайплайна как «Доработать»: промпт про замечания к пайплайну не подходит | `mrPrompt`; сценарий 10 | открыто |
