# decision-log фичи 04 - дерево файлов сессии

Решения и допущения прогона цели `tree-expand-independent` (2026-10-24). Исход «открыто» - допущение, принятое за
постановщика без оператора; подтверждает либо меняет владелец продукта.

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | Клик по каталогу меняет раскрытие только его; соседние, вложенные и одноимённые в других корнях каталоги остаются как были; раскрытие вложенных каталогов переживает сворачивание родителя | раскрытие, общее для одноимённых каталогов | формулировка оператора; ответ оператора на уточнение «клик раскрывает все» - описание симптома; цель, критерии 1-2 | принято |
| D-02 | Когда рабочий каталог сессии ушёл в другой репозиторий проекта, свой корень дерева - этот репозиторий, а стартовый репозиторий сессии остаётся прочим корнем; у worktree стартового репозитория корни прежние | фильтр прочих корней «не стартовый и не свой корень»: прячет стартовый репозиторий, хотя сессия в нём запущена | прогон, выбор из двух фильтров диагноза | открыто: показывать ли стартовый репозиторий после ухода рабочего каталога |
| D-03 | Путь корня в дереве не повторяется дважды на двух уровнях: построение корней не даёт повтора, и дерево при установке корней отбрасывает повторный путь, оставляя первый (свой корень) | только правка построения корней: дерево делит состояние корней по пути и остаётся беззащитным перед любым другим источником повтора | прогон, диагноз (состояние корня хранится по пути, `src/renderer/tree.ts:44-46`) | принято |
| D-04 | Корень, куда ушёл рабочий каталог (другой репозиторий проекта), подписан своим именем и подсказкой «другой репозиторий проекта, куда перешёл рабочий каталог сессии»; стартовый репозиторий среди прочих - подсказкой «репозиторий, где сессия была запущена»; та же подпись идёт во вкладку сессии | подпись «стартовый ⎇ корень» и подсказка «worktree репозитория …»: корень - отдельный репозиторий, не worktree; подсказка «доступен сессии через --add-dir» для стартового репозитория: он каталог запуска, через `--add-dir` не передаётся | прогон, находка ревью F2 | принято |
| D-05 | Строка дерева с фокусом клавиатуры переживает перерисовку: фокус возвращается на строку с тем же путём (корень плюс относительный путь), иначе на ближайшего родителя, иначе на первую; в порядке табуляции одна строка (выбранный файл, иначе первая); `Enter` и пробел нажимают строку как клик; `aria-selected` стоит у всех файлов (`true`/`false`), у каталогов его нет; в строках без `role=group` уровень задаёт `aria-level` | вложенные `role=group` (дерево плоское, `aria-level` достаточно); фокус на контейнере с `aria-activedescendant` (строки пересоздаются, ссылка на id рвётся); `aria-selected` только у выбранного | осмотр интерфейса 2026-10-28; практика WAI-ARIA tree | открыто: владелец продукта подтверждает набор клавиш и то, что кнопка ветки остаётся в табуляции отдельной остановкой |
| D-06 | Опрос git status номера отрисовки не занимает (берёт текущий), отрисовка клика занимает новый: опрос, начатый после клика, ответом «не изменилось» отрисовку клика не отменяет | один общий счётчик, как было: опрос вытеснял клик и сам возвращал пустой ответ; блокировать опрос на время отрисовки клика: опрос между кликами пропускался бы, правки вне хуков подхватывались бы позже | находка при проверке FR-4006; FR-4007 | открыто |
| D-07 | Ускорение обновления дерева ограничено безопасным: статус и ветка корня запрашиваются одновременно, в проверке фильтров конфиг и индекс читаются параллельно, опрос раз в 3 с не запускается, пока предыдущий не закончил (зависший старше 30 с не блокирует). Замер до: `gitStatus` 112-130 мс (5 процессов git) плюс ветка 18 мс последовательно, 129-143 мс на корень; после: 77-80 мс на корень, процессов 6 как раньше; в собранном приложении (вызовы `gitStatus` и `gitBranch` через IPC, медиана 7) 139 мс до и 77 мс после. Кэша проверок по mtime конфигов нет | кэш результата `repoFilterKeys` по mtime конфигов: основной выигрыш даёт параллельность, а кэш мог бы пережить смену конфига вложенного репозитория; распараллеливание `listDir` раскрытых каталогов: 40 каталогов читаются за 5 мс, не узкое место; общий на главный процесс запрос `git status` одного корня: клик после правки получил бы статус, начатый до неё | замер 2026-10-28 на репозитории из 5003 файлов с одним заполненным подмодулем (macOS, git 2.50, медиана 7 прогонов); NFR-4001 | открыто: владелец подтверждает, что дальнейшее снижение числа процессов git (кэш проверок) не нужно |
