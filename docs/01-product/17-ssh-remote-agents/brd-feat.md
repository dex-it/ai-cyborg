# BRD фичи 17 - удалённые сессии Claude Code по SSH: человек и оркестратор ведут агентов на серверах

Источник: цель `ssh-remote-agents` (2026-11-09): «Cyborg запускает сессии Claude Code на серверах разработчика по SSH и ведёт их жизненный цикл - создание с заданием, живой терминал, явный итог агента, закрытие с уборкой места на хосте - для человека из интерфейса и для сессии-оркестратора через MCP-инструменты, и удалённая сессия переживает обрыв связи и выход Cyborg». Источник требований выше цели оператор не назвал. Решения проектирования - `decision-log.md`, исход «принято проектировщиком» либо «принято составителем» до подтверждения владельцем.

## 1. BRS overview

Разработчик держит длинную работу и параллельных агентов Claude Code на серверах, а следить за ними, принимать итог и убирать за ними приходится вне Cyborg. Фича даёт запуск сессии на хосте SSH из окна Cyborg (терминал, дерево, статус, просмотр файлов, уведомления), три инструмента MCP для оркестратора (`spawn_agent`, `report_done`, `close_agent`) и жизнь удалённой сессии независимо от канала и окна. Адресована владельцу продукта и составителям SRS.

## 2. Business purpose

Разработчик и сессия-оркестратор отдают работу агентам на серверах и получают итог без ручного захода на хост; место на хосте остаётся чистым, а несохранённая работа агента не пропадает.

## 3. Business scope

Внутри границы: хосты SSH в свойствах проекта; запуск на хосте стрелкой у «Новой сессии» (ручная сессия открывается как локальная, без задания, D-32, D-33); вкладка удалённой сессии со значком и плашкой хоста; проверка хоста и установка агента Cyborg в `~/.cyborg`; клоны всех репозиториев проекта на хосте; сессия `claude` в pty на хосте со вкладкой в Cyborg; переподключение и подхват после выхода Cyborg; дерево, статус и просмотр файлов клонов без правки; обратный туннель к MCP-серверу Cyborg с токеном сессии; инструменты `spawn_agent`, `report_done`, `close_agent`; продолжение сессии после итога; лимиты хоста; закрытие с уборкой клонов; сон простаивающей сессии и пробуждение из «Истории»; место на хосте; доступы git и вход Claude агента токенами машины разработчика; зеркало настройки Claude на хосте; поиск по клонам (этап 2, D-21..D-31).

`non-goals`:

- установка на хосте чего-либо, кроме агента Cyborg в `~/.cyborg`, зеркала настройки Claude и её плагинов (D-27); `node`, `git`, `claude` и `script` на хосте - работа разработчика (проверка хоста называет нехватку), вход в `claude` и ключи git - тоже, если на машине Cyborg нет токена Claude или токена `gh`/`glab` (D-25, D-26);
- правка файлов и смена ветки клонов из Cyborg: клон принадлежит агенту (D-12);
- пробуждение спящих сессий оркестратором и возврат памяти агента с хоста (D-22, D-27);
- изоляция людей на одной учётной записи хоста: её дают контейнер или виртуальная машина (D-24);
- пароль или фраза ключа в окне Cyborg: вход по ключу из `ssh-agent` и `~/.ssh/config` (D-01);
- порождение агентов удалённой сессией: `spawn_agent` и `close_agent` у неё недоступны (D-11);
- лимиты и таймеры для сессий человека: их не обрывает ни простой, ни срок задачи (D-09);
- изменение соседства сессий проекта и локальных сессий: набор каталогов вкладки - локальные каталоги проекта (D-04, ADR-0019 п.3).

## 7. Mission, goals and objectives

### BR-17001 Сессии на серверах ведутся из Cyborg, оркестратор раздаёт им работу и получает итог

- **Требование:** разработчик из окна Cyborg запускает на хосте SSH сессию Claude Code с заданием и веткой, видит её терминал, изменения и файлы клонов, получает уведомление об итоге и закрывает её с уборкой клонов; сессия-оркестратор с подтверждения разработчика порождает на хосте агентов, получает их итог сообщением и закрывает их; удалённая сессия переживает обрыв связи и выход Cyborg.
- **traced from:** BR-010.
- **rationale:**
  - reason: параллельные сессии проекта уже есть локально (BR-001, BR-009), но длинную работу разработчик держит на серверах;
  - assumptions: хост готов (раздел 6); клоны берутся из `origin` локальных репозиториев (D-04);
  - relationships: BR-010 BRD продукта, BR-001, BR-009 (фича `15-session-mcp`), ADR-0020, ADR-0019, ADR-0003;
  - design constraints: сессия остаётся нативной (BR-001): `claude` в pty на хосте; подтверждение вызовов - запросом разрешения Claude Code (D-11).
- **MOE:** разработчик запускает сессию на хосте, закрывает окно Cyborg, возвращается и находит её вкладкой; оркестратор получает итог порождённого агента сообщением, а клон с незапушенной работой остаётся на хосте с названным путём (качественная).

## 12. Business operational constraints

Хост видит MCP-сервер Cyborg только обратным туннелем `ssh`, порт на `127.0.0.1` Cyborg наружу не открывается (D-06). Хост без `node` 18+, `git`, `claude` или `script`, а также без входа `claude`, когда токен Claude в Cyborg не задан, сессию не запускает (D-01, D-26). Токены хостингов и Claude на диск хоста не пишутся (D-25, D-26).
