# decision-log фичи 17 - удалённые сессии Claude Code по SSH

Решения по цели `ssh-remote-agents` (2026-11-09): «Cyborg запускает сессии Claude Code на серверах разработчика по SSH и ведёт их жизненный цикл - создание с заданием, живой терминал, явный итог агента, закрытие с уборкой места на хосте - для человека из интерфейса и для сессии-оркестратора через MCP-инструменты, и удалённая сессия переживает обрыв связи и выход Cyborg». Источник требований выше цели оператор не назвал; решения, названные в цели и в проектировании, - исход «принято проектировщиком», выведенные составителем из кода правки - «принято составителем», до подтверждения владельцем.

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | Хост - алиас из `~/.ssh/config`, список алиасов лежит в поле `hosts` проекта (до 16, имя из `[A-Za-z0-9._-]`, без ведущего «-»); Cyborg запускает системный `ssh` без оболочки (`spawn` с массивом аргументов) и без запроса пароля; отказ `ssh` называется причиной | библиотека SSH на Node; пароль и фраза в окне Cyborg; адрес и порт в поле проекта | параметры, ключи и ProxyJump разработчик уже держит в `~/.ssh/config`; новых npm-зависимостей нет; ведущий «-» ssh принял бы за ключ | принято проектировщиком |
| D-02 | На хосте работает долгоживущий демон: бандл `dist/agentd.js` (Node 18+) ставится в `~/.cyborg/agentd/<первые 16 hex sha256>/` скриптом, который уходит в `sh -s` по `ssh`, с проверкой суммы до переименования; сокет демона `~/.cyborg/run/agentd.sock` под замком, мост `connect.sh` соединяет stdio `ssh` с сокетом и поднимает демона, если его нет; демон выходит после 10 мин без сессий и клиентов | `tmux`/`screen` на хосте; `claude` напрямую под `ssh -tt`; установка пакетом | сессия должна жить без канала, а `script` даёт `claude` pty без `tmux`; версия по сумме не путает старый и новый файл | принято проектировщиком |
| D-03 | Протокол демона - строки JSON по каналу, версия `PROTO` в `hello`; демон другой версии без сессий останавливается (`shutdown`) и заменяется новым, с сессиями и той же `PROTO` - остаётся как есть, с сессиями и другой `PROTO` - отказ с числом сессий | принудительная остановка старого демона с сессиями | остановка демона оборвала бы работающие сессии | принято составителем |
| D-04 | Клоны всех репозиториев проекта делаются на хосте из `origin` локальных репозиториев; сессия запускается в клоне выбранного репозитория, остальные клоны - `--add-dir`; вкладка Cyborg несёт набор локальных каталогов проекта, поэтому соседство сессий (`sameDirs`) и ADR-0019 п.3 не меняются; репозиторий без `origin` - отказ с путём | клон только выбранного репозитория; перенос рабочего дерева с машины Cyborg | цель требует работы «в границах проекта»; набор каталогов сессии держит её проект (FR-15006) | принято проектировщиком |
| D-05 | Ветка: есть на `origin` - `git switch <ветка>`, нет - `git switch -c <ветка>` от HEAD клона; имя проверяется до отправки (`branchNameProblem`) | всегда создавать ветку; произвольная строка | `git` принял бы имя с «-» за ключ; существующую ветку не пересоздают | принято составителем |
| D-06 | MCP-сервер Cyborg виден хосту обратным туннелем сокета `ssh -R <сокет хоста>:127.0.0.1:<порт>`; токен выдаёт Cyborg, демон кладёт его в `mcp.json` 0600 каталога сессии; в `claude` идёт адрес прокси демона на `127.0.0.1` хоста, прокси при живом туннеле пересылает байты в сокет, без Cyborg отвечает на `tools/call` ошибкой инструмента «Cyborg не на связи» (код 200, `isError`), на прочее - 503 | порт Cyborg наружу; токен в аргументе `claude` | порт на `127.0.0.1` Cyborg не покидает машину; командную строку процесса видят все пользователи хоста; `report_done` без связи не должен молча пропасть | принято проектировщиком |
| D-07 | Состояние удалённой сессии ведётся теми же хуками, что у локальной: `settings.json` на хосте пишет события в `events.jsonl`, демон читает их по росту файла и шлёт строки со смещением; при подхвате прошлые события догоняются без уведомлений, кроме последнего | разбор вывода терминала; уведомление по каждому событию догона | вывод терминала ADR-0003 отверг; устаревший `asking` не должен будить человека | принято проектировщиком |
| D-08 | Обрыв: вкладка помечена «нет связи», Cyborg переподключается с паузами 1, 2, 4, 8, 16, 32, 60 с, пока есть удалённые сессии; после подключения вывод и события берутся с отметок; отметка старше кольца вывода (1 МиБ) - сброс терминала и хвост кольца. Экземпляр Cyborg назван идентификатором: сессию, которую держит другое окно, не подхватывают | подхват чужих сессий; бесконечный частый повтор | два окна не должны писать в один терминал | принято проектировщиком |
| D-09 | Лимиты хоста: не более 4 живых сессий (сессии человека считаются), задача агента - 240 мин, простой в `working` - 30 мин; таймеры только у сессий `spawn_agent` до `report_done`; `limits` в `spawn_agent` меняет их в диапазонах 1-16, 1-1440, 1-1440; превышение закрывает вкладку и отдаёт вызвавшей итог `failed` с причиной | лимиты на стороне Cyborg; лимиты для сессий человека | демон работает без Cyborg, поэтому лимит держит он; человека таймер не обрывает | принято проектировщиком |
| D-10 | Закрытие убирает клон, у которого нет изменений в дереве, неотправленных коммитов, неотслеживаемых файлов и stash; остальные остаются, ответ называет путь и причину, окно Cyborg показывает отказ уборки; `keep` оставляет все клоны без проверки. Естественный выход `claude` равен закрытию без `keep` | удалять клоны безусловно; не убирать ничего | незапушенная работа агента не должна пропасть; без уборки хост зарастает клонами | принято проектировщиком |
| D-11 | Инструменты: `spawn_agent(host, repo, branch, prompt, limits?, keep?)` и `close_agent(id, keep?)` - у локальной сессии проекта с хостами, `report_done(status, summary, branch?, pr?)` - у удалённой; `report_done` принимается один раз; вкладка агента без `keep` закрывается через секунду после итога; удалённой сессии `spawn_agent` и `close_agent` недоступны, даже если имя известно | порождение агентов удалённой сессией; итог по завершению процесса | итог - явное решение агента, а не код выхода; рекурсия агентов выходит за лимиты | принято проектировщиком |
| D-12 | Дерево, статус, ветка, чтение файла и сравнение с HEAD удалённой сессии - запросы `fs` к демону, который выполняет только чтение внутри каталога клонов сессии (путь разрешается через `realpath`, `..` и symlink наружу отвергаются); правки файла и смены ветки у канала нет | общий сетевой диск; перенос файлов в Cyborg | правка и `git switch` над клоном агента ломают его работу; границу каталога держит демон | принято проектировщиком |
| D-13 | Демон сам строит аргументы `claude` для сессии (`claudeArgs` с системным промптом удалённой сессии `REMOTE_SYSTEM_PROMPT`), а не получает их от Cyborg: пути клонов на хосте знает только он. Отступление от «аргументы строит Cyborg» (ADR-0003 п.2) | аргументы, собранные Cyborg по предполагаемым путям | пути клонов выбирает демон (`work/<сессия>/<имя>`) | принято составителем |
| D-14 | Удалённая сессия не входит в `liveDirs`, `uses`, `count` и `killAll` локального менеджера: закрытие окна и смена воркспейса не завершают их; вкладка закрывается крестиком с подтверждением и при живой связи; без связи закрыть нельзя, окно называет причину | завершать удалённые вместе с окном | цель требует, чтобы сессия переживала выход Cyborg | принято проектировщиком |
