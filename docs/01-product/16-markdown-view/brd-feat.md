# BRD фичи 16 - Markdown в просмотрщике: документ отрендерен, исходник правится по кнопке

Источник: запрос владельца (2026-11-08): «просмотрщик файлов - можем рендерить мд файл а редактировать по отдельной кнопке?»; решения оператора о правке внутри Cyborg и о зависимостях - D-01, D-05, D-06. Решения составителя - `decision-log.md`, исход «принято составителем» до подтверждения владельцем.

## 1. BRS overview

Документацию репозитория (README, корпус требований, заметки) разработчик читает в Cyborg исходником Markdown, а поправить её может только в сессии или во внешнем редакторе. Фича показывает Markdown отрендеренным документом и по кнопке «Править» открывает исходник в редакторе с сохранением в файл. Адресована владельцу продукта и составителям SRS.

## 2. Business purpose

Разработчик читает документ репозитория в виде, в котором его прочтут другие, и правит в нём фразу или ссылку, не уходя из рабочего места и не отдавая мелкую правку сессии.

## 3. Business scope

Внутри границы: рендер файлов `.md` и `.markdown` в просмотрщике (вкладка сессии и просмотр без сессии); переключение изменённого против HEAD между документом и сравнением; ссылки документа на сайт, на раздел и на файл; правка исходника по кнопке и сохранение в тот же файл; вопрос, когда файл изменён на диске после начала правки; защита несохранённой правки при закрытии вкладки, окна и смене воркспейса.

`non-goals`:

- правка файлов, кроме Markdown: код и прочие файлы просмотрщик только читает (D-02);
- создание, переименование и удаление файлов (D-04);
- загрузка картинок и прочего содержимого из сети при рендере (D-07);
- предпросмотр рядом с исходником во время правки: правка и просмотр сменяют друг друга.

## 7. Mission, goals and objectives

### BR-16001 Markdown читается документом и правится в Cyborg, не затирая чужую правку

- **Требование:** разработчик открывает Markdown-файл из дерева, поиска или ссылки другого документа и читает его отрендеренным: заголовки, списки, таблицы, код, картинки из репозитория; изменённый против HEAD переключает на сравнение с HEAD и обратно; ссылки ведут на сайт, раздел или файл. По кнопке «Править» он правит исходник и сохраняет его в тот же файл; если файл изменён на диске после начала правки, Cyborg не перезаписывает его без вопроса, а несохранённая правка не теряется молча ни при закрытии вкладки, ни при закрытии окна.
- **traced from:** BR-003.
- **rationale:**
  - reason: документацию репозитория читают отрендеренной, а мелкая правка в ней не стоит отдельной сессии или внешнего редактора;
  - assumptions: файл Markdown одновременно с разработчиком может менять сессия Claude Code (D-05);
  - relationships: BR-003 и сценарий 2 раздела 17 BRD продукта, BR-007 (переход к строке из поиска), фича `13-file-search`, ADR-0002;
  - design constraints: документ из репозитория - недоверенные данные, интерфейс изолирован (ADR-0002): рендер без скриптов и сети (D-07), запись - отдельным каналом с проверкой пути в главном процессе (D-03).
- **MOE:** Markdown-файл открывается документом; правка, сохранённая из Cyborg, оказывается в файле на диске; файл, изменённый сессией во время правки, без согласия разработчика не перезаписан (качественная).
