# SRS фичи 16 - Markdown в просмотрщике: рендер и правка по кнопке

## 1. SRS overview

Требования к показу Markdown-файла отрендеренным документом, к ссылкам и картинкам документа, к правке исходника по кнопке и её сохранению, к каналу записи `fs:write`, к конфликту с диском и к защите несохранённой правки. Вход - BRD фичи (`brd-feat.md`, BR-16001), запрос владельца 2026-11-08, код `src/renderer/markdown.ts`, `src/renderer/md-links.ts`, `src/renderer/md-viewer.ts`, `src/renderer/app.ts`, `src/main/files.ts`, `src/main/allowed-paths.ts`, `src/main/main.ts`, `src/main/preload.ts`. Основания решений - `decision-log.md` (D-NN).

## 2. Purpose

Задать наблюдаемое поведение рендера и правки так, чтобы правка проверялась по требованию, а не по коду.

## 3. Scope

Файлы `.md` и `.markdown` во вкладке сессии и в просмотре без сессии; каналы `fs:write` и `edits:unsaved`. Вне фичи: правка прочих файлов, создание и удаление файлов, содержимое из сети, предпросмотр рядом с исходником (`brd-feat.md`, раздел 3).

## 4. Product perspective

Просмотрщик - часть интерфейса (ADR-0001, ADR-0002); Markdown получает свой вид просмотра рядом с Monaco для прочих файлов. Чтение идёт прежним каналом `fs:read`, запись - новым `fs:write` в главном процессе.

## 5. Product functions

Рендер документа; изоляция документа от окна и сети; ссылки и картинки; правка и сохранение; канал записи; конфликт с диском; защита несохранённой правки.

## 6. User characteristics

`inherited`: BRD продукта, раздел 5.

## 7. Limitations

Рендер - marked (GFM) и DOMPurify в интерфейсе, обе зависимости объявлены в `dependencies` `package.json` (D-06). Правка и файл - до 5 МБ, как у просмотра (`src/main/files.ts`).

## 8. Assumptions and dependencies

Файл может менять сессия Claude Code во время правки (D-05). Допущения D-02..D-04, D-07, D-09..D-11 - решения составителя до подтверждения владельцем.

## 9. Apportioning of requirements

Интерфейс: FR-16001, FR-16002, FR-16003, FR-16005, NFR-16001. Главный процесс: FR-16004. Интерфейс и главный процесс: FR-16006 (интерфейс - вопрос при закрытии вкладки и счётчик несохранённых правок, главный процесс - вопрос при закрытии окна и смене воркспейса).

## 11. External interfaces

### FR-16004 Канал fs:write перезаписывает только существующий Markdown внутри разрешённых каталогов

- **Требование:** канал `fs:write` принимает `{file, content, base, force?}`: `file`, `content`, `base` - строки, `force` - boolean либо нет поля; иначе ошибка «Некорректная запись файла». Путь проходит проверку каналов чтения (FR-1027 фичи 01), затем: файл существует (иначе «Файл не найден»); имя кончается на `.md` либо `.markdown` без учёта регистра и до, и после раскрытия символьных ссылок (иначе «Править можно только Markdown»); раскрытый путь не содержит сегмента `.git` (иначе «В каталог .git писать нельзя»); раскрытый путь лежит внутри раскрытого разрешённого каталога (иначе «Путь вне репозиториев проектов и каталогов сессий»). При отказе к записи главный процесс не обращается. Правка больше 5 МБ - ошибка «Правка больше 5 МБ». Содержимое файла на диске сверяется с `base`: разошлось и `force` не `true` - ответ `{conflict: true}` без записи; иначе файл перезаписывается, ответ `{saved: true}`; ошибка чтения либо записи - `{error}` с причиной.
- **traced from:** BR-16001.
- **источник:** ответ оператора «Править внутри Cyborg» (D-01); D-02, D-03, D-04, D-05.
- **rationale:** reason - интерфейсу не доверяют, а канал записи - самый опасный из его каналов; assumptions - D-05: файл может менять сессия; relationships - FR-1027 фичи 01, FR-16003, FR-16005, ADR-0002 п.3 и п.5; design constraints - символьная ссылка внутри репозитория наружу дала бы запись вне него, поэтому граница записи - по раскрытым путям, в отличие от чтения (D-03).
- **verification:** испытание - `test/allowed-paths.test.ts` («fs:write: только существующий Markdown в физических границах репозитория и вне .git»), `test/write-file.test.ts` («диск совпадает с base - файл перезаписан», «файл изменён на диске после начала правки - конфликт без записи; force перезаписывает», «файла нет - ошибка, файл не создан; правка больше предела - отказ»), `test/static-guards.test.ts` (перечень пишущих файлов).
- **класс:** External interfaces. **origin:** source; сообщения отказов и предел - derived.

## 12. Functions

### FR-16001 Markdown-файл открывается отрендеренным документом

- **Требование:** файл с именем на `.md` либо `.markdown` (без учёта регистра), открытый из дерева, окна поиска или ссылки документа - во вкладке активной сессии либо в просмотре без сессии, - показывается документом Markdown с расширениями GFM: заголовки, списки, таблицы, блоки кода, цитаты, флажки задач (флажки не переключаются). Заголовок получает якорь `md-<slug>`: текст строчными, знаки кроме букв, цифр, `_`, `-` и пробела выброшены, пробелы - `-`, повтор - с суффиксом `-1`, `-2`. Изменённый против HEAD Markdown тоже открывается документом; у него в заголовке файла кнопка «Сравнение» - показывает сравнение с HEAD в одной колонке, только чтение, как у прочих файлов, - а в сравнении кнопка «Документ» возвращает рендер (D-08). Выбранный вид держится, пока вкладка открыта; файл сравнялся с HEAD - показывается документ, кнопки нет. Документ и сравнение перечитываются с диска и HEAD при каждом показе вкладки и раз в 3 с в просмотре без сессии; положение прокрутки документа сохраняется. Файл не прочитан - вместо документа причина, кнопки «Править» нет. В заголовке файла - кнопка «Править» (FR-16003).
- **traced from:** BR-16001.
- **источник:** запрос владельца 2026-11-08 («рендерить мд файл»; «смотреть дифф тоже нужно как было, должен мочь переключить»); D-08.
- **rationale:** reason - документацию читают отрендеренной; assumptions - нет; relationships - FR-16002, FR-16003, FR-13009 фичи 13; design constraints - NFR-16001.
- **verification:** испытание - `test/md-links.test.ts` («якоря как на GitHub: строчные, без знаков, повтор с суффиксом», «Markdown по расширению без учёта регистра»); демонстрация - `scripts/smoke.mjs` («Markdown: рендер без скриптов и картинок из сети, якоря заголовков, ссылка открывает файл», «Markdown: изменённый против HEAD переключается между документом и сравнением»).
- **класс:** Functions. **origin:** source; якоря и перечитывание - derived.

### FR-16002 Ссылки и картинки документа

- **Требование:** щелчок по ссылке документа: `http:` либо `https:` - адрес открывается браузером системы (`url:open`); `#якорь` - документ прокручивается к заголовку с этим якорем; относительный путь - файл от каталога документа, путь с `/` в начале - от корня дерева, к которому относится документ; запрос (`?…`) и якорь отбрасываются, `#L<номер>` - переход к строке; файл открывается там же, где открылся бы файл из дерева (вкладка активной сессии либо просмотр без сессии). Прочие схемы (`javascript:`, `file:`, `mailto:` и любые другие), адрес с `//` в начале и пустая ссылка ничего не делают. Картинка с относительным путём или путём от корня грузится из файла (`file://`), `data:image/…` - как есть; картинка из сети, с адресом `//…` и прочими схемами не грузится и помечена подсказкой «Картинка из сети не загружается». Подсказка ссылки - её адрес.
- **traced from:** BR-16001.
- **источник:** запрос владельца 2026-11-08; D-07.
- **rationale:** reason - документация ссылается на соседние файлы и разделы, и переход по ним должен вести в Cyborg, а не в окно Electron; assumptions - нет; relationships - FR-16001, NFR-16001, FR-10012 фичи 10 (`url:open`); design constraints - окно не переходит по ссылкам внутри себя (ADR-0002 п.5); картинка из сети - пиксель слежения в недоверенном файле (D-07).
- **verification:** испытание - `test/md-links.test.ts` («resolveLink», «imageSource», «.. выше корня останавливается на корне»); демонстрация - `scripts/smoke.mjs` (ссылка на `other.md` открывает его, картинка из сети без `src`, локальная - `file://`).
- **класс:** Functions. **origin:** source; разбор путей и схем - derived.

### FR-16003 Правка исходника по кнопке и сохранение

- **Требование:** кнопка «Править» заменяет документ редактором Monaco с исходником, подсветкой Markdown и переносом строк; фокус - в редакторе. В режиме правки в заголовке файла - метка «не сохранено» (видна, пока текст отличается от сохранённого), кнопка «Сохранить» (доступна, пока есть несохранённая правка) и кнопка «Готово»; вкладка файла с несохранённой правкой помечена. `Ctrl+S` (на macOS `Cmd+S`) в редакторе и «Сохранить» отправляют текст в `fs:write` с содержимым, от которого шла правка (FR-16004); при успехе метка гаснет; ошибка - сообщение с причиной, правка остаётся. Пометка порядка байтов (BOM) файла при сохранении возвращается в начало текста. «Готово» возвращает вид, из которого начата правка, - документ либо сравнение (FR-16001); при несохранённой правке сначала вопрос «Выйти из правки … без сохранения? Правка будет потеряна.», отказ оставляет правку. Переход к строке (из окна поиска, FR-13009 фичи 13, либо ссылкой `#L<номер>`) открывает правку и ставит курсор на эту строку. Пока правка не тронута, показ вкладки перечитывает исходник с диска; несохранённую правку перечитывание не затирает.
- **traced from:** BR-16001.
- **источник:** запрос владельца 2026-11-08 («редактировать по отдельной кнопке»); ответ оператора (D-01); D-09, D-11.
- **rationale:** reason - мелкая правка документа без сессии и внешнего редактора; assumptions - нет; relationships - FR-16004, FR-16005, FR-16006, FR-13009 фичи 13; design constraints - у отрендеренного документа нет строк, поэтому переход к строке открывает исходник (D-09); Monaco отбрасывает BOM, и без возврата сохранение меняло бы файл сверх правки (D-11).
- **verification:** демонстрация - `scripts/smoke.mjs` («Markdown: «Править», ввод, Ctrl/Cmd+S пишет файл на диск»: до ввода метки нет и «Сохранить» недоступна, после ввода - есть и доступна, после `Ctrl/Cmd+S` файл на диске начинается с правки и метка гаснет; «Готово» возвращает документ с правкой).
- **класс:** Functions. **origin:** source; BOM, перечитывание и вопрос «Готово» - derived.

### FR-16005 Файл изменён на диске после начала правки - вопрос, без согласия не перезаписан

- **Требование:** `fs:write` ответил конфликтом (FR-16004) - вопрос «Файл «<имя>» изменён на диске после начала правки. OK - перезаписать его правкой, Отмена - не перезаписывать.»: OK - запись повторяется с `force`, файл получает правку. Отмена - второй вопрос «Перечитать «<имя>» с диска? Правка будет потеряна.»: OK - редактор получает содержимое диска, правка отброшена; Отмена - файл на диске не тронут, правка остаётся несохранённой в редакторе.
- **traced from:** BR-16001.
- **источник:** ответ оператора «конфликт решается вопросом» (D-05).
- **rationale:** reason - файл правит и сессия, и молча затереть её правку нельзя; assumptions - D-05; relationships - FR-16003, FR-16004, FR-16006; design constraints - нет.
- **verification:** демонстрация - `scripts/smoke.mjs` («Markdown: файл изменён на диске - вопрос, без согласия не перезаписан, с согласием перезаписан»); испытание - `test/write-file.test.ts` («файл изменён на диске после начала правки - конфликт без записи; force перезаписывает»).
- **класс:** Functions. **origin:** source; второй вопрос о перечитывании - derived.

### FR-16006 Несохранённая правка не теряется молча

- **Требование:** закрытие вкладки файла, закрытие сессии с этой вкладкой и закрытие просмотра без сессии при несохранённой правке спрашивают «В «<имя>» несохранённая правка. Сохранить её? OK - сохранить, Отмена - отбросить.»: вкладка закрывается в обоих случаях; OK - правка уходит в `fs:write` уже после закрытия, конфликт - вопрос о перезаписи (FR-16005, без второго вопроса), отказ либо ошибка - сообщение «<имя> не сохранён: <причина>». Интерфейс сообщает главному процессу число файлов с несохранённой правкой (`edits:unsaved`); закрытие окна, выход из приложения и смена воркспейса при ненулевом числе сначала спрашивают «Файлов с несохранённой правкой: N» / «Правка будет потеряна.» с кнопками действия и «Отмена» (по умолчанию «Отмена»); отказ отменяет действие, согласие ведёт к прежнему вопросу о работающих сессиях.
- **traced from:** BR-16001.
- **источник:** D-10.
- **rationale:** reason - правку, на которую ушло время, теряют одним нажатием; assumptions - нет; relationships - FR-16003, FR-16005, FR-1033 фичи 01 (смена воркспейса); design constraints - окно закрывает главный процесс, а правки он не видит, поэтому интерфейс сообщает ему счётчик (D-10).
- **verification:** демонстрация - `scripts/smoke.mjs` («Markdown: закрытие с несохранённой правкой спрашивает, отказ её отбрасывает»); осмотр - `src/main/main.ts` (`confirmEndSessions`, канал `edits:unsaved`): автотеста у вопроса при закрытии окна нет.
- **класс:** Functions. **origin:** derived.

## 18. Software system attributes

### NFR-16001 Документ из репозитория не исполняет кода, не грузит сеть и не меняет окно

- **Требование:** классификация данных: содержимое Markdown-файла - недоверенные данные пользователя и сессии, только локально. Разметка документа проходит санитизацию DOMPurify (профиль HTML) до вставки в окно: скрипты, обработчики событий и ссылки `javascript:` удаляются; удаляются элементы `style`, `form`, `button`, `textarea`, `select`, `iframe`, `frame`, `object`, `embed`, `video`, `audio`, `source`, `track`, `picture`, `base`, `link`, `meta` и атрибуты `style`, `id`, `name`, `srcset`, `background`, `poster`, `ping`, `action`, `formaction`. Сеть документ не трогает: картинки - по FR-16002, переход по ссылке - только через `url:open` или открытие файла в Cyborg. Модель авторизации: субъект - интерфейс окна, право записи - канал `fs:write` по FR-16004; рендер права записи не получает.
- **traced from:** BR-16001.
- **источник:** ADR-0002 (интерфейс показывает недоверенные данные); D-07.
- **rationale:** reason - Markdown пропускает сырой HTML, и файл из репозитория, написанный сессией или чужим коммитом, иначе выполнил бы скрипт в окне с доступом к каналам Cyborg; assumptions - нет; relationships - FR-16001, FR-16002, ADR-0002 п.1 и п.5; design constraints - `id` и `name` затеняли бы глобальные имена окна, `style` - вид всего окна (D-07).
- **verification:** демонстрация - `scripts/smoke.mjs` (документ с `<script>` и `<img onerror>`: в документе нет `script` и обработчиков, глобальный признак не выставлен; картинка из сети без `src`); испытание - `test/md-links.test.ts` («прочие схемы, протокол-относительные и пустые ссылки никуда не ведут», «из сети и чужие схемы не грузятся»).
- **класс:** Software system attributes. **origin:** derived.
