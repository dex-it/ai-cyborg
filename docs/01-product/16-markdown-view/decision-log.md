# decision-log фичи 16 - Markdown в просмотрщике: рендер и правка по кнопке

Решения по запросу владельца (2026-11-08): «просмотрщик файлов - можем рендерить мд файл а редактировать по отдельной кнопке?». Ответы оператора на вопросы составителя - исход «принято оператором»; выведенные составителем из кода правки - «принято составителем» до подтверждения владельцем.

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | Markdown правится внутри Cyborg: снимается non-goal BRD продукта «правка файлов в Cyborg» для Markdown | только рендер, правка снаружи кнопкой «Открыть в системе» | ответ оператора «Править внутри Cyborg» (2026-11-08) | принято оператором |
| D-02 | Правится только Markdown - имя на `.md` либо `.markdown` без учёта регистра, и до, и после раскрытия символьных ссылок; прочие файлы просмотрщик только читает | правка любого текстового файла | запрос - о Markdown; правка кода - работа сессии (BR-001); ссылка `x.md` на код иначе открыла бы запись в код | принято составителем |
| D-03 | Граница записи: путь проходит проверку каналов чтения (FR-1027 фичи 01), затем раскрытый путь лежит внутри раскрытого разрешённого каталога и не содержит сегмента `.git` | проверка только по строке пути, как у чтения | символьная ссылка внутри репозитория наружу дала бы запись вне его; в `.git` лежат хуки и конфиг - запись туда равна запуску кода | принято составителем |
| D-04 | Пишется только существующий файл: создания, переименования и удаления нет | «Сохранить как», новый файл по ссылке | запрос - о правке открытого документа; новый файл - поверхность записи без нужды | принято составителем |
| D-05 | Запись сверяет диск с содержимым, от которого шла правка; разошлось - вопрос: перезаписать, перечитать или оставить правку несохранённой | последняя запись побеждает; слияние правок | файл одновременно правит сессия; ответ оператора - конфликт решается вопросом | принято оператором |
| D-06 | Рендер в интерфейсе - marked (GFM) и DOMPurify, обе объявлены в `dependencies` `package.json` | рендер в главном процессе; свой разборщик; зависимость без объявления | DOMPurify работает с DOM окна; ответ оператора «Объявить в package.json» | принято оператором (зависимости), выбор библиотек - принято составителем |
| D-07 | Документ не грузит сеть и не меняет окно: картинки из сети не грузятся и помечены, локальные - `file://` от каталога документа либо корня дерева, `data:image` - как есть; удаляются стили, формы, фреймы, медиа, `base`, `link`, `meta`, атрибуты `id`, `name`, `srcset` и подобные | картинки из сети; санитизация профилем DOMPurify без дополнительных запретов | картинка из сети в недоверенном файле - пиксель слежения; `id` и `name` затеняют глобальные имена окна, `style` меняет вид всего окна | принято составителем |
| D-08 | Изменённый против HEAD Markdown открывается рендером; кнопка «Сравнение» переключает на сравнение с HEAD (то же, что у прочих файлов), «Документ» - обратно; вид держится, пока открыта вкладка, «Готово» правки возвращает его | только рендер, без сравнения (первая редакция); изменённый Markdown сразу сравнением | ответ владельца (2026-11-08): «смотреть дифф тоже нужно как было, должен мочь переключить»; рендер - смысл запроса, поэтому вид по умолчанию | принято оператором |
| D-09 | Переход к строке (окно поиска, ссылка `#L<номер>`) открывает правку и ставит курсор на строку | переход к ближайшему заголовку документа; переход без строки | у отрендеренного документа нет строк исходника | принято составителем |
| D-10 | Закрытие вкладки с несохранённой правкой спрашивает «Сохранить?», запись уходит после закрытия; закрытие окна, выход и смена воркспейса спрашивают в главном процессе по счётчику, который сообщает интерфейс (`edits:unsaved`) | закрытие вкладки ждёт конца записи; правка теряется молча | вкладка закрывается сразу и не ждёт ответа канала; окно закрывает главный процесс, а правок он не видит | принято составителем |
| D-11 | Пометка порядка байтов (BOM) файла при сохранении возвращается в начало текста | сохранять текст редактора как есть | Monaco отбрасывает BOM, и без возврата сохранение меняло бы файл сверх правки | принято составителем |
| D-12 | Правки корпуса вне фичи, род - расширение области: BRD продукта (раздел 3 - просмотр и non-goal правки файлов, раздел 11, BR-003, BR-007, сценарий 2 раздела 17, заметка в шапке), FR-13009 фичи 13 (переход к строке Markdown), ADR-0002 п.3, п.5 и последствия (каналы `fs:write`, `edits:unsaved`), ADR-0015 (контекст о просмотрщике); зависимые места найдены поиском по «только чтение», «только читает», «просмотр» в корпусе | новые единицы рядом с задетыми | один предмет - одна единица (unit-identity) | принято составителем |
| D-13 | Историй с AC (`stories/`) у фичи нет: поведение проверяют автотесты и дымовой сценарий `markdownEdit`, названные в верификации FR-16001..FR-16006 и NFR-16001 | нарезка историй с критериями приёмки | у фичи один BR и линейный сценарий; дымовой сценарий проходит его целиком | принято составителем |
