# Cyborg Harness: идея на одной странице

## Идея

Сделать Cyborg **хостом плагинов**: небольшое ядро без предметной области (воркспейс, загрузка плагинов, связь через контракты, изоляция сбоев, pty-хост, права и секреты, каркас окна, клавиши, конфиг) и все функции - агент, сессии, файлы, просмотрщик, проекты, трекеры - как равные плагины. Затем открыть эту модель сторонним плагинам и другим агентам. Всё, что работает сегодня, сохраняется.

## Проблема

- Каждая возможность правит три общих файла (`main.ts`, `preload.ts`, `app.ts`) и копится в одном целом: 14 тыс. строк, 58 каналов IPC (51 `handle` и 7 `on`), 61 член моста, шесть диалогов в одном `index.html`.
- Claude Code зашит в ядро: другой агент невозможен без форка.
- Расширить приложение снаружи нельзя.
- Побочный дефект связности: список занятых сочетаний ведётся вручную и не знает акселераторов меню (D-27 фичи 12).

## Решение

Ядро - хост плагинов ([SAD2](../03-architecture/design/sad2.md)): плагины знают друг друга только через контракты в манифесте (граф проверяется до запуска кода), главные части работают в хостах `utilityProcess` со сторожем, процессы агентов держит отдельный pty-хост ядра и они переживают перезапуск плагина, UI каждого плагина живёт в своём `<iframe>` с закрытой CSP и получает вывод терминала напрямую по `MessagePort`, секреты хранит ядро (плагины хранят только ссылки), а изоляцию доступа для стороннего кода (процесс на плагин с `--permission`) строим вторым этапом, когда появится сторонний автор или каталог. Приёмы переноса и проверки - из [bb](../research/bb.md) и [DeepSeek Harness](../research/deepseek-harness.md); контракт агента проектируем сами (никто из образцов не встраивает интерактивный CLI в pty). Перенос «душителем» с паритетными проверками. Подробно - [OVERVIEW](../OVERVIEW.md), [ресёрч-2](../research/sad2-validation.md).

## Почему сейчас

- Корпус и тесты уже зрелые (153 требования, 925 тестов, дымовой тест): есть на что опереться при паритете.
- Приложение ещё небольшое (14 тыс. строк): перестройка дешевле, чем будет после следующих десяти функций.
- Два сильных образца появились и открыты; архитектура проверена замерами в Electron и сверкой с кодом: хосты, мост и `<iframe>` дёшевы по задержке.

## Кому и что даёт

| Кто | Что получает |
|---|---|
| Пользователь | То же приложение; зависший плагин не останавливает терминал; позже - выбор и контроль плагинов |
| Мейнтейнер | Новая функция без правки трёх общих файлов |
| Автор плагина | Понятные контракты, тестовый хост, видимые права |
| Владелец продукта | Предсказуемая стоимость развития, возможность подключать новые агенты |

## Меры успеха

| Мера | Цель |
|---|---|
| Общих файлов, которые надо править при добавлении функции | с 3-5 до 0 |
| Требований корпуса подтверждено на каждом шаге миграции | 153 из 153 |
| Тесты и дымовой тест на каждом шаге | зелёные |
| Второй агент подключён без правок ядра | да (P5) |
| Время запуска | не хуже базового более чем на 10% (база пока не измерена) |
| Сбой или зависание плагина роняет окно или терминал | никогда |
| Вызов через шлюз, вывод терминала (предлагаемые допустимые значения) | не более 1 мс на p99, не более 16 мс |

## Риски

Числа - из [ресёрча-2](../research/sad2-validation.md); измерено на одном компьютере (macOS, Apple M1 Pro, Electron 45).

- **Память.** Хост плагинов - около 15 МБ и 70-100 мс (десять хостов - 150 МБ). Кадр `<iframe>` с собственным origin - около 17 МБ, с общим - около 3 МБ: для базовой части (6-12 кадров) это 100-200 МБ против 20-35 МБ, поэтому встроенные плагины делят один origin.
- **Изоляция доступа.** `utilityProcess` флаг `--permission` принимает и не применяет; `Compartment` (`ses`) не граница против злого кода (Figma ушла с такой песочницы); сеть и окружение флагом не закрываются. Граница для стороннего кода - процесс на плагин (около 12 МБ), и это второй этап.
- **Не проверено.** Перехват системных сочетаний с фокусом в `<iframe>` настоящей клавиатурой (до спайка - акселераторы меню); Monaco и xterm под `sandbox`; `claude` в pty-хосте (`resize` и перерисовка после `attach`); сторож не имеет прецедента (перезапуск зависшего локального хоста в VS Code не делается), пороги стартовые.
- **Переход.** Старый `ProjectStore` стирает поля нового формата воркспейса (нужен шаг 0); восстановление сессий противоречит non-goal основного корпуса; потеря функции при переносе; базы старта и памяти нет (`scripts/measure.mjs` их не замеряет).

Меры - в [SAD2, раздел 9](../03-architecture/design/sad2.md#9-риски) и [OVERVIEW, раздел 8](../OVERVIEW.md#8-риски).

## Что просим у владельца

Решения, без которых нельзя начинать ([открытые вопросы SAD2](../03-architecture/design/sad2.md#8-открытые-вопросы)):

- **Сторонние плагины** (D-07 фичи 01): нужны ли вообще; повод для второго этапа; источник, подпись, повторное согласие (вопрос 8, D-23 фичи 01).
- **Второй агент** (D-11 фичи 02): какой проверит контракт `cyborg.agent`.
- **12.** Что держит экран терминала после перезапуска хоста: сырой хвост или снимок экрана (headless-xterm); решает спайк с настоящим `claude`.
- **13.** Модель процессов и окон: процесс на воркспейс (предложение, как сегодня) или одно приложение с несколькими окнами.
- **14.** Форма API: вклады плагинов в меню, сочетания с условиями, отмена запросов, вклады в промпт агента.
- **15.** Восстановление сессий противоречит non-goal основного корпуса: отменяем или нет (нужно решение до P1).
- **16.** Владелец git: отдельный плагин `git` с контрактом `cyborg.git`.
- **17.** Как жить прежнему `ProjectStore` рядом с новым форматом (предложение: сохранять неизвестные поля первым шагом).
- Переход трекеров с CLI на HTTP API (D-26 фичи 02): новое требование, а не перенос.

Остальные открытые решения - [OVERVIEW, раздел 9](../OVERVIEW.md#9-открытые-решения-нужен-ответ-владельца).
