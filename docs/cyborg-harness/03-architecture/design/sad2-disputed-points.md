Позиция автора - как она записана в SAD2 до правок этого PR; проверка - замеры, аналоги и код. Чьи-то устные мнения здесь не выдуманы: где позиция одной из сторон неизвестна, так и сказано.

## A. Расхождения с текстом автора

### 1. Кто держит pty

- **SAD2 (автор):** `node-pty` в главном процессе, ядро держит процесс и буфер ([3.6](sad2.md#36-ресурсы-дольше-плагина-pty)).
- **Проверка:** в VS Code терминал живёт в отдельном процессе (`ptyHost`) с heartbeat и перезапуском; `node-pty` в `utilityProcess` загружается; путь «хост - `<iframe>`» не дороже пути через главный процесс (45 мкс на круг, около 1,9 ГБ/с). Зависание или падение нативного модуля в главном процессе замораживает окно и убивает все сессии.
- **Предложение:** pty-хост - отдельный `utilityProcess` ядра ([ADR-CH-0012](../adr/ADR-CH-0012-hosts-watchdog-pty-host.md)). Цена: ещё один вид процесса и сторож за ним.
- **Что нужно:** согласие автора; прогон `claude` в pty-хосте (спайк, раздел 7 ресёрча).

### 2. Origin `<iframe>` плагина

- **SAD2 (автор):** `cyborg-plugin://<id>/` на каждый плагин, физическая изоляция DOM; общий origin для встроенных - запасной путь, если памяти много (вопрос 11).
- **Проверка:** кадр со своим origin - отдельный процесс рендера, 17 МБ против 3 МБ при общем origin; в базовой части 6-12 кадров, то есть 100-200 МБ разницы. Кадр с `sandbox` без `allow-same-origin` изолирует DOM по цене общего origin, но лишает хранилищ origin; Monaco под ним не проверен.
- **Предложение:** встроенные плагины делят `cyborg-plugin://builtin/`, сторонние получают свой origin ([ADR-CH-0013](../adr/ADR-CH-0013-plugin-ui-iframe-bridge.md)). Изоляция DOM между своими плагинами - статическая проверка, не граница.
- **Возражение, которое стоит услышать:** дисциплина «не трогать чужой DOM» без границы со временем размывается. Ответ: между встроенными плагинами одной команды граница безопасности не нужна, а ошибки ловит статическая проверка.

### 3. Что даёт второй этап изоляции

- **SAD2 (автор):** `Compartment` (`ses`) в хостах даёт гарантию «ничего сверх объявленного»; запасной путь - процесс на плагин без `Compartment`; флаг `--permission` в `utilityProcess` как второй слой - вопрос.
- **Проверка:** `utilityProcess` флаг принимает и **не применяет**; процесс Electron как Node его применяет, но сеть и окружение не закрыты. `ses` работает и дёшев (+3,5 МБ, около 0,1 мкс на вызов), но общая виртуальная машина пробивается: Figma ушла с такой песочницы после нескольких побегов; сканер `ses` отвергает часть бандлов (zod, marked).
- **Предложение:** граница - процесс на плагин с `--permission` (12 МБ на плагин), `Compartment` вторым слоем, сеть и окружение держит шлюз ([ADR-CH-0011](../adr/ADR-CH-0011-isolation-stages.md)).
- **Что нужно:** согласие автора; решение о поводе для второго этапа (пункт 14).

### 4. Модель процессов и окон

- **SAD2 (автор):** «Один воркспейс - одно окно; второй экземпляр приложения передаёт путь первому и завершается».
- **Проверка:** в коде нет `requestSingleInstanceLock`; сегодня отдельный процесс на воркспейс с общим `userData`, повторное открытие отказывает (FR-1029, FR-1033). Фраза допускает два прочтения: «одно приложение, одно окно» (тогда второй воркспейс не открыть) или «процесс на воркспейс» (тогда передавать путь некому); с кодом и FR-1029 согласуется только второе.
- **Предложение:** оставить процесс на воркспейс (паритет); передача фокуса окну владельца - улучшение после паритета.
- **Если автор имел в виду одно приложение с несколькими окнами:** это отдельное решение, оно меняет FR-1029, FR-1033, модель `userData` и замок; в пакете оформлено как вопрос 13.

### 5. Перехват системных клавиш

- **SAD2 (автор):** `before-input-event` в главном процессе, одинаково из любого `<iframe>` ([3.9](sad2.md#39-системные-клавиши-и-события)).
- **Проверка:** с фокусом внутри `<iframe>` синтетические нажатия до `before-input-event` не доходят, ни подтвердить, ни опровергнуть обещание без настоящей клавиатуры нельзя. Хоткеи кнопок задаёт пользователь и они условные (не в поле ввода, не при диалоге, только видимая сессия) - статические `keybindings` манифеста их не выражают. `Cmd/Ctrl+Shift+N` и `Cmd/Ctrl+0` сегодня живут только в слушателе окна.
- **Предложение:** сочетания остаются акселераторами меню (работают на уровне ОС до страницы), `before-input-event` - дополнение после спайка; динамическая регистрация `ctx.keys.register` с условием `when`.
- **Что нужно:** спайк с живой клавиатурой.

### 6. Что показывать после `attach`: хвост или снимок

- **SAD2 (автор):** сырой кольцевой буфер, после `attach` `resize`, TUI перерисуется по `SIGWINCH`.
- **Проверка:** VS Code восстанавливает экран снимком (headless-xterm) вместе с размерами; в обсуждении для Zed предложено то же. Для `claude` это не проверялось: может оказаться, что хвост с `resize` достаточен.
- **Предложение:** начать с решения автора (хвост + `resize`), снимок оставить как запасной вариант, если спайк покажет сломанную перерисовку. Пока вопрос 12.

## B. Чего в SAD2 нет

### 7. Восстановление сессий и non-goal корпуса

- **SAD2 (автор):** `sessions` хранит `{agent, resumeId, cwd, projectId, title, order}` и поднимает сессии через `resume` ([5.3](sad2.md#53-восстановление-сессий)).
- **Корпус:** автоматическое восстановление сессий - non-goal (`docs/01-product/brd.md`); FR-1015 и FR-2014 запрещают хранить привязку задачи или MR к сессии на диске, это закреплено тестом `static-guards`.
- **Позиции:** (а) оставить non-goal, держать только живые pty при перезагрузке окна; (б) снять non-goal, восстанавливать вкладки и `resume`, привязку задачи теряем.
- **Предложение:** выполнить пункт (а) в первой версии (pty-хост даёт «живые сессии при перезагрузке окна»), восстановление после перезапуска приложения - отдельным решением владельца ([FR-CH-3014](../../01-product/03-migration/srs.md) помечен условным).
- **Решает:** владелец.

### 8. Владелец git

- **SAD2 (автор):** владелец не назван; в схеме «базовой части» есть `git-status` как поставщик отметок дерева.
- **Проверка:** шесть каналов `git:*`, потребители `files`, `viewer` (diff через `headContent`), `search`, `trackers`, `command-buttons` (подстановка `{branch}`); у `viewer` нет права на процессы; `git:switch` отказывает, если репозиторий занят сессией.
- **Варианты:** (а) плагин `git` с контрактом `cyborg.git`; (б) git в ядре; (в) каждый плагин вызывает git сам, каждому нужно право `process`.
- **Предложение:** (а). Нужны ещё `gitRemotes` (для `trackers`) и `gitFiles` (для `fs:files` и `search`), зависимость `git` - `sessions` для `switch` решается через опциональный контракт.

### 9. Граница `trackers`

- **SAD2 (автор):** плагин `trackers`, в SAD старого состава - шесть плагинов.
- **Проверка:** общий `TrackersService`, составная карточка «Статус», одна секция `project-settings`, одна привязка задачи к сессии.
- **Предложение:** один плагин `trackers` с тремя видами (Задачи, MR/PR, Статус) ([parity-plan, 4.4](../../04-verification/parity-plan.md#44-граница-trackers)); разбивать, когда появится второй независимый трекер.

### 10. Вклады плагинов в меню, условные сочетания

- **SAD2 (автор):** меню - забота ядра, вкладов плагинов нет.
- **Проверка:** `project:selected` включает пункты «Свойства проекта», «Поиск», «Расширения»; `notifications:toggle` держит галочку; FR-5006 и FR-10007 запрещают убирать пункты.
- **Варианты:** (а) `contributes.menus` в манифесте с `enabled`/`checked` из контракта владельца; (б) меню статично в ядре, плагины только исполняют команды (теряем состояния пунктов).
- **Предложение:** (а). Вместе с динамическими сочетаниями закрывает известный дефект D-27.

### 11. Промпты, `prompts.json` и цикл `command-buttons` - `trackers`

- **SAD2 (автор):** `prompts.json` у `command-buttons` ([5.5](sad2.md#55-пробелы-паритета-найденные-сверкой-с-кодом)).
- **Проверка:** все пять шаблонов (`mr.review`, `mr.rework`, `mr.ci`, `task.start`, `jira.start`) относятся к стартам из трекеров, а подстановки `{pr}`, `{task}` кнопок берутся из `trackers`. Граф с циклом не загрузится ([FR-CH-1004](../../01-product/01-plugin-host/srs.md)).
- **Варианты:** (а) шаблоны старта лежат у `trackers`, у `command-buttons` только кнопки; (б) отдельный маленький плагин `prompts` с контрактом, которым пользуются оба.
- **Предложение:** (б); подстановки `{pr}` и `{task}` приходят из контекста сессии, который заполняет `trackers`. Форма контракта - в P1. Заодно решается владелец фрагмента изоляции сессии (FR-9001): сегодня его нет ни у одного плагина SAD2.

### 12. Полоса кнопок под терминалом

- **SAD2 (автор):** слоты сняты, на панель инструментов переходят четыре кнопки; «чужой UI в свой не встраивается».
- **Проверка:** кнопки-команды (FR-12001, FR-12008) показываются под терминалом, а терминал живёт в `<iframe>` другого плагина.
- **Варианты:** (а) род области «подвал документа» в ядре; (б) кнопки на панели инструментов (меняется вид); (в) `command-buttons` отдаёт данные контрактом, `sessions` рисует полосу сам.
- **Предложение:** (в): совпадает с принципом «задача, а не виджет», вид не меняется.

### 13. Привязка задачи и MR к сессии

- **SAD2 (автор):** в `cyborg.sessions` такого члена нет.
- **Проверка:** сегодня поля сессии в окне (`s.task`, `s.mr`, `s.jira`); от них зависят заголовок, возврат к строке панели (FR-1031) и подстановки.
- **Предложение:** `cyborg.sessions` даёт незахранимый «мешок меток» сессии (в памяти), туда пишет `trackers`; на диск он не попадает, что соответствует FR-1015 и FR-2014.

## C. Решения владельца

### 14. Сторонние плагины и второй агент

- **SAD2 (автор):** второй этап включается по поводу (автор вне команды или каталог плагинов).
- **Проверка:** без повода второй этап не окупается; первый этап с дисциплиной (асинхронные контракты, `structuredClone`, импорт только `@cyborg/contracts`) сохраняет возможность перехода и стоит дёшево. Аналоги (Obsidian, Chrome) показывают, что подпись и источник важны не меньше окна согласия.
- **Предложение:** второй этап не планировать до повода; второй агент - P5 по запросу, как условие стабилизации `cyborg.agent`. Нужен ответ владельца: нужны ли сторонние плагины вообще и какой второй агент проверит контракт.

### 15. Трекеры: CLI или HTTP API

- **SAD2 (автор):** узкий класс плагинов (только `net`, свой токен) на примере `jira`.
- **Проверка:** сегодня все трекеры через CLI (`gh`, `glab`, `jira`), токенов в приложении нет; узкий класс возможен лишь после перехода на HTTP API - это новое требование и новая работа с секретами.
- **Предложение:** для паритета оставить CLI с правом `process`; HTTP-плагин (например, Jira) - отдельный плагин позже, первый кандидат в узкий класс.

### 16. Бюджеты и база замеров

- **SAD2 (автор):** бюджеты числами - открытый вопрос 9.
- **Проверка:** базы старта и памяти нет (`scripts/measure.mjs` замеряет только панель задач и MR); задержки моста измерены (около 50 мкс).
- **Предложение:** бюджет «вызов через шлюз не более 1 мс на p99», «вывод терминала не более 16 мс»; перед переносом расширить `measure` стартом и памятью; бюджет «не хуже 10%» ([ADR-CH-0006](../adr/ADR-CH-0006-strangler-migration-and-parity.md)) без базы не проверяется.

## D. Мелочи, которые надо закрыть до фиксации контрактов

### 17. Список

- **Область `path:open`.** `openablePath` пускает любой существующий неисполняемый путь (файлы из вывода сессии), а в SAD2 области `workspace`, `plugin-data`, `granted`. Предложение: явная область для `shell` с этим правилом, иначе теряются FR-10012 и FR-10013.
- **`config:reveal`.** Открывает файл воркспейса целиком, а он по SAD2 защищённый путь. Предложение: команда ядра «показать файл воркспейса».
- **Копия повреждённого файла.** FR-1026 требует `<файл>.corrupt-<время>`; SAD2 говорит только об отказе раздела по схеме. Предложение: поведение сохраняется, владелец - ядро.
- **`experimental_` и реестр аудита.** SAD2 о них молчит, ADR-CH-0002 оставляет. Предложение: решить в P1 вместе с формой API.
- **Пороги сторожа.** Стартовые значения (5 с, 15 с, 3 перезапуска за 5 минут, 3 зависания) без прецедента в изученных системах; проверяются тестом до каркаса.
