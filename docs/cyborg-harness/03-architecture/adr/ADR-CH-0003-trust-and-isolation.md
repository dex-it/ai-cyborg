# ADR-CH-0003 Три уровня доверия: ядро, встроенные плагины, сторонние в отдельном процессе с правами из манифеста

> Решение составителя по запросу владельца (2026-11-02), не согласовано; ждёт приёмки. Основано на [ресёрче](../../research/README.md): [bb](../../research/bb.md), [DeepSeek Harness](../../research/deepseek-harness.md), [сравнение](../../research/comparison.md). Устройство целиком - [SAD](../design/sad.md).

## Decision Drivers

- Рядом с Cyborg работают настоящие сессии `claude` с правами пользователя; чужой код в главном процессе получил бы те же права.
- Образцы дают сторонним плагинам полное доверие: bb («full trust»), dsh («in-process outside the workspace sandbox»).
- Безопасность - инвариант продукта ([cyborg-today, раздел 9](../../research/cyborg-today.md#9-инварианты-которые-нельзя-потерять)).

## Context

В bb серверный код плагина грузится в процессе сервера, host-код - в отдельном процессе на плагин, манифеста прав нет, есть безопасный режим. В dsh плагин - доверенный код процесса; подтверждения касаются инструментов агента, а не плагинов. Подписей пакетов нет ни там, ни там. Из dsh стоит взять закрытые исходы подтверждения и отказ по умолчанию ([bb 5.4](../../research/bb.md), [dsh 8-9](../../research/deepseek-harness.md)).

## Decision

1. **Три уровня.** L0 - ядро. L1 - встроенные плагины, поставляются с приложением, работают в главном процессе, пользуются только публичным API (проверяет храповик). L2 - сторонние плагины.
2. **L2 исполняется в отдельном процессе** (`utilityProcess`), без доступа к Node-API приложения; с ядром общается RPC по каналу сообщений; шлюз проверяет каждую возможность. Интерфейс L2 - изолированное окно, обмен сообщениями (набор слотов ограничен).
3. **Манифест перечисляет `capabilities`** ([SAD, раздел 12](../design/sad.md#12-доверие-и-изоляция)); не названное недоступно. Пользователь видит список при установке.
4. **Закрытые исходы подтверждения** для опасных действий: `allowed-once`, `rejected`, `cancelled`, `unavailable`; разрешает только первое; нет ответа - отказ.
5. **Безопасный режим**: запуск с флагом отключает все L2 (и загружает встроенные).
6. **До P4 уровня L2 нет**: внешние плагины не загружаются, API помечен `experimental_`.
7. Пригодность `utilityProcess` и изолированных окон проверяется **спайком** в начале P4; если не проходит, сторонние плагины откладываются, а не запускаются без изоляции.

## Consequences

- Positive: плагин не получает права пользователя неявно; поверхность проверяется в одном месте (шлюз); отказ по умолчанию.
- Negative: у плагинов L2 меньше возможностей, чем у встроенных; RPC добавляет задержку и сложность; разработка прав и интерфейса подтверждения - отдельная работа.
- Risks: список возможностей окажется неполон (расширяем через `experimental_`); спайк покажет, что интерфейс стороннего плагина в изолированном окне неудобен - тогда в P4 остаются только плагины без интерфейса.

## Alternatives Considered

- **Один уровень полного доверия (как bb и dsh).** Pros: проще, быстрее. Cons: чужой код с правами пользователя рядом с сессиями агента. Why rejected: несовместимо с инвариантами безопасности.
- **Песочница в одном процессе (`vm`, ShadowRealm).** Cons: не является границей безопасности в Node. Why rejected: создаёт иллюзию изоляции.
- **Вообще без сторонних плагинов.** Pros: нет проблемы. Cons: нет расширяемости. Why rejected: это запасной вариант, если спайк P4 не пройдёт; пока открыт вопрос 1 в [OVERVIEW](../../OVERVIEW.md#9-открытые-решения-нужен-ответ-владельца).

## Расхождения с текущим кодом

Решение целевое: код приложения пока устроен иначе ([Cyborg сегодня](../../research/cyborg-today.md)). Расхождение снимается фазами [дорожной карты](../../05-plans/roadmap.md).
