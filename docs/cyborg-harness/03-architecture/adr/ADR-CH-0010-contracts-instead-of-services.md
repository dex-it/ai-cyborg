# ADR-CH-0010 Контракты вместо реестра сервисов, шины и inject; агент - обычный плагин

> Решение сведено из [SAD2](../design/sad2.md) (договорённости 2026-11-02 - 2026-11-04) и проверено [ресёрчем-2](../../research/sad2-validation.md); не согласовано, ждёт приёмки. Заменяет [ADR-CH-0005](ADR-CH-0005-extension-points.md), меняет [ADR-CH-0004](ADR-CH-0004-agent-provider-contract.md) в части места агента в архитектуре.

## Decision Drivers

- Плагины не должны знать друг друга по имени; ошибку связи надо видеть до запуска кода.
- Семь точек расширения и три режима событий (ADR-CH-0005) оказались шире, чем нужно, и тянут за собой каскад выгрузки.
- API между плагинами должен переживать RPC между хостами ([ADR-CH-0012](ADR-CH-0012-hosts-watchdog-pty-host.md)).

## Context

SAD связывал плагины через реестр сервисов (`provide` / `get` / `inject`), шину событий с режимами observe, waterfall, guard и точку расширения `providers` для агента. Это берёт у dsh модель Cordis, которую ADR-CH-0001 уже отказался подключать. В SAD2 пять базовых плагинов (`sessions`, `agent-claude-code`, `files`, `viewer`, `projects`) связываются иначе ([SAD2, раздел 4-5](../design/sad2.md#4-взаимодействие-плагинов)).

## Decision

1. **Связь только через контракты в манифесте:** `provides`, `requires`, `optional`, `consumes`. Контракт - имя, версия и типы в пакете `@cyborg/contracts` без логики.
2. **Кратность объявляет потребитель:** `one` (два поставщика - отказ при загрузке) или `many` (список). Граф проверяется до запуска кода: недостающий `requires`, цикл, два поставщика при `one`.
3. **Версии семантические.** Минорное изменение обязано пропускаться потребителем; поставщик может давать две мажорные версии сразу; `@deprecated` живёт до следующей мажорной, ядро пишет в журнал, кто вызывает. Пространство `cyborg.*` закреплено за репозиторием.
4. **События - часть контракта владельца** (`sessions.onChange`, `projects.onChange`). Общей шины, waterfall и guard нет.
5. **Ещё две связи без зависимости:** команда по имени и MIME при перетаскивании (`application/x-cyborg-path`).
6. **API контракта асинхронный и только с данными:** аргументы переживают `structuredClone`; отмена запроса - часть протокола вызова (идентификатор и сообщение об отмене). Подписки привязаны к вызывающему.
7. **Агент - обычный плагин, поставщик `cyborg.agent`.** Содержание контракта из ADR-CH-0004 в силе; точки расширения «провайдер» нет. Права вызывающего проверяются при вызове через чужой контракт (`via-contract`).

## Consequences

- Positive: порядок активации и ошибки связи видны из манифестов; один и тот же вызов работает внутри хоста и между хостами; второй агент - ещё один поставщик `cyborg.agent`.
- Negative: нужны пакет `@cyborg/contracts`, набор тестов контракта для поставщиков (вопрос 10 SAD2) и перенос общих типов, которые сегодня импортируют 20+ файлов окна из `../main/*`.
- Risks: форма вкладов в промпт агента (сегодня waterfall `session.prompt`) и вкладов в меню открыта; критерий «нужна ли отмена» проверяется при переносе поиска.

## Alternatives Considered

- **Реестр сервисов с `inject` и каскадом выгрузки (ADR-CH-0001, SAD §6.3).** Pros: знакомая модель Cordis. Cons: связь по ключу строки, граф неочевиден до запуска. Why rejected: контракты проверяются статически.
- **Общая шина событий с режимами (ADR-CH-0005).** Pros: перехват и запрет. Cons: владельца события нет, версий нет, забытый `next()` тихо рвёт цепочку. Why rejected: событие принадлежит тому, кто владеет предметом.
- **Прямой импорт чужого плагина.** Cons: связь по имени, ломает изоляцию хостов. Why rejected.
- **Агент как точка расширения `providers`.** Cons: ядро знает вид «агент». Why rejected: см. [ADR-CH-0009](ADR-CH-0009-core-boundary-and-compactness.md).

## Расхождения с текущим кодом

Сегодня связи заданы импортами: `workspaces.ts` импортирует `projects` и `trackers`, `sessions` → `suggestions` → `commands`. Расхождение снимается фазами [дорожной карты](../../05-plans/roadmap.md).
