# ADR-CH-0005 Семь точек расширения v1 и три режима событий

> Решение составителя по запросу владельца (2026-11-02), не согласовано; ждёт приёмки. Основано на [ресёрче](../../research/README.md): [bb](../../research/bb.md), [DeepSeek Harness](../../research/deepseek-harness.md), [сравнение](../../research/comparison.md). Устройство целиком - [SAD](../design/sad.md).

## Decision Drivers

- Образцы показали обратную сторону широкого API: у bb 6000 строк контрактов интерфейса и сотни `experimental_`-членов, у dsh 108 сервисов в классификации.
- Нужно закрыть все нынешние функции минимальным набором точек.
- Режим события - часть контракта: «наблюдать», «перехватывать», «запрещать» ведут себя по-разному.

## Context

dsh: режимы `emit`, `parallel`, `serial`, `bail`, `waterfall`, `guard` (монотонный запрет, не может разрешить); тонкость: waterfall-слушатель, не вызвавший `next()`, тихо обрывает цепочку. bb: события «уже случилось» и единственный хук `message.dispatch` с глобальным локом и тайм-боксом 10 с ([bb 5.3](../../research/bb.md), [dsh 4](../../research/deepseek-harness.md)).

## Decision

1. **Семь точек**: `services`, `commands`, `slots`, `ipc`, `events`, `settings` и `storage`, `providers` (агент, трекер). Детали - [SAD, разделы 7-11](../design/sad.md#7-точки-расширения-v1).
2. **Три режима событий**: observe (значение игнорируется, сбой слушателя изолирован), waterfall (`next()`, забытый вызов фиксируется диагностикой), guard (только запрещает; нет ответа за таймаут - запрет). Тип и режим объявляются в одном месте.
3. **Хуков «ядро спрашивает плагин» с глобальным локом нет**; единственный guard v1 - `session.start`.
4. **Проверка аргументов каналов** - внутренний маленький помощник по образцу `validateAction`; новых зависимостей не вводим.
5. **Ничего нового в API без префикса `experimental_`** и записи в реестре аудита.
6. **Пересмотр точек** возможен только записью решения: добавление восьмой - новый ADR с обоснованием, какую функцию не закрывают семь.

## Consequences

- Positive: небольшой API, который можно удержать в голове и проверить; все нынешние функции раскладываются на семь точек (проверено классификацией в SAD).
- Negative: часть функций потребует обходных приёмов (например, диалоги - сервис, не слот).
- Risks: классификация даст пробелы при переносе `app.ts`; тогда решаем по ADR, не расширяем молча.

## Alternatives Considered

- **Широкий API с самого начала (как bb).** Cons: заморозка лишних контрактов, большой объём. Why rejected.
- **Одна универсальная шина без режимов.** Cons: перехват и запрет не выразить. Why rejected.
- **Общая библиотека схем (zod).** Pros: готово. Cons: новая зависимость. Why rejected на v1; пересмотр, если помощник станет громоздким.

## Расхождения с текущим кодом

Решение целевое: код приложения пока устроен иначе ([Cyborg сегодня](../../research/cyborg-today.md)). Расхождение снимается фазами [дорожной карты](../../05-plans/roadmap.md).
