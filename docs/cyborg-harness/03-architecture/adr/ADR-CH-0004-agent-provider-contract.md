# ADR-CH-0004 Контракт провайдера агента: pty-first, ядро запускает процесс, провайдер описывает запуск и адаптирует события

> Уточнён ADR-CH-0010: содержание контракта (pty-first, `resume`, нормализованные события, типизированное восстановление) остаётся в силе, но агент - обычный плагин, поставщик контракта `cyborg.agent`, а не отдельная точка расширения.

Что меняется в формулировке (остальное решение без изменений):

- Вместо `AgentProvider` как вида провайдера в SAD §9.1 - контракт `cyborg.agent` в `@cyborg/contracts` ([SAD2, раздел 5](../design/sad2.md#5-пример-базовая-часть)); потребитель - `sessions` (кратность `many`).
- Пункт 2: плагин решает, что запустить (`ctx.os.pty.spawn`, право `pty` в манифесте), процесс держит pty-хост ядра ([ADR-CH-0012](ADR-CH-0012-hosts-watchdog-pty-host.md)); `LaunchSpec` собирает плагин, ядро проверяет право.
- Пункт 6: waterfall `session.prompt` заменён контрактом-источником фрагментов промпта (`many`), который опрашивает `sessions`; форма - в P1.

> Решение составителя по запросу владельца (2026-11-02), не согласовано; ждёт приёмки. Основано на [ресёрче](../../research/README.md): [bb](../../research/bb.md), [DeepSeek Harness](../../research/deepseek-harness.md), [сравнение](../../research/comparison.md). Устройство целиком - [SAD](../design/sad.md).

## Decision Drivers

- Продуктовая идея Cyborg: настоящий интерактивный `claude` в pty, человек работает в терминале; сессия не подменяется (ADR-0003).
- Нужен шов, чтобы подключить другой агент без правок ядра.
- Образцы подключают агентов структурным протоколом и строят таймлайн сами; интерактивный CLI в pty не встраивает никто ([comparison](../../research/comparison.md)).

## Context

bb: провайдер - плагин; мост по JSON-RPC (stdio) с рукопожатием, дельтами, типизированными подсказками восстановления; Claude Code подключён через Agent SDK; паритет по записанным сессиям. dsh: `SubagentProvider.start()` даёт один терминальный результат; Claude Code - неинтерактивный субагент через SDK ([bb 5.6](../../research/bb.md), [dsh 8](../../research/deepseek-harness.md)). Сегодня у нас Claude Code зашит в `sessions.ts`, `claude-args.ts`, `history.ts`.

## Decision

1. Вводим **вид провайдера «pty-агент»** (`AgentProvider`, [SAD, раздел 9.1](../design/sad.md#91-провайдер-агента)): `handshake`, `launch`, `attach`, `history`, `recover`.
2. **Ядро запускает pty**; провайдер описывает `LaunchSpec` (программа, аргументы, окружение, cwd), ядро проверяет и исполняет его сама. Провайдер не создаёт процессы.
3. **Рукопожатие сообщает факты** (найден ли CLI, версия, вход выполнен); ядро не вызывает того, что провайдер не объявил в `capabilities`.
4. **События нормализуются** в `session.cwd`, `session.activity`, `session.waiting`, `session.turnEnd`; адаптер провайдера (у Claude Code - хуки и файл событий) их излучает. Агент без таких следов остаётся с запуском и выводом.
5. **Восстановление типизировано** (`authRequired`, `notFound`, `rateLimited`...), сопоставления по тексту ошибок нет.
6. **Вклад в системный промпт** - через waterfall-событие `session.prompt` (изоляция сессий и предложения кнопок становятся плагинами, провайдер собирает фрагменты).
7. Первый провайдер `agent-claude-code` повторяет нынешнее поведение дословно; **второй провайдер обязателен до стабилизации API** (P5), чтобы контракт не оказался выточенным под один агент.
8. Структурные провайдеры (SDK, ACP) - **отдельный вид** контракта, после v1; Claude Code через SDK как основной путь не используется (одноразовый неинтерактивный режим противоречит живым сессиям).

## Consequences

- Positive: Claude Code перестаёт быть особым случаем в ядре; новый агент - плагин; пути «истории», «продолжения» и «изоляции» становятся возможностями провайдера.
- Negative: контракт описывает меньше, чем у образцов (нет таймлайна, нет дельт): у нас его строит сам агент в терминале.
- Risks: события для агентов без хуков окажутся эвристикой; контракт придётся расширять при появлении структурных провайдеров.

## Alternatives Considered

- **Только Agent SDK.** Pros: структурные события, как у образцов. Cons: нативный интерактивный терминал пропадает; противоречит сути продукта. Why rejected.
- **ACP как основа.** Pros: стандарт, много агентов. Cons: интерактивный pty тоже не получить; Claude Code в ACP - через мост. Why rejected для v1; остаётся видом провайдера позже.
- **Оставить Claude Code зашитым.** Cons: второй агент невозможен без форка ядра. Why rejected.

## Расхождения с текущим кодом

Решение целевое: код приложения пока устроен иначе ([Cyborg сегодня](../../research/cyborg-today.md)). Расхождение снимается фазами [дорожной карты](../../05-plans/roadmap.md).
