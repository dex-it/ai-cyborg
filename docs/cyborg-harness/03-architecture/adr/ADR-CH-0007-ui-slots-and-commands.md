# ADR-CH-0007 Интерфейс плагинов: слоты на обычном DOM, граница ошибок на слот, единый реестр команд и сочетаний

> Решение составителя по запросу владельца (2026-11-02), не согласовано; ждёт приёмки. Основано на [ресёрче](../../research/README.md): [bb](../../research/bb.md), [DeepSeek Harness](../../research/deepseek-harness.md), [сравнение](../../research/comparison.md). Устройство целиком - [SAD](../design/sad.md).

## Decision Drivers

- В интерфейсе нет фреймворка: DOM строится функцией `el()`, `innerHTML` запрещён охранным тестом.
- Сегодня список занятых сочетаний ведётся вручную и не знает акселераторов меню «Поиск» и «Расширения» (D-27 фичи 12).
- Образцы: слоты, где компонент не получает контекст (dsh), граница ошибок на слот и эксклюзивные слоты с запасным вариантом (bb) ([bb 5.5](../../research/bb.md), [dsh 7](../../research/deepseek-harness.md)).

## Decision

1. **Вклад в интерфейс - функция монтирования**: `mount(container, api) -> Disposable` в слот; React и общий глобальный рантайм не нужны.
2. **Слоты** по местам, где интерфейс уже разделён: `strip.action`, `sidebar.tab`, `session.view`, `panel`, `terminal.footer` ([SAD, раздел 10](../design/sad.md#10-слоты-интерфейса)). Диалоги - сервис ядра `dialogs.open`, а не слот.
3. **Граница ошибок на слот**: сбой скрывает слот и показывает компактную заглушку, соседи работают, ошибка уходит в диагностику плагина. Порядок слотов детерминирован.
4. **Эксклюзивные слоты** имеют запасную реализацию ядра, если плагин не активен.
5. **Единый реестр команд, сочетаний и меню**: плагин объявляет команды декларативно (`contributes.commands`), ядро собирает таблицу, проверяет конфликты **при загрузке** (с акселераторами меню, сочетаниями терминала, сочетаниями кнопок) и отдаёт одно место для чтения списка занятых.
6. **Доступность** (роли ARIA, фокус, клавиатура вкладок и списков) обеспечивает ядро: общие помощники и общий тест слотов; плагин не обязан изобретать её заново.
7. **Стили**: у каждого плагина свой префикс классов (`.p-<id>-...`), общие переменные темы из ядра; стили плагина грузятся вместе с его интерфейсной частью.
8. **Правило «нет `innerHTML`»** распространяется на плагины и проверяется тем же охранным тестом.

## Consequences

- Positive: класс ошибок «сочетание занято меню» закрыт на уровне ядра; новые панели не правят `index.html`; единая доступность.
- Negative: нужен перенос шести `<dialog>` и панелей из `index.html` в сервис и слоты; `styles.css` (2233 строки) придётся разрезать по плагинам.
- Risks: `app.ts` распадается неравномерно; для сторонних плагинов в изолированном окне слоты - подмножество (проверка в P4).

## Alternatives Considered

- **React или другой фреймворк для плагинов.** Cons: перестройка всего интерфейса ради плагинов; общий глобальный рантайм (как у bb) связывает плагины с одной копией библиотеки. Why rejected.
- **Web Components.** Pros: стандарт, изоляция стилей. Cons: Shadow DOM усложняет общие стили и тесты; выигрыш неясен. Why rejected на v1; можно вернуться.
- **Оставить сочетания в каждом плагине.** Why rejected: именно так возник D-27.

## Расхождения с текущим кодом

Решение целевое: код приложения пока устроен иначе ([Cyborg сегодня](../../research/cyborg-today.md)). Расхождение снимается фазами [дорожной карты](../../05-plans/roadmap.md).
