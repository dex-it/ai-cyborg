# ADR-CH-0014 Секреты, config и state: хранилище ядра как корень доверия

> Решение сведено из [SAD2, 3.3, 3.7, 3.10](../design/sad2.md#310-главный-конфиг-и-состояние); не согласовано, ждёт приёмки. Уточняет данные из [ADR-CH-0002](ADR-CH-0002-manifest-and-compatibility.md).

## Decision Drivers

- Секреты не должны попасть в `config`, `state` и журнал.
- Обновление плагина или ошибка в файле, который правит пользователь, не должны ронять плагин или окно.
- Источников секретов (Vault, 1Password, `pass`) будет несколько; ядро не должно знать ни один.

## Context

Сегодня трекеры работают через CLI (`gh`, `glab`, `jira`) и токенов в приложении не хранят. Формат воркспейса `{projects, lastProjectId, commands}`; прежний `ProjectStore` стирает все поля, кроме `commands` (`OWN_FIELDS`) ([ресёрч-2, 5.1](../../research/sad2-validation.md#51-что-в-sad2-и-parity-plan-неверно-или-неточно)).

## Decision

1. **Секреты - две роли.** Хранилище ядра (`ctx.os.secrets`, `safeStorage`, ключи `<pluginId>/<key>`) - корень доверия: работает без плагинов, плагин видит только свои ключи, без шифрования ОС вызов получает `Unavailable`, при удалении плагина секреты стираются. Источник секретов - плагин, поставщик `cyborg.secret-source` (кратность `many`, поставщик выбирается по схеме ссылки; две одинаковые схемы - отказ при загрузке).
2. **В `config` только ссылка** `{ "$secret": "vault://kv/data/jira#token" }`; без схемы - ключ хранилища ядра вызывающего плагина. Ядро проверяет ссылку по праву `secrets.ref` вызывающего (`via-contract`).
3. **Значение секрета не кэшируется и не пишется** в `config`, `state` и журнал; кэш до `expiresAt` - решение потребителя. Значение не проходит через третьи плагины.
4. **Config и state - разделы по плагинам** со схемой и версией в манифесте. Плагин видит только свой раздел. Config - намеренные настройки (файл воркспейса и файл пользователя), state - память машины (каталог приложения, ключ по воркспейсу).
5. **Проверка по схеме до активации и при правке файла извне.** Версия раздела ниже версии плагина - ядро вызывает `migrate(fromVersion, data)` до активации. Версия выше (откат плагина) или раздел не прошёл схему - отказ только этому плагину, раздел не трогается.
6. **Перенос старого формата один раз:** `projects` → `settings.projects`, трекеры → `settings.trackers.byProject`, `commands` → раздел `command-buttons`, `lastProjectId` → state; вместе с файлами пользователя и ключами `localStorage`. Шаг 0: `ProjectStore` учится сохранять неизвестные поля.

## Consequences

- Positive: утечка источника секретов ограничена его схемой; сбой раздела локален; смена формата не теряет данные.
- Negative: перенос единственного места, где ядро знает чужие поля, удаляется через пару версий; плагинам нужны схемы и `migrate`.
- Risks: на Linux без keyring хранилище недоступно; плагин-источник со своим токеном зависит от хранилища ядра.

## Alternatives Considered

- **Источник секретов подменяет хранилище ядра.** Cons: он увидит секреты всех плагинов, выключение лишит секретов всех, включая токен самого источника. Why rejected.
- **Значение секрета в `config` (как токены в файлах).** Why rejected: значения секретов не лежат ни в `config`, ни в `state`.
- **Один общий `config` без разделов.** Cons: плагин видит чужое, ошибка ломает всех. Why rejected.
- **Кэш значений в ядре.** Cons: ломает аренды и отзыв в источнике. Why rejected.
- **`storage.legacy` и «миграция рядом» (ADR-CH-0002).** Why rejected: заменено `migrate` до активации.

## Расхождения с текущим кодом

Разделов, схем и хранилища секретов в коде нет; файлы пользователя (`commands.json`, `prompts.json`, `hubs.json`) и `localStorage` не мигрируют. Расхождение снимается фазами [дорожной карты](../../05-plans/roadmap.md).
