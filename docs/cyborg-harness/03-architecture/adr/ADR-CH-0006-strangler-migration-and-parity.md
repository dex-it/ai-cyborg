# ADR-CH-0006 Миграция «душителем» и паритет: ничего не теряется, каждый шаг закрыт проверками

> Решение составителя по запросу владельца (2026-11-02), не согласовано; ждёт приёмки. Основано на [ресёрче](../../research/README.md): [bb](../../research/bb.md), [DeepSeek Harness](../../research/deepseek-harness.md), [сравнение](../../research/comparison.md). Устройство целиком - [SAD](../design/sad.md).

## Decision Drivers

- Условие владельца: всё, что есть сейчас, должно сохраниться.
- Приложение живое: 153 требования, 893 теста, дымовой тест, пользователи с данными.
- bb держит паритет записанными сессиями; dsh - снапшотами и реальным загрузчиком в тестах ([bb 5.6, 5.8](../../research/bb.md), [dsh 10](../../research/deepseek-harness.md)).

## Context

Исходное состояние: связность в `main.ts` (58 каналов), `preload.ts` (65 методов), `app.ts` (1360 строк) и `index.html` ([cyborg-today, раздел 8](../../research/cyborg-today.md#8-что-мешает-разделению-связность)). Большой рефакторинг одним шагом исключён.

## Decision

1. **Перестраиваем «душителем»**: в работающем коде вырастает каркас ядра, функции переезжают в плагины по одной; старый и новый пути сосуществуют до окончания переноса функции.
2. **Порядок переноса - по возрастанию риска**: `path-drop`, `session-notifications`, `search`, `command-buttons`, `claude-extensions`, трекеры (`tasks`, `merge-requests`, `status`), `files`, провайдер `agent-claude-code`, оболочка окна - последней. Каждый перенос - отдельный PR.
3. **Прокладка совместимости каналов**: старые имена каналов IPC и методы `window.cyborg` обслуживаются поверх нового шлюза, пока интерфейс не переехал; удаление прокладки - отдельный шаг после зелёного паритета.
4. **Паритет как механизм**: (а) матрица «функция, требование, канал, плагин, проверка» без пустых строк; (б) все прежние тесты зелёные на каждом шаге; (в) записанные сессии и подставные CLI (`claude`, `gh`, `jira`) повторяются на каждом коммите; (г) допустимые расхождения - в явном allowlist, лишняя запись роняет проверку; (д) закреплённые счётчики (число каналов, команд, пунктов меню, требований). Подробнее - [план паритета](../../04-verification/parity-plan.md).
5. **Храповики границ**: ядро не импортирует плагины; плагин - только публичный API; число прямых обращений плагинов к `electron` и `fs` может только уменьшаться.
6. **Бюджеты**: время запуска и открытия окон измеряется до начала (P0) и не ухудшается более чем на 10%.
7. **Данные не меняют формата в ходе миграции**; если формат меняется, то по правилам [ADR-CH-0002](ADR-CH-0002-manifest-and-compatibility.md).
8. **Каждая фаза имеет условие выхода** ([дорожная карта](../../05-plans/roadmap.md)); фаза не закрывается при красном паритете.
9. **Обратимость шага**: каждый перенос можно откатить без потери данных (перенос - PR, прокладка остаётся до закрытия фазы).

## Consequences

- Positive: продукт всё время рабочий; потеря функции ловится автоматически, а не обнаруживается пользователями.
- Negative: временно две дорожки кода и прокладки; дороже, чем переписать с нуля; нужно собрать записанные сессии и подставные программы (часть уже есть в smoke).
- Risks: оболочка (`app.ts`) может не поддаваться пошаговому разрезу - тогда сначала слоты в старой оболочке, затем перенос кусками.

## Alternatives Considered

- **Переписать с нуля («большой взрыв»).** Cons: потеря поведения неизбежна, долго нет работающего продукта. Why rejected.
- **Заморозить функции и строить рядом новый Cyborg.** Cons: два продукта, перенос данных и пользователей. Why rejected.
- **Не гарантировать паритет, исправлять по обращениям.** Why rejected: условие владельца.

## Расхождения с текущим кодом

Решение целевое: код приложения пока устроен иначе ([Cyborg сегодня](../../research/cyborg-today.md)). Расхождение снимается фазами [дорожной карты](../../05-plans/roadmap.md).
