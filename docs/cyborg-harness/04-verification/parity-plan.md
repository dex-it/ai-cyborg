# План паритета: как проверяем, что ничего не потеряно

> План на этапе проектирования: механизмов ещё нет, они создаются в P0-P1 ([дорожная карта](../05-plans/roadmap.md)). Решение - [ADR-CH-0006](../03-architecture/adr/ADR-CH-0006-strangler-migration-and-parity.md), требования - [фича 03](../01-product/03-migration/srs.md).

## 1. Что значит «не потеряно»

Функция считается сохранённой, если одновременно:

1. все её требования основного корпуса (`docs/01-product/NN-*/srs.md`) по-прежнему подтверждены своими проверками;
2. все прежние тесты зелёные, а их утверждения не изменены (меняются только пути импорта);
3. поведение, снятое на записанных сессиях и подставных программах, совпадает с эталоном до допустимых расхождений;
4. прежние данные пользователя читаются, прежние каналы IPC отвечают как раньше (пока работает прокладка);
5. бюджеты производительности не нарушены.

## 2. Что можно менять, а что нет

| Допустимо без записи | Допустимо с записью в allowlist | Недопустимо |
|---|---|---|
| Внутреннее устройство, имена модулей и файлов, пути импорта | Переименование «Расширения» в «Расширения Claude Code» ([FR-CH-3008](../01-product/03-migration/srs.md)) | Менять утверждения существующих тестов |
| Порядок активации плагинов, если результат тот же | Изменение порядка вызовов, не видимое пользователю, с объяснением | Менять форматы файлов пользователя |
| | | Убирать пункт меню, сочетание, кнопку, канал IPC, настройку |

## 5. Записанные сессии и подставные программы

**Подставные программы.** Уже есть в дымовом тесте (`scripts/smoke.mjs`): `claude`, `gh`, `jira`. Расширяем: `glab`, `claude plugin ...` (магазины, установка, удаление), `git` на фикстурных репозиториях.

**Записанная сессия** - набор файлов в `test/parity/<сценарий>/`:

| Файл | Что |
|---|---|
| `events.jsonl` | События хуков, которые получает приложение (формат `claude-hooks.json` событий) |
| `output.txt` | Вывод pty (как есть) |
| `cli.json` | Ответы подставных `gh`, `glab`, `jira`, `claude plugin` на запросы |
| `expect.json` | Эталон: нормализованные события `session.*`, строки дерева, панелей, меню, состояние слотов |
| `manifest.json` | Версия записи, версия Claude Code, на которой снята, описание |

Сценарии для первой записи (по функциям, около 15): новая сессия и ввод; смена cwd на worktree (дерево идёт за сессией); запрос разрешения и уведомление; конец хода с предложением кнопок; продолжение сессии и удаление из истории; старт по задаче; ревью MR; карточка «Статус» с Jira; поиск файла, текста, изменений; установка и удаление плагина Claude Code; чтение хаба; смена ветки; перетаскивание пути; кнопка-команда с подстановкой; открытие второго воркспейса.

**Повтор.** Тест проигрывает запись против текущей сборки и сравнивает нормализованный результат с `expect.json`. Расхождение допустимо только при записи в allowlist (`test/parity/allowlist.json`: сценарий, поле, причина, ссылка на решение). Запись в allowlist, которой не пользуется ни одно расхождение, роняет проверку.

## 6. Чек-лист PR переноса

PR, переносящий функцию в плагин, обязан:

- [ ] перенести код в `src/plugins/<id>`, не меняя утверждений существующих тестов;
- [ ] оставить прежние каналы IPC и методы `window.cyborg` работающими через прокладку;
- [ ] обновить строку матрицы (статус «перенесено, паритет подтверждён»), счётчики и allowlist, если нужны;
- [ ] приложить прогон: тесты, дымовой тест, паритет, храповики, `check:corpus`;
- [ ] приложить замер бюджета, если функция в пути запуска или открытия окна;
- [ ] описать откат шага;
- [ ] не менять форматы данных; если меняет - отдельный ADR и миграция «рядом».
