# SRS фичи 03 - миграция и паритет

## 1. SRS overview

Требования к процессу переноса и к проверкам, которые гарантируют, что ничего не потеряно: матрица паритета, перенос функций по одной, перенос данных пользователя (формат воркспейса, файлы, `localStorage`), подготовительный шаг на текущем коде, порядок первого этапа, восстановление сессий (условно), пробелы паритета, найденные сверкой с кодом. Подробности и таблицы - [план паритета](../../04-verification/parity-plan.md), порядок - [дорожная карта](../../05-plans/roadmap.md), решения - [ADR-CH-0006](../../03-architecture/adr/ADR-CH-0006-strangler-migration-and-parity.md), [ADR-CH-0012](../../03-architecture/adr/ADR-CH-0012-hosts-watchdog-pty-host.md), [ADR-CH-0014](../../03-architecture/adr/ADR-CH-0014-secrets-config-state.md). Целевая картина - [SAD2](../../03-architecture/design/sad2.md), разделы 3.10, 5.3, 5.5, 6.1; сверка с кодом - [ресёрч-2, раздел 5](../../research/sad2-validation.md#5-сверка-с-кодом). Требования 3010-3016 добавлены по SAD2.

## 2. Требования

### FR-CH-3001 Матрица паритета

- **Требование:** поддерживается матрица «функция, требования основного корпуса, каналы IPC, целевой плагин, проверки, статус»; каждая из 14 фич, каждое из 153 требований и каждый из 58 каналов (51 `ipcMain.handle` и 7 `ipcMain.on`, `src/main/main.ts`) присутствует в ней минимум раз; целевой плагин каждого канала назван по модели SAD2 ([ресёрч-2, 5.3](../../research/sad2-validation.md#53-каналы-ipc-и-владелец-в-модели-sad2)); пустой целевой плагин или пустая проверка блокируют закрытие фазы. Каналы без владельца в модели (`project:selected`, `session:reveal`, `menu:*`, `notifications:toggle`, `git:*`) закрываются [FR-CH-3016](#fr-ch-3016-владельцы-пробелов-паритета).
- **traced from:** BR-CH-002.
- **источник:** bb 5.6 (`row-counts.json`, паритет); матрица верификации основного корпуса; ресёрч-2, 5.1 (в parity-plan учитывались только `handle`).
- **verification:** испытание - скрипт сверяет матрицу с `docs/.req_counter` основного корпуса, списком каналов (`handle` и `on`) в `main.ts` и перечнем фич; расхождение роняет проверку.
- **класс:** Process.

### FR-CH-3002 Перенос функции отдельным PR

- **Требование:** каждая функция переносится в плагин отдельным PR; PR не меняет поведения, не правит утверждения существующих тестов (только пути импорта и среду выполнения, [FR-CH-3015](#fr-ch-3015-перенос-тестов-с-сохранением-утверждений)) и содержит строку матрицы со статусом «перенесено, паритет подтверждён».
- **traced from:** BR-CH-002.
- **verification:** осмотр PR по чек-листу [плана паритета](../../04-verification/parity-plan.md#6-чек-лист-pr-переноса); проверка CI.
- **класс:** Process.

### FR-CH-3003 Прокладка совместимости каналов

- **Требование:** пока интерфейс не переехал, все прежние имена каналов IPC и методы `window.cyborg` работают через прокладку поверх нового шлюза с прежним поведением и прежними проверками; удаление прокладки - отдельный PR после закрытия фазы с зелёным паритетом.
- **traced from:** BR-CH-002.
- **verification:** испытание - тест, перебирающий все 58 прежних каналов (`handle` и `on`) с эталонными запросами и сравнивающий ответы с записанными (для `on` - наблюдаемый эффект).
- **класс:** Functions.

### FR-CH-3004 Записанные сессии и подставные программы

- **Требование:** паритет проверяется на записанных сессиях и подставных `claude`, `gh`, `glab`, `jira`: записи содержат события хуков, вывод, ответы CLI; повтор на каждом коммите сравнивает нормализованные события и строки интерфейса с эталоном; допустимые расхождения перечислены в allowlist, лишняя запись роняет проверку; счётчики (каналы, команды, пункты меню, требования) закреплены. Записи включают перезапуск хоста плагина: сессия продолжается, события после `attach` совпадают с эталоном.
- **traced from:** BR-CH-002.
- **источник:** bb 5.6, 5.8 (`provider-parity`, `parity-allowlist.json`, `row-counts.json`); dsh 10 (снапшоты сессий).
- **verification:** испытание - собственные тесты инструмента паритета (на заведомо расходящейся записи проверка падает).
- **класс:** Process.

### FR-CH-3005 Храповики границ

- **Требование:** `scripts/check-boundaries.mjs` в CI: ядро не импортирует плагины; плагин импортирует только `@cyborg/contracts` и свои модули (ни чужого плагина, ни `node:*`, ни `electron`, [FR-CH-1020](../01-plugin-host/srs.md#fr-ch-1020-дисциплина-первого-этапа-проверяется-тестами)); для кода, ещё не перенесённого в плагин, число прямых обращений к `electron`, `node:*` и `fs` не растёт (счётчик в репозитории, значение можно только уменьшить); общие типы, которые сегодня импортируют 20+ файлов окна из `../main/*`, выносятся в `@cyborg/contracts` до переноса; `experimental_`-члены внесены в реестр аудита.
- **traced from:** BR-CH-001.
- **источник:** bb 8 (`check-provider-literal-ratchet`); dsh 6 (`check-workspace-constraints`); [ресёрч-2, 5.2](../../research/sad2-validation.md#52-допущения-sad2-которые-код-нарушает) п. 5 (21 из 38 модулей `src/main` импортируют `node:*`, `electron` или `node-pty` напрямую).
- **verification:** испытание - тесты проверки на заведомо нарушающих фикстурах.
- **класс:** Process.

### FR-CH-3006 Сохранность данных пользователя при переносе

- **Требование:** данные пользователя не теряются: файл воркспейса, `commands.json`, `prompts.json`, `hubs.json`, `trackers.json`, `recent-workspaces.json`, `extensions-usage.json` и ключи окна `cyborg.*` переносятся миграцией ([FR-CH-3011](#fr-ch-3011-перенос-формата-воркспейса), [FR-CH-3012](#fr-ch-3012-перенос-файлов-пользователя-и-localstorage)) без потери содержимого и без ручных действий; старый `projects.json` по-прежнему открывается как воркспейс. Пока работает прежний код, он не стирает данные нового формата ([FR-CH-3010](#fr-ch-3010-шаг-0-подготовка-на-текущем-коде)). Формат меняется только по правилам [ADR-CH-0002](../../03-architecture/adr/ADR-CH-0002-manifest-and-compatibility.md) и [ADR-CH-0014](../../03-architecture/adr/ADR-CH-0014-secrets-config-state.md). Прежнее «читаются новой версией без миграции и пишутся прежнего формата» снято: SAD2 переводит формат один раз.
- **traced from:** BR-CH-002.
- **источник:** SAD2, 3.10; ресёрч-2, 5.1, 5.4.
- **verification:** испытание - тест миграции эталонных файлов, снятых с версии `e4beb72`: содержимое после миграции эквивалентно исходному; старый `projects.json` открывается как воркспейс.
- **класс:** Compatibility.

### FR-CH-3007 Бюджеты производительности

- **Требование:** до начала P1 снимаются и записываются базовые значения: время до готового окна, время открытия окон поиска, расширений, панелей, память приложения; на каждой фазе значения не хуже базовых более чем на 10% (допустимое значение предлагается). `scripts/measure.mjs` сегодня замеряет только время загрузки панели задач и MR через CLI: скрипт расширяется замерами старта и памяти, иначе базы нет ([NFR-CH-1001](../01-plugin-host/srs.md#nfr-ch-1001-бюджет-запуска)). Бюджеты горячих путей - [NFR-CH-2003](../02-extension-contracts/srs.md#nfr-ch-2003-задержка-вызова-через-шлюз), [NFR-CH-2004](../02-extension-contracts/srs.md#nfr-ch-2004-задержка-вывода-терминала).
- **traced from:** BR-CH-007.
- **источник:** ресёрч-2, 5.1 и раздел 6 (вопрос 9).
- **verification:** испытание - замер (`npm run measure`, дымовой тест) на каждой фазе, результат в [план паритета](../../04-verification/parity-plan.md#8-базовые-метрики-p0).
- **класс:** Performance.

### FR-CH-3008 Переименование окна «Расширения»

- **Требование:** при переносе функции в плагин `claude-extensions` меню и окно «Расширения» переименовываются в «Расширения Claude Code»; сочетание `Cmd/Ctrl+Shift+X` и вкладки не меняются; тесты меню, дымовой тест, руководство и корпус фичи 14 основного корпуса обновляются тем же PR.
- **traced from:** BR-CH-002.
- **источник:** [ADR-CH-0008](../../03-architecture/adr/ADR-CH-0008-terminology.md).
- **verification:** испытание - обновлённые `menu.test.ts`, дымовой тест; осмотр руководства.
- **класс:** Functions.

### FR-CH-3009 Условия выхода фазы

- **Требование:** фаза закрывается, только если: паритетные проверки зелёные, все тесты и дымовой тест зелёные, `check:corpus` согласован, храповики проходят, бюджеты в норме, матрица без пустых строк; результат записан в [дорожную карту](../../05-plans/roadmap.md). Спайки, которые SAD2 оставляет непроверенными (клавиши настоящей клавиатурой, Monaco и xterm под `sandbox`, `claude` в pty-хосте, сторож), закрыты до фазы, которая от них зависит.
- **traced from:** BR-CH-002.
- **verification:** осмотр - запись о закрытии фазы со ссылками на прогон CI.
- **класс:** Process.

### FR-CH-3010 Шаг 0: подготовка на текущем коде

- **Требование:** до каркаса на прежнем коде выполняются два малых шага: (1) `ProjectStore` сохраняет неизвестные поля файла воркспейса (сегодня он стирает все поля, кроме `commands` - `OWN_FIELDS`, и считает формат `{cyborg: 2, settings}` повреждённым, так как требует массив `projects`); (2) счётчик id сессии `nextId++`, обнуляемый при каждом старте, заменяется устойчивым идентификатором.
- **traced from:** BR-CH-002.
- **источник:** SAD2, 3.10, 5.3, 6.1 (шаг 0); [ресёрч-2, 5.1 и 5.2](../../research/sad2-validation.md#51-что-в-sad2-и-parity-plan-неверно-или-неточно); открытый вопрос 17 SAD2.
- **verification:** испытание - тест: файл с неизвестными полями после загрузки и сохранения прежним `ProjectStore` содержит эти поля; id сессии не повторяется после перезапуска; существующие тесты `ProjectStore` проходят.
- **класс:** Compatibility.

### FR-CH-3011 Перенос формата воркспейса

- **Требование:** старый формат `{projects, lastProjectId, commands}` (`src/main/workspaces.ts`, `src/main/projects.ts`) `config` переводит один раз: `id`, `name`, `description`, `repos` - в `settings.projects`; `trackers` и `jira` - в `settings.trackers.byProject`; `commands` - в раздел плагина `command-buttons`; `lastProjectId` - в `state`. Код миграции - единственное место, где ядро знает чужие поля, и он удаляется через пару версий. Сегодняшняя копия повреждённого файла (`<файл>.corrupt-<время>`) в SAD2 не упомянута; поведение сохраняется до отдельного решения.
- **traced from:** BR-CH-002.
- **источник:** SAD2, 3.10; [ADR-CH-0014](../../03-architecture/adr/ADR-CH-0014-secrets-config-state.md); ресёрч-2, 5.1 (в списке полей миграции SAD2 не хватало `commands`), 5.4.
- **verification:** испытание - тест на эталонном файле: каждое поле попадает в назначенный раздел, повторный запуск миграции ничего не меняет, секретов в результате нет.
- **класс:** Compatibility.

### FR-CH-3012 Перенос файлов пользователя и `localStorage`

- **Требование:** файлы пользователя `commands.json`, `prompts.json`, `hubs.json`, `trackers.json` переезжают в разделы `config` и `state` соответствующих плагинов; ключи `localStorage` окна `cyborg.*` (шрифт, уведомления, фильтры панелей; FR-10002 основного корпуса) переносятся в `state`, потому что у `<iframe>` с другим origin они иначе теряются. Остальные файлы получают назначение в матрице паритета: `extensions-usage.json` - `state` или `plugin-data`; `claude-hooks.json` и `sessions/<pid>-<id>.jsonl` - `plugin-data` агента (имя без pid); `recent-workspaces.json` - «Недавние» ядра.
- **traced from:** BR-CH-002.
- **источник:** SAD2, 3.10, 5.3; [ресёрч-2, 5.4](../../research/sad2-validation.md#54-что-на-диске) (назначения последних трёх файлов - предложение ресёрча, SAD2 их не называет).
- **verification:** испытание - тест: настройки интерфейса и кнопки-команды пользователя после миграции совпадают с прежними; `static-guards` по спискам писателей файлов и ключей `localStorage` обновлён с сохранением утверждений.
- **класс:** Compatibility.

### FR-CH-3013 Порядок первого этапа

- **Требование:** первый этап идёт в порядке: (0) шаг 0 ([FR-CH-3010](#fr-ch-3010-шаг-0-подготовка-на-текущем-коде)); (1) pty-хост ядра с `persist` и `attach` на текущем коде, видимый пользователю сразу ([FR-CH-1021](../01-plugin-host/srs.md#fr-ch-1021-pty-хост-ядра-persist-list-attach-буфер-resize)); (2) спайки до каркаса: сделаны стоимость хостов и `<iframe>`, мост `MessagePort`, права Node, `ses`; остаются клавиши настоящей клавиатурой, Monaco и xterm в кадре, `claude` в pty-хосте, сторож; (3) каркас: воркспейс, загрузка, версии, реестр контрактов, `config` и `state` с переносом, хост `builtin` со сторожем, `<iframe>` с `mount`; (4) пилот `session-notifications` (не `path-drop`: он в этой модели часть `sessions` и не проверяет ни контракт, ни права); (5) перенос остальных функций по одному плагину, каждый с проверкой паритета.
- **traced from:** BR-CH-002, BR-CH-001.
- **источник:** SAD2, 6.1.
- **verification:** осмотр - дорожная карта следует этому порядку; запись о закрытии шагов 2 и 4 ссылается на результаты спайков и пилота.
- **класс:** Process.

### FR-CH-3014 Восстановление сессий (условно)

- **Требование (условное, пока владелец не отменит non-goal основного корпуса):** `sessions` ведёт в своём `state` список открытых сессий `{agent, resumeId, cwd, projectId, title, order}`; после перезапуска хоста или окна подключается к живым pty (`attach`), после перезапуска приложения поднимает сессии через `resume` поставщика `cyborg.agent`. Настройка `sessions.restore`: `lazy` (по умолчанию: вкладки сразу, процесс агента при первом показе вкладки), `eager`, `off`. Сбой `resume` показывает вкладку с причиной, а не теряет её. Привязка задачи или MR к сессии (FR-1015, FR-2014 основного корпуса) только в памяти и при восстановлении теряется.
- **traced from:** BR-CH-002, BR-CH-006.
- **источник:** SAD2, 5.3, 6.1 (шаг 1), вопрос 15; [ресёрч-2, 5.5](../../research/sad2-validation.md#55-требования-основного-корпуса-которые-sad2-меняет). **Противоречит non-goal «восстановление сессий» в `docs/01-product/brd.md`, FR-1015 и FR-2014 (закреплено `static-guards.test.ts`); нужно решение владельца и изменение основного корпуса.**
- **verification:** испытание (после решения владельца) - тест: восстановление в режимах `lazy`, `eager`, `off`; сбой `resume`; десять сессий не поднимают десять процессов при `lazy`. До решения требование не реализуется.
- **класс:** Functions.

### FR-CH-3015 Перенос тестов с сохранением утверждений

- **Требование:** `smoke.mjs` (проверяет DOM окна: `#tree`, `#session-list`, заголовок, `localStorage`) и `static-guards.test.ts` (закрытые списки писателей файлов и ключей `localStorage`) переписываются вместе с переносом UI в `<iframe>` и данных в `state`; утверждения сохраняются, меняется только способ их проверки; расхождение, которое нельзя сохранить, вносится в allowlist паритета.
- **traced from:** BR-CH-002.
- **источник:** SAD2, 5.5 (последняя строка); [ресёрч-2, 5.2](../../research/sad2-validation.md#52-допущения-sad2-которые-код-нарушает) п. 6.
- **verification:** осмотр PR по чек-листу плана паритета; число утверждений в `smoke.mjs` и `static-guards.test.ts` не уменьшается.
- **класс:** Process.

### FR-CH-3016 Владельцы пробелов паритета

- **Требование:** в матрице паритета названы плагины-владельцы для функций, которых нет среди пяти плагинов базовой части: `git` (контракт `cyborg.git`: `root`, `branch`, `status`, `headContent`, `branches`, `switch`; право `process` на `git`; потребители `files`, `viewer`, `search`, `trackers`, `command-buttons`; `git:switch` по-прежнему отказывает, если репозиторий занят сессией); `command-buttons` (раздел `config`, `commands.json`, `prompts.json`, редакторы, подстановки `{branch}`, вклад в панель инструментов, динамические сочетания); `claude-extensions` (окно «Расширения», `extensions:*`, `hubs:*`); `search`; `session-notifications` (фокус из `ctx.window.onFocusChange`, активная сессия из `cyborg.sessions`). Для каждой функции из таблицы SAD2 5.5 названо требование, которое её закрывает: меню ([FR-CH-2031](../02-extension-contracts/srs.md#fr-ch-2031-вклады-плагинов-в-меню)), сочетания с условиями (2029), отмена запросов (2016), вклады в промпт (2032), заголовок и буфер обмена (2033), каталог из диалога (2034).
- **traced from:** BR-CH-002.
- **источник:** SAD2, 5.5, вопрос 16; [ресёрч-2, 5.3](../../research/sad2-validation.md#53-каналы-ipc-и-владелец-в-модели-sad2). Бросок файлов ОС в окно (FR-3004 основного корпуса) и перетаскивание MIME между кадрами - открытый вопрос 11 SAD2.
- **verification:** испытание - скрипт [FR-CH-3001](#fr-ch-3001-матрица-паритета): ни один канал и ни одна функция не остаются без плагина-владельца.
- **класс:** Process.

### NFR-CH-3001 Обратимость шага

- **Требование:** каждый шаг переноса можно откатить без потери данных пользователя: прокладка остаётся до закрытия фазы; пока работает прежний код, он сохраняет неизвестные поля ([FR-CH-3010](#fr-ch-3010-шаг-0-подготовка-на-текущем-коде)), поэтому откат не стирает данные нового формата.
