# BRD: Cyborg Harness - ядро и плагины

> Составлено по запросу владельца (2026-11-02): «сделать Cyborg таким же [как bb и DeepSeek Harness]: чтобы было ядро, чтобы были плагины, работало всё круто и качественно, и то, что уже сейчас есть, было сохранено». Решения составителя не согласованы, статус `review`. Идентификаторы с префиксом `CH-` не пересекаются с корпусом основного продукта (`docs/01-product/`).

## 1. BRS overview

Cyborg сегодня - цельное приложение: возможности (дерево файлов, поиск, задачи, MR, статус, кнопки-команды, окно расширений Claude Code) связаны через три общих файла и знают о Claude Code напрямую. Это замедляет развитие, не позволяет подключить другого агента и не позволяет расширять приложение снаружи. Решение: перестроить Cyborg в **ядро и плагины** по образцу изученных проектов [bb](../research/bb.md) и [DeepSeek Harness](../research/deepseek-harness.md), с сохранением всех нынешних возможностей. Документ адресован владельцу продукта и тем, кто проектирует и реализует перестройку.

## 2. Business purpose

1. Снизить стоимость и риск добавления возможности: новая возможность - плагин, а не правка трёх общих файлов.
2. Подключать других агентов, помимо Claude Code, без форка ядра.
3. Дать пользователям и командам расширять приложение своими плагинами безопасно.
4. Ничего не потерять из существующего: поведение, данные, требования, тесты.

## 3. Business scope

Внутри границы: загрузчик плагинов и манифест; реестр сервисов, событий и команд; шлюз IPC; слоты интерфейса; провайдеры агента и трекера; три уровня доверия; перенос всех нынешних функций во встроенные плагины; паритетные проверки; набор для автора плагина; раздел «Плагины Cyborg».

`non-goals`:

- свой цикл модели, замена Claude Code или перехват его вывода (сессия остаётся нативной);
- облако, удалённые хосты, мобильный клиент, учётные записи пользователей;
- публичный каталог плагинов и обновление плагинов из каталога (после P5);
- Windows (по-прежнему не поддерживается);
- вынос в плагины оболочки окна и терминала (остаются в ядре);
- копирование масштаба образцов: сотни пакетов, двуязычные документы, 100% покрытие по файлам.

## 4. Стороны

| Сторона | Интерес |
|---|---|
| Пользователь Cyborg | Всё работает как раньше; позже - выбор и контроль плагинов |
| Владелец продукта | Управляемое развитие, предсказуемая стоимость, безопасность |
| Мейнтейнер | Добавлять возможности без правки общих файлов |
| Автор плагина (команда, сообщество) | Понятный API, тестовый хост, стабильная совместимость |
| Авторы агентов (Claude Code, другие CLI) | Подключение без форка |

## 5. Бизнес-требования

### BR-CH-001 Модульность

- **Требование:** новая возможность добавляется как плагин без правки `main.ts`, `preload.ts`, `app.ts`, `index.html` и общего `styles.css`.
- **traced from:** цель владельца «ядро и плагины».
- **rationale:** reason - каждая возможность сегодня правит три общих файла (58 каналов, 65 методов моста, 1360 строк оболочки); assumptions - семи точек расширения хватает ([ADR-CH-0005](../03-architecture/adr/ADR-CH-0005-extension-points.md)); relationships - BR-CH-002.
- **MOE:** число общих файлов, которые надо править при добавлении возможности: сегодня 3-5, цель 0 (измеряется на пилотных плагинах P1-P2).

### BR-CH-002 Сохранение возможностей

- **Требование:** после перестройки доступны все нынешние возможности с прежним поведением, прежние данные пользователя читаются без миграции.
- **traced from:** прямое условие владельца «то, что уже сейчас есть, было сохранено».
- **rationale:** reason - продукт живой, 153 требования и 893 теста; relationships - [план паритета](../04-verification/parity-plan.md), [ADR-CH-0006](../03-architecture/adr/ADR-CH-0006-strangler-migration-and-parity.md).
- **MOE:** на каждом шаге миграции: 153 из 153 требований подтверждены, 893 теста и дымовой тест зелёные, строк матрицы паритета без плагина и проверки - 0, потерянных функций - 0.

### BR-CH-003 Подключение других агентов

- **Требование:** новый pty-агент подключается плагином-провайдером без правок ядра.
- **traced from:** цель «модульный клиент для агентов, локальных и готовых вроде Claude Code».
- **rationale:** reason - Claude Code зашит в `sessions.ts`, `claude-args.ts`, `history.ts`; assumptions - агент имеет CLI с хуками или файловыми следами; relationships - [ADR-CH-0004](../03-architecture/adr/ADR-CH-0004-agent-provider-contract.md).
- **MOE:** второй провайдер (P3) пишется без правок ядра; общий набор тестов провайдера проходит оба.

### BR-CH-004 Сторонние плагины

- **Требование:** автор создаёт, тестирует и устанавливает сторонний плагин по документации, пользователь видит и подтверждает его права.
- **traced from:** цель «подключать их плагинами».
- **rationale:** reason - расширения должны появляться без правок ядра; relationships - BR-CH-005; сторонние плагины включаются только после P3 ([OVERVIEW, вопрос 1](../OVERVIEW.md#9-открытые-решения-нужен-ответ-владельца)).
- **MOE:** автор доводит рабочий плагин от шаблона до установки за день по руководству (проверяется пробным плагином в P4).

### BR-CH-005 Безопасность и доверие

- **Требование:** плагин не получает прав сверх заявленных в манифесте и подтверждённых; недоверенный код не исполняется в главном процессе; есть безопасный режим.
- **traced from:** инварианты продукта (секреты вне интерфейса, чтение по умолчанию, проверка путей).
- **rationale:** reason - рядом работают сессии с правами пользователя; образцы дают плагинам полное доверие и это не подходит ([ADR-CH-0003](../03-architecture/adr/ADR-CH-0003-trust-and-isolation.md)).
- **MOE:** все вызовы возможностей проходят проверку в шлюзе (0 обходов в тестах отказов); в безопасном режиме загружены только встроенные плагины.

### BR-CH-006 Наблюдаемость и устойчивость

- **Требование:** состояние каждого плагина видно пользователю и в логе; сбой плагина не роняет приложение и не затрагивает остальные плагины.
- **traced from:** слабость молчаливого ожидания зависимостей у dsh и скрытых сбоев у bb.
- **rationale:** reason - плагины множат места отказа; relationships - [SAD, раздел 17](../03-architecture/design/sad.md#17-наблюдаемость).
- **MOE:** в тестах отказов (исключение при активации, при монтировании слота, в обработчике) приложение остаётся рабочим, причина сбоя видна в разделе «Плагины Cyborg».

### BR-CH-007 Производительность

- **Требование:** перестройка не ухудшает время запуска и отклика заметно.
- **traced from:** опыт образцов (рост цены загрузки при множестве плагинов).
- **rationale:** reason - десяток плагинов при старте; assumptions - ленивая активация; relationships - [SAD, раздел 19](../03-architecture/design/sad.md#19-нефункциональные-требования).
- **MOE:** время до готового окна и открытия окон поиска, расширений и панелей не хуже базового более чем на 10% (базовое значение снимается в P0).

## 6. Ограничения

1. Сессия остаётся нативным `claude` в pty; вывод не подменяется.
2. Главный процесс не доверяет интерфейсу; пути - только из разрешённых корней.
3. Интерфейс на обычном DOM, `innerHTML` запрещён.
4. Новых зависимостей по возможности нет; плагины - папки в одном пакете.
5. Форматы данных пользователя не меняются в рамках миграции.

## 7. Предположения и риски

Предположения: семи точек расширения хватит для всех нынешних функций (проверено классификацией, подтверждается пилотами P1-P2); `utilityProcess` годится для плагинов L2 (спайк в P4). Риски и меры - [OVERVIEW, раздел 8](../OVERVIEW.md#8-риски).
