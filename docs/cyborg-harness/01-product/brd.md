# BRD: Cyborg Harness - ядро и плагины

> Составлено по запросу владельца (2026-11-02): «сделать Cyborg таким же [как bb и DeepSeek Harness]: чтобы было ядро, чтобы были плагины, работало всё круто и качественно, и то, что уже сейчас есть, было сохранено». Решения составителя не согласованы, статус `review`. Идентификаторы с префиксом `CH-` не пересекаются с корпусом основного продукта (`docs/01-product/`). Документ приведён к [SAD2](../03-architecture/design/sad2.md): бизнес-требования менялись только там, где были привязаны к снятым решениям.

## 1. BRS overview

Cyborg сегодня - цельное приложение: возможности (дерево файлов, поиск, задачи, MR, статус, кнопки-команды, окно расширений Claude Code) связаны через три общих файла и знают о Claude Code напрямую. Это замедляет развитие, не позволяет подключить другого агента и не позволяет расширять приложение снаружи. Решение: перестроить Cyborg в **ядро и плагины** по образцу изученных проектов [bb](../research/bb.md) и [DeepSeek Harness](../research/deepseek-harness.md), с сохранением всех нынешних возможностей. Ядро - хост плагинов без предметной области: агенты, сессии, файлы, проекты и трекеры - обычные плагины, связанные только контрактами. Документ адресован владельцу продукта и тем, кто проектирует и реализует перестройку.

## 2. Business purpose

1. Снизить стоимость и риск добавления возможности: новая возможность - плагин, а не правка трёх общих файлов.
2. Подключать других агентов, помимо Claude Code, без форка ядра.
3. Дать пользователям и командам расширять приложение своими плагинами безопасно.
4. Ничего не потерять из существующего: поведение, данные, требования, тесты.

## 3. Business scope

Внутри границы: ядро как хост плагинов (воркспейс, загрузчик с манифестом, версиями и графом контрактов, хосты со сторожем, pty-хост, шлюз безопасности, каркас и рендер, клавиши и события, главный конфиг и состояние); связь плагинов через контракты, команды и типы данных; UI плагина в своём `<iframe>`; секреты (хранилище ядра, ссылки на источники); права плагинов и изоляция трёх видов (сбоев и рендера - с первого этапа, доступа - на втором этапе по поводу); агент как обычный плагин, поставщик контракта; перенос всех нынешних функций во встроенные плагины и перенос данных пользователя; паритетные проверки; набор для автора плагина; раздел «Плагины Cyborg».

`non-goals`:

- свой цикл модели, замена Claude Code или перехват его вывода (сессия остаётся нативной);
- облако, удалённые хосты, мобильный клиент, учётные записи пользователей;
- публичный каталог плагинов и обновление плагинов из каталога (повод для второго этапа изоляции, не часть первого);
- Windows (по-прежнему не поддерживается);
- агент, сессии, терминал, файлы, проекты и трекеры в ядре: ядро рисует каркас по манифестам, остальное - плагины;
- копирование масштаба образцов: сотни пакетов, двуязычные документы, 100% покрытие по файлам.

## 4. Стороны

| Сторона | Интерес |
|---|---|
| Пользователь Cyborg | Всё работает как раньше; позже - выбор и контроль плагинов |
| Владелец продукта | Управляемое развитие, предсказуемая стоимость, безопасность |
| Мейнтейнер | Добавлять возможности без правки общих файлов |
| Автор плагина (команда, сообщество) | Понятный API, тестовый хост, стабильная совместимость |
| Авторы агентов (Claude Code, другие CLI) | Подключение без форка |

## 5. Бизнес-требования

### BR-CH-001 Модульность

- **Требование:** новая возможность добавляется как плагин без правки `main.ts`, `preload.ts`, `app.ts`, `index.html` и общего `styles.css`.
- **traced from:** цель владельца «ядро и плагины».
- **rationale:** reason - каждая возможность сегодня правит три общих файла (58 каналов, 61 член моста, 1360 строк оболочки); assumptions - контрактов, команд и типов данных хватает для всех нынешних функций (пробелы паритета названы в [SAD2, 5.5](../03-architecture/design/sad2.md#55-пробелы-паритета-найденные-сверкой-с-кодом); [ADR-CH-0010](../03-architecture/adr/ADR-CH-0010-contracts-instead-of-services.md), [ADR-CH-0009](../03-architecture/adr/ADR-CH-0009-core-boundary-and-compactness.md)); relationships - BR-CH-002.
- **MOE:** число общих файлов, которые надо править при добавлении возможности: сегодня 3-5, цель 0 (измеряется на пилотных плагинах P1-P2).

### BR-CH-002 Сохранение возможностей

- **Требование:** после перестройки доступны все нынешние возможности с прежним поведением; данные пользователя переносятся без потерь и без ручных действий (формат воркспейса и файлы пользователя переводятся одной миграцией).
- **traced from:** прямое условие владельца «то, что уже сейчас есть, было сохранено».
- **rationale:** reason - продукт живой, 153 требования и 925 тестов; assumptions - восстановление сессий противоречит non-goal основного корпуса и входит только по решению владельца ([SAD2, вопрос 15](../03-architecture/design/sad2.md#8-открытые-вопросы)); relationships - [план паритета](../04-verification/parity-plan.md), [ADR-CH-0006](../03-architecture/adr/ADR-CH-0006-strangler-migration-and-parity.md), [ADR-CH-0014](../03-architecture/adr/ADR-CH-0014-secrets-config-state.md).
- **MOE:** на каждом шаге миграции: 153 из 153 требований подтверждены, 925 тестов и дымовой тест зелёные, строк матрицы паритета без плагина и проверки - 0, потерянных функций и данных - 0.

### BR-CH-003 Подключение других агентов

- **Требование:** новый pty-агент подключается плагином, поставщиком контракта `cyborg.agent`, без правок ядра.
- **traced from:** цель «модульный клиент для агентов, локальных и готовых вроде Claude Code».
- **rationale:** reason - Claude Code зашит в `sessions.ts`, `claude-args.ts`, `history.ts`; assumptions - агент имеет CLI с хуками или файловыми следами; relationships - [ADR-CH-0010](../03-architecture/adr/ADR-CH-0010-contracts-instead-of-services.md) (меняет [ADR-CH-0004](../03-architecture/adr/ADR-CH-0004-agent-provider-contract.md)).
- **MOE:** второй поставщик `cyborg.agent` (P5) пишется без правок ядра; общий набор тестов контракта проходят оба.

### BR-CH-004 Сторонние плагины

- **Требование:** автор создаёт, тестирует и устанавливает сторонний плагин по документации, пользователь видит и подтверждает его права.
- **traced from:** цель «подключать их плагинами».
- **rationale:** reason - расширения должны появляться без правок ядра; relationships - BR-CH-005; сторонние плагины и их установка относятся ко второму этапу изоляции и включаются по поводу (автор вне команды или каталог), после P3 ([OVERVIEW, вопрос 1](../OVERVIEW.md#9-открытые-решения-нужен-ответ-владельца), [ADR-CH-0011](../03-architecture/adr/ADR-CH-0011-isolation-stages.md)).
- **MOE:** автор доводит рабочий плагин от шаблона до установки за день по руководству (проверяется пробным плагином на втором этапе).

### BR-CH-005 Безопасность и доверие

- **Требование:** права плагина видны с первого этапа (прозрачность); гарантию «ничего сверх объявленного и подтверждённого» для стороннего кода даёт второй этап; код плагинов не исполняется в главном процессе; секреты не попадают в `config`, `state` и журнал; есть безопасный режим.
- **traced from:** инварианты продукта (секреты вне интерфейса, чтение по умолчанию, проверка путей).
- **rationale:** reason - рядом работают сессии с правами пользователя; образцы дают плагинам полное доверие и это не подходит; права `process` и `pty` дают программе все права пользователя ОС (честная граница); relationships - [ADR-CH-0011](../03-architecture/adr/ADR-CH-0011-isolation-stages.md) (заменяет [ADR-CH-0003](../03-architecture/adr/ADR-CH-0003-trust-and-isolation.md)), [ADR-CH-0014](../03-architecture/adr/ADR-CH-0014-secrets-config-state.md).
- **MOE:** все вызовы возможностей проходят проверку в шлюзе (0 обходов в тестах отказов); значений секретов в `config`, `state` и журнале - 0; в безопасном режиме все плагины выключены.

### BR-CH-006 Наблюдаемость и устойчивость

- **Требование:** состояние каждого плагина видно пользователю и в журнале; сбой, зависание или падение плагина не роняет окно и не затрагивает остальные хосты и процессы агентов.
- **traced from:** слабость молчаливого ожидания зависимостей у dsh и скрытых сбоев у bb.
- **rationale:** reason - плагины множат места отказа; relationships - [ADR-CH-0012](../03-architecture/adr/ADR-CH-0012-hosts-watchdog-pty-host.md), [SAD, раздел 17](../03-architecture/design/sad.md#17-наблюдаемость).
- **MOE:** в тестах отказов (исключение при активации, в вызове, при монтировании вида; зависший и упавший хост) окно остаётся рабочим, pty с `persist` живы, причина сбоя видна в разделе «Плагины Cyborg».

### BR-CH-007 Производительность

- **Требование:** перестройка не ухудшает время запуска и отклика заметно.
- **traced from:** опыт образцов (рост цены загрузки при множестве плагинов).
- **rationale:** reason - десяток плагинов при старте, хосты и `<iframe>` плагинов добавляют процессы (хост около 15 МБ, кадр общего origin около 3 МБ, измерено в [ресёрче-2](../research/sad2-validation.md)); assumptions - ленивая активация; relationships - [SAD, раздел 19](../03-architecture/design/sad.md#19-нефункциональные-требования).
- **MOE:** время до готового окна и открытия окон поиска, расширений и панелей не хуже базового более чем на 10% (допустимое значение предлагается; базовое значение не снято и снимается в P0, `scripts/measure.mjs` старт и память не замеряет).

## 6. Ограничения

1. Сессия остаётся нативным `claude` в pty; вывод не подменяется.
2. Главный процесс не доверяет интерфейсу; пути - только из разрешённых корней.
3. Интерфейс на обычном DOM, `innerHTML` запрещён.
4. Новых зависимостей по возможности нет; плагины - папки в одном пакете.
5. Данные пользователя не теряются: формат воркспейса и файлы пользователя переводятся одной миграцией, пока работает прежний код, он сохраняет неизвестные поля файла.

## 7. Предположения и риски

Предположения: контрактов, команд и типов данных хватит для всех нынешних функций (пробелы паритета названы и закрываются в [SAD2, 5.5](../03-architecture/design/sad2.md#55-пробелы-паритета-найденные-сверкой-с-кодом)); `utilityProcess` годится для хостов плагинов и pty-хоста (измерено, не проверены клавиши настоящей клавиатурой, Monaco и xterm под `sandbox`, `claude` в pty-хосте и сторож - [ресёрч-2, раздел 7](../research/sad2-validation.md#7-что-осталось-непроверенным)); для стороннего кода потребуется процесс на плагин (второй этап). Риски и меры - [OVERVIEW, раздел 8](../OVERVIEW.md#8-риски), [SAD2, раздел 9](../03-architecture/design/sad2.md#9-риски).
