# SRS фичи 01 - ядро и загрузчик плагинов

## 1. SRS overview

Требования к загрузчику: манифест, совместимость, жизненный цикл, зависимости, сбои, безопасный режим, диагностика, набор автора. Контракты точек расширения - [фича 02](../02-extension-contracts/srs.md); перенос функций - [фича 03](../03-migration/srs.md). Устройство - [SAD](../../03-architecture/design/sad.md), разделы 5-6 и 17. Формат требований - как в корпусе основного продукта; верификация указана как план (реализации пока нет).

## 2. Требования

### FR-CH-1001 Манифест плагина

- **Требование:** манифест - блок `cyborg` в `package.json` плагина со строгой схемой; лишние поля отклоняются; обязательны `id`, `title`, `engines.cyborg`, `engines.api`; необязательны `main`, `renderer`, `activation`, `requires`, `provides`, `capabilities`, `contributes`, `storage.legacy`. `id` уникален; префикс `cyborg.` зарезервирован за встроенными.
- **traced from:** BR-CH-001.
- **источник:** ресёрч bb 5.1, dsh 5; [ADR-CH-0002](../../03-architecture/adr/ADR-CH-0002-manifest-and-compatibility.md).
- **verification:** испытание - модульные тесты схемы: валидный манифест, лишнее поле, нет обязательного, повтор `id`, зарезервированный префикс.
- **класс:** Functions.

### FR-CH-1002 Проверка совместимости до загрузки кода

- **Требование:** до импорта кода плагина проверяются `engines.cyborg` (диапазон версий приложения) и `engines.api` (версия API равна текущей); несовместимый плагин получает статус `Invalid` с причиной и не загружается.
- **traced from:** BR-CH-006.
- **источник:** bb 5.1; dsh 5; ADR-CH-0002.
- **verification:** испытание - тесты на диапазоны и версии API; код плагина-пробы не выполняется (счётчик загрузок равен нулю).
- **класс:** Functions.

### FR-CH-1003 Обнаружение и состояния

- **Требование:** встроенные плагины обнаруживаются из реестра, собранного при сборке; пользовательские - из каталога установки (после P4). Состояния: `Discovered`, `Invalid`, `Validated`, `Waiting`, `Activating`, `Active`, `Failed`, `Unloading`, `Disabled` ([SAD, 6.2](../../03-architecture/design/sad.md#62-жизненный-цикл)).
- **traced from:** BR-CH-006.
- **verification:** испытание - тест перехода состояний по таблице.
- **класс:** Functions.

### FR-CH-1004 Зависимости и видимое ожидание

- **Требование:** `requires` разрешается топологически; плагин с отсутствующим сервисом получает `Waiting` и причину «ждёт сервис X», а не молчит; появление сервиса запускает активацию; цикл зависимостей называется ошибкой с перечнем участников.
- **traced from:** BR-CH-006.
- **источник:** dsh 11 (молчаливый PENDING как слабость); ADR-CH-0001.
- **verification:** испытание - тесты: отсутствующий сервис, цикл, поздний провайдер.
- **класс:** Functions.

### FR-CH-1005 Активация с тайм-боксом и изоляцией сбоя

- **Требование:** активация выполняется с тайм-боксом (по умолчанию 30 с); исключение или превышение времени переводит плагин в `Failed` с причиной, не затрагивает другие плагины и не останавливает приложение; повтор - с экспоненциальной задержкой до 60 с, сбрасывается через 5 минут здоровой работы.
- **traced from:** BR-CH-006.
- **источник:** bb 5.4, 5.3 (`background`).
- **verification:** испытание - тест с плагином, который бросает, виснет, падает асинхронно.
- **класс:** Functions.

### FR-CH-1006 Откат регистраций

- **Требование:** каждая регистрация плагина (сервис, событие, команда, канал IPC, слот, настройка) возвращает `Disposable`; выгрузка снимает все в обратном порядке и ждёт асинхронные; после выгрузки в реестрах не остаётся записей плагина.
- **traced from:** BR-CH-001, BR-CH-006.
- **источник:** dsh 2 (эффекты с откатом), dsh 10 (HMR-safety тест).
- **verification:** испытание - **HMR-safety тест каждого реестра**: загрузить плагин, выгрузить, проверить, что записей нет.
- **класс:** Functions.

### FR-CH-1007 Каскад зависимых

- **Требование:** выгрузка или сбой провайдера сервиса выгружает зависимые плагины (статус `Waiting`), возврат сервиса активирует их снова.
- **traced from:** BR-CH-006.
- **verification:** испытание - тест цепочки A -> B -> C.
- **класс:** Functions.

### FR-CH-1008 Ленивая активация

- **Требование:** плагин с `activation: "lazy"` активируется при первом вызове его команды, первом показе его слота или первом запросе его сервиса; `startup` - при запуске. Декларативный `contributes` виден ядру без запуска кода плагина.
- **traced from:** BR-CH-007.
- **verification:** испытание - тест: до первого вызова код плагина не загружен; замер времени запуска на пилотных плагинах (NFR-CH-1001).
- **класс:** Functions.

### FR-CH-1009 Безопасный режим

- **Требование:** запуск с флагом или переменной окружения активирует только ядро и встроенные плагины; сторонние (после P4) не загружаются; режим виден в интерфейсе.
- **traced from:** BR-CH-005.
- **источник:** bb 5.4 (`safe-mode`).
- **verification:** испытание - тест на наличие и отсутствие L2 в графе; дымовой тест запуска.
- **класс:** Functions.

### FR-CH-1010 Раздел «Плагины Cyborg» и журнал

- **Требование:** раздел показывает у каждого плагина состояние, причину, версию, источник, права, время активации; у каждого плагина журнал `userData/logs/plugins/<id>.log` с ротацией; флаг `--dump-plugins` печатает разрешённый граф и порядок активации.
- **traced from:** BR-CH-006.
- **verification:** испытание - тесты модели раздела и формата дампа; дымовой тест открывает раздел.
- **класс:** Functions.

### FR-CH-1011 Атомарная перезагрузка

- **Требование:** новая версия плагина загружается как кандидат; прежняя снимается только после успешной активации; при ошибке остаётся прежняя со статусом «reload failed» и причиной.
- **traced from:** BR-CH-006.
- **источник:** bb 5.4.
- **verification:** испытание - тест перезагрузки с исправной и сломанной версией.
- **класс:** Functions.

### FR-CH-1012 Версия API

- **Требование:** `API_VERSION` - целое число; интерфейс и главный процесс сверяют его на старте; несовпадение показывается явной ошибкой, приложение не работает частично. Каждый новый публичный член API имеет префикс `experimental_` и запись в реестре аудита.
- **traced from:** BR-CH-001.
- **источник:** bb 3 (версия протокола демона), bb 5.3.
- **verification:** испытание - тест рукопожатия версии; проверка реестра аудита скриптом (каждый `experimental_` член внесён).
- **класс:** Functions.

### FR-CH-1013 Набор автора плагина

- **Требование:** шаблон плагина, тестовый хост (настоящий загрузчик, подставные `claude`, `gh`, `jira`, `renderSlot`), проверка «плагин импортирует только публичный API», описанный порядок сборки и установки из локальной папки.
- **traced from:** BR-CH-004.
- **источник:** bb 5.8 (`createFakePluginHost`, `public-sdk-only`); dsh 10.
- **verification:** демонстрация - пробный плагин от шаблона до работы за день (P4); испытание - сам тестовый хост покрыт тестами.
- **класс:** Functions.

### NFR-CH-1001 Бюджет запуска

- **Требование:** время до готового окна с загрузкой всех встроенных плагинов не хуже базового более чем на 10%; базовое значение снимается в P0 (`npm run measure` и дымовой тест).
- **traced from:** BR-CH-007.
- **verification:** испытание - замер на каждой фазе, результат записывается в план.
- **класс:** Performance.

### NFR-CH-1002 Устойчивость

- **Требование:** необработанная ошибка плагина (при активации, в обработчике, при монтировании слота) не завершает ни главный процесс, ни окно.
- **traced from:** BR-CH-006.
- **verification:** испытание - тесты отказов; дымовой тест с намеренно сбойным плагином-пробой.
- **класс:** Reliability.

### NFR-CH-1003 Размер публичного API

- **Требование:** публичный API ядра ограничен семью точками расширения ([ADR-CH-0005](../../03-architecture/adr/ADR-CH-0005-extension-points.md)); восьмая вводится только новым ADR.
- **traced from:** BR-CH-001.
- **verification:** осмотр - реестр аудита и список точек в `plugin-api`.
- **класс:** Maintainability.
