# decision-log фичи 01 - ядро и загрузчик плагинов

Решения составителя по запросу владельца. Исход «открыто» - допущение, принятое за владельца; подтверждает либо меняет владелец продукта. Записи D-11 и далее фиксируют решения [SAD2](../../03-architecture/design/sad2.md) и [ресёрча-2](../../research/sad2-validation.md); заменённые записи не удалены, а помечены в колонке «Исход».

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | Своё минимальное ядро, без Cordis и без форка | Cordis как зависимость; форк Cordis | ADR-CH-0001 (уточнён [ADR-CH-0009](../../03-architecture/adr/ADR-CH-0009-core-boundary-and-compactness.md)); цена чужой парадигмы и форка у dsh | открыто |
| D-02 | Манифест - блок `cyborg` в `package.json` | Отдельный `cyborg-plugin.json`; манифест как код | ADR-CH-0002; npm-совместимость на будущее, статические проверки | открыто |
| D-03 | Плагины - папки в одном пакете, не отдельные npm-пакеты | pnpm workspaces на плагин | Ритуалы образцов; храповик даёт ту же границу | открыто |
| D-04 | Статус `Waiting` с названием недостающего сервиса виден пользователю | Молчаливое ожидание (как dsh) | dsh 11 | **снято: заменено D-12** (граф проверяется до запуска кода, отказ вместо ожидания) |
| D-05 | Тайм-бокс активации 30 с, бэкофф до 60 с | Без тайм-бокса | bb 5.4 | **снято: заменено D-14** (сторож с порогами) |
| D-06 | Ленивая активация по умолчанию для окон (поиск, расширения), `startup` для оболочки | Всё при старте | NFR-CH-1001; SAD2, 3.2 (активация по первому показу вида или первой команде) | открыто |
| D-07 | Нужны ли **сторонние** плагины вообще | Только внутренняя модульность | Вопрос 1 [OVERVIEW](../../OVERVIEW.md#9-открытые-решения-нужен-ответ-владельца); по умолчанию «да, по поводу»: он же запускает этап 2 (D-17) | **открыто, нужен ответ владельца** |
| D-08 | Структура репозитория: `src/core`, пакет объявлений `@cyborg/contracts`, `src/plugins/<id>` | Отдельные пакеты | Вопрос 5 OVERVIEW; SAD2, 4 (прежний `src/plugin-api` заменён `@cyborg/contracts`) | открыто |
| D-09 | Первый пилотный плагин - `path-drop` | `search`; `command-buttons` | Самый малый и изолированный; проверяет каркас без риска | **снято: заменено D-11 фичи 03** (пилот `session-notifications`, `path-drop` - часть `sessions`) |
| D-10 | Реестр API на аудит - файл `plugin-api/AUDIT.md`, проверка скриптом | Без реестра | bb 5.3 (`api_to_audit.md`) | открыто |
| D-11 | Ядро - хост плагинов без предметной области; задача входит в ядро, только если нужна всем плагинам или окну без плагинов и плагин не решит её сам, не нарушив гарантию остальным; центральных плагинов нет | Ядро с рантаймом сессий, уведомлениями и шиной (SAD, 5); выделенные центральные плагины | [ADR-CH-0009](../../03-architecture/adr/ADR-CH-0009-core-boundary-and-compactness.md); SAD2, 2 | принято в SAD2 |
| D-12 | Граф контрактов разрешается до запуска кода; недостающий поставщик, два при `one` и цикл - отказ плагину с причиной в журнале | Статус `Waiting` (D-04); последний поставщик выигрывает | [ADR-CH-0010](../../03-architecture/adr/ADR-CH-0010-contracts-instead-of-services.md); SAD2, 3.2, 4 | принято в SAD2 |
| D-13 | Главные части плагинов - в хостах `utilityProcess`; группы задаёт `plugins.hosts`: встроенные в `builtin`, сторонние каждый в своём; пользователь может переопределить с предупреждением | Все плагины в главном процессе; один общий хост для всех; процесс на плагин сразу | [ADR-CH-0012](../../03-architecture/adr/ADR-CH-0012-hosts-watchdog-pty-host.md); [ресёрч-2, 2.1](../../research/sad2-validation.md#21-хост-плагинов-в-utilityprocess): 15 МБ, 70-100 мс, круг 47 мкс; VS Code делит хост между расширениями | принято в SAD2 |
| D-14 | Сторож со стартовыми порогами: ответ раз в 5 с, порог 15 с, 3 перезапуска за 5 минут, выключение плагина после 3 зависаний подряд; следит и за pty-хостом | Без сторожа, как в VS Code для локального хоста; перезапуск без выключения виновника | ADR-CH-0012; ресёрч-2, 4.1 и раздел 7: прецедента нет, пороги проверяются тестом до каркаса | принято в SAD2; **значения подтвердить тестом** |
| D-15 | pty держит отдельный pty-хост ядра (`utilityProcess`): `persist`, `list`, `attach`, кольцевой буфер, `resize` после `attach`, льготное время для сироты | pty в главном процессе; pty в плагине; pty в общем хосте плагинов | ADR-CH-0012; ресёрч-2, 4.1 (ptyHost в VS Code), 2.1 (`node-pty` в хосте загружается); зависание нативного модуля не должно замораживать окно | принято в SAD2; хвост или снимок экрана - открытый вопрос 12 |
| D-16 | Воркспейс - процесс на воркспейс; повторное открытие отказывает («Воркспейс уже открыт») | Второй экземпляр передаёт путь первому (`requestSingleInstanceLock`); одно приложение с несколькими окнами | SAD2, 3.1 и раздел 10; [ресёрч-2, 5.1](../../research/sad2-validation.md#51-что-в-sad2-и-parity-plan-неверно-или-неточно): в коде `requestSingleInstanceLock` нет, FR-1029 и FR-1033 | принято в SAD2; модель процессов - открытый вопрос 13 |
| D-17 | Изоляция трёх видов: сбоев и рендера - с первого этапа для всех плагинов, доступа - второй этап по поводу (сторонний автор или каталог); права видны с первого этапа как прозрачность, гарантию даёт второй | Уровни доверия L0-L2 с изоляцией сторонних в одной модели; изоляция доступа сразу | [ADR-CH-0011](../../03-architecture/adr/ADR-CH-0011-isolation-stages.md) (заменяет [ADR-CH-0003](../../03-architecture/adr/ADR-CH-0003-trust-and-isolation.md)); SAD2, 6; Obsidian, Figma ([ресёрч-2, 4.2, 4.4](../../research/sad2-validation.md)) | принято в SAD2 |
| D-18 | Этап 2: процесс на плагин (Electron как Node) с `--permission`, `Compartment` (`ses`) вторым слоем; сеть и окружение держит шлюз | `utilityProcess` с `--permission`; `Compartment` как единственная граница | ADR-CH-0011; [ресёрч-2, 2.2 и 2.3](../../research/sad2-validation.md): флаг в `utilityProcess` не применяется, `Compartment` пробивается (Figma), цена 12 МБ на процесс | принято в SAD2 |
| D-19 | Безопасный режим выключает все плагины без исключений | Безопасный режим оставляет встроенные плагины | SAD2, 3.2; окно без плагинов - нормальное состояние (D-11); режим новый для Cyborg, [ресёрч-2, 5.5](../../research/sad2-validation.md#55-требования-основного-корпуса-которые-sad2-меняет) | принято в SAD2 |
| D-20 | Смена набора плагинов в v1 - перезапуск хостов и окна; горячей выгрузки, каскада и атомарной перезагрузки нет, `Disposable` ведутся с первого дня | Атомарная перезагрузка с кандидатом (FR-CH-1011); каскад зависимых (FR-CH-1007) | SAD2, 3.2; ADR-CH-0010 | принято в SAD2 |
| D-21 | Дисциплина первого этапа (асинхронные члены, `structuredClone`, импорт только `@cyborg/contracts`, доступ к ОС через `ctx.os`) проверяется тестами | Проверка ревью; изоляция доступа сразу | ADR-CH-0011; SAD2, 6.1; MetaMask Snaps ([ресёрч-2, 4.3](../../research/sad2-validation.md)) | принято в SAD2 |
