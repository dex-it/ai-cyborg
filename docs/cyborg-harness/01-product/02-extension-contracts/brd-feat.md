# BRD фичи 02 - контракты, UI плагинов, клавиши, секреты и права

Источник: запрос владельца (2026-11-02), [ресёрч](../../research/comparison.md) и [SAD2](../../03-architecture/design/sad2.md) (проверен [ресёрчем-2](../../research/sad2-validation.md)). Родитель - [BRD продукта](../brd.md): BR-CH-001, BR-CH-003, BR-CH-004, BR-CH-005.

## 1. BRS overview

Плагин полезен ровно настолько, насколько ему есть как связаться с другими плагинами и с ядром. Образцы показали две крайности: у bb контракты интерфейса на 6000 строк и сотни `experimental_`-членов, у dsh 108 классифицированных сервисов. Нам нужна одна узкая модель: плагины знают друг друга только через контракты в манифесте (имя, версия, кратность, типы без логики), ядро проверяет граф до запуска кода, а доступ к ОС идёт только через шлюз по объявленным правам. Агент - обычный плагин, поставщик контракта `cyborg.agent`. UI плагина живёт в своём `<iframe>`, секреты держит хранилище ядра. Модель закрывает все нынешние функции, позволяет подключить второй агент без правок ядра и выдерживает недоверенный код на втором этапе.

## 2. Business purpose

Дать единый способ связи (контракты, команды по имени, MIME при перетаскивании), чтобы функции Cyborg и чужие плагины подключались одинаково, а другие агенты - без правок ядра; дать понятные права и безопасное обращение с секретами.

## 3. Business scope

Внутри: реестр контрактов, версии и `@deprecated`; события как часть контракта владельца; команды, статические и динамические сочетания, вклады в меню; роды областей и виды, UI в `<iframe>` с CSP, origin по классу плагина, мост `MessagePort`, токены темы и элементы ядра, блокировка окна; шлюз `ctx.os` с пространствами имён и областями путей; секреты (хранилище ядра, ссылки `$secret`, контракт `cyborg.secret-source`); `config` и `state` по разделам со схемой и миграцией; контракт `cyborg.agent`, плагины `agent-claude-code` и `trackers`; отмена запросов, вклады в промпт агента. Второй этап: окна согласия.

`non-goals`:

- структурные провайдеры агента (SDK, ACP): отдельный вид контракта позже;
- общая шина событий, реестр сервисов по ключам, `inject`, waterfall и guard;
- общий UI-фреймворк для плагинов и встраивание чужих видов (пока нет случая, который не решается вызовом владельца);
- кроссплагинный доступ к внутренностям (только через контракты);
- окна согласия, установка и подпись плагинов на первом этапе (второй этап).

## 4. Стороны и сценарии

Мейнтейнер, автор плагина, автор плагина агента, пользователь. Сценарии: [второй агент](../../02-use-cases/second-agent/scenario.md), [установка стороннего плагина](../../02-use-cases/third-party-install-permissions/scenario.md), [мейнтейнер добавляет функцию](../../02-use-cases/maintainer-adds-feature/scenario.md), [терминал переживает хост](../../02-use-cases/terminal-survives-host-restart/scenario.md).

## 5. Меры эффективности

| MOE | Значение |
|---|---|
| Все нынешние функции раскладываются на плагины и контракты без обходов через ядро | 100% строк классификации SAD2 (раздел 5.5 закрывает пробелы паритета) |
| Второй поставщик `cyborg.agent` написан без правок ядра | 0 правок ядра |
| Недостающий поставщик, два поставщика при `one` и цикл находятся до запуска кода | 100% в тестах графа |
| Каждый вызов `ctx.os` проходит проверку права в шлюзе | 0 обходов в тестах отказов |
| Конфликт сочетаний находится при загрузке (включая акселераторы меню и динамические сочетания) | 100% конфликтов |
| Значения секретов в `config`, `state` и журнале | 0 |
| Вызов через шлюз (предлагаемое допустимое значение; база: 54-96 мкс) | не более 1 мс на p99 |
| Вывод терминала до экрана (предлагаемое допустимое значение; база: 45 мкс на круг) | не более 16 мс |
| Кадр плагина с общим origin (измерено) | около 3 МБ против около 17 МБ при собственном origin |
