# decision-log фичи 02 - контракты, UI плагинов, клавиши, секреты и права

Решения составителя по запросу владельца. Исход «открыто» - допущение, принятое за владельца. Записи D-12 и далее фиксируют решения [SAD2](../../03-architecture/design/sad2.md) и [ресёрча-2](../../research/sad2-validation.md); заменённые записи не удалены, а помечены в колонке «Исход».

| ID | Решение | Отвергнуто | Основание | Исход |
|---|---|---|---|---|
| D-01 | Семь точек расширения; восьмая - только новым ADR | Широкий API сразу | ADR-CH-0005; bb: 6000 строк контрактов | **снято: заменено D-12** (контракты в манифесте вместо точек расширения) |
| D-02 | Три режима событий: observe, waterfall, guard | Только observe; шесть режимов dsh | Достаточно для нынешних функций; dsh 8 | **снято: заменено D-12** (событие - часть контракта владельца, режимов нет) |
| D-03 | Хуков «ядро спрашивает плагин» с локом нет; единственный guard - `session.start` | Хук как `message.dispatch` bb | Цена лока и тайм-бокса, редкая польза | **снято: заменено D-12** (guard нет совсем) |
| D-04 | Контракт провайдера агента - pty-first; ядро запускает процесс | SDK как основа; ACP как основа | ADR-CH-0004 | **изменено: D-15** (pty-first сохранён, но процесс запускает плагин по праву `pty`, ядро держит) |
| D-05 | Второй провайдер обязателен до стабилизации API (P5) | Стабилизировать по одному агенту | Риск выточенного под один агент контракта; теперь это второй поставщик `cyborg.agent` | открыто |
| D-06 | Вклад в системный промпт - waterfall `session.prompt` | Правка `claude-args.ts` плагинами | Изоляция и кнопки становятся плагинами | **снято: заменено D-25** (контракт-источник фрагментов, `many`) |
| D-07 | Проверка аргументов каналов - свой маленький помощник | zod | Нет новых зависимостей; zod 4.6 не загружается в `Compartment` ([ресёрч-2, 2.3](../../research/sad2-validation.md)) | открыто |
| D-08 | Диалоги - слой ядра, а не вклад плагина | Диалог как слот | Единая доступность и фокус у ядра; диалоги и меню выходят за рамку `<iframe>` только через слой ядра (SAD2, 3.8) | открыто |
| D-09 | Единый реестр сочетаний, проверка при загрузке | Ручной список занятых | D-27 фичи 12 основного корпуса; расширен D-24 | открыто |
| D-10 | L2: отдельный процесс (`utilityProcess`), изолированное окно для интерфейса | Один процесс с полным доверием; `vm` | ADR-CH-0003; спайк в P4 | **снято: заменено D-18 фичи 01** (процесс на плагин с `--permission`, `utilityProcess` флаг не применяет) |
| D-11 | Какой второй агент проверит контракт | - | Выбор владельца (вопрос 3 OVERVIEW); теперь проверяет `cyborg.agent` | **открыто, нужен ответ владельца** |
| D-12 | Связь плагинов только через контракты в манифесте (`provides` / `requires` / `optional` / `consumes`); события - часть контракта владельца; пакет `@cyborg/contracts`; реестр сервисов по ключам, шина, `inject`, waterfall и guard сняты | Семь точек расширения и реестр сервисов (D-01); общая шина событий; режимы событий (D-02, D-03) | [ADR-CH-0010](../../03-architecture/adr/ADR-CH-0010-contracts-instead-of-services.md) (заменяет [ADR-CH-0005](../../03-architecture/adr/ADR-CH-0005-extension-points.md)); SAD2, 3.4, 4; в изученных системах прямых данных о контрактах нет ([ресёрч-2, 4.7](../../research/sad2-validation.md)) | принято в SAD2 |
| D-13 | Кратность объявляет потребитель: `one` - ровно один поставщик, при двух отказ при загрузке и выбор за пользователем; `many` - список | Приоритеты поставщиков; последний регистрирующий выигрывает | ADR-CH-0010; SAD2, 4 | принято в SAD2 |
| D-14 | Версии контрактов семантические; две мажорные одновременно; `@deprecated` живёт до следующей мажорной с журналом вызывающих; `cyborg.*` закреплено за репозиторием, сторонние - по автору | Одна версия контракта; удаление без переходного периода | ADR-CH-0010; SAD2, 3.3 | принято в SAD2 |
| D-15 | Агент - обычный плагин, поставщик `cyborg.agent`; процесс запускает сам агент через `ctx.os.pty` по праву `pty`, ядро держит | Точка расширения `registerAgent`; `LaunchSpec`, который запускает ядро | ADR-CH-0010 (меняет [ADR-CH-0004](../../03-architecture/adr/ADR-CH-0004-agent-provider-contract.md)); [ADR-CH-0012](../../03-architecture/adr/ADR-CH-0012-hosts-watchdog-pty-host.md); SAD2, 3.6, 5 | принято в SAD2 |
| D-16 | Мост окно - хост через `MessageChannelMain` и `postMessage` оболочки, без preload в подкадрах | Preload в каждом подкадре | [ADR-CH-0013](../../03-architecture/adr/ADR-CH-0013-plugin-ui-iframe-bridge.md); [ресёрч-2, 3.3](../../research/sad2-validation.md#33-мост-окно---хост-и-задержки): проверено, 45 мкс | принято в SAD2 |
| D-17 | UI плагина - свой `<iframe>` с CSP по умолчанию (`default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self'; img-src 'self' data:`), у UI нет `ctx.os` | Слоты в общем DOM оболочки (ADR-CH-0007); сеть UI через `connect-src`; общий DOM | ADR-CH-0013 (заменяет [ADR-CH-0007](../../03-architecture/adr/ADR-CH-0007-ui-slots-and-commands.md)); [ресёрч-2, 3.2](../../research/sad2-validation.md#32-изоляция-кадра); Figma, VS Code ([4.1-4.2](../../research/sad2-validation.md)) | принято в SAD2 |
| D-18 | Origin по классу: встроенные делят `cyborg-plugin://builtin/`, сторонние получают `cyborg-plugin://<id>/` | Origin на каждый плагин; `sandbox` без `allow-same-origin` | ADR-CH-0013; [ресёрч-2, 3.1](../../research/sad2-validation.md#31-процессы-и-память): ~17 МБ против ~3 МБ на кадр; `sandbox` с Monaco не проверен | принято в SAD2; `sandbox` - открытый вопрос 11 |
| D-19 | Общего UI-фреймворка нет: токены темы и веб-компоненты ядра; чужой UI не встраивается («задача, а не виджет») | Общий React/UI-фреймворк; встраиваемые виды | ADR-CH-0013; SAD2, 3.8; [ресёрч-2, 4.6](../../research/sad2-validation.md): встраиваемых чужих видов в изученных системах нет | принято в SAD2; составные экраны - отдельное решение при появлении случая |
| D-20 | Блокировка окна `ui.lock`: механизм в ядре, политика в плагине | Блокировка целиком в плагине; блокировка в ядре с пином | ADR-CH-0013; SAD2, 3.8, 5.4: плагин не может закрыть чужие `<iframe>`, не нарушив изоляцию рендера | принято в SAD2 |
| D-21 | `pty.share()`: вывод из pty-хоста в `<iframe>` напрямую по `MessagePort`, мимо хоста плагина | Вывод через хост плагина; вывод через главный процесс | ADR-CH-0012, ADR-CH-0013; [ресёрч-2, 3.3](../../research/sad2-validation.md#33-мост-окно---хост-и-задержки): 1,9 ГБ/с, 45 мкс | принято в SAD2 |
| D-22 | Секреты: хранилище ядра (`safeStorage`, ключи `<pluginId>/<key>`) - корень доверия; источник секретов (`cyborg.secret-source`) - плагин; в `config` только ссылка `$secret`; значения не кэшируются и не пишутся | Все `secrets.get` через плагин-источник; значения в `config` | [ADR-CH-0014](../../03-architecture/adr/ADR-CH-0014-secrets-config-state.md); SAD2, 3.7: источник видел бы секреты всех плагинов | принято в SAD2 |
| D-23 | `config` и `state` по разделам плагина со схемой и версией; `migrate` до активации; откат версии - отказ только плагину | Единый конфиг без схем; ошибка раздела роняет окно | ADR-CH-0014; SAD2, 3.3, 3.10 | принято в SAD2 |
| D-24 | Системные сочетания - акселераторы меню до спайка (`before-input-event` с фокусом в `<iframe>` не подтверждён); динамические сочетания с условиями `ctx.keys.register` для кнопок пользователя | Перехват только `before-input-event`; статические сочетания для кнопок | SAD2, 3.9; [ресёрч-2, 3.4 и 5.2](../../research/sad2-validation.md#34-клавиши-не-подтверждено) | принято в SAD2; спайк с настоящей клавиатурой |
| D-25 | Пробелы паритета закрываются в ядре и контрактах: вклады плагинов в меню (`contributes.menus`), отмена запросов (идентификатор и сообщение отмены), контракт-источник фрагментов промпта, заголовок и фокус окна, буфер обмена, каталог из диалога через `projects` | Оставить пробелы до переноса | SAD2, 5.5; [ресёрч-2, 5.3 и 6](../../research/sad2-validation.md) | принято в SAD2; форма API - вопрос 14 |
| D-26 | Два класса плагинов: интеграции по HTTP API (`net: ["config:baseUrl"]`) и базовые модули с `process` и `pty`; для интеграций правило «HTTP API, а не CLI» | Единое описание всех прав; трекеры на CLI в узком классе | SAD2, 3.7; [ресёрч-2, 5.1](../../research/sad2-validation.md#51-что-в-sad2-и-parity-plan-неверно-или-неточно): трекеры сегодня на CLI, переход на API - новое требование | принято в SAD2; переход трекеров на API - **открыто, нужен ответ владельца** |
