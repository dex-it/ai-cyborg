# Автор создаёт плагин

- **Актор:** автор плагина (в команде или вне её).
- **Цель:** от шаблона до работающего плагина за день.
- **Предусловия:** есть набор автора (шаблон, тестовый хост); сторонние плагины включены (после P4).
- **Требования:** BR-CH-004; FR-CH-1001, FR-CH-1002, FR-CH-1013, FR-CH-2012.

## Основной ход

1. Автор копирует шаблон: `package.json` с блоком `cyborg`, `main`, `renderer`.
2. В манифесте указывает `id`, `engines`, `requires` (например, `git`), `capabilities` (`process.git`) и вклад: команду с сочетанием и слот `panel`.
3. Пишет `main` (регистрация обработчика канала, команды) и `renderer` (функция монтирования в панель).
4. Запускает тесты через тестовый хост: настоящий загрузчик, подставные `claude`, `gh`; проверка «только публичный API» проходит.
5. Устанавливает плагин из локальной папки; Cyborg показывает права и просит подтвердить (сценарий [установка стороннего плагина](../third-party-install-permissions/scenario.md)).
6. Плагин активируется; пункт меню и панель появляются.

## Альтернативы

- **А1. Конфликт сочетания.** Загрузчик отклоняет запись и называет, с чем конфликт (FR-CH-2004).
- **А2. Несовместимая версия API.** Статус `Invalid` с причиной; код плагина не выполнялся (FR-CH-1002).

## Постусловия

Плагин живёт в каталоге установки, его данные - в `userData/plugins/<id>/`.
