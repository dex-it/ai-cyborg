# Автор создаёт плагин

- **Актор:** автор плагина (в команде или вне её).
- **Цель:** от шаблона до работающего плагина за день.
- **Предусловия:** есть набор автора (шаблон, тестовый хост). Плагин автора из команды попадает в поставку сборкой (первый этап). Установка плагина автора вне команды возможна только на втором этапе ([сценарий установки](../third-party-install-permissions/scenario.md)).
- **Требования:** BR-CH-004; FR-CH-1001, FR-CH-1002, FR-CH-1013, FR-CH-1020, FR-CH-2012, FR-CH-2014, FR-CH-2021.

## Основной ход

1. Автор копирует шаблон: манифест (`package.json` с блоком `cyborg`), главная часть, UI.
2. В манифесте указывает `id`, `version`, `engines.cyborg`, контракты (`requires`: `cyborg.git`; при желании `provides`), `permissions` (например, `process` на `git`), вклад: команду с сочетанием в `keybindings` и вид в панели инструментов основной области (род области и `order`).
3. Пишет главную часть (`activate(ctx)`: регистрация команды, обращение к `ctx.contracts.get('cyborg.git')`, доступ к ОС только через `ctx.os`) и UI (`mount(root, ctx)` в своём `<iframe>`, токены темы и элементы ядра).
4. Запускает тесты через тестовый хост: настоящий загрузчик, подставные `ctx.os` и программы; проверки дисциплины проходят: члены контрактов асинхронные, данные переживают `structuredClone`, импорт только `@cyborg/contracts` и своих модулей, доступ к ОС только через `ctx.os`.
5. Плагин попадает в поставку (команда) или ждёт второго этапа (вне команды); в «Плагины Cyborg» права показаны человеческим языком.
6. Плагин активируется в своей группе хоста; граф контрактов проверен до запуска кода; команда и вид появляются.

## Альтернативы

- **А1. Конфликт сочетания.** Загрузчик сообщает, с чем конфликт, при загрузке; сочетание достаётся встроенному плагину, между равными - первому по `id`; пользователь может переназначить в `config` (FR-CH-2004).
- **А2. Несовместимая версия API.** Плагин не загружается, причина в журнале; код плагина не выполнялся (FR-CH-1002).
- **А3. Нарушена дисциплина.** Импорт `node:fs`, функция в результате вызова или вызов `ctx.os.fs` без права - тест падает, плагин не принимается в поставку (FR-CH-1020).
- **А4. Нет поставщика `requires`.** Плагин не загружается, причина называет недостающий контракт (FR-CH-1004).

## Постусловия

Данные плагина - в `plugin-data`, настройки и состояние - в его разделах `config` и `state` со схемой и версией (FR-CH-2008).
