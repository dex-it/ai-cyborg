# Мейнтейнер добавляет функцию как плагин

- **Актор:** разработчик Cyborg.
- **Цель:** добавить новую возможность, не трогая общие файлы и ядро.
- **Требования:** BR-CH-001; FR-CH-1013, FR-CH-1020, FR-CH-2014, FR-CH-3002, FR-CH-3005, NFR-CH-1004.

## Основной ход

1. Мейнтейнер создаёт папку `src/plugins/<id>` с манифестом, главной частью и UI.
2. Описывает в манифесте контракты (`provides` / `requires` / `optional` / `consumes`), права, команды, сочетания, виды, разделы `config` и `state` со схемой; пишет код только против `@cyborg/contracts` и своих модулей.
3. Добавляет тесты через тестовый хост и строку матрицы паритета, если функция заменяет существующую.
4. CI проверяет границы: нет импортов `node:*`, `electron` и чужих плагинов, ядро не импортирует плагины, число прямых обращений непереведённого кода к `electron` и `fs` не выросло.
5. Правки `main.ts`, `preload.ts`, `app.ts`, `index.html`, `styles.css` не требуются (MOE BR-CH-001).
6. PR проходит тесты, дымовой тест и `check:corpus`; в корпусе заводятся требование и решение.

## Альтернативы

- **А1. Нужного контракта нет.** Контракт добавляется в `@cyborg/contracts` (минорная версия для нового необязательного члена, мажорная для несовместимого) или объявляется плагином-владельцем; общая шина событий и реестр сервисов не вводятся (FR-CH-2014).
- **А2. Функция требует правки ядра.** Допустимо, только если запись в ADR показывает, что функция нужна всем плагинам или окну без плагинов и плагин не решит её сам, не нарушив гарантию остальным (NFR-CH-1004).

## Постусловия

Функция отключается без поломки остального приложения: плагины, у которых она была `optional`, продолжают работать.
