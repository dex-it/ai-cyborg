# Терминал продолжает работать, пока хост плагина зависает и перезапускается

- **Актор:** пользователь, ведущий сессию Claude Code.
- **Цель:** зависание или перезапуск хоста плагина не прерывает работу в терминале; после возврата плагин подключается к тому же процессу.
- **Предусловия:** `sessions` и `agent-claude-code` работают в хосте `builtin`; сессия запущена с `persist: true`, процесс держит pty-хост ядра; UI `sessions` получил билет `pty.share()` и показывает терминал в своём `<iframe>`.
- **Требования:** BR-CH-006, BR-CH-003; FR-CH-1017, FR-CH-1018, FR-CH-1021, FR-CH-1022, FR-CH-2024, NFR-CH-1002, NFR-CH-2004.

## Основной ход

1. Пользователь работает в терминале: вывод идёт из pty-хоста прямо в `<iframe>` по `MessagePort`, ввод - обратно, мимо хоста плагина.
2. Хост `builtin` зависает (один из плагинов хоста вошёл в бесконечный цикл). Терминал продолжает показывать вывод и принимать ввод; временно не обновляются то, что считает хост: статус сессии, события хуков, уведомления, список сессий.
3. Сторож не получает ответа хоста 15 секунд и перезапускает его; другие хосты, окно и pty-хост не затронуты; запись о перезапуске идёт в журнал плагинов.
4. Плагины хоста активируются заново. `agent-claude-code` вызывает `ctx.os.pty.list()` (видны только его pty) и `ctx.os.pty.attach(id)`: возвращается тот же `PtyHandle` с `backlog` - выводом, накопленным без владельца; ядро отправляет `resize`, и TUI перерисовывает экран.
5. `sessions` подключается к живым pty и выдаёт UI новый билет `pty.share()`; терминал продолжает работу в том же процессе `claude`.
6. Статус сессии, события и уведомления возобновляются; в «Плагины Cyborg» запись о перезапуске хоста.

## Альтернативы

- **А1. Плагин не вернулся.** После трёх зависаний подряд сторож выключает плагин; осиротевший pty завершается по истечении льготного времени (значение выбирается в P1); при ручном выключении плагина ядро спрашивает, завершать ли процессы (FR-CH-1022).
- **А2. Падает pty-хост.** Процессы pty теряются, плагины получают это как завершение; сторож перезапускает pty-хост; окно не замирает (FR-CH-1018).
- **А3. Перезагрузка окна.** Воркспейс, хосты и pty остаются; терминал подключается заново (FR-CH-1015).
- **А4. Перезапуск приложения.** Процессы pty завершаются; сессии поднимаются через `resume` только если принято решение владельца по FR-CH-3014 (противоречит non-goal основного корпуса).
- **А5. Что показывает экран после `attach`.** Сырой хвост буфера (может начинаться посреди escape-последовательности, TUI перерисуется по `resize`) или снимок экрана (headless-xterm) - открытый вопрос 12 SAD2; не проверено на настоящем `claude`.

## Постусловия

Процесс `claude` тот же, что до зависания; данные не потеряны в пределах кольцевого буфера ядра; остальные плагины и хосты не перезапускались. Зависание нескольких плагинов одного хоста остановило бы их всех, поэтому группировку по хостам пользователь может менять (FR-CH-1016).
