# Сравнение bb, dsh и Cyborg

Основано на разборах [bb](bb.md) и [DeepSeek Harness](deepseek-harness.md) и на исходном состоянии [Cyborg](cyborg-today.md). Последняя колонка - целевое решение по [SAD2](../03-architecture/design/sad2.md); обоснования - в ADR (`../03-architecture/adr/`), прежде всего [ADR-CH-0009](../03-architecture/adr/ADR-CH-0009-core-boundary-and-compactness.md) и [ADR-CH-0010](../03-architecture/adr/ADR-CH-0010-contracts-instead-of-services.md). Первая версия колонки (ядро с реестром сервисов, шиной событий и около восьми точек расширения) снята: проверка SAD2 ([ресёрч-2](sad2-validation.md)) и решения владельца её заменили.

## 1. Сводная таблица

| Тема | bb | dsh | Cyborg сегодня | Cyborg цель |
|---|---|---|---|---|

| **Что запускает** | Агента через мост провайдера (SDK Claude Code, ACP) | Свой цикл модели; внешних - как субагентов через SDK | Интерактивный `claude` в pty | pty-провайдеры; позже SDK и ACP как другие виды |

## 2. Что у Cyborg иначе

1. **Агент интерактивный и живёт в pty.** И bb, и dsh управляют агентом структурным протоколом (SDK, ACP, собственный цикл) и сами строят из него таймлайн. Cyborg держит настоящий терминал с человеком внутри, а о происходящем узнаёт косвенно: хуки, файлы, git. Интерактивный Claude Code в pty ни bb, ни dsh не встраивают (dsh запускает его как неинтерактивный субагент). Значит, контракт агента (`cyborg.agent`) придётся проектировать самим; у образцов берётся форма (рукопожатие, закрытые наборы, типизированное восстановление), а не готовая реализация.
2. **Порядок событий не наш.** Журнал как источник правды (dsh) и серверная нумерация событий (bb) требуют, чтобы мы владели циклом агента. У нас нет: журналы пишет Claude Code, а мы читаем.
3. **Один пользователь, одна машина.** Облако, удалённые демоны, мобильный клиент и модель прав пользователей нам не нужны. Это убирает целые подсистемы bb.
4. **Продукт уже есть и работает.** У bb и dsh плагинная архитектура - с самого начала. У нас - миграция действующего приложения с 153 требованиями, поэтому паритет важнее красоты (раздел 4).
5. **Интерфейс без фреймворка.** У bb React и шимы, у dsh Cordis-клиент. У Cyborg обычный DOM с функцией `el()` и охранным правилом «нет `innerHTML`». Вклад плагина в интерфейс - функция монтирования `mount(root, ctx)` в его собственном `<iframe>`; общего UI-фреймворка нет, плагину даются токены темы и веб-компоненты ядра.
6. **Над нами стоит ещё одна плагинная система.** Claude Code сам имеет плагины, скиллы, серверы MCP; окно «Расширения» их показывает и ставит. Плагины Cyborg должны быть видны отдельно и называться иначе.

## 3. Что берём

Колонка «Где используем» дана по первоначальным ADR; что из этого пересмотрено SAD2 - в примечании под таблицей.

| Идея | Откуда | Где используем |
|---|---|---|
| Минимальное ядро: загрузчик (реестр сервисов и общая шина событий после SAD2 не берутся) | dsh | ADR-CH-0001, ADR-CH-0009 |
| Откат регистраций: все регистрации возвращают `Disposable`, выгрузка плагина снимает всё (`inject` и каскад зависимых не берутся) | dsh | ADR-CH-0001, ADR-CH-0010 |
| Видимая причина отказа вместо молчаливого PENDING: граф контрактов проверяется до запуска кода, причина - в журнале плагинов | ответ на слабость dsh | ADR-CH-0010 |
| Definition, Provider, Consumer; «не делить заранее» | dsh | ADR-CH-0001, ADR-CH-0004 |
| ~~Режимы событий: наблюдать, waterfall, guard~~ - не берём после SAD2 | dsh | ADR-CH-0005 заменён ADR-CH-0010 |
| Манифест со строгой схемой, диапазон совместимости, проверка до запуска кода; в SAD2 дополнен `provides` / `requires` / `optional` / `consumes` | bb | ADR-CH-0002, ADR-CH-0010 |
| ~~Целочисленная версия API~~ - заменена семантическими версиями API плагинов и контрактов | bb | ADR-CH-0002, SAD2 3.3 |
| Префикс `experimental_` и реестр API на аудит; upgrade-guide на каждое ломание | bb, dsh | ADR-CH-0002 |
| Нулевая привилегия первых лиц: встроенные пользуются публичным API, одним путём с плагинами | bb | ADR-CH-0001, ADR-CH-0006 |
| Три рантайма плагина: главная часть, отдельный процесс, интерфейсный бандл - в SAD2 это хост, процесс на плагин (второй этап) и `<iframe>` | bb | ADR-CH-0003 заменён ADR-CH-0011, ADR-CH-0012 |
| Атомарная перезагрузка (кандидат, затем переключение), `error` с причиной, безопасный режим | bb | ADR-CH-0003 |
| Граница ошибок на вид и эксклюзивные места; слоты заменены родами областей и `<iframe>` на плагин | bb, dsh | ADR-CH-0007 заменён ADR-CH-0013 |
| Рукопожатие поставщика «факты, а не догадки», типизированное восстановление (контракт `cyborg.agent`) | bb | ADR-CH-0004, ADR-CH-0010 |
| Закрытые исходы подтверждения, отказ по умолчанию | dsh | ADR-CH-0011 |
| Паритет по записанным сессиям, allowlist расхождений, закреплённые счётчики | bb, dsh | ADR-CH-0006, `04-verification/` |
| Тестовый хост SDK; тест через настоящий загрузчик; HMR-safety тест реестра | bb, dsh | `04-verification/` |
| «Храповики»: плагин импортирует только `@cyborg/contracts` и свои модули; нет имён плагинов и агента в коде ядра | bb, dsh | ADR-CH-0006, ADR-CH-0011 |
| Очередь допуска для git; зачистка процессов по cwd; хуки worktree | bb | отдельные задачи после основной миграции |
| Версия формата отдельно от версии приложения; миграции; отказ на будущую версию (откат версии плагина - отказ только ему) | dsh | ADR-CH-0014 |
| Постмортемы как жанр | dsh | `05-plans/` |

**Что изменилось после SAD2.** Не берём общую шину событий, реестр сервисов по ключам, `inject`, waterfall и guard: связь идёт через контракты в манифесте, событие - часть контракта владельца. Берём манифест, паритет по записанным сессиям и откат регистраций через `Disposable`. Строки таблицы, помеченные зачёркиванием, сохранены как история решения.

## 4. Чего не берём

Дробление на сотни пакетов; форк и вендоринг фреймворка; общий глобальный React; облачный и мобильный слои; двуязычие и 100% покрытие по файлам как обязательные ритуалы; установку плагинов через менеджер пакетов с исполнением чужих скриптов; плагины в одном процессе с полными правами как единственный уровень доверия; хуки «ядро спрашивает плагин» с глобальным локом; вынос в плагины сайдбара и композера на раннем этапе; журнал событий как источник правды по сессии. После SAD2 к списку добавлены общая шина событий, реестр сервисов по ключам, `inject`, режимы waterfall и guard, общий UI-фреймворк для плагинов и встраивание чужого UI в свой.

## 5. Выводы

1. Правильная форма для нас - **ядро - хост плагинов без предметной области** (критерий компактности, [ADR-CH-0009](../03-architecture/adr/ADR-CH-0009-core-boundary-and-compactness.md)) с **откатом регистраций через `Disposable`** из dsh, **манифестом, совместимостью и паритетной дисциплиной** из bb и **связью через контракты** вместо реестра сервисов и шины ([ADR-CH-0010](../03-architecture/adr/ADR-CH-0010-contracts-instead-of-services.md)). Без Cordis и без масштаба обоих проектов.
2. **Контракт агента придётся проектировать самостоятельно**: `cyborg.agent`, pty-first, с адаптером событий (хуки Claude Code), чтением истории, вкладом в промпт и типизированным восстановлением. Агент - обычный плагин, а не точка расширения ядра. Структурные поставщики (SDK, ACP) - расширение позже, не основа.
3. **Доверие нужно закладывать сразу.** У обоих образцов сторонний код выполняется без изоляции. У нас рядом работают сессии с правами пользователя, поэтому права в манифесте видны с первого этапа, изоляция сбоев и рендера - тоже с первого, а гарантию доступа даёт второй этап по поводу (сторонний автор, каталог); проверка показала, что `Compartment` для этого одного мало ([ADR-CH-0011](../03-architecture/adr/ADR-CH-0011-isolation-stages.md)).
4. **Миграция идёт «душителем»**: сначала шаг 0 и pty-хост на текущем коде, затем каркас ядра, пилот `session-notifications` и перенос функций в встроенные плагины по одному. Каждый шаг закрывается паритетными проверками.
5. **Размер ритуалов - главный риск процесса**, а не кода: перенимать их выборочно (манифест, паритет, откат регистраций, upgrade-guide, храповики), отбрасывая то, что окупается только большой командой.
