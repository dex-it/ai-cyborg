# Сравнение bb, dsh и Cyborg

Основано на разборах [bb](bb.md) и [DeepSeek Harness](deepseek-harness.md) и на исходном состоянии [Cyborg](cyborg-today.md). Последняя колонка - целевое решение; обоснования - в ADR (`../03-architecture/adr/`).

## 1. Сводная таблица

| Тема | bb | dsh | Cyborg сегодня | Cyborg цель |
|---|---|---|---|---|
| **Позиционирование** | Агентная IDE, управляет собой, треды | Харнес агента, «everything is a plugin» | Рабочее место для параллельных сессий настоящего Claude Code | То же, но с ядром и плагинами |
| **Что запускает** | Агента через мост провайдера (SDK Claude Code, ACP) | Свой цикл модели; внешних - как субагентов через SDK | Интерактивный `claude` в pty | pty-провайдеры; позже SDK и ACP как другие виды |
| **Ядро** | Хранилище, состояния, доставка, рантайм агентов, установка плагинов | Только загрузчик и реестр сервисов (форк Cordis); даже цикл агента - плагин | Всё в одном коде, `main.ts` и `app.ts` как корни | Загрузчик, реестр сервисов, события, IPC-шлюз, сессии, воркспейс; ~8 точек расширения |
| **Единица плагина** | npm-пакет, блок `bb` в `package.json`, строгая схема | npm-пакет, блок `dsh`, плюс функция/класс `Service` | нет | Каталог или пакет, блок `cyborg` в `package.json`, строгая схема |
| **Распространение** | Путь, npm, git, коллекция, встроенные, маркетплейс | Путь, npm, `github:`, tarball; индекс | нет | Встроенные и локальный путь; позже каталог |
| **Совместимость** | `engines.bb`, `engines.bbPluginSdk`, мажор SDK, целочисленная версия протокола демона | `engines.dsh`, исключения `acceptRisk`, upgrade-guide | нет | Диапазон приложения плюс целочисленная версия API; `experimental_`-префикс; upgrade-guide |
| **Изоляция** | Серверный код в процессе сервера, host-код в отдельном процессе, UI в общем контексте | Всё в процессе, без песочницы | Нет понятия | Встроенные - в главном процессе (доверенные); сторонние - отдельный процесс и права из манифеста |
| **Права** | Нет манифеста прав; доверие при установке; безопасный режим | Нет; подтверждения на уровне инструментов агента | Нет | Манифест возможностей (`capabilities`), проверка в шлюзе, безопасный режим |
| **Вклад в интерфейс** | Слоты, React, общий рантайм через шимы | Слоты (`ctx.slots`), компонент не получает контекст | Нет, интерфейс зашит | Слоты на обычном DOM, граница ошибок на слот, компонент получает узкий контекст |
| **Провайдер агента** | JSON-RPC по stdio, рукопожатие, дельты, восстановление, паритет по записям | `SubagentProvider.start() -> Run` одним результатом | Зашит `sessions.ts` и `claude-args.ts` | Контракт pty-провайдера: запуск, события, история, подсказки промпта, восстановление |
| **События** | `events.on` (после факта), один хук `message.dispatch` | Режимы: emit, parallel, serial, bail, waterfall; guard | `SessionManager` излучает `session:*` | Три режима: наблюдать, перехватывать (waterfall), запрещать (guard) |
| **Настройки** | Декларативные, секреты в файле 0600 | Схема, volatile-поля меняются вживую, форма строится сама | Ключи `cyborg.*` и JSON-файлы без реестра | Схема в манифесте, форма из схемы, две области: пользователь и воркспейс |
| **Хранение** | SQLite + таблица событий, свои `data.db` на плагин | Журнал JSONL с версией формата, миграции «рядом» | JSON-файлы, журналы Claude Code | JSON-файлы с пространствами имён плагинов; БД не вводим |
| **Тесты плагинов** | Тестовый хост SDK, конформность моста, паритет по записям, `public-sdk-only`, проверка форка | HMR-safety тест реестра, реальный загрузчик, снапшоты записанных сессий, бенчмарки | 893 теста, smoke с подставными программами | То же направление: тестовый хост, паритет по записанным сессиям, храповики границ |
| **Масштаб** | Огромный: контракты по 6000 строк, облако, мобильный клиент | 372 пакета, 359 скриптов-гейтов | 14 тыс. строк кода | Малый: 5-8 точек расширения, папки в одном пакете |

## 2. Что у Cyborg иначе

1. **Агент интерактивный и живёт в pty.** И bb, и dsh управляют агентом структурным протоколом (SDK, ACP, собственный цикл) и сами строят из него таймлайн. Cyborg держит настоящий терминал с человеком внутри, а о происходящем узнаёт косвенно: хуки, файлы, git. Интерактивный Claude Code в pty ни bb, ни dsh не встраивают (dsh запускает его как неинтерактивный субагент). Значит, контракт провайдера придётся проектировать самим; у образцов берётся форма (рукопожатие, закрытые наборы, типизированное восстановление), а не готовая реализация.
2. **Порядок событий не наш.** Журнал как источник правды (dsh) и серверная нумерация событий (bb) требуют, чтобы мы владели циклом агента. У нас нет: журналы пишет Claude Code, а мы читаем.
3. **Один пользователь, одна машина.** Облако, удалённые демоны, мобильный клиент и модель прав пользователей нам не нужны. Это убирает целые подсистемы bb.
4. **Продукт уже есть и работает.** У bb и dsh плагинная архитектура - с самого начала. У нас - миграция действующего приложения с 153 требованиями, поэтому паритет важнее красоты (раздел 4).
5. **Интерфейс без фреймворка.** У bb React и шимы, у dsh Cordis-клиент. У Cyborg обычный DOM с функцией `el()` и охранным правилом «нет `innerHTML`». Вклад плагина в интерфейс - функция монтирования в переданный узел.
6. **Над нами стоит ещё одна плагинная система.** Claude Code сам имеет плагины, скиллы, серверы MCP; окно «Расширения» их показывает и ставит. Плагины Cyborg должны быть видны отдельно и называться иначе.

## 3. Что берём

| Идея | Откуда | Где используем |
|---|---|---|
| Минимальное ядро: загрузчик, реестр сервисов, события | dsh | ADR-CH-0001 |
| `inject` и эффект с откатом (все регистрации возвращают деструктор, выгрузка целиком, каскад зависимых) | dsh | ADR-CH-0001, ADR-CH-0005 |
| Видимый статус «ожидает сервис X» вместо молчаливого PENDING | ответ на слабость dsh | ADR-CH-0001 |
| Definition, Provider, Consumer; «не делить заранее» | dsh | ADR-CH-0001, ADR-CH-0004 |
| Режимы событий: наблюдать, waterfall, guard (только запрещает) | dsh | ADR-CH-0005 |
| Манифест в `package.json`, строгая схема, два диапазона совместимости, проверка до импорта кода | bb | ADR-CH-0002 |
| Целочисленная версия API | bb | ADR-CH-0002 |
| Префикс `experimental_` и реестр API на аудит; upgrade-guide на каждое ломание | bb, dsh | ADR-CH-0002 |
| Нулевая привилегия первых лиц: встроенные пользуются публичным API, одним путём с плагинами | bb | ADR-CH-0001, ADR-CH-0006 |
| Три рантайма плагина: основной процесс, отдельный процесс, интерфейсный бандл | bb | ADR-CH-0003 |
| Атомарная перезагрузка (кандидат, затем переключение), `error` с причиной, безопасный режим | bb | ADR-CH-0003 |
| Слоты интерфейса, граница ошибок на слот, эксклюзивные слоты с запасным вариантом | bb, dsh | ADR-CH-0007 |
| Рукопожатие провайдера «факты, а не догадки», типизированное восстановление | bb | ADR-CH-0004 |
| Закрытые исходы подтверждения, отказ по умолчанию | dsh | ADR-CH-0003 |
| Паритет по записанным сессиям, allowlist расхождений, закреплённые счётчики | bb, dsh | ADR-CH-0006, `04-verification/` |
| Тестовый хост SDK; тест через настоящий загрузчик; HMR-safety тест реестра | bb, dsh | `04-verification/` |
| «Храповики»: запрет новых импортов ядра в плагины и литералов провайдера в ядре | bb, dsh | ADR-CH-0006 |
| Очередь допуска для git; зачистка процессов по cwd; хуки worktree | bb | отдельные задачи после основной миграции |
| Версия формата отдельно от версии приложения; миграции «рядом»; отказ на будущую версию | dsh | ADR-CH-0002 (данные плагинов) |
| Постмортемы как жанр | dsh | `05-plans/` |

## 4. Чего не берём

Дробление на сотни пакетов; форк и вендоринг фреймворка; общий глобальный React; облачный и мобильный слои; двуязычие и 100% покрытие по файлам как обязательные ритуалы; установку плагинов через менеджер пакетов с исполнением чужих скриптов; плагины в одном процессе с полными правами как единственный уровень доверия; хуки «ядро спрашивает плагин» с глобальным локом; вынос в плагины сайдбара и композера на раннем этапе; журнал событий как источник правды по сессии.

## 5. Выводы

1. Правильная форма для нас - **маленькое собственное ядро в духе dsh** (реестр сервисов, `inject`, откат регистраций, режимы событий) **плюс манифест, совместимость и паритетная дисциплина в духе bb**, без Cordis и без масштаба обоих проектов.
2. **Контракт провайдера агента придётся проектировать самостоятельно**: pty-first, с адаптером событий (хуки Claude Code), чтением истории, вкладом в системный промпт и типизированным восстановлением. Структурные провайдеры (SDK, ACP) - расширение позже, не основа.
3. **Доверие нужно закладывать сразу.** У обоих образцов сторонний код выполняется без изоляции. У нас рядом работают сессии с правами пользователя, поэтому уровни доверия и список возможностей в манифесте - часть первого релиза плагинов, а не поздняя добавка.
4. **Миграция идёт «душителем»**: сначала каркас ядра без смены поведения, затем перенос функций в встроенные плагины от малорисковых к рискованным, оболочку окна - последней. Каждый шаг закрывается паритетными проверками.
5. **Размер ритуалов - главный риск процесса**, а не кода: перенимать их выборочно (манифест, паритет, upgrade-guide, храповики), отбрасывая то, что окупается только большой командой.
