# Разбор bb

Источник: репозиторий [get-bb/bb](https://github.com/get-bb/bb), коммит `916d684` (2026-10-30), сайт [getbb.app](https://getbb.app/). Код только читался: ничего не устанавливалось и не запускалось. Метка **Факт** - прочитано в коде или документе (путь указан от корня репозитория bb), **Вывод** - наша интерпретация. Чего не нашли, названо прямо.

## 1. Что это

bb называет себя «agentic IDE that builds itself»: агентная среда, которая управляет собой, настраивается и автоматизирует себя. Работа идёт в **тредах** (threads), за которыми можно следить, которые можно направлять и передавать другому агенту. Поверхности - десктоп (Electron), веб, CLI и HTTP API, мобильный клиент - равноправны. Поддерживаются агенты Claude, OpenAI, Cursor, Pi, opencode, Grok Build, oh-my-pi, Hermes Agent и ещё несколько. Платформы: macOS Apple Silicon (основная), Linux и Windows (alpha). Установка: десктоп или `npx bb-app@latest`. Заявлено в README: «Core architecture is stable, but workflows and surfaces are still evolving». Лицензия и цены на сайте не указаны.

## 2. Карта репозитория и процессов

**Факт.** pnpm-монорепо с Turbo, TypeScript, ESM, Node 22.19 и выше. Единственный публикуемый артефакт - `packages/bb-app` (лаунчер, CLI `bb`, SDK).

| Процесс | Роль | Как общается |
|---|---|---|
| `apps/server` | Центр: Hono на Node, SQLite (better-sqlite3, Drizzle). Источник правды - БД, сам сервер без состояния | HTTP `/api/v1` (публичный), `/internal` (для демонов), три WebSocket: `/ws`, `/ws/terminals/:id`, `/internal/ws` |
| `apps/host-daemon` | По одному на машину. Запускает агентов, pty-терминалы, наблюдатели файлов, git и worktree | К серверу идёт исходящими соединениями; локальный API на 127.0.0.1:38887 |
| `apps/app` | Веб-интерфейс: React, Vite, TanStack Query; раздаётся сервером | `@bb/sdk/browser` |
| `apps/desktop` | Electron 44. Бизнес-логики не содержит: грузит тот же веб-интерфейс и супервизирует дочерний процесс `bb-app` | Контракт `desktop-contract` на zod, preload с валидацией |
| `apps/cli` | `bb` на commander | `@bb/sdk` по HTTP; контекст агента из `BB_SERVER_URL`, `BB_PROJECT_ID`, `BB_THREAD_ID` |
| `apps/mobile` | Expo, грузит веб-приложение сервера плюс нативные экраны | Тот же SDK |
| Облачная обвязка (`web`, `connect`, `ai-gateway`) | К локальному ядру отношения не имеет | - |

Направление зависимостей: `domain` (схемы zod и конечные автоматы) не зависит ни от чего; над ним `host-daemon-contract`, `server-contract`, затем `db`, `thread-view`, `client-core`, `sdk`, затем приложения. Правило `docs/system-overview.md`: реализации не импортируют друг друга через границу. Правило не абсолютное (демон зависит от `@bb/cli`).

**Вывод.** Продукт большой (около 2260 тестовых файлов; только `apps/host-daemon/src` - 33 тыс. строк). Переносить надо идеи, а не объём.

## 3. Контракты между частями

**Факт.**
- Один типизированный API: `defineRoute` на zod-схемах (`packages/hono-typed-routes`), тип `PublicApiRoutes` собирается в `packages/server-contract` (2180 строк), клиент строится как `hc<PublicApiRoutes>`. Сервер валидирует вход той же схемой.
- Живые обновления: WebSocket присылает `ServerChangedMessage` (какая сущность изменилась), а не данные. На клиенте теговая инвалидация поверх TanStack Query (`@bb/query-tags`, 1900 строк).
- Сервер и демон: рукопожатие `POST /internal/session/open`, сервер сначала сверяет `protocolVersion`, потом разбирает тело. Протокол - одно целое число (`HOST_DAEMON_PROTOCOL_VERSION = 258`), совместимость строго по равенству; несовпадение даёт `protocol_version_mismatch`, демон с `--auto-update` обновляется сам. Heartbeat 5 с, lease 30 с. Команды сервера идут RPC по WebSocket (около 60 типов), события обратно пачками; **порядковый номер события присваивает сервер**.
- Electron: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.

## 4. Доменная модель и хранение

**Факт.** Сущности: Project, Thread, Environment, Host. Сообщений как таблицы нет: всё в append-only таблице `events` с уникальной парой `(threadId, sequence)`; таймлайн - серверная проекция событий. Сообщения пользователя идут через outbox (`queued_thread_messages`) с состоянием, повторами и отложенной отправкой. Жизненные циклы треда и окружения описаны **данными** (таблицы переходов), единственный писатель делает compare-and-swap, недопустимый переход - залогированный no-op; диаграммы в документации генерируются из таблиц тестом.

SQLite в режиме WAL, 150 SQL-миграций Drizzle, `db:push` намеренно не выставлен. Прореживание таблицы событий: удаляются только вытесненные объёмные события, последнее событие треда сохраняется всегда. Восстановление: проход при старте и периодические sweeps (каждые 10 с) по категориям (retention, orphan-cleanup, scheduler и др.). Незавершённый запуск агента автоматически не повторяется. Откатов миграций нет.

## 5. Плагинная система

Это главная часть разбора. Версия SDK плагинов - 0.6.109 (`packages/domain/src/plugin-sdk-version.ts`).

### 5.1 Что такое плагин

**Факт.** Плагин - npm-пакет, манифест в блоке `bb` файла `package.json` (схема `packages/domain/src/plugin-manifest.ts`, строгая, лишние поля отклоняются).

| Поле блока `bb` | Назначение |
|---|---|
| `name`, `description`, `branding` | обязательны |
| `server` | обязательный бэкенд: `export default (bb: BbPluginApi) => void` |
| `app` | необязательный фронтенд на React |
| `host` | необязательный Node-код, который запускается на машине хоста |
| `skills[]`, `themes[]`, `experimental_providers[]` | вклад скиллов, тем, провайдеров |

Совместимость - диапазоны `engines.bb` и `engines.bbPluginSdk`, проверяются на загрузке и при обновлении. Идентификатор выводится из имени пакета (префикс `bb-plugin-` убирается; `bb--` зарезервирован за встроенными). **Манифеста прав и разрешений нет.**

Сборка `bb plugin build` даёт `dist/server.js`, `dist/app.js`, `dist/host.js` и `*.meta.json` (версия SDK, `pluginId`, `pluginVersion`, формат артефакта). Установка отвергает артефакт, у которого id, версия или мажор SDK не совпадают с манифестом.

### 5.2 Распространение

**Факт.** Источники установки: локальный путь, `npm:`, `git:url@ref` (в том числе диапазон semver-тегов), манифест коллекции `.bb/plugins.json`, `builtin:`. Маркетплейс - один файл `marketplace.json` со ссылками на npm или git (код не хранит); адрес по умолчанию `https://getbb.app/marketplace/v2/marketplace.json`. Зарезервированы `bb-official` (внутри приложения, без сети) и `bb-community` (заявка PR-ом в отдельный репозиторий). Установка из git запускает `npm install --omit=dev --omit=optional --ignore-scripts` (скрипты жизненного цикла не выполняются) и затем сборку; передвинутый semver-тег отвергается.

Обновление: `bb plugin outdated` и `update` выбирают только версии, совместимые по обоим диапазонам. **Откат при неудачной активации**: слепок состояния на диске и в БД и окно стабилизации 30 с; если плагин за это время ушёл в `error`, возвращается прежняя версия. Артефакты лежат в неизменяемых каталогах с хешем содержимого, неиспользуемые убирает сборщик мусора. Данные плагина: `<dataDir>/plugins/<id>/` (своя `data.db`, `secrets/` с правами 0600, `logs/plugin.log`).

### 5.3 Точки расширения

**Факт** (`packages/plugin-sdk/src/backend-contract.ts`, `app-contract.ts`).

Бэкенд (`BbPluginApi`):

| Точка | Суть |
|---|---|
| `settings` | Декларативные настройки (string, number, boolean, select, project); секретные хранятся в файле 0600 |
| `storage` | KV (до 256 КБ) и собственная SQLite на плагин |
| `http`, `rpc`, `realtime` | Маршруты `/api/v1/plugins/<id>/...`; RPC типизирован схемами и валидируется на входе и выходе |
| `background` | Сервисы с перезапуском (экспоненциальный бэкофф до 60 с) и cron-расписания |
| `cli` | Подкоманда `bb <имя>`; при коллизии имён побеждает ядро |
| `agents` | `registerTool`, `configure` (какие инструменты и скиллы отдать в сессию), `contributeInstructions` |
| `providers.register` | Провайдер агента |
| `experimental_environments` | Окружения: `availability`, `validate`, `create`, `restore`, `remove` |
| `events.on` | События «уже случилось» (`thread.created`, `thread.idle`, `turn.failed` и др.); возвращаемое значение игнорируется |
| `experimental_hooks.on("message.dispatch")` | **Единственный хук**, на который ядро реагирует: `accept`, `wait` или `reject`; цепочка под глобальным локом, лимит 10 с, при сбое отказ |
| `hosts` | Типизированный RPC к коду плагина на машине |
| `onInstall`, `onDispose` | Жизненный цикл |

Фронтенд (`PluginAppSlots`): страницы и панели (`homepageSection`, `settingsSection`, `navPanel`, вкладки, `sidebarFooterAction`), вклад в тред (`threadAction`, `messageAction`, карточки), рендереры (`fileOpener`, `diffRenderer`, `timelineRenderer`, `providerIcon`), **эксклюзивные замены** (`threadList`, `sidebarNavigation`, `composer`), команды и палитра, контент-скрипты.

**Правило проекта** (`AGENTS.md`): каждый публичный член API имеет префикс `experimental_` и запись в `docs/api_to_audit.md`; API плагина, выполняющий действие ядра, обязан быть тем же путём, которым действует ядро - параллельных путей только для плагинов не заводят.

### 5.4 Жизненный цикл, изоляция, права

**Факт.**
- Серверный код плагина загружается динамическим `import()` **в процессе сервера**, без песочницы. Фабрика выполняется с тайм-боксом 30 с. Новая версия загружается как кандидат: если упала, прежняя остаётся запущенной со статусом «reload failed». Нативные `.node`-модули не поддерживаются.
- Код `host` - отдельный Node-процесс на каждый плагин и каждый хост: пакет скачивается по дайджесту, окружение очищается (`sanitizeInheritedChildProcessEnv`), воркер ленивый и гасится через 5 мин простоя; при падении текущие вызовы падают, следующий поднимает новый воркер.
- Мост провайдера - тоже отдельный процесс, переменные окружения - по списку `env.passthrough`.
- Фронтенд-бандл грузится в общий JS-контекст приложения; контент-скрипты названы «trusted same-origin page code, not a sandbox». Падающий слот скрывается, соседи не затрагиваются.
- Права: манифеста прав нет; защита - «доверие при установке» (подтверждение источника) и глобальный **безопасный режим** `bb plugin safe-mode`, который подавляет загрузку всех не встроенных плагинов. Документация прямо: «Install and update run third-party code with full trust».
- Секреты: файл с правами 0600, запись через временный файл и `rename`; токен HTTP на плагин. Шифрования на диске, подписи пакетов, единой модели прав пользователей не нашли.

### 5.5 Интерфейс плагина

**Факт.** `bb plugin build` собирает `app.tsx` esbuild-ом, стили Tailwind привязываются к плагину селекторами нулевой специфичности. React, react-dom, Radix и другие общие библиотеки не входят в бандл, а подменяются шимами, читающими `globalThis.__bbPluginRuntime` (общая копия React приложения). Приложение подгружает бандл через `import(url)` с повторами после первого рендера маршрута; регистрации слотов заменяются целиком при каждой перезагрузке. Остальные компоненты плагин копирует в свой код из реестра в стиле shadcn.

**Вывод.** Приём «шимы плюс общая копия React плюс стили под областью плагина» работает, но привязывает плагины к одному React и одному DOM.

### 5.6 Агенты и провайдеры

**Факт.** Любой провайдер (Claude Code, Codex, Pi, ACP-агенты) - плагин; принцип «Zero first-party privilege». Провайдер реализуется мостом (`experimental_providerBridge`) - один процесс на провайдера, а не на тред.

Протокол моста (`docs/provider-bridge-protocol.md`): JSON-RPC 2.0 построчно по stdin/stdout, версия 2.
- Рантайм к мосту: `initialize`, `model/list`, `commands/list`, `provider/health`, `thread/{start,resume,fork,stop,...}`, `turn/{start,steer}`, `skills/configure`.
- Мост к рантайму: уведомления `thread/identity`, `session/replaced`, `provider/recovery`, `error` и главное `thread/delta`; запросы `item/tool/call`, `interaction/request`.
- Разделение труда: «мост знает диалект, рантайм знает таймлайн». Мост парсит свой вывод в семантические **дельты** (`turn.open`, `item.open/close`, `item.textDelta`, `usage`); сборщик дельт в ядре выдаёт идентификаторы и строит канонические события.
- Разрешения: закрытый набор подтверждений (`command`, `file_change`, `tool_use`, `permission_grant`), режимы `accept-edits`, `auto`, `full` решают автоматически.
- Восстановление типизировано: `provider/recovery` с видами `sessionArchived`, `authRequired`, `restartRecommended`, `staleTurn`, `rateLimited`; сопоставления по тексту ошибок нет нигде.
- Рукопожатие сообщает факты поведения, ядро не шлёт метод, которого мост не объявил.

Claude Code подключён через `@anthropic-ai/claude-agent-sdk` (функция `query`), а не разбором потока CLI. ACP (`packages/provider-bridge-acp`) - общий мост для Cursor, opencode и других: превращает ACP в те же дельты. **Паритет** (`packages/provider-parity`): CLI сравнивает события и строки таймлайна по **записанным ячейкам** (`recordings/<провайдер>/<ячейка>`: `approval-allow`, `fork`, `steer`, `compaction`, `plan-mode`, `subagent`, `user-question` и др.); допустимые расхождения - в `parity-allowlist.json`, лишняя запись роняет проверку, счётчики строк закреплены в `row-counts.json`.

### 5.7 Что в ядре, а что плагин

**Факт.** Ядро: проекты, треды, очередь сообщений, события, таймлайн, жизненные циклы, хосты и демон, терминалы, настройки, CLI и SDK, рантайм агентов, установка плагинов. Плагины: провайдеры (`provider-claude-code`, `-codex`, `-pi`, `-acp`), окружения (чекаут, git worktree, песочница Modal), git (статус, Diff), GitHub, список тредов, навигация, композер (заменяемые эксклюзивные слоты), черновики, отложенная отправка, библиотека промптов, ретраи и лимиты, автоматизации, workflows, задачи, память, секреты, MCP-сервер, push, просмотрщики файлов, темы, аккаунт и удалённый доступ. Встроенные плагины перечислены в `builtin-registry.ts` (`BUILTIN_PLUGINS` ставятся сами, `OFFICIAL_PLUGINS` по запросу).

**Вывод.** «Ядро» bb - хранилище, состояния и доставка; почти всё видимое пользователю, включая сайдбар и композер, вынесено. Что происходит при отключении `thread-list` или `composer`, не проверялось; для списка есть замена и заглушка при падении.

### 5.8 Тесты, релиз, форки

**Факт.**
- Тестовый хост `@get-bb/plugin-sdk/testing`: `createFakePluginHost` (настоящая SQLite, валидация RPC, эмуляция событий и расписаний), `loadPluginApp`, `renderSlot`.
- Для мостов - набор конформности `experimental_runBridgeConformance`; повтор записей в CI на каждом коммите. Тест `public-sdk-only` проверяет, что плагин импортирует только публичный SDK.
- Режим записи `BB_PROVIDER_BRIDGE_RECORD_DIR` пишет NDJSON по четырём направлениям; записи редактируются скриптом (секреты убираются).
- Официальные плагины едут внутри приложения без отдельного пайплайна (turbo-задача `prepare:bundled`). Lockstep версий десктопа и `bb-app`.
- Форки: `scripts/forkable-plugins.json` перечисляет плагины, которые должны собираться вне монорепо только на опубликованном SDK; правило линта запрещает импорты за пределы каталога; `pnpm check:plugin-forks` копирует плагин во временный каталог и гоняет typecheck, тесты и сборку.

## 6. Git, worktree, процессы

**Факт.**
- **Очередь допуска для внешних процессов** (`packages/process-utils/src/vcs-process-scheduler.ts`): два пула (локальный и сетевой, из сетевого не более двух слотов для `gh`), три приоритета (interactive, status, background), старение: ожидание повышает приоритет каждые 15 с; сетевые подкоманды git определяются по аргументам. Мутации чекаута сериализуются очередью блокировок по абсолютному `.git`.
- Worktree создаёт плагин: новая ветка без upstream, `.worktreeinclude` (файлы по gitignore-синтаксису копируются без перезаписи отслеживаемых), скрипты `.bb-env-setup.sh` (таймаут 15 мин) и `.bb-env-teardown.sh` (его падение удалению не мешает). Очистка: после удаления треда сразу, после архивации через 5 мин; процессам с cwd внутри воркспейса SIGTERM, затем SIGKILL, затем `git worktree remove --force`; ветка остаётся. Тред живёт 30 с после архивации, чтобы Undo восстановил всё.
- Потолок прав на машину: `hosts.maxPermissionMode` ограничивает режимы `accept-edits`, `auto`, `full` сверху.

## 7. Безопасность

**Факт.** Публичный API без аутентификации **по замыслу**: сервер привязан к 127.0.0.1, а защиту дают проверки запроса: заголовок Host должен быть localhost или адресом из настроек (защита от DNS rebinding), Origin проверяется по списку локальных, то же для WebSocket. Маршруты плагина обходят проверку Origin и защищены токеном. Демоны аутентифицируются bearer-ключами с 15-минутным ключом энролла. Удалённый доступ - Tailscale или облачный шлюз (для нас неактуален). Телеметрия: анонимная PostHog, отключается `BB_TELEMETRY=false`; README перечисляет четыре вида событий, а тип содержит больше (расхождение).

## 8. Сборка, релиз, тесты, CI

**Факт.** Turbo с явными inputs и outputs; нативные аддоны (better-sqlite3, node-pty, @parcel/watcher) остаются зависимостями npm, типичный сбой - «Could not locate the bindings file». Десктоп: electron-builder, обновления с GitHub Releases, подпись и нотаризация macOS в отдельном workflow; ночной канал с отдельной идентичностью приложения. Обновление npm-версии - скачивание в `<dataDir>/app-versions/<ver>/`, **откатов нет**, старая версия может не открыть БД, мигрированную новой.

Тесты: БД не мокается (копия шаблона, построенного настоящими миграциями), сквозные тесты с «scripted echo»-провайдером через настоящий протокол моста, реальные провайдеры отдельно, ручной регламент QA. «Храповик» `check-provider-literal-ratchet.mjs` запрещает новые литералы провайдеров в ядре. CI на 1035 строк: план проверок по `turbo query affected`, шардирование, отдельный контур Windows, бюджет размера бандла UI.

## 9. Что стоит перенять

1. Манифест плагина в `package.json` со строгой схемой и двумя диапазонами совместимости (приложение и SDK).
2. «Нулевая привилегия первых лиц»: встроенные функции пользуются только публичным API, и действие ядра идёт тем же путём, что и действие плагина.
3. Контракт провайдера агента на стандартном протоколе с рукопожатием «факты, а не догадки» и типизированными подсказками восстановления.
4. **Паритет по записанным сессиям**, повтор на каждом коммите, allowlist расхождений, закреплённые счётчики строк. Это прямой ответ на «не потерять ни одной функции».
5. Атомарная перезагрузка (кандидат, затем переключение), статус `error` с причиной, безопасный режим, откат обновления.
6. Три рантайма плагина (серверный, процесс хоста, UI-бандл) с типизированным RPC между ними.
7. Слоты интерфейса с границей ошибок на слот и эксклюзивные слоты с запасным вариантом.
8. Целочисленная версия протокола между оркестратором и исполнителем, проверка до разбора тела.
9. Конечные автоматы как данные и единственный писатель с CAS; события с порядковым номером от одной точки.
10. Очередь допуска для git с приоритетами и старением; зачистка процессов по cwd при удалении worktree; хуки setup/teardown.
11. Тестовый хост SDK и проверка «только публичный SDK»; «храповик» против утечки провайдеров в ядро; проверка форка в CI.
12. Префикс `experimental_` и реестр API на аудит: дисциплина, которая не даёт случайно заморозить контракт.

## 10. Чего не брать

- Серверный код плагинов в одном процессе с полным доверием и без манифеста прав: у нас на машине живут настоящие сессии Claude Code с правами пользователя.
- Общий глобальный React с шимами для сторонних интерфейсов: у Cyborg нет React, интерфейс на обычном DOM.
- Масштаб API (6000 строк контрактов интерфейса, сотни `experimental_`-членов): начинать нужно с 5-8 точек расширения.
- Облачный слой, перенос сервера, мульти-машинный энролл, мобильный клиент, PostHog в нынешнем виде.
- Хук «ядро спрашивает плагин» с глобальным локом и тайм-боксом 10 с.
- Миграцию «ядро и интерфейс тоже плагины» (сайдбар, композер) на раннем этапе: для переноса это высокий риск потери функций, выносить такое надо последним.
- Нет отката миграций БД и откатов обновлений приложения: нам нужна обратная совместимость данных.

## 11. Чего мы не нашли

Отдельный песочничный режим для сторонних плагинов, шифрование секретов на диске, подпись пакетов, единую модель прав пользователей, манифест прав плагина. Поведение при отключении плагинов, заменяющих базовые слоты (список тредов, композер), не проверялось.
