# Корпус документации Cyborg

Адреса корпуса задаёт `.docs_layout` в корне репозитория; дерево ниже - их значения на момент заведения.

| Вопрос | Документ |
|---|---|
| Зачем продукт, для кого, где его граница | `01-product/brd.md` - BRD продукта, `BR-NNN` |
| Что требуется от фичи | `01-product/<NN>-<слаг>/` - BRD и SRS фичи, `stories/` |
| Какие идеи ждут решения | `00-strategy/` - one-pager и canvas, файл на идею |
| Как пользователь проходит сценарий | `02-use-cases/<слаг>/` - файл на сценарий |
| Как устроена система целиком | `03-architecture/design/` - SAD и дизайн-документы |
| Почему устройство выбрано таким | `03-architecture/adr/` - ADR, привязка к фичам полем `relates_to` |
| Как проверяется продукт | `04-verification/` - план верификации |
| Как реализуется работа | `05-plans/` - план на прогон |
| Какой номер выдать новой единице | `.req_counter/` - файл на ключ, содержимое - последний выданный номер |

Единицы, заведённые при онбординге, реконструированы из кода и не согласованы: статус `review` до валидации владельцем продукта.
