## Не запускается или не находит инструменты

**`./cyborg`: нужен Node.js 24 или новее.** Скрипт проверяет версию до установки. Поставьте Node 24 (например, через `fnm` или `nvm`) и запустите снова.

**В сессии `claude: command not found`.** Cyborg запускает `$SHELL -lc 'exec claude ...'`, то есть в логин-шелле. Убедитесь, что `claude` лежит в `PATH` логин-шелла. На macOS zsh в логин-режиме читает `.zprofile`, но не `.zshrc`: если путь добавлен только в `.zshrc`, запускайте Cyborg из терминала, где он уже есть в `PATH`.

**На Linux окно не открывается, ошибка песочницы.** `./cyborg` добавит `--no-sandbox` сам, если нет ни setuid `chrome-sandbox`, ни user namespaces. Чтобы песочница работала, см. [Установка и запуск](/start/install/).

## Задачи и MR

**Кнопок «Задачи» и «MR/PR» нет.** Включите источник в свойствах проекта («Воркспейс → Свойства проекта» → «Источники задач»).

**Написано «gh не установлен» или «gh не залогинен».** Установите [`gh`](https://cli.github.com/) и выполните `gh auth login`; то же для `glab`. Если запускали Cyborg не из терминала, `gh` может не быть в `PATH` процесса.

**Список задач пуст, хотя они есть.** По умолчанию включён фильтр «Назначено мне»: снимите его. Задачи берутся по remote репозиториев проекта, у репозитория без подходящего remote источника нет.

**У «Ревью» ничего не происходит в сессии.** Нужен плагин `dex-auto` в Claude Code ([требования](/start/requirements/)): без него команду `/dex-auto:auto` Claude не узнаёт.

## Статус и Jira

**Кнопки «Статус» нет.** Она появляется, когда у проекта включён хотя бы один источник: GitHub, GitLab или Jira («Воркспейс → Свойства проекта» → «Источники задач»).

**Точка серая, хотя MR есть.** Данных о MR нет: нет входа в `gh`/`glab` либо у репозиториев проекта нет remote GitHub или GitLab. Причина написана в карточке.

**В карточке «jira-cli не установлен / не настроен / не вошёл».** Поставьте `jira-cli`, задайте токен и выполните `jira init` ([требования](/start/requirements/)); проверка: `jira me` называет вас. После этого нажмите «Обновить»: пока вход не принят, Cyborg не повторяет запросы к Jira, чтобы сервер не заблокировал учётную запись.

**Задач Jira нет, хотя они есть.** Показываются открытые задачи, назначенные на вас, и только в выбранных проектах Jira (свойства проекта → «Проекты Jira»; пусто - проект из `jira init`). Если один из проектов не ответил, причина написана под списком. Задачи со статусом категории «Done» не показываются.

**Написано «ответ не JSON».** `jira-cli` вернул не то, что ждёт Cyborg: смотрите `jira issue list --raw` в терминале и версию `jira version`.

## Кнопки-команды

**Нажал кнопку, текст не ушёл, у полосы красная строка.** Это отказ подстановки: у ветки нет открытого PR/MR (`{pr}`), их несколько, сессия начата не из задачи (`{task}`) или у сессии нет ветки git (`{branch}`). Причина названа в строке; текст без значения Cyborg не отправляет ([подстановки](/features/commands/)).

**Текст вставился, но не отправился.** У кнопки `submit: false` (так и задумано для опасных действий): нажмите Enter сами или поставьте `"submit": true`.

**Под ответом Claude видна строка `<!-- cyborg-buttons: ... -->`.** Так модель предлагает кнопки: Cyborg читает этот комментарий и показывает кнопки на полосе, а вывод терминала не меняет, поэтому строка остаётся. См. [кнопки, которые предлагает модель](/features/commands/#кнопки-которые-предлагает-модель).

**Модель не предлагает кнопок.** Она предлагает их, только когда следующие шаги понятны; если шаги неочевидны, комментария нет. Кнопка, предложенная моделью, исчезает после вашего следующего запроса.

**Сочетание клавиш не срабатывает.** Нужен Alt (Option) либо Cmd, либо Ctrl с Shift; сочетания, занятые приложением, и повторы отвергаются, причина - в подсказке «Кнопки: замечаний N» у полосы и в диалоге правки. Под открытой панелью задач, при вводе в поле и при открытом диалоге сочетание не действует.

**«Кнопки команд…» в меню недоступен.** Нет открытого воркспейса: создайте его («Воркспейс → Создать…») или откройте.

**Правка в Monaco не сохраняется.** Диалог называет кнопку и поле с ошибкой, файл в этом случае не меняется. Повреждённый файл воркспейса Cyborg кнопками не затирает: сначала исправьте его.

## Дерево, ветки, история

**Дерево не обновляется.** Пока окно закрыто другими окнами, опрос git приостанавливается и возобновляется, как только окно снова видно. Пока работает сессия, дерево также обновляется по её событиям.

**Не получается сменить ветку.** Либо в репозитории работает сессия (веткой управляет она), либо конфиг репозитория мог бы запустить команду при смене (`filter.*`, partial clone), и Cyborg отказывается. Причина показана в меню ветки, ветку в этом случае переключите в терминале.

**На вкладке «Сессии» пусто.** Показываются только интерактивные сессии с заголовком в репозиториях проекта; фоновые запуски (`claude -p`, SDK) нет. Сессии, ушедшие в worktree, показываются тоже.

**Файл не открывается.** Просмотр читает только текстовые файлы до 5 МБ; двоичные и большие файлы Cyborg не показывает и пишет причину.

## Данные

**Где хранятся проекты?** В файле воркспейса, который вы выбрали (прежний вариант - `projects.json` в [каталоге данных](/concepts/data/)). Токены Cyborg не хранит.

**«Воркспейс уже открыт».** Этот файл открыт в другом окне Cyborg. Закройте то окно или откройте другой файл. Если Cyborg с файлом не запущен, удалите файл замка `<файл>.lock` рядом с ним.
