## Обязательное

| Что | Зачем |
|---|---|
| macOS или Linux | Проверено на macOS (Apple Silicon) и Linux. На Windows приложение не проверялось. |
| Node.js 24 и npm | Сборка и запуск из исходников. |
| git | Дерево, ветки и статусы читаются вызовом `git`. |
| [Claude Code](https://docs.claude.com/en/docs/claude-code) | Команда `claude` в `PATH`, вход уже выполнен. Cyborg запускает обычный CLI. |

## Для задач и MR

| Что | Зачем |
|---|---|
| [`gh`](https://cli.github.com/) | Задачи и PR из GitHub. Нужен вход (`gh auth login`). |
| [`glab`](https://gitlab.com/gitlab-org/cli) | Задачи и MR из GitLab, в том числе самохостного. Нужен вход (`glab auth login`). |

Свои токены Cyborg не хранит и не читает: `gh` и `glab` работают под своим входом, Cyborg вызывает их как программы. Исключение - [удалённые сессии](/features/remote/): при запуске и пробуждении Cyborg берёт у них токены (`gh auth token`, `glab config get token`) и передаёт на хост окружением агента, не записывая на диск.

## Для Jira

| Что | Зачем |
|---|---|
| [`jira-cli`](https://github.com/ankitpokhrel/jira-cli) | Задачи Jira в карточке «Статус». Бинарь `jira` в `PATH` и работающий вход: `jira me` должен назвать вас. |

Подготовка: `brew tap ankitpokhrel/jira-cli && brew install jira-cli`, затем токен в `JIRA_API_TOKEN` (Jira Cloud - email и API-токен, Server и Data Center - `JIRA_AUTH_TYPE=bearer` и персональный токен) и `jira init`. Cyborg читает Jira только через этот CLI, токен и конфиг не читает и не хранит. Включается галочка «Jira» в свойствах проекта ([Статус проекта](/features/status/)).

## Для запуска файла

Нужен только для кнопки «▶ Запустить в терминале» ([запуск файла](/features/run-file/)).

| Платформа | Что нужно |
|---|---|
| macOS | Terminal.app. При первом запуске система спросит разрешение на управление им |
| Linux | Любой из эмуляторов: `$TERMINAL`, `x-terminal-emulator`, `gnome-terminal`, `konsole`, `xfce4-terminal`, `kitty`, `alacritty`, `wezterm`, `foot`, `xterm`. Cyborg берёт первый найденный; нет ни одного - отказ с подсказкой про `TERMINAL` |
| Обе | `SHELL` из семейства `sh` (`bash`, `zsh`, `dash`): fish, tcsh и csh Cyborg отвергает |

## Для удалённых сессий

Нужны, только если вы запускаете сессии на серверах ([удалённые сессии](/features/remote/)).

| Где | Что | Зачем |
|---|---|---|
| Ваша машина | `ssh` (OpenSSH) | Cyborg запускает системный `ssh` без оболочки и без запросов (`BatchMode`): пароль и фраза ключа в окне не вводятся |
| Ваша машина | алиас хоста в `~/.ssh/config` и ключ в `ssh-agent` | хост проекта - это алиас из `~/.ssh/config`; ключ хоста один раз подтверждается вручную (`ssh <алиас>`) |
| Ваша машина | `gh` и `glab` со входом | токены для клона и push агента на хосте; нет токена - клон идёт ключами хоста |
| Хост | Linux | на другой системе проверка хоста откажет: нужны `script` и `stty` из util-linux |
| Хост | `node` 18 или новее | на нём работает агент Cyborg; npm-зависимостей у него нет |
| Хост | `git` | клоны репозиториев проекта |
| Хост | `claude` в `PATH` логин-оболочки | сама сессия |
| Хост | `script` (util-linux) | pty для `claude` без `tmux` и `screen` |
| Хост | вход `claude` либо токен в Cyborg | `claude auth login` на хосте или токен из `claude setup-token` в «Воркспейс → Вход Claude на хостах…» |
| Хост | `gh` и `glab` | необязательно: без них агент работает, но не откроет PR и MR |
| Хост | `sshd` с `AllowStreamLocalForwarding` | Cyborg пробрасывает на хост обратный туннель unix-сокета к MCP-серверу |
| Проект | `origin` у каждого репозитория проекта | клон на хосте делается из `origin` |

Cyborg сам ставит на хост только агента в `~/.cyborg` и зеркало вашей настройки Claude (`~/.claude`); `node`, `git`, `claude`, `script` и вход он не ставит и не настраивает. Недостающее проверка хоста называет одним сообщением. Для голосового ввода Cyborg не требует отдельных программ на хосте: подставной `arecord` кладётся в каталог сессии сам. Хост, где systemd завершает процессы пользователя после выхода последнего сеанса, нужно настроить (`loginctl enable-linger`): иначе вместе с сеансом пропадут и демон, и сессии.

## Для ревью MR

Действие «Ревью» у MR отдаёт сессии команду `/dex-auto:auto review <ссылка>`. Она принадлежит плагину `dex-auto` из каталога [ai-kit](https://dex-it.github.io/ai-kit/): без него Claude Code не узнает команду. «Доработать» и старт по задаче плагина не требуют.

## Что не поддерживается

- Windows.
- Установщики и подписанные сборки: приложение запускается только из исходников.
