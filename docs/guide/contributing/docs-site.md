Сайт - проект [Astro](https://astro.build/) с [Starlight](https://starlight.astro.build/) в каталоге `site/`. Страницы лежат не в нём, а в `docs/guide/` рядом с корпусом: так текст виден там же, где код, и правится обычным PR.

## Локально

```bash
cd site
npm ci
npm run dev        # сервер разработки
npm run build      # сборка в site/dist
npm run verify     # проверка собранного сайта
npm run check      # типы страниц и конфига
```

`dev`, `build` и `check` сначала копируют значок из `assets/icon.svg` в `site/src/generated` и `site/public`: своей копии сайт не держит (оба пути в `.gitignore`).

## Как добавить страницу

1. Создайте `docs/guide/<раздел>/<страница>.md` с `title` и `description` в начале.
2. Добавьте её в `sidebar` в `site/astro.config.mjs`: порядок страниц в меню задаёт он.
3. Корневые ссылки пишите как `/features/tree/` - к ним сам добавляется базовый путь сайта. Внешние ссылки пишутся целиком.
4. Выполните `npm run build && npm run verify`.

## Проверка сборки

`npm run verify` (`site/scripts/check-dist.mjs`) идёт по собранному `site/dist` без сети:

- каждая внутренняя ссылка и ассет ведут под базовый путь на существующий файл, якоря находят свой `id`;
- у каждой страницы есть `canonical` под адресом сайта;
- индекс поиска Pagefind собран, русский, и покрывает все страницы;
- есть `sitemap-index.xml`.

Внешние ссылки намеренно не проверяются: проверка не должна падать от чужих сайтов.

## Публикация

Workflow `.github/workflows/docs-site.yml` на GitHub Pages:

- на PR, затрагивающий сайт или страницы, собирает и проверяет, ничего не публикуя;
- на пуш в `master` и вручную (`workflow_dispatch`) собирает, проверяет и публикует.

Адрес и название задаёт `site/site.config.mjs`: при переименовании репозитория меняются `OWNER` и `REPO_NAME`, остальное подтягивается оттуда. Проверка сайта не должна быть обязательной в защите ветки: у PR-запуска есть фильтр путей, а обязательная проверка, которая не запустилась, вешает PR.
