## Тесты

`npm test` запускает два набора на встроенном `node:test`, без тестового фреймворка:

- модульные тесты рядом с кодом главного процесса (`src/main/*.test.ts`);
- тесты из `test/`: каждый файл собирается esbuild во временный каталог и запускается в Node. Electron и нативный модуль терминала в них подменяются, поэтому тесты идут без окна.

Покрыты:

- хранилища и файлы: проекты, воркспейсы и замки, общие кнопки и промпты, хабы, кэш статистики вызовов, история и журнал сессий;
- git: фильтры и смена ветки, поиск по содержимому и изменениям, проверка путей каналов файлов и git, аргументы каналов `session:*` и поиска, уведомлений;
- трекеры: `gh`, `glab` и пределы их вызовов, MR, задачи, чтение Jira через `jira-cli`, сводка статуса;
- кнопки-команды: разбор и подстановки, сочетания клавиш, промпты кнопок запуска сессий, кнопки, которые предлагает модель;
- окно «Расширения»: чтение магазинов, плагинов, скиллов и серверов MCP, действия установки и удаления, хабы, статистика вызовов;
- интерфейс: панели, дерево, вкладки и списки с клавиатуры (роли ARIA), заголовок окна, настройки окна и размер шрифта, платформенные сочетания клавиш, меню приложения, скрипт запуска, сама проверка корпуса.

Статические проверки следят, что в интерфейсе нет `innerHTML` и что на диск и в хранилище окна пишутся только известные данные.

На файловых системах, не допускающих имена не в UTF-8 (APFS), один тест пропускается с объяснением.

## Дымовой тест

`npm run smoke` запускает собранное приложение с временным каталогом данных, подставными `claude`, `gh`, `jira` и репозиторием-пробой и по DevTools Protocol проверяет:

- запуск: окно открывается, заголовок называет проект и версию приложения, дерево показывает git-статус; первый запуск создаёт воркспейс, `--workspace` открывает файл (относительный путь, несуществующий файл не создаётся), замок снимается по `SIGTERM`; прежний `projects.json` открывается как воркспейс;
- клавиши и сессии: подсказки называют сочетание своей системы, оно открывает сессию, чужое - нет; вывод pty доходит до терминала; событие хука с новым рабочим каталогом переводит дерево на worktree; колесо и сброс клавишей меняют размер шрифта;
- границы: каналы файлов и git отклоняют путь вне репозиториев проекта и каталогов сессий; бросок файла вне зон интерфейса отменён;
- поиск: файл по имени, строка в файлах и в изменениях, регулярное выражение и его ошибка, переход к строке;
- окно «Расширения»: меню, вкладки, область, фильтр, установка и удаление плагина, серверы MCP без секретов и проверка связи, хабы и подключение магазина;
- задачи, MR и Jira: панель «Задачи» открывается и закрывается, у проекта без источников кнопок нет; выбор проектов Jira; кнопка «Статус» открывает карточку с задачей Jira (подставной `jira`), раскрывает детали, закрывается кликом и `Esc`, запускает сессию по задаче и возвращает к ней;
- кнопки-команды и промпты: встроенные кнопки, правка в Monaco, подстановки, сочетание, вставка без Enter, общий набор, кнопки от модели; негодный промпт не запускает сессию молча;
- завершение: приложение с работающей сессией завершается по `SIGTERM`.

Нужен дисплей: на Linux запускайте под `xvfb-run`, `--no-sandbox` передаётся аргументом (`node scripts/smoke.mjs --no-sandbox`). Новых зависимостей тест не требует.

## CI

GitHub Actions (`.github/workflows/ci.yml`) на каждый PR и каждый пуш в `master`, на `macos-latest` и `ubuntu-latest`:

1. `npm ci` - чистая установка по `package-lock.json`; `./cyborg` ставит зависимости через `npm install`, и оба запуска пересобирают нативный модуль терминала под Electron;
2. `npm run build`;
3. `npm run typecheck`;
4. `npm test`;
5. дымовой тест окна.

Отдельное задание `corpus` запускает `npm run check:corpus` (без установки зависимостей). Оно проверяет корпус `docs/` на согласованность: front matter и статусы, нумерацию ADR, `verification` и `traced from` каждого требования, ссылки на требования, решения и строки кода, счётчики `.req_counter` и актуальность матрицы `docs/04-verification/verification-matrix.md`. После правки SRS пересоберите матрицу: `npm run corpus:matrix`.

Отдельная проверка `CI` сводит результат матрицы и проверки корпуса в одно имя: его можно сделать обязательным в защите ветки. Экшены закреплены по SHA коммита, обновления присылает Dependabot.
