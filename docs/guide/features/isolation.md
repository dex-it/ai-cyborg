---
title: "Изоляция сессий"
description: "Как параллельные сессии в одних репозиториях не мешают друг другу."
---

Две сессии в одном репозитории легко затирают правки друг друга. Cyborg решает это, не вмешиваясь в Claude Code: при запуске он добавляет к системному промпту сессии (`--append-system-prompt`) короткую инструкцию.

> В этих репозиториях параллельно работают другие сессии. Перед первой правкой в репозитории, сменой ветки или коммитом - EnterWorktree, дальше работа только в нём; основной каталог - только чтение. Файлы вне репозиториев (скрэтчпад, временные) worktree не требуют. EnterWorktree изолирует только репозиторий рабочего каталога: перед правкой в репозитории из --add-dir - git worktree add <репозиторий>/.claude/worktrees/<то же имя> -b <та же ветка>, и правки только по этому пути.

`EnterWorktree` - инструмент самого Claude Code: он создаёт worktree в `<репозиторий>/.claude/worktrees/<имя>` на новой ветке и переводит в него сессию. Результат в Cyborg:

- обе сессии работают каждая в своём worktree, основной каталог остаётся чистым (в нём появляется только неотслеживаемый `.claude/`);
- вкладка и дерево переходят за сессией: `CC1 · repo ⎇ create-a-txt`;
- историю таких сессий Cyborg видит ([сессии](/features/sessions/)).

В проекте из нескольких репозиториев сессия стартует в том, который выбран в меню «Где запустить Claude Code», остальные подключены через `--add-dir`. `EnterWorktree` уводит в worktree только стартовый; для каждого из остальных, где нужна правка, модель заводит worktree с тем же именем командой `git worktree add`. Дерево Cyborg следует за рабочим каталогом сессии: первым корнем идёт каталог, где сессия сейчас, с подписью репозитория, которому он принадлежит, - `front ⎇ readme-v3` либо `back ⎇ readme-v3`. Если сессия перешла в другой репозиторий проекта или в его worktree, репозиторий, где она была запущена, остаётся в дереве ниже.

Как именно Claude выберет имя worktree и когда в него уйдёт, решает модель: Cyborg только передаёт инструкцию и следит за рабочим каталогом сессии по событиям хуков ([как это устроено](/concepts/hooks/)).
