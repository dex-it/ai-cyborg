## Вкладки

Каждая сессия - вкладка вида `CC1 · repo`: номер, репозиторий, а когда сессия ушла в worktree, и его имя (`CC1 · repo ⎇ create-a-txt`). Цвет вкладки отличает сессии друг от друга. Когда вкладки не помещаются, полоса прокручивается, а вкладка выбранной сессии всегда оказывается на виду. Если закрыть выбранную вкладку, выбирается соседняя справа, у последней - слева. Новая сессия - кнопка «Новая сессия» или `Ctrl+Shift+N` (на macOS `Cmd+Shift+N`).

| Что на вкладке | Что значит |
|---|---|
| Залитая точка | Claude работает: от вашего запроса и после каждого вызова инструмента, удачного или упавшего |
| Пустая точка (контур) | Сессия ждёт ввода |
| Бледное кольцо и приглушённая подпись | Сессия завершена |
| `CC2 ↳1 · repo` | Дочерняя сессия: её открыла сессия CC1 ([делегирование](/features/delegation/)); цвет вкладки тот же, что у родителя |
| Квадратная метка вместо точки, значок `⇄`, плашка хоста | Удалённая сессия ([удалённые сессии](/features/remote/)) |

Лампа гаснет, когда Cyborg узнаёт, что сессия ждёт: на запросе разрешения или вопросе - сразу, после законченного хода - через 30 секунд тишины (та же выдержка, что у [уведомлений](#уведомления)). Esc и `Ctrl+C` в терминале гасят её сразу: при прерывании хода Claude Code не присылает событие `Stop`. Если Esc лишь закрыл подсказку, а сессия продолжила работу, лампа зальётся снова с её следующим вызовом инструмента. Упавший инструмент тоже считается работой: ход, где команды агента падают по таймауту, не выглядит простоем. Известное ограничение: после ответа на запрос разрешения лампа остаётся пустой до конца следующего инструмента, потому что хука на «разрешено» у Claude Code нет. Сессии, открытые до обновления Cyborg, получат хук упавшего инструмента после перезапуска.

Лампа не мигает: бесконечная анимация держала бы окно на 60 кадрах в секунду, пока хоть одна сессия занята, поэтому состояние показывают заливка и контур.

### Подсказка вкладки

Наведите курсор на вкладку, чтобы вспомнить, о чём сессия. Подсказка собирается из строк, лишние пропускаются:

1. данные задачи, MR или Jira, если сессия запущена из них ([задачи и MR](/features/tasks-mrs/));
2. название разговора: заголовок, который Claude Code придумал сам, или заданный командой `/rename`;
3. «Задача: …» - первый запрос;
4. «Последний запрос: …» - последний, если он отличается от первого;
5. «Открыта сессией …» - у дочерней: подпись вкладки родителя, а после его закрытия - `CC1 (закрыта)`;
6. текущий каталог сессии.

Те же строки, кроме родителя и каталога, видны в подсказке шапки дерева. Запрос берётся из события `UserPromptSubmit`: пробелы свёрнуты, длина до 300 знаков, служебные вставки Claude Code, начинающиеся с `<`, запросом не считаются. Название и первый запрос Cyborg читает из журнала Claude Code при старте и по окончании хода, поэтому у продолженной сессии «Задача» - из прошлого запуска, а название появляется, когда оно уже записано в журнал. У удалённой сессии журнал лежит на хосте, и в подсказке только запросы.

Внутри вкладки - терминал сессии (вкладка «Claude») и открытые файлы. Терминал - обычный xterm.js с настоящим процессом `claude` внутри. В окне без фокуса вывод появляется на экране пачками 4 раза в секунду, а не на каждый кадр: спиннер Claude Code пишет в терминал десятки раз в секунду, и без этого фоновые окна тратили бы процессор и видеокарту. Запросы программы к терминалу (о цветах, режимах, возможностях) уходят сразу, чтобы ответы не опаздывали. Вернувшись в окно, вы видите накопленное сразу; завершение сессии тоже сначала выводит накопленное. Окно в фокусе работает как обычно.

Абсолютный путь в выводе сессии (`/tmp/shot.png`, `~/.config/cyborg/prompts.json`) подчёркивается при наведении, клик открывает файл или каталог приложением системы по умолчанию. Исполняемые файлы так не открываются (запуск файла - кнопкой в просмотре, [запуск файла](/features/run-file/)); относительные пути (`src/main.ts`) не распознаются. Путь, который Claude Code перенёс на следующую строку, открывается целиком. Ссылки `http(s)://` в выводе, в том числе скрытые за текстом (OSC 8), открываются браузером системы; окно Cyborg по ссылке не уходит и новых окон не открывает.

## Завершение

- Закрытие вкладки работающей сессии спрашивает подтверждение: «Сессия Claude Code ещё работает. Завершить её?». Когда вкладку закрывает другая сессия инструментом `close_session`, окна подтверждения нет: решение уже подтвердил Claude Code запросом разрешения ([делегирование](/features/delegation/#как-закрывается-вкладка)).
- Закрытие окна или выход (`Cmd+Q` / `Ctrl+Q`), пока идут сессии, тоже спрашивает, сколько сессий будет завершено. Выход по сигналу (`Ctrl+C` в терминале, где запущен `./cyborg`, `kill`) вопроса не задаёт.
- Если процесс `claude` завершился сам, терминал остаётся на месте с пометкой `[сессия завершена, код N]`.

## Уведомления

Когда сессия ждёт вас - закончила ход, просит разрешение на инструмент, задаёт вопрос от MCP-сервера или стоит на лимите, - Cyborg показывает уведомление на рабочем столе. Заголовок - вкладка сессии и проект, текст - что она ждёт: «Ход завершён, ждёт ответа», «Просит разрешение», «Задаёт вопрос», «Ждёт ответа» (событие `agent_needs_input`) или «Остановилась на лимите». Ответ Claude и текст запроса в уведомление не попадают: оно может быть видно на заблокированном экране. О законченном ходе уведомление приходит через 30 секунд тишины: если сессия продолжила работу сама, его не будет.

- Об открытой сессии в окне, которое в фокусе, уведомления нет: вы её и так видите.
- Клик по уведомлению поднимает окно, переключает проект и открывает сессию.
- Уведомление исчезает, когда вы открыли сессию, ответили ей, закрыли её или она завершилась. У сессии одно уведомление: следующее заменяет прежнее.
- Выключатель - меню **Вид → Уведомления о ждущих сессиях**. Выбор сохраняется между запусками.

Какие события Claude Code считаются ожиданием - в разделе [хуки](/concepts/hooks/).

## История

Вкладка «Сессии» вверху слева (рядом с «Файлы») показывает прошлые сессии проекта: заголовок, репозиторий и сколько времени прошло. В список попадают интерактивные сессии, запущенные человеком (Cyborg или обычная консоль), у которых есть заголовок. Фоновые запуски `claude -p` и SDK не показываются. Спящие [удалённые сессии](/features/remote/#жизненный-цикл) хоста показываются строкой `репо · host · спит`: клик будит сессию на хосте, крестик удаляет её вместе с клонами. Строка дочерней сессии, открытой другой сессией, помечена «· дочерняя» ([делегирование](/features/delegation/#как-это-видно-в-интерфейсе)); продолженная из истории, она открывается самостоятельной вкладкой. Дочерние, открытые до появления метки, не помечены.

- Клик по записи продолжает сессию: `claude --resume <id>` в репозитории сессии.
- Крестик удаляет журнал сессии вместе с каталогом её вывода инструментов. После этого продолжить её нельзя, Cyborg переспрашивает.
- Звезда справа от записи (или `*` на записи) кладёт сессию в избранное: избранные стоят вверху группой «Избранное» и показываются всегда, даже старше 50 последних. Повторный щелчок по звезде убирает сессию из избранного. Отметки лежат в `session-favorites.json` [каталога данных](/concepts/data/), отдельно для каждого проекта.
- Поле «Поиск сессии» над списком отбирает записи по заголовку, имени репозитория и хосту, без учёта регистра; несколько слов ищутся в любом порядке. Стрелка вниз из поля переходит к записям, `Escape` очищает поле.
- Несколько сессий удаляются разом: флажок слева от записи, `Ctrl`+клик (`Cmd`+клик на macOS) или `Shift`+клик для диапазона выделяют записи, пока что-то выделено, клик тоже выделяет, а не продолжает сессию. Над списком появляется полоса «Выбрано: N» с кнопками «Все», «Удалить» и «Отмена»; `Delete` на записи удаляет всё выделенное, `Escape` снимает выделение.

Cyborg только читает журналы Claude Code из `~/.claude/projects` (для истории и для [статистики вызовов](/features/extensions/#статистика-вызовов) в окне «Расширения») и удаляет ту сессию, которую вы выбрали. История та же, что у `claude` в консоли, поэтому сессию можно продолжить и там, и там.

Сессии, ушедшие в worktree ([изоляция](/features/isolation/)), хранятся Claude Code в отдельных каталогах, и Cyborg показывает и их.

## Инструкции для всех сессий

Меню **Воркспейс → Глобальный CLAUDE.md…** открывает в редакторе Monaco глобальные инструкции Claude Code - файл `CLAUDE.md` в `~/.claude` (или в `CLAUDE_CONFIG_DIR`, если он задан). Claude Code подгружает этот файл в каждую сессию на этой машине, в любом проекте: здесь удобно задать язык, тон и длину ответов, свои предпочтения в работе. Правила одного репозитория живут в его собственном `CLAUDE.md`.

- Пункт доступен и без воркспейса. Файла ещё нет - редактор открывается пустым, сохранение создаёт его.
- Сохранённый текст читает следующая сессия; уже идущие его не перечитывают. [Удалённые сессии](/features/remote/) получают копию файла на хосте при следующем запуске.
- Если файл изменился на диске, пока редактор был открыт (его поправила сессия или другой редактор), Cyborg его не затрёт: сохранение откажет, правку останется скопировать и открыть редактор заново.
- Если `CLAUDE.md` - символьная ссылка (например, из репозитория dotfiles), записывается файл, на который она указывает; ссылка остаётся ссылкой.
- Кнопка «Открыть в системе» открывает файл приложением системы по умолчанию.
