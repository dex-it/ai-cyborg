Под терминалом каждой сессии есть полоса кнопок. Нажатие кнопки отправляет её текст в ту сессию, которая видна (Enter уходит отдельно, сразу за текстом); кнопка с пунктирной рамкой только вставляет текст, а Enter вы нажимаете сами. Cyborg сам ничего не отправляет: без вашего нажатия текст в сессию не уходит.

Встроенные кнопки:

| Кнопка | Что отправляет | Клавиша |
|---|---|---|
| Сливай | `сливай` и Enter | F1 |
| Сделай PR | `сделай PR` и Enter | F2 |
| Мердж | `открой PR текущей ветки, если его ещё нет, и смерджи его в целевую ветку` без Enter | F3 |
| Приберись | `приберись` и Enter | F4 |

У каждой кнопки есть описание: оно показывается в подсказке при наведении (в подсказке: сочетание клавиш, описание, текст кнопки).

Кнопки не блокируются, пока Claude работает: Claude Code сам ставит ввод в очередь. Cyborg не проверяет, пусто ли поле ввода: если там что-то набрано, текст кнопки допишется к нему. У завершившейся сессии кнопки недоступны.

## Свои кнопки

Кнопки правятся в окне **«Кнопки»**: меню **Воркспейс → Кнопки…** (доступно и без открытого воркспейса) или ⚙ у полосы. Правый клик по кнопке полосы открывает меню: «Изменить «Сливай»…» открывает окно на этой кнопке, а у встроенной и общей кнопки при открытом воркспейсе есть ещё «Выключить в этом воркспейсе» - без окна.

Набор складывается из трёх слоёв, каждый поверх предыдущего:

- **Встроенные** - четыре кнопки из таблицы выше.
- **Все воркспейсы** - общие кнопки, файл `commands.json` [каталога данных](/concepts/data/).
- **Этот воркспейс** - поле `commands` файла воркспейса. Без открытого воркспейса этот слой недоступен.

Переключатель вверху окна выбирает слой, в который ляжет правка. Окно показывает одним списком все кнопки по местам: «Полоса сессии · в открытую сессию» и три группы кнопок запуска сессий ([ниже](#промпты-кнопок-запуска-сессий)). У каждой строки видно происхождение («встроенная», «общая», «этот воркспейс») и пометки выбранного слоя:

| Пометка | Что значит |
|---|---|
| «изменена здесь», «изменена в общих» | В слое есть правка полей этой кнопки |
| «выключена» | Кнопка выключена и не видна на полосе |
| «сочетание отдано «X»» | Её сочетание забрала кнопка «X» слоя выше |
| «заменена «X»», «вместо «X»» | Пара замены: исходная кнопка выключена, новая стоит на её месте |
| «новая» | Кнопку добавила или изменила сессия ([ниже](#кнопки-которые-добавляет-сессия)) |
| «Запись негодна» | Запись файла, правленного руками, с ошибкой; причина рядом |

**Правка по полям.** Форма кнопки полосы: подпись, текст с кнопками вставки [подстановок](#подстановки), «отправлять с Enter», сочетание клавиш, описание. У встроенной или общей кнопки можно поменять одно поле, остальные берутся снизу. Правка нижнего слоя доходит до верхних: новый текст общей кнопки появится во всех воркспейсах, где этот текст не переопределён. У каждого поля унаследованной кнопки видно, откуда значение («из: встроенная», «из: общая», «из: этот воркспейс»), а «сбросить» возвращает значение снизу. Подпись унаследованной кнопки не правится: если нужна другая, замените кнопку.

Что ещё можно сделать с кнопкой полосы в выбранном слое:

- **«Выключить» / «Включить».** Выключенная кнопка пропадает с полосы и освобождает сочетание. Выключение в слое «Этот воркспейс» другие воркспейсы не затрагивает; там же включается и кнопка, выключенная в общих.
- **«Заменить другой кнопкой…»** - у встроенной и общей. Исходная выключается в выбранном слое, новая встаёт на её место и получает её сочетание. Если потом включить исходную, сочетание останется у новой.
- **«Вернуть сочетание этой кнопке»** - у кнопки, чьё сочетание забрали сверху.
- **«Удалить»** - у своей кнопки слоя; её подпись можно править.
- **Порядок** меняется перетаскиванием строки или кнопками «Выше» / «Ниже» и пишется в выбранный слой.
- **«+ Кнопка»** в группе заводит свою кнопку слоя. Подпись, уже занятая в действующем наборе, не принимается.

**Сохранение.** Окно правит черновик, «Сохранить» записывает слой целиком. Cyborg проверяет слой заново. При любой ошибке отказ виден у кнопки и поля, а файлы не меняются. Если файлы кнопок изменились на диске после открытия окна, запись тоже откажет: «Кнопки изменились на диске после открытия окна». Закрытие окна и смена слоя при несохранённой правке спрашивают подтверждение. После записи полоса обновляется сама, без перезапуска. Правка файлов в другом редакторе подхватывается, когда окно Cyborg снова получает фокус. Запись кнопок не трогает проекты и остальные поля файла воркспейса.

**Сохранить предложенную кнопку.** Правый клик по кнопке ✦, которую предложила модель, - «Сохранить как кнопку…». Окно откроется с формой новой кнопки: подпись, текст, Enter и описание взяты из предложения, сочетания нет. Кнопка ляжет в слой «Этот воркспейс», а без открытого воркспейса - в общий. Файл не меняется, пока вы не нажмёте «Сохранить».

### Записи в файле

Общий `commands.json` и поле `commands` файла воркспейса устроены одинаково: это массив записей. Окно пишет в файл только то, что отличается от нижнего слоя, поэтому файл легко читать и править руками:

```json
[
  { "label": "Сливай", "hotkey": "Alt+S" },
  { "label": "Приберись", "text": "/cleanup-merged-branches", "submit": true },
  { "label": "Ревью", "text": "сделай ревью PR {pr}", "description": "Ревью PR ветки сессии" },
  { "label": "Сделай PR", "disabled": true },
  { "label": "Мердж", "hotkey": null }
]
```

| Поле | Значение |
|---|---|
| `label` | Подпись, до 40 знаков. Запись с подписью кнопки нижнего слоя (регистр не важен) меняет у неё только названные поля; новая подпись - своя кнопка слоя. |
| `text` | Фраза или слеш-команда скилла, одна строка до 2000 знаков. У своей кнопки обязателен. |
| `submit` | `true` - текст и Enter; `false` - только вставка. Запись со своим `text` задаёт и `submit`: если поля нет, кнопка только вставляет, `submit` снизу ей не достаётся. Для опасных действий оставьте `false`. |
| `hotkey` | Сочетание: `Alt+S`, `Ctrl+Shift+K`, `CmdOrCtrl+Shift+M`. `null` снимает сочетание нижней кнопки. |
| `description` | Описание до 200 знаков в одну строку. Показывается в подсказке. |
| `disabled` | `true` - кнопка скрыта (так выключается и встроенная) и освобождает сочетание; `false` в верхнем слое снимает выключение нижнего. |

Запись только с подписью (`{ "label": "Сливай" }`) ничего не меняет, а задаёт место кнопки нижнего слоя. Кнопка нижнего слоя, которую слой не упомянул, встаёт за той, что стояла перед ней внизу. Запись без `text`, у которой ниже нет кнопки с той же подписью, на полосу не попадает. Записей в слое не больше 30, считая записи правки, выключения и места.

Сочетание принадлежит кнопке, чьё значение `hotkey` взято из самого верхнего слоя. У нижней кнопки с тем же сочетанием оно снимается без замечания, а окно показывает, кому оно отдано. Если верхняя кнопка выключена, удалена или сняла сочетание, оно снова у нижней. Повтор сочетания внутри одного слоя - ошибка.

Негодная запись в файле, правленном вручную, пропускается, а у полосы появляется «Кнопки: замечаний N». Список причин - в подсказке. В окне такая запись видна строкой «Запись негодна»: поправьте её в форме или удалите («Удалить запись»), иначе слой не сохранится.

Файл воркспейса общий для команды, и версии Cyborg у людей могут отличаться. Версия до окна «Кнопки» не понимает правку отдельных полей: запись без `text` с одним `hotkey` или `description` она назовёт негодной и пропустит, а кнопку с переопределённым текстом покажет без сочетания и описания нижней кнопки. Ещё более старая называет `description` и `disabled` неизвестными полями, не скрывает отключённую встроенную кнопку и стирает поле `prompts`, когда сохраняет проекты. Если файл общий, обновите Cyborg у всех.

## Кнопки, которые предлагает модель

Часть действий ситуативна, и заранее кнопку под них не напишешь. Поэтому Cyborg добавляет к каждой сессии короткую инструкцию (к системному промту, рядом с инструкцией об изоляции): если после ответа понятны следующие шаги, Claude в самом конце ответа пишет комментарий вида

```text
<!-- cyborg-buttons: [{"label": "Написать тест", "text": "напиши тест на пустой массив для sum"}] -->
```

Когда шаги неочевидны, комментарий не пишется. Cyborg читает его из последнего сообщения хода (событие `Stop`) и показывает кнопки на полосе после заданных. Комментарий остаётся и в терминале: Cyborg вывод сессии не меняет, поэтому под ответом видны одна-три строки.

- **Чем отличаются.** Заданные вами кнопки нейтральные, предложенные моделью - голубоватые, со значком ✦ перед подписью; в подсказке написано «Предложено моделью» и показан текст. Рамка, как у остальных кнопок: пунктирная у той, что только вставляет текст, сплошная у той, что отправит его.
- **Enter - только если модель попросила и вы нажали.** По умолчанию предложенная кнопка вставляет текст в поле ввода: вы читаете его и нажимаете Enter сами. Если модель добавила `"submit": true` (реплику можно отправить без правки), кнопка отправит текст сразу; у такой кнопки сплошная рамка, а подсказка говорит «нажатие отправит текст с Enter». Ответ модели не считается доверенным: она могла прочитать файл с чужими указаниями, поэтому прочитайте подпись и текст в подсказке, прежде чем нажимать. Кнопка нажимается только вами.
- **Чего нет никогда.** Реплика, начинающаяся с «!», отбрасывается: Claude Code выполняет такой ввод как команду оболочки без запроса разрешения. Реплика с «/» (команда Claude Code) вставляется без Enter, даже если модель попросила `submit`. Символы направления текста и управляющие символы в подписи и тексте отвергают кнопку.
- **Что принимается.** Не больше двух кнопок, `label` до 40 знаков (длиннее обрезается до 40 с «…» на конце), `text` до 2000 знаков в одну строку, необязательные `submit` и `description`; сочетания клавиш и `disabled` из предложения не действуют. В `text` работают подстановки.
- **Сколько живут.** До вашего следующего запроса, до нового предложения или пока модель сама не продолжит работу либо не остановится на вопросе или запросе разрешения; между запусками они не сохраняются. Понравившуюся кнопку сохраните: правый клик по ней - «Сохранить как кнопку…» ([выше](#свои-кнопки)).

## Кнопки, которые добавляет сессия

Кнопку можно попросить словами: «добавь кнопку «Тесты», которая запускает npm test». У каждой сессии Cyborg, локальной и [удалённой](/features/remote/), есть инструменты кнопок `list_buttons`, `add_button`, `update_button` и `disable_button` ([все инструменты сессий](/features/delegation/#инструменты)). Каждый вызов подтверждается обычным запросом разрешения Claude Code.

- **Куда пишет.** По умолчанию в слой «Этот воркспейс»; если воркспейс не открыт, вызов откажет. В общий слой - только если вы сами сказали «во все воркспейсы». Кнопки запуска сессий (у MR, задачи GitHub и GitLab, задачи Jira) пишутся только в общий слой.
- **Сочетание.** Сессия ставит сочетание, только если вы его назвали. Если оно занято кнопкой нижнего слоя, новая кнопка его забирает, а ответ инструмента и уведомление называют, у какой.
- **Что не пропускается.** Текст, начинающийся с «!», - отказ. Кнопка полосы с «/» или «#» в начале только вставляет текст, Enter вы нажимаете сами. Промпт кнопки запуска не может начинаться с «#». Остальные проверки те же, что у окна; при отказе файлы не меняются.
- **Уведомление.** У полосы сессии появляется «Сессия добавила кнопку «Тесты»» (или изменила, выключила, включила; с сочетанием и тем, у какой кнопки оно взято) с «Отменить», «Изменить…» и ✕. Оно держится, пока его не закроют или не придёт следующее. «Изменить…» открывает окно «Кнопки» на этой кнопке. «Отменить» снимает только запись этого вызова и возвращает отнятое сочетание; если ту же кнопку после вызова уже меняли, отмена откажет и назовёт причину. Отменить можно последние 50 вызовов, пока Cyborg не закрыт.
- **«Новая».** Кнопка от сессии помечена «новая» на полосе и в окне, пока вы не наведёте на неё или не откроете её в окне.

## Промпты кнопок запуска сессий

Кнопки «Ревью» и «Доработать» у MR (список MR и карточка «Статус»), «Разобрать пайплайн» у MR (только карточка «Статус»), «Взять в работу» у задачи GitHub и GitLab и запуск сессии по задаче Jira начинают сессию с первого сообщения - промпта. Промпты правятся в том же окне «Кнопки», в группах «Карточка MR · новая сессия», «Задача GitHub / GitLab · новая сессия» и «Задача Jira · новая сессия». Они общие для всех воркспейсов и лежат в файле `prompts.json` [каталога данных](/concepts/data/). Поэтому правятся они только в слое «Все воркспейсы», а в слое «Этот воркспейс» видны только для чтения с пометкой «правятся во всех воркспейсах».

Форма кнопки запуска: подпись (только у своей), промпт с кнопками вставки подстановок своего места, описание. У встроенной кнопки есть «Вернуть встроенный промпт». Встроенные кнопки запуска не выключаются. Следующая сессия по кнопке получает новый текст без перезапуска.

**Свои кнопки запуска.** «+ Кнопка» в группе места заводит свою кнопку запуска со своим промптом. Она стоит на карточках этого места после встроенных и открывает сессию так же, как они. Пока по записи открыта сессия, вместо кнопок запуска стоит «К сессии». Свою кнопку можно выключить и удалить. Подсказка у встроенных и своих кнопок запуска называет описание и промпт.

```json
{
  "mr.review": { "text": "/dex-auto:auto review {mr_url}", "description": "Кнопка «Ревью» у MR" },
  "jira.start": { "text": "Задача Jira {jira_key}: прочитай её и предложи план. Код не правь, пока я не подтвержу план." },
  "buttons": [
    { "place": "mr", "label": "Безопасность", "text": "проверь MR {mr_url} на уязвимости", "description": "Ревью безопасности MR" }
  ]
}
```

| Промпт | Кнопка | Подстановки |
|---|---|---|
| `mr.review` | «Ревью» | `{mr_url}` - ссылка на MR |
| `mr.rework` | «Доработать» | `{mr_url}` |
| `mr.ci` | «Разобрать пайплайн» в карточке «Статус» | `{mr_url}` |
| `task.start` | «Взять в работу» у задачи GitHub и GitLab | `{task_url}` - ссылка на задачу, `{status_command}` - `gh issue edit` либо `glab issue update` |
| `jira.start` | сессия по задаче Jira | `{jira_key}` - ключ задачи |

Свои кнопки запуска лежат в ключе `buttons`: `place` - место (`mr`, `task` или `jira`), `label`, `text` и необязательные `description` и `disabled`. Подстановки у своей кнопки те же, что у встроенных её места.

Без записи в файле отправляется прежний встроенный текст. Подставляются только ссылка или ключ: название задачи или MR, ветки и автор - чужой текст, в промпт они не попадают, и подстановками стать не могут. Текст - одна строка до 2000 знаков и не начинается с «-» (первое сообщение передаётся программе аргументом, и дефис она приняла бы за параметр). Неизвестный промпт или подстановка (например, опечатка `{jira_kye}`) называются, и окно не даст такое сохранить.

Если файл правили руками и запись встроенного промпта негодна, сессия по этой кнопке не запустится: окно сообщения назовёт промпт и причину. Cyborg не подставит вместо вашего текста встроенный молча. Негодная своя кнопка видна на карточке недоступной, а её подсказка называет причину. Остальные кнопки это не затрагивает.

## Подстановки

В `text` работают три подстановки:

| Подстановка | Что подставляется |
|---|---|
| `{branch}` | Ветка git сессии в момент нажатия. |
| `{pr}` | Ссылка на PR/MR, с которого начата сессия; иначе ссылка на открытый PR/MR с этой веткой в репозиториях проекта. Ваш PR приоритетнее чужого; если подходящих несколько, Cyborg откажет и назовёт номера; PR из форка с той же веткой назначения (например, `main`) за PR ветки сессии не принимается. |
| `{task}` | Ключ задачи Jira либо ссылка на задачу трекера, из которых начата сессия. |

Нет значения (у ветки нет PR или их несколько, сессия начата не из задачи, в проекте не включены GitHub и GitLab) - текст не уходит, а у полосы на несколько секунд называется подстановка и причина. Ветка должна состоять из букв, цифр и знаков `. _ / -`: иначе Cyborg откажется подставлять её в запрос к модели.

## Сочетания клавиш

Сочетание кнопки видно в подсказке при наведении на неё. Сочетание нажимает кнопку видимой сессии. Нужен Alt (Option) либо Cmd, либо Ctrl вместе с Shift, либо F-клавиша, с модификаторами или без: чистый Ctrl с буквой - управляющие символы терминала (`Ctrl+C` и другие). На macOS F-клавиши по умолчанию управляют яркостью и звуком: для кнопок их нажимают с Fn либо включают «Использовать F1, F2 и т. д. как стандартные функциональные клавиши» в настройках клавиатуры. Занятые приложением сочетания и повтор сочетания у второй кнопки отвергаются: кнопка остаётся без сочетания. На macOS заняты `Cmd+Q`, `Cmd+C`, `Cmd+V`, `Cmd+X`, `Cmd+A`, `Cmd+Z`, `Cmd+W`, `Cmd+M`, `Cmd+H`, `Cmd+0`, `Cmd+Shift+N`, `Cmd+Shift+Z`; на Linux `Ctrl+Shift+N`, `Ctrl+Shift+C`, `Ctrl+Shift+V`, `F11`. Сочетания меню «Поиск» и «Расширения» (`Cmd+P`, `Ctrl+Shift+P`, `CmdOrCtrl+Shift+F`, `CmdOrCtrl+Shift+D`, `CmdOrCtrl+Shift+X`) окно не отвергает, но и не назначайте их кнопкам: меню перехватит их раньше кнопки. Файл воркспейса переносят между macOS и Linux, поэтому окно не даст сохранить сочетание, которое не годится на другой системе (например, `CmdOrCtrl+K`: на Linux нужен Shift). Сочетание не срабатывает при вводе в поле, при открытом диалоге и под открытой панелью задач.

:::note
Окно «Кнопки» и инструменты кнопок меняют только поле `commands` файла воркспейса, общий `commands.json` и `prompts.json`. Файлы репозиториев Cyborg по-прежнему не правит.
:::
