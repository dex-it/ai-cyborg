Кнопка «Статус» на полосе сессий появляется, когда у проекта включён хотя бы один источник: GitHub, GitLab или Jira. Цветная точка на ней называет худшее состояние проекта, число рядом - сколько записей ждёт вас. Нажатие открывает карточку; закрыть её можно повторным нажатием, кликом мимо или клавишей `Esc`.

| Точка | Что значит |
|---|---|
| Красная | У вашего открытого MR/PR упал пайплайн. |
| Янтарная | К вашему MR есть замечания либо чужой MR ждёт вашего ревью. |
| Синяя | Пайплайны ваших MR идут. |
| Зелёная | Данные получены, ничего не горит. У проекта только с Jira - список задач получен. |
| Серая | Данных нет: нет входа в `gh`/`glab`, нет remote, у проекта только с Jira список задач не получен, или проект ещё не загрузился. Причина написана в карточке. |

Задачи Jira в цвет точки не входят: по списку задач нельзя понять, что требует внимания.

## Карточка

**Jira · на мне.** Открытые задачи, назначенные на вас, свежие первыми, двумя группами: «В работе» и «Остальные открытые». В строке: ключ, название, статус, приоритет, давность обновления и связанные MR с их пайплайном (`#12 ✓`, `#12 ✕`, `#12 …`). MR связан с задачей, если её ключ стоит в названии или ветке MR целым словом, регистр не важен (`dex-12-fix`).

- Клик по ключу раскрывает детали: тип, статус, приоритет, исполнитель, автор, метки, описание и последние три комментария.
- **Открыть в Jira** откроет задачу в браузере.
- **Начать** запускает сессию Claude Code. Первое сообщение - ключ задачи и просьба прочитать её (`jira issue view`), разобраться и предложить план; код сессия не правит, пока вы не подтвердите план. Сессия стартует в репозитории связанного MR, а если связанного MR нет, то в единственном репозитории проекта или в выбранном из меню. Повторное нажатие ведёт к уже открытой сессии.

**Мои MR/PR** и **Ждут моего ревью.** Номер (ссылка в браузер), название, пайплайн, апрувы, причина внимания и ветка; записи с причиной идут первыми.

- **Разобрать пайплайн** - у вашего MR с упавшим пайплайном: сессия ищет причину в логах упавших заданий, переключается на ветку MR и исправляет её.
- **Доработать** - у вашего MR с замечаниями; **Ревью** - у чужого. Те же действия, что на вкладке «MR/PR».
- Если по MR уже идёт сессия, вместо кнопок одна - **К сессии**.

Cyborg ничего не запускает сам: сессию открывает только ваше нажатие.

## Обновление

Данные собираются при выборе проекта, при открытии карточки (если им больше минуты), кнопкой «Обновить» и раз в 5 минут, пока окно на виду. Свёрнутое окно ничего не опрашивает. «Обновить» заново проверяет вход в трекеры.

Если какой-то источник недоступен, карточка называет причину, а остальные показывает: упавший `gh` не прячет задачи Jira и наоборот.

## Настройка Jira

Свойства проекта («Воркспейс → Свойства проекта») → «Источники задач» → галочка **Jira**. Под ней видно, в каком состоянии `jira-cli`: не установлен, не настроен, не вошёл или «вход выполнен». Ниже блок **Проекты Jira**: список проектов, доступных вам (поиск по ключу и названию), галочки до 10 проектов, подсказки «В ветках репозиториев: DEX · 13» по ключам в названиях веток и ввод ключа вручную по Enter. Задачи показываются по выбранным проектам, объединённые по давности обновления; пусто - проект, сохранённый командой `jira init`.

Cyborg читает Jira через [`jira-cli`](https://github.com/ankitpokhrel/jira-cli) и не хранит токен: нужен бинарь в `PATH` и работающий вход (`jira me` называет вас). Подробности - в [требованиях](/start/requirements/).

:::note
Cyborg ничего не пишет в Jira, GitHub и GitLab: ни статусов, ни комментариев. Это делает агент внутри сессии своими инструментами.
:::

:::caution
Формат вывода `jira-cli` проверен по тестам и на живом сервере Jira Server 9.2 (jira-cli 1.7.0); Jira Cloud и Data Center вживую не проверялись. Если список пуст или написано «ответ не JSON», сообщите версию `jira version` и тип Jira (Cloud, Server).
:::
