Cyborg - Electron-приложение на TypeScript. Сессии запускаются в pty ([node-pty](https://github.com/microsoft/node-pty)), терминал - [xterm.js](https://xtermjs.org/), просмотр файлов - [Monaco](https://microsoft.github.io/monaco-editor/). Всё, что умеет Cyborg сверх терминала, он узнаёт из трёх источников: событий хуков Claude Code, вызовов `git` и вызовов `gh` / `glab`.

```text
┌─ окно Cyborg (Electron) ───────────────────────────────┐
│  Интерфейс: терминал, дерево, просмотр                 │
│        ↕  мост preload                                 │
│  Главный процесс ──────────┬── pty ──→ claude (CLI)    │
│        ↑                   │                  │        │
│        └── хуки: каталог, активность ─────────┘        │
│                            ├──→ git                    │
│                            └──→ gh / glab              │
└────────────────────────────────────────────────────────┘
```

## Процессы и граница

- **Интерфейс** (renderer) показывает данные и не обращается к ОС сам: изоляция контекста включена, Node в интерфейсе нет.
- **Мост** (preload) - единственный объект API, через который интерфейс говорит с главным процессом. Запросы с ответом идут вызовом, потоки без ответа (ввод в сессию, размер терминала) - отправкой.
- **Главный процесс** запускает сессии, читает git, вызывает `gh` и `glab`, хранит проекты. Аргументам из интерфейса он не доверяет: смена ветки, история, продолжение сессии, любой запуск сессии (с задачей, MR и просто «Новая сессия») проверяют, что каталог входит в репозитории проекта. Чтение каталогов и файлов и вызовы git для дерева отвечают только по репозиториям проектов, по каталогам работающих сессий (в том числе ушедших командой `cd` из репозитория) и по каталогу, который вы только что выбрали в диалоге; любой другой путь, в том числе с `..`, отклоняется.
