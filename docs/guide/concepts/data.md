## Каталог данных приложения

| Платформа | Путь |
|---|---|
| macOS | `~/Library/Application Support/cyborg` |
| Linux | `~/.config/cyborg` |

| Файл | Что внутри |
|---|---|
| файл воркспейса (например, `~/team.cyborg.json`; прежний вариант - `projects.json` в этом каталоге) | Проекты: название, описание, репозитории, включённые источники задач, настройка Jira (включена ли и выбранные проекты Jira), последний выбранный проект, свои [кнопки-команды](/features/commands/) (поле `commands`). Лежит там, куда вы его положили; запись атомарна (временный файл и переименование). Подробнее - [Воркспейс](#воркспейс). |
| `commands.json` | Общие [кнопки-команды](/features/commands/#свои-кнопки) для всех воркспейсов; кнопки воркспейса ложатся поверх них. Нет файла - действуют встроенные. |
| `prompts.json` | [Промпты кнопок запуска сессий](/features/commands/#промпты-кнопок-запуска-сессий), общие для всех воркспейсов. Нет файла - действуют встроенные. |
| `hubs.json` | Свои [хабы магазинов](/features/extensions/#хабы) (название и https-адрес) и отключённые хабы, в том числе встроенные. Общий для всех воркспейсов. |
| `extensions-usage.json` | Кэш [статистики вызовов](/features/extensions/#статистика-вызовов) окна «Расширения»: по каждому журналу Claude Code его путь, размер, время изменения, прочитанное смещение и счётчики вызовов по ключам (`/скилл`, `agent:имя`, `mcp:сервер`). Содержимого журналов в нём нет. Общий для всех воркспейсов; можно удалить, счёт будет собран заново. |
| `recent-workspaces.json` | «Недавние»: до 10 путей воркспейсов, последний открытый сверху. Общий для всех запущенных Cyborg. |
| `workspaces/` | Настройки интерфейса каждого воркспейса, по одному подкаталогу на файл воркспейса. |
| `trackers.json` | Прежние общие настройки источников. Читается один раз для проектов без своего поля. |
| `claude-hooks.json` | Хуки сессий ([хуки](/concepts/hooks/)). Пишется при каждом запуске. |
| `sessions/` | Файлы событий работающих сессий. Каталог `0700`, файлы `0600`, удаляются с сессией. |
| `remote-claude-token.bin` | Токен входа Claude для удалённых сессий («Воркспейс → Вход Claude на хостах…»), зашифрованный средствами ОС, права `0600`. Если шифрование ОС недоступно, файла нет: токен живёт в памяти до выхода. |

Пути репозиториев при загрузке проекта приводятся к физическим (без символьных ссылок): так их называют git и Claude Code.

## Воркспейс

Воркспейс - файл с набором проектов. Один запущенный Cyborg держит один воркспейс; другой воркспейс открывается отдельным запущенным Cyborg со своим окном и своими сессиями (меню «Воркспейс → Открыть в новом окне…»). «Воркспейс → Открыть…» меняет воркспейс этого окна: работающие сессии завершаются, пока они идут, Cyborg спрашивает подтверждение.

- Запуск без аргументов открывает последний воркспейс из «Недавних»; если он уже открыт в другом окне или файла больше нет, берётся следующий. Если «Недавних» нет, но есть прежний `projects.json`, открывается он как есть, ничего не переносится. Иначе окно предлагает создать воркспейс: имя, файл и первый проект.
- `cyborg --workspace /путь/к/файлу.cyborg.json` открывает указанный файл (относительный путь считается от каталога, из которого вызвана команда, в том числе при запуске через `./cyborg`). Нет значения или указан каталог - окно с причиной, и Cyborg закрывается.
- Файл, открытый в одном окне, во втором не открывается: «Воркспейс уже открыт». Для этого рядом с файлом лежит замок `<файл>.lock` с номером процесса; замок завершившегося процесса не учитывается. Если Cyborg с этим файлом не запущен, а отказ остался, удалите файл замка.
- Размер шрифта, фильтры и сортировка панелей, вид и переключатели поиска, вкладка, область, фильтр и размер окна «Расширения», метки задач по проектам и выключатель уведомлений хранятся отдельно у каждого воркспейса. Если перенести файл воркспейса, проекты останутся, а эти настройки начнутся заново.
- Заголовок окна: «Воркспейс - Проект - Cyborg v.версия» (имя воркспейса, имя выбранного проекта, версия); без проекта - «Воркспейс - Cyborg v.версия», без воркспейса - «Cyborg v.версия».

## Если файл воркспейса повреждён

Cyborg не затирает файл проектов молча.

- **Файл не разобран** (оборван, не JSON, неверная форма). Рядом с файлом появляется копия его байт `<файл>.corrupt-<дата UTC>` (например, `team.cyborg.json.corrupt-20261026T081530`), приложение стартует с пустым перечнем проектов, а окно называет причину, путь копии и путь самого файла. Чтобы вернуть проекты: закройте Cyborg, исправьте копию и положите её на место файла воркспейса.
- **Файл не прочитан** (нет прав доступа). Окно называет код ошибки, запись в файл отключена, пока он недоступен: файл не будет затёрт. Исправьте доступ и перезапустите Cyborg.

Копии приложение не удаляет: уберите их сами, когда они станут не нужны.

Настройки интерфейса хранятся в самом окне (в каталоге `workspaces/`) и переживают перезапуск.

## Чего Cyborg не хранит

- **Токены.** `gh` и `glab` работают под своим входом: панель задач и MR их токенов не читает. Исключение - удалённые сессии: при запуске и пробуждении Cyborg берёт токены `gh auth token` и `glab config get token`, держит их в памяти и передаёт на хост окружением агента, на диск они не пишутся. Токен входа Claude для хостов, который вы задали сами, хранится зашифрованным (`remote-claude-token.bin`).
- **Содержимое сессий.** Журналы пишет Claude Code в `~/.claude/projects`. Cyborg читает их для списка истории и для статистики вызовов в окне «Расширения» (во втором случае все журналы, а не только открытых проектов; в `extensions-usage.json` остаются только счётчики) и удаляет только ту сессию, которую вы выбрали.
- **Свой клиент модели.** Работает только локальный `claude`.

## Что Cyborg пишет

- В каталог данных приложения: файлы из таблицы выше (`commands.json`, `prompts.json`, `hubs.json`, `extensions-usage.json`, `recent-workspaces.json`, `claude-hooks.json`, `sessions/`, `workspaces/`, `remote-claude-token.bin`). Прежний `trackers.json` только читается.
- Рядом с файлом воркспейса: сам файл воркспейса (проекты и кнопки команд из его поля `commands`), замок `<файл>.lock`, копия `<файл>.corrupt-<дата UTC>` при повреждении.
- В Claude Code: только вызовом `claude plugin install`, `uninstall` и `marketplace add`/`remove` из окна «Расширения» по вашему подтверждению. Что и куда пишет `claude`, решает он сам: настройки пользователя, личные настройки репозитория либо, в области «Проект», `.claude/settings.json` репозитория ([безопасность](/concepts/git-safety/#расширения)). На этой машине напрямую в настройки Claude Code Cyborg не пишет.
- На хост SSH удалённых сессий, в учётную запись, под которой вы входите: зеркало вашего `~/.claude` (`CLAUDE.md`, `settings.json`, `hooks/`, `commands/`, `agents/`, `skills/`, `output-styles/`, `bin/`) в `~/.claude` хоста (прежний файл хоста с тем же именем сохраняется как `.cyborg-orig`), перечень зеркальных файлов в `~/.cyborg/config.json` (снятые у вас файлы удаляются и на хосте), плагины - вызовом `claude plugin` на хосте, в `~/.claude.json` хоста - пройденный онбординг и доверие к каталогам клонов, память проекта - под каталогом клона в `~/.claude/projects`. Каталоги сессий и клоны лежат в `~/.cyborg`; конфиг MCP сессии с токеном (права `0600`) удаляется при её выходе и сне.
- Журнал сессии удаляется (вместе с каталогом её вывода инструментов) только по вашему подтверждению в списке истории.
- В репозиторий: только файл Markdown, который вы правите в просмотре и сохраняете сами (`Ctrl+S` или «Сохранить»). Других файлов репозитория Cyborg не меняет.

В трекеры, MR и Jira Cyborg не пишет.

## Сеть

Сам Cyborg выходит в сеть в одном случае: окно «Расширения», вкладка «Хабы». Это запросы GET по https без токенов и cookie: к `api.github.com` (поиск по теме) и `raw.githubusercontent.com` (проверка каталогов найденных репозиториев) для хаба «GitHub: поиск по теме» и по адресам ваших хабов. Остальные обращения идут через программы под вашим входом:

- `gh` и `glab` - задачи, MR и пайплайны ([задачи и MR](/features/tasks-mrs/));
- `jira-cli` - задачи Jira ([статус](/features/status/));
- `claude plugin ...` - установка, удаление, подключение магазина (`claude` клонирует магазины и плагины);
- `claude mcp list` - только по кнопке «Проверить связь», серверы MCP сами ходят по сети;
- ссылки (задача, MR, страница магазина) открываются браузером системы.

Остальное (git, терминал, файлы, журналы) локально.
