title: "Хуки и слежение за сессией"
description: "Как Cyborg узнаёт рабочий каталог и активность сессии, не подменяя Claude Code."
---

Сессия остаётся нативной: Cyborg не оборачивает `claude`, а запускает его командой

```text
$SHELL -lc 'exec claude --settings "$CYBORG_SETTINGS" "$@"' cyborg <аргументы>
```

Логин-шелл даёт `PATH` пользователя (приложение из меню ОС стартует без `~/.local/bin`). Аргументы: `--append-system-prompt` с инструкцией об изоляции, при продолжении сессии `--resume <id>`, первое сообщение (для сессии по задаче или MR), затем `--add-dir` для остальных репозиториев проекта.

## Хуки

Через `--settings` Cyborg подключает к сессии свои хуки, не трогая ваших настроек Claude Code. Файл `claude-hooks.json` лежит в [каталоге данных](/concepts/data/); события `SessionStart`, `UserPromptSubmit`, `PostToolUse` и `Stop`. Каждый хук дописывает JSON события в файл этой сессии (`$CYBORG_EVENTS`).

Cyborg следит за файлом и берёт из события две вещи:

- **рабочий каталог** (`cwd`): когда он меняется - например, сессия ушла в worktree, - дерево переходит в новый корень;
- **факт активности**: после события дерево обновляется.

Файлы событий закрыты от других пользователей машины (каталог `0700`, файлы `0600`), потому что в событиях есть пути и имена инструментов. Файл удаляется, когда сессия завершается; файлы убитого экземпляра убираются при следующем запуске.

## Чего хуки не дают

События приходят от Claude Code. Если сессия сменила каталог без вызова инструмента (например, возобновлённая сессия сама вернулась в worktree), дерево перейдёт за ней с первым событием.

Изменения файлов вне сессии хуков не порождают, их подхватывает опрос `git status` раз в три секунды, пока окно видно.
