Сессия остаётся нативной: Cyborg не оборачивает `claude`, а запускает его командой

```text
$SHELL -lc 'exec claude --settings "$CYBORG_SETTINGS" [--plugin-dir "$CYBORG_PLUGIN"] [--mcp-config "$CYBORG_MCP"] "$@"' cyborg <аргументы>
```

Логин-шелл даёт `PATH` пользователя (приложение из меню ОС стартует без `~/.local/bin`). Ключи в квадратных скобках появляются, только если у сессии есть что подключать: `--mcp-config` - когда MCP-сервер Cyborg слушает ([делегирование](/features/delegation/)), `--plugin-dir` - когда есть каталог плагина Cyborg. Переменные `CYBORG_MCP` и `CYBORG_PLUGIN` ставятся только вместе с ключами; значения родительской сессии, если Cyborg запущен из неё, перед запуском удаляются. Аргументы: `--append-system-prompt` с инструкцией об изоляции, инструкцией предлагать [кнопки](/features/commands/#кнопки-которые-предлагает-модель) и, если у сессии есть и MCP, и плагин, коротким поводом делегировать работу другим сессиям; при продолжении сессии `--resume <id>`, первое сообщение (для сессии по задаче или MR, а у дочерней - задание родителя), затем `--add-dir` для остальных репозиториев проекта.

## Хуки

Через `--settings` Cyborg подключает к сессии свои хуки, не трогая ваших настроек Claude Code. Файл `claude-hooks-<хеш>.json` лежит в [каталоге данных](/concepts/data/), хеш - от содержимого: Cyborg другой версии, запущенный рядом, не подменит сессиям набор хуков; события `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `SubagentStop`, `Stop` и `Notification`. Каждый хук дописывает JSON события в файл этой сессии (`$CYBORG_EVENTS`). Упавший инструмент Claude Code сообщает событием `PostToolUseFailure`, а не `PostToolUse`: Cyborg считает оба, как и `PreToolUse`, признаком работы сессии (лампа на вкладке, состояние `working`, снятие предложенных кнопок). По `PreToolUse` и `Post*` с одним `tool_use_id` Cyborg знает, какие вызовы инструментов сейчас идут: пока идёт вызов, на экране может появиться запрос разрешения, и сообщение другой сессии [ждёт в очереди](/features/delegation/). Хуки подключаются к сессии при её запуске: уже открытая сессия получит новое событие после перезапуска.

Cyborg следит за файлом и берёт из события:

- **рабочий каталог** (`cwd`): когда он меняется - например, сессия ушла в worktree, - дерево переходит в новый корень;
- **факт активности**: после события дерево обновляется, а лампа вкладки заливается;
- **состояние и контекст сессии**: `starting`, `working`, `waiting` или `asking` для инструментов [делегирования](/features/delegation/), первый и последний запрос и название разговора для [подсказки вкладки](/features/sessions/#подсказка-вкладки); номер разговора дочерней сессии для пометки в «Истории»;
- **предложенные кнопки**: из `last_assistant_message` события `Stop` берётся комментарий `<!-- cyborg-buttons: [...] -->` в конце ответа, если он есть;
- **ожидание человека**: по нему приходит [уведомление на рабочий стол](/features/sessions/#уведомления). Сессия ждёт после `Stop`, если за 30 секунд от неё не пришло других событий и у неё нет фоновых задач и запланированных пробуждений (иначе она продолжит сама), и сразу после `Notification` одного из типов: `permission_prompt`, `elicitation_dialog`, `elicitation_url_dialog`, `agent_needs_input`, `quota_auto_resume_stale`, `quota_auto_resume_disabled`. Остальные типы `Notification` - напоминания и сообщения о ходе работы, ответа они не ждут; `idle_prompt` повторяет `Stop` через минуту.

Файлы событий закрыты от других пользователей машины (каталог `0700`, файлы `0600`), потому что в событиях есть пути и имена инструментов. Файл удаляется, когда сессия завершается; файлы убитого экземпляра убираются при следующем запуске.

## Хуки плагина Cyborg

Это отдельный набор, не путать с хуками событий выше. Плагин Cyborg, который подключается ключом `--plugin-dir`, приносит собственные хуки Claude Code; в файл событий они ничего не пишут. Сейчас один:

| Хук | Событие | Что делает |
|---|---|---|
| `lsp-reap` | `PostToolUse` для `EnterWorktree`, `ExitWorktree` и `Bash`, таймаут 10 с | Останавливает языковой сервер сессии, который остался в удалённом каталоге или после смены worktree в прежнем; Claude Code поднимает его заново в текущем каталоге при следующем обращении. Нужен `/proc`, поэтому на macOS хук ничего не делает |

Подробности и зачем это нужно - в разделе [«Хук lsp-reap»](/features/delegation/#хук-lsp-reap) страницы о делегировании. Хук есть у локальных сессий; удалённые плагин Cyborg не получают.

## Чего хуки не дают

События приходят от Claude Code. Если сессия сменила каталог без вызова инструмента (например, возобновлённая сессия сама вернулась в worktree), дерево перейдёт за ней с первым событием.

Изменения файлов вне сессии хуков не порождают, их подхватывает опрос `git status` раз в пять секунд. Он идёт только в окне с фокусом; когда окно получает фокус обратно, опрос выполняется сразу.
