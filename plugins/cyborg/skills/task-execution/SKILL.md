# Задача под ключ

Тебе поручили результат, а не шаги: постановщик ждёт только итог. Спроектировать, реализовать, проверить - твоё. Спрашивай постановщика, только когда без ответа не продолжить: задание противоречит коду или само себе, нужна чужая граница. Цель - результат не хуже, чем у одной сильной сессии, с наименьшей общей ценой: время, токены всех участников, прогоны.

## 1. Прочитай и оцени

- Задание целиком и инструкции проекта для путей задачи: `CLAUDE.md` корня и каталогов, правила `.claude/rules/`. Принятый порядок работы (этапы, треки, гейты, корпус требований) обязателен.
- Жанр: баг, фича, проектирование, исследование, ревью, механика.
- Уровень задания: дана цель - план твой; дан план - сверь с кодом и делай; даны конкретные правки - делай как написано.
- Размер. Правка в пару файлов с ясным местом - делай сама целиком: субагент дороже - ему нужны свой контекст, бриф и приёмка.

## 2. Скиллы - до первого файла

Список скиллов у тебя в контексте, но в длинном списке описания обрезаны, и сами по себе скиллы не срабатывают: просмотри список и выбери по жанру и стеку (язык и фреймворк - по манифесту в корне). Загрузи подходящие до первой правки; скиллы, названные в задании, - обязательно. Подробное задание не отменяет загрузку: в нём сказано, что сделать, а в скилле - как это делать в этом стеке и этом проекте.

## 3. Сама или субагенты

Субагент окупается, когда:
- часть отделима и возвращает короткий вывод - широкий поиск по коду, разбор причины, ревью, проверка;
- нужна независимость - проверяет не тот, кто писал;
- части независимы и идут параллельно - одним сообщением;
- часть по силам младшей модели, а ты на старшей.

Не окупается: кусок, бриф на который не короче самой работы; работа, которой нужна вся твоя история.

Тип субагента подбирай по этапу из списка доступных тебе, по описанию:

| Этап | Что искать в списке типов |
|---|---|
| Широкий поиск по коду, где что лежит | `Explore` |
| Причина бага, воспроизведение красным тестом | debugger, root-cause |
| Проект решения, план реализации | `Plan`, architect, designer |
| Реализация по плану | кодер стека, иначе `general-purpose` |
| Тесты к готовому коду | test-writer стека |
| Ревью своей правки | self-review, reviewer, security-review |

Нет подходящего типа - `general-purpose` либо сама.

## 4. Модель и effort субагента

Без `model` и `effort` субагент наследует твою модель - обычно самую дорогую. Задавай оба явно:

| Работа субагента | model / effort |
|---|---|
| Поиск без суждений: найти файл, символ, значение; запустить проверку и вернуть код выхода | `haiku` / `low` |
| Правка по готовому плану, поиск с отбором и выводами | `sonnet` / `low`–`medium` |
| Код и тесты по ясной постановке | `sonnet` / `medium` |
| Отладка: цель ясна, место нет | `sonnet` / `high` |
| Проект, план, неизвестная причина, рискованное ревью | `opus` / `high`, тяжёлое - `xhigh` |

`fable` на исполнение не ставь. Правило человека из памяти о выборе модели сильнее таблицы.

Бриф субагенту: чем дешевле модель, тем больше решений принято в брифе - файлы, контракт, граничные случаи, команда проверки. В брифе строка «До первого файла загрузи скиллы, подходящие задаче и стеку; в ответе перечисли загруженные» и форма короткого ответа: статус, файлы, проверка с кодом выхода, отступления от брифа.

## 5. Проверка

Готово - когда критерий задания проверен командой и она прошла, а не когда субагент сказал «готово». Его итог сверь с брифом по диффу. Провал - повтор с хвостом провала в брифе: не та работа - уточни бриф; неверная правка - модель на ступень выше. Причина в окружении - нет ключа, сети, прав - моделью не лечится: сдавай `blocked`.

## 6. Итог

Сдай итог так, как велит задание; дочерняя Cyborg - вызовом `report_done`. В итоге: что сделано, проверка - команда и код выхода, какие скиллы загружены и каких субагентов на какой модели запускала, отступления от задания, вопросы. Упёрлась - выясненное и причина, без перебора до лимита.
